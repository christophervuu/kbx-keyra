## Summary

Create comprehensive unit tests for the `suggest-expression` Lambda handler at `tests/lambda/ai/suggest-expression.test.ts`. Tests follow the identical pattern established by `tests/lambda/ai/explain-rule.test.ts`: mock `invokeAI` via `vi.hoisted()` + `vi.mock()`, use dynamic `import()` for the handler, and cover all 15 acceptance examples from the spec including valid requests, all required field validation cases, empty string rejection, optional field defaults, variable mapping, AI error code mapping, unexpected exception handling, and header verification.

## Change Requirements

Create `tests/lambda/ai/suggest-expression.test.ts` with:

1. **Mock setup** (matching explain-rule pattern):
   ```typescript
   const invokeAIMock = vi.hoisted(() => vi.fn());
   vi.mock('../../../src/lib/ai/index.js', () => ({
     invokeAI: invokeAIMock,
   }));
   ```

2. **Helper function**:
   ```typescript
   function createEvent(body: string | null): APIGatewayProxyEvent {
     return { body, headers: {} };
   }
   ```

3. **Test describe block**: `'aiSuggestExpression handler'`

4. **beforeEach**: `invokeAIMock.mockReset()` and `vi.resetModules()`

5. **Required test cases** (each using dynamic `import()` for handler):

   | Test | AE | Assertion |
   |---|---|---|
   | Valid request returns 200 with AI result | AE-01 | status 200, `success: true`, has `data`, `promptId: 'nl-to-rule'`, has `model`, invokeAI called with correct args |
   | Missing instruction returns 400 | AE-02 | status 400, error message mentions `instruction` |
   | Missing targetPath returns 400 | AE-03 | status 400, error message mentions `targetPath` |
   | Missing targetType returns 400 | AE-04 | status 400, error message mentions `targetType` |
   | Missing sourceContext returns 400 | AE-05 | status 400, error message mentions `sourceContext` |
   | Empty string for required field returns 400 | AE-06 | status 400, error message for first empty required field |
   | Missing targetDescription defaults to empty string | AE-07 | invokeAI called with `targetDescription: ''` |
   | sourceContext maps to sourceFields variable | AE-08 | invokeAI called with `sourceFields` key (not `sourceContext`) |
   | Null body returns 400 | AE-09 | status 400, `Invalid request body` |
   | Invalid JSON body returns 400 | AE-10 | status 400, `Invalid request body` |
   | PROMPT_NOT_FOUND maps to 404 | AE-11 | status 404 |
   | MODEL_RATE_LIMITED maps to 429 | AE-12 | status 429 |
   | Unknown AI error maps to 500 | AE-13 | status 500 |
   | Unexpected exception returns 500 with synthetic error | AE-14 | status 500, body contains `MODEL_ERROR` and `nl-to-rule` |
   | All responses include CORS and JSON headers | AE-15 | headers check on any response |

6. **Variable mapping verification** (AE-07 and AE-08):
   - For AE-07: Assert `invokeAIMock` was called and the second argument has `targetDescription: ''`
   - For AE-08: Assert the second argument has key `sourceFields` matching the request's `sourceContext` value, and does NOT have key `sourceContext`

7. **Valid request fixture** for AE-01 test:
   ```json
   {
     "instruction": "default currency to USD if missing",
     "targetPath": "Order.Header.CurrencyCode",
     "targetType": "string",
     "targetDescription": "ISO currency code for the document",
     "sourceContext": "- InvoiceCurrency (string)\n- Header.Currency (string)"
   }
   ```
