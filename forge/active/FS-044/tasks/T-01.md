## Summary

Create the `suggest-expression.ts` Lambda handler at `src/lambda/ai/suggest-expression.ts` following the identical pattern established by `explain-rule.ts`. This thin handler parses the API Gateway event body, validates required fields, maps request variables to prompt placeholders, calls `invokeAI('nl-to-rule', variables)`, and returns the standard AI response envelope with appropriate HTTP status codes and CORS headers.

---

## Scope

### In Scope

- New file: `src/lambda/ai/suggest-expression.ts`
- Inline `APIGatewayProxyEvent` / `APIGatewayProxyResult` interfaces (same as explain-rule)
- `jsonResponse()` utility function
- `statusCodeForAIError()` mapping function
- `parseRequestBody()` utility function
- Input validation for 4 required string fields: `instruction`, `targetPath`, `targetType`, `sourceContext`
- Empty-string rejection for required fields (empty strings treated as missing)
- Optional `targetDescription` field with empty-string default
- Variable mapping: request `sourceContext` -> invokeAI variable `sourceFields`
- `invokeAI('nl-to-rule', variables)` call
- HTTP status code mapping: success -> 200, `PROMPT_NOT_FOUND` -> 404, `MODEL_RATE_LIMITED` -> 429, `VALIDATION_ERROR` -> 400, default -> 500
- Top-level try/catch returning 500 with synthetic error for unexpected exceptions
- CORS headers (`Content-Type: application/json`, `Access-Control-Allow-Origin: *`) on all responses
- Exported `handler` function, exported `APIGatewayProxyEvent` and `APIGatewayProxyResult` types

### Out of Scope

- Local test fixtures (T-03)
- Architecture documentation updates (T-04)
- Any changes to the shared AI runtime (`src/lib/ai/`)
- Extracting shared handler utilities from explain-rule — duplicate for now

## Change Requirements

The new handler file must:

1. **Import** `invokeAI` and `AIErrorCode` from `../../lib/ai/index.js`

2. **Export** `APIGatewayProxyEvent` and `APIGatewayProxyResult` interfaces (identical to explain-rule)

3. **Implement** `jsonResponse(statusCode, payload)` — identical to explain-rule

4. **Implement** `statusCodeForAIError(code: AIErrorCode)` — identical to explain-rule:
   - `PROMPT_NOT_FOUND` -> 404
   - `MODEL_RATE_LIMITED` -> 429
   - `VALIDATION_ERROR` -> 400
   - default -> 500

5. **Implement** `parseRequestBody(body: string | null)` — identical to explain-rule

6. **Implement** `handler(event: APIGatewayProxyEvent)` with this logic:
   - Parse request body via `parseRequestBody()` — return 400 on failure
   - Validate `instruction` is a non-empty string — return 400 on failure
   - Validate `targetPath` is a non-empty string — return 400 on failure
   - Validate `targetType` is a non-empty string — return 400 on failure
   - Validate `sourceContext` is a non-empty string — return 400 on failure
   - Read `targetDescription` — default to `""` if missing or not a string
   - Build variables map:
     ```typescript
     {
       instruction,
       targetPath,
       targetType,
       targetDescription,
       sourceFields: sourceContext,  // name mapping
     }
     ```
   - Call `invokeAI('nl-to-rule', variables)` inside try/catch
   - Return 200 with result on success
   - Map AI error code to HTTP status on failure
   - Return 500 with synthetic error on unexpected exception (promptId: `'nl-to-rule'`)

7. **Validation order**: instruction, targetPath, targetType, sourceContext — this order is deterministic and testable

8. **Empty string check**: For each required field, validate both `typeof field !== 'string'` and `field === ''` (or use `!field` after the type check, since empty string is falsy). This is a divergence from explain-rule which does not check for empty strings. The spec requires it (AE-06).

## Notes

- The handler is intentionally a near-copy of `explain-rule.ts`. The main differences are: (1) four required fields instead of two, (2) one optional field with a default, (3) `sourceContext` -> `sourceFields` variable mapping, (4) promptId is `'nl-to-rule'` instead of `'explain-rule'`, (5) empty-string validation on required fields.
- The empty-string validation is a minor enhancement over the explain-rule pattern. If `explain-rule.ts` is later updated to also reject empty strings, this Lambda is already consistent with that behavior.
- Do not extract shared utilities (jsonResponse, statusCodeForAIError, parseRequestBody) into a shared module as part of this task. Duplication is acceptable for the second Lambda. Extraction should be considered if a third Lambda is added.
