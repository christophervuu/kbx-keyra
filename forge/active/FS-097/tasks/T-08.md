## Summary

Perform technical discovery to catalog legacy conditional draft state shapes and validate whether per-usage transform chains can be reconstructed losslessly. Establish deterministic fallback criteria that preserve original DSL and require Advanced DSL when reconstruction is not lossless.

---

## Scope

### In Scope

- Inventory historical slot-based conditional draft shapes from current fixtures/storage paths.
- Define lossless reconstruction criteria for per-usage transform chains.
- Build fixture-based discovery tests for representable and non-representable legacy patterns.
- Define explicit fallback signals used by migration execution task.

### Out of Scope

- Shipping full migration UI behavior (implemented in T-09).
- Rewriting or normalizing unsupported DSL to fit guided mode.

---

## Relevant Areas

- `ui/src/features/mappings/lib/smart-builder-state.ts`
- `ui/src/features/mappings/lib/*decomposer*.ts`
- `ui/src/features/mappings/lib/*smart-builder*.test.ts`
- Legacy draft fixtures/storage adapters used in mapping editor tests

---

## Change Requirements

- Discovery must identify all known legacy conditional slot-state variants used in active code/test fixtures.
- Lossless reconstruction criteria must be deterministic and testable.
- Non-lossless patterns must be explicitly flagged for Advanced-only fallback.

---

## Verification Requirements

- Discovery test suite covering legacy variants and transform-chain recovery outcomes.
- Documented criteria embedded in code comments/tests for migration handoff.

---

## Acceptance Checks

- Inventory of legacy conditional draft shapes exists in tests/docs associated with migration code.
- Lossless vs non-lossless outcomes are deterministically asserted.
- Fallback criteria ensure original DSL preservation and Advanced-only routing for non-lossless cases.
- Tests pass for discovery coverage.

---

## Blockers / Risks

- Legacy draft variants may exist outside currently maintained fixtures.

---

## Notes

- This task intentionally front-loads risk before migration execution.
