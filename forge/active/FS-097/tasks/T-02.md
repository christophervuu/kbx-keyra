## Summary

Implement the Input Tray redesign with grouped rows by input origin, schema type badges, sample states, usage labels, remove actions, and reusable non-consuming behavior.

---

## Scope

### In Scope

- Tray header (`Inputs N`, `+ Add input`) and grouped list rendering.
- Row metadata: display name, path, schema type badge, sample display/state, usage indicator.
- Multiple-usage disclosure (`Used N×` details).
- Remove flow UX for unused vs referenced fields.
- Independent tray scrolling/max-height behavior.

### Out of Scope

- Source Browser mode internals.
- DSL parsing/generation logic beyond usage display inputs.

---

## Relevant Areas

- `ui/src/features/mappings/components/InputTray.tsx`
- `ui/src/features/mappings/components/SmartBuilderPanel.tsx`
- `ui/src/features/mappings/components/*.test.tsx`

---

## Change Requirements

- Tray must be method-independent shell UI and remain mounted/visible across method changes.
- Group rows by input document when multiple origins exist; preserve first-seen group order.
- Prevent duplicate tray rows using input+path identity.
- Tray row selection with no active value must not place data unexpectedly.
- Implement deterministic density/scroll rule (>5 rows or >320px content height).
- Referenced-field remove requires explicit confirmation listing all affected usages.

---

## Verification Requirements

- Component tests for grouping, badges, sample formatting, usage labels, and scroll behavior.
- Tests for duplicate-prevention and referenced remove confirmation behavior.
- Accessibility checks for row focusability and accessible labels.

---

## Acceptance Checks

- Tray remains visible/mounted across supported method changes and preserves contents.
- Tray renders grouped multi-input rows with required metadata.
- Tray items are reusable and never consumed by selection.
- Deterministic density/scroll threshold behavior is implemented (>5 rows or >320px).
- Referenced removal requires confirmation and clears usages atomically (AE-07).
- Multi-usage state for reused fields is visible.
- Tests pass for tray component behavior and accessibility semantics.
