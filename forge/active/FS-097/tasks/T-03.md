## Summary

Add distinct source-selection modes for adding staged tray inputs versus filling currently active values, and implement deterministic Source panel click routing in Direct/Conditional contexts with duplicate suppression.

---

## Scope

### In Scope

- Add-to-Tray mode with multi-select and explicit add action.
- Fill-Current-Value mode with single-select and immediate active-value placement.
- Source panel click routing matrix behavior (Direct empty/assigned, Conditional active/inactive).
- Auto-add selected field to tray when filled from outside tray.
- Distinct mode labeling/messaging and return-focus behavior.

### Out of Scope

- Full Source Browser IA redesign beyond mode state and selection semantics.

---

- `ui/src/features/mappings/components/SourceSchemaPanel.tsx`

## Change Requirements

- Add-to-Tray mode must not mutate active conditional values.
- Fill-Current-Value mode must fill active value and then advance focus where appropriate.
- Source panel clicks must follow FS-097 routing matrix and avoid accidental expression replacement.
- Duplicate tray entries are prevented in both modes.

---

## Verification Requirements

- Component/integration tests for both mode flows and focus return.
- Tests confirming newly selected fill-field is added to tray if missing.
- Tests covering source click behavior across Direct/Conditional matrix states.

## Acceptance Checks

- Add-to-Tray and Fill-Current-Value are visibly distinct and functionally correct.
- Multi-select add appends grouped rows without duplicates.
- Fill selection populates active value, updates usage, and returns to builder.
- Source panel click behavior matches routing matrix and avoids accidental direct-expression replacement.
- Tests pass for mode behavior and duplicate-prevention.
