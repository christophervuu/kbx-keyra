## Summary

Build the Source Data Input component — a textarea for entering JSON source data with real-time JSON validation, inline error display, and integration with PreviewContext to publish valid parsed data for consumption by other panels (including FS-011's expression preview).

---

## Scope

### In Scope

- New file `ui/src/features/mappings/components/preview/SourceDataInput.tsx`
- Textarea for JSON input with monospace font styling
- Real-time JSON validation on change (with lightweight debounce)
- Inline error message showing parse error details (position)
- Publishes valid parsed JSON to PreviewContext
- Sets PreviewContext sourceData to null when JSON is invalid
- Passes raw string to usePreviewExecution as sourceDataRaw
- Integration into PreviewPanel (placed above or beside tabs, per layout)

### Out of Scope

- JSON syntax highlighting (Phase 0 — plain textarea is acceptable)
- Schema-aware validation of source data structure
- File upload for source data

---

## Relevant Areas

- `ui/src/features/mappings/components/preview/SourceDataInput.tsx` (new)
- `ui/src/features/mappings/components/preview/PreviewPanel.tsx` (integration)
- `ui/src/features/mappings/context/preview-context.tsx` (updates sourceData)

---

## Change Requirements

- Textarea with:
  - Monospace font (`font-mono`)
  - Placeholder text: `Paste or type JSON source data...`
  - Resize handle (vertical)
  - Min height ~80px, adapts to available space
- On change:
  - Attempt `JSON.parse(value)`
  - If valid: clear error, update PreviewContext sourceData with parsed object, pass raw string to execution hook
  - If invalid: show error message below textarea with parse error details, set PreviewContext sourceData to null
- Error display:
  - Red text below textarea
  - Shows error message from `JSON.parse` catch (e.g., "Unexpected token } at position 18")
- Debounce validation by ~150ms to avoid excessive parsing during typing
- Empty textarea: no error shown, sourceData is null, Run button disabled

---

## Verification Requirements

- Valid JSON clears error and updates context
- Invalid JSON shows error and sets context to null
- Empty input shows no error
- Debounce prevents excessive re-parsing
- `tsc --noEmit` passes
- Component test covers valid/invalid/empty states

---

## Acceptance Checks

- Entering `{"x": 1}` clears error state and publishes parsed data to PreviewContext
- Entering `{"x": 1,}` shows inline error with position info
- Empty textarea shows no error, context sourceData is null
- `tsc --noEmit` passes
- `forge/architecture/project-structure.md` updated if new files created
