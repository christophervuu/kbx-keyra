## Summary

Adjust the ChainStepCard expanded body layout and TransformStepForm padding to ensure parameter inputs use the full available width. Currently, multiple layers of padding (card → body → form → slot) compress the effective input width. This task reduces unnecessary nesting so parameters feel like the primary editing surface.

---

## Scope

### In Scope

- Reduce `ChainStepCard` expanded body internal padding: change from `px-3 py-3` (or current) to `px-2 py-3` or `px-0 py-3` as appropriate
- Ensure `TransformStepForm` does not add redundant horizontal padding when rendered inside `ChainStepCard`
- Ensure `ParameterValueInput` inputs render at full available width within the card body
- Verify that the function change dropdown (ChevronDown in `TransformStepForm`) still works correctly
- Verify collapsed state rendering is unaffected
- Visual verification that the step card body feels spacious and primary

### Out of Scope

- Changes to ChainStepCard collapsed header styling
- Changes to the step picker or [+ Add Step] button layout
- ChainBuilder overall spacing between steps
- ScalarFieldBuilder/ArrayBuilder shell changes (FS-051)

## Change Requirements

- In `ChainStepCard`, reduce the expanded body container padding to minimize dead space between card edge and input content
- In `TransformStepForm`, ensure the root container does not add left/right padding that compounds with parent padding
- The resulting effective horizontal space for parameter inputs should be: card border → ~8-12px padding → input edge (no more than 12px total from card visual boundary to input)
- Preserve the card's border, rounded corners, and expand/collapse animation behavior
- Preserve the remove-step (X) button positioning in the card header
