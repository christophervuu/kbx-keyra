## Summary

Create the new `ParameterValueInput` component that implements the intent-based mode model (Source/Static/Item/Options/Expression-as-secondary). This is the foundation component that replaces the mode toggle and value entry portion of `ArgumentSlotInput`. It emits the same `ArgumentSlot` shapes as today to preserve backward compatibility with all consumers.

---

## Scope

### In Scope

- Create `ui/src/features/mappings/components/ParameterValueInput.tsx`
- Implement the primary mode toggle (segmented control) with Source, Static, conditional Item/Options segments, and External (disabled/coming-soon) chip
- Implement the "Use advanced expression" inline secondary action (text link directly below the toggle, inside the parameter card)
- Implement mode → `ArgumentSlot` emission mapping (Source → `makeSourceSlot`, Static → `makeLiteralSlot`, Options → `makeLiteralSlot`, Expression → `makeExpressionSlot`)
- Implement basic Source mode: text input with combobox field picker (reuse existing pattern from `ArgumentSlotInput`)
- Implement basic Static mode: text input with placeholder
- Implement External chip: disabled visual treatment (`opacity-50`, non-interactive, `aria-disabled="true"`, tooltip on hover)
- Implement Expression mode trigger: opens `TransformFunctionPicker`, renders nested function form, provides "Back to simple input" escape
- Export `ParameterValueInputProps` and `ParameterOptions` interfaces

- Preserve `aria-label`, `role="group"`, `role="radio"` accessibility patterns from current mode toggle

## Change Requirements

- Create `ParameterValueInput` as a functional React component accepting `ParameterValueInputProps`
- The mode toggle renders only primary modes: Source (or Item when `isItemContext`), Static, Options (when `options` prop is provided), and External (disabled/coming-soon, shown by default when `showExternal !== false`)
- "Expression" is never rendered in the segmented toggle — it is accessible only via a secondary "Use advanced expression" text link rendered **inline directly below the toggle** inside the parameter card (not in a footer area)
- The "Use advanced expression" link uses subtle styling: `text-[11px] text-zinc-500 hover:text-blue-400` — positioned as a contextual escape hatch for that specific parameter
- When the expression link is clicked, open `TransformFunctionPicker` (same component as today's expression mode); on function selection, switch internal state to expression mode and render nested `ArgumentForm` for the selected function
- When in expression mode, show a "Back to simple input" link that returns to the previous primary mode (discarding expression state with confirmation if non-trivial)
- External chip in toggle: `opacity-50 cursor-not-allowed` styling, `aria-disabled="true"`, tooltip on hover: "External data sources — available in a future release", no click handler
- Mode toggle uses the same visual pattern as existing: `inline-flex rounded border border-slate-700 overflow-hidden text-xs` with active `bg-blue-700 text-white` and inactive `bg-zinc-800 text-zinc-400`
- Each mode change calls `onSlotChange` with the appropriate `ArgumentSlot` factory
- Source mode: render combobox text input with optional suggestion dropdown (using `sourceOptions` + `SourceFieldOptionRow`); emit `makeSourceSlot(path)`
- Static mode: render text input; emit `makeLiteralSlot(value)`
- Item mode: render item-scoped field picker; emit `makeExpressionSlot({ functionName: 'item', slots: [makeLiteralSlot(path)] })`
- The component maintains local state for each mode's value (source path, literal value) so switching modes preserves previously-entered values (same as current `ArgumentSlotInput` behavior)
