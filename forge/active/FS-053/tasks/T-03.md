## Summary

Refine the Static mode in `ParameterValueInput` to provide clear empty string handling UX. Users should understand that leaving a text input empty produces a blank/empty string value without needing to type quotes. The UI should distinguish between required-but-empty (validation warning) and optional-and-empty (valid, treated as empty string).

---

## Scope

### In Scope

- Update Static mode placeholder text: for optional string parameters, use "Leave empty for blank value" or equivalent
- For required parameters, use "Enter a value…" as placeholder
- Implement interaction-state-based empty string model: track whether user has interacted (focused) with the input
- For untouched required parameters: show amber "Required" unmet indicator
- For interacted-but-empty required parameters: show helper text "Leave blank to use an empty string" — the required indicator transitions to a softer state
- For optional parameters with empty value: no validation warning; render subtle helper text: "Empty = blank text (empty string)"
- Ensure no quotes or DSL syntax are visible to the user in Static mode
- For number-typed parameters: placeholder "Enter a number…"; empty is invalid regardless of required flag
- Add/update tests for empty handling behavior including interaction state
- Update `ParameterValueInput` component and tests

### Out of Scope

- Changes to how `makeLiteralSlot('')` is consumed downstream (engine handles empty strings already)
- No checkbox or chip for "intentionally blank" — this decision is final per Q2 resolution
- Integration with `ArgumentForm` (T-04)

## Change Requirements

- Track interaction state: add internal `hasInteracted` boolean (set to true on input focus/blur)
- Static mode input renders different placeholder text based on `parameter.required` and `parameter.type`:
  - String, optional: "Leave empty for blank value"
  - String, required: "Enter a value…"
  - Number, required/optional: "Enter a number…"
  - Any other type: "Enter a value…"
- When `parameter.required && !hasInteracted && literalValue === ''`: show amber "Required" badge (unmet state — user hasn't engaged yet)
- When `parameter.required && hasInteracted && literalValue === ''`: show softer helper text "Leave blank to use an empty string" — the amber "Required" badge is removed or softened, indicating user made a deliberate choice
- When `!parameter.required && literalValue === ''`: show subtle muted text below input: "Empty = blank text (empty string)" in `text-[11px] text-zinc-500`
- When `!parameter.required && literalValue !== ''`: no helper text
- When `parameter.required && literalValue !== ''`: no validation warning
- The slot always emits `makeLiteralSlot(value)` regardless of empty/non-empty — the semantic meaning comes from the parameter's required flag + interaction state
