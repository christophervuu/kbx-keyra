## Summary

Create a `useSuggestExpression()` hook in `ui/src/features/mappings/hooks/` that manages the async lifecycle for the suggest-expression adapter call. The hook provides state transitions (idle → inputting → loading → success → error), abort semantics on re-invocation/unmount/target-change, and user-friendly error mapping. Follows the pattern of `useExplainRule()` with extensions for the richer suggest flow.

## Change Requirements

### Hook API

```typescript
export interface SuggestExpressionState {
  status: 'idle' | 'inputting' | 'loading' | 'success' | 'error';
  result: SuggestExpressionResult | null;
  error: string | null;
}

export interface UseSuggestExpressionReturn {
  state: SuggestExpressionState;
  /** Open the input area (transition idle → inputting) */
  openInput: () => void;
  /** Submit instruction to generate a suggestion */
  generate: (input: SuggestExpressionInput) => void;
  /** Dismiss the panel (close input or result) — aborts in-flight */
  dismiss: () => void;
  /** Reset state when target changes — aborts in-flight */
  reset: () => void;
}
```

### State transitions

- `idle` → user clicks Suggest → `openInput()` → `inputting`
- `inputting` → user clicks Generate → `generate(input)` → `loading`
- `loading` → response success → `success`
- `loading` → response error → `error`
- `success` → user clicks Dismiss → `dismiss()` → `idle`
- `error` → user clicks Try Again → `generate(input)` → `loading`
- `error` → user clicks Dismiss → `dismiss()` → `idle`
- any → target field changes → `reset()` → `idle` (aborts in-flight)
- any → user clicks Suggest again → `openInput()` → `inputting` (aborts in-flight, clears result)

### Abort semantics

- `generate()` aborts any previous in-flight request before starting a new one
- `dismiss()` aborts any in-flight request
- `reset()` aborts any in-flight request
- Cleanup on unmount aborts in-flight request
- Aborted requests do not update state (guard via `controller.signal.aborted`)

### Error mapping

Follow the same pattern as `useExplainRule()`:
- "offline mode" fragment → "Suggest Expression is not available in offline mode"
- "temporarily busy" or "rate limit" → pass through
- "Could not reach" → pass through
- "unexpected response" → pass through
- Other → "An unexpected error occurred. Please try again."

## Notes

The hook is similar to `useExplainRule()` but has an extra `inputting` state to represent the instruction-entry phase before the API call. This allows the component to know whether to show the input form (inputting) vs the result (success/error) vs nothing (idle).

The hook does NOT manage the instruction text state — that is owned by the component. The hook only manages the API lifecycle and result state.
