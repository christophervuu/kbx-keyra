## Summary

Create a `SuggestExpressionInline` component that provides the inline NL → Rule interaction surface. The component renders below the AI action row (same position as `ExplanationPanel`) and handles two phases: (1) instruction input with a Generate button, and (2) suggestion result display with Accept/Dismiss actions. The component is state-driven from the `useSuggestExpression` hook.

---

## Scope

### In Scope

- Create `ui/src/features/mappings/components/SuggestExpressionInline.tsx`
- Input phase: textarea for instruction, contextual info (target path/type), Generate button, Cancel button
- Result phase: suggested expression in monospace code block, optional explanation, Accept button, Dismiss button
- Loading state: spinner on Generate button
- Error state: error message + Try Again button (reuse error display pattern from ExplanationPanel)
- Keyboard: Ctrl+Enter to submit, Escape to dismiss
- Generate button disabled when instruction is empty/whitespace
- Component tests

## Change Requirements

### Props interface

```typescript
export interface SuggestExpressionInlineProps {
  /** Current state from useSuggestExpression hook */
  state: SuggestExpressionState;
  /** Target field context for display */
  targetPath: string;
  targetType: string;
  /** Callback: user clicks Generate */
  onGenerate: (instruction: string) => void;
  /** Callback: user clicks Accept */
  onAccept: (expression: string) => void;
  /** Callback: user clicks Dismiss or Cancel */
  onDismiss: () => void;
}
```

### Rendering behavior by state

- **`idle`**: render nothing (component returns null)
- **`inputting`**:
  - Context line: "Suggest expression for `{targetPath}` ({targetType})" in muted text
  - Textarea: placeholder "Describe the mapping logic…", auto-focused
  - Button row: [Generate] (disabled when empty) + [Cancel] (calls onDismiss)
  - Ctrl+Enter keyboard shortcut submits if instruction is non-empty
- **`loading`**:
  - Same layout as inputting but textarea is disabled
  - Generate button shows spinner + "Generating…" (disabled)
  - Cancel available (calls onDismiss which aborts)
- **`success`**:
  - Expression display: monospace `<code>` block with the suggested expression
  - Optional explanation text below (if `state.result.explanation` is present)
  - Button row: [Accept] (primary, calls onAccept with expression) + [Dismiss] (secondary)
- **`error`**:
  - Error message in amber-tinted area (consistent with ExplanationPanel error state)
  - [Try again] button + [Dismiss] button

### Styling

Follow the existing ExplanationPanel styling patterns:
- Container: `mt-2 rounded-lg border p-3 border-slate-700 bg-slate-800/80`
- Text: `text-xs` / `text-sm`, slate color palette
- Buttons: same styling as ExplanationPanel dismiss/retry buttons
- Accept button: uses primary styling (blue border + text) to indicate the positive action
- Code block: `font-mono text-xs bg-slate-900/60 rounded p-2 border border-slate-700 break-all whitespace-pre-wrap`

### Accessibility

- `data-testid="suggest-expression-inline"`
- `role="region"` with `aria-label="Suggest expression"`
- Textarea: `aria-label="Natural language instruction"`
- Generate button: `aria-label` includes disabled reason when empty
- Result area: `aria-live="polite"`

## Notes

This component is purely presentational + local-state for the instruction text. It receives the async lifecycle state from props (driven by the `useSuggestExpression` hook in the parent). The instruction text is managed locally within this component (unlike the hook state which manages the API lifecycle).

The component is similar in structure to `ExplanationPanel` but more complex due to the input phase. It's intentionally a single component (not split into InputPhase/ResultPhase subcomponents) unless the implementation warrants splitting for clarity.
