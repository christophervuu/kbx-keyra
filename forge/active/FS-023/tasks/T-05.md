## Summary

Implement the Conditional mode of the `UnifiedExpressionBuilder`. This provides a form-based Boolean condition builder with comparison operators, then/else branches that can be static values, source fields, or inline mini-builders, and nested else-if support. The form generates `if(condition, then, else)` DSL expressions.

---

## Scope

### In Scope

- Create `ConditionalModeBuilder.tsx` component rendered when `activeMode === 'conditional'` in `UnifiedExpressionBuilder`.
- Condition section: left operand input (source field picker or typed expression), comparison operator dropdown, right operand input (typed value, source field, or expression).
- Comparison operator dropdown with human-readable labels: "equals", "not equal", "greater than", "less than", "greater or equal", "less or equal", "contains", "is null", "is not null". Map to DSL functions.
- Compound conditions: **Grouped (enforced)** — each condition group shares a single logical operator (AND or OR). [+ Add condition] appends a row within the current group. An AND/OR toggle above the group controls the shared operator. To mix AND/OR, users add a **nested group** via [+ Add nested group] button (e.g., "ALL of: [A, ANY of: [B, C]]" generates `and(a, or(b, c))`).
- Then branch: a value selector with options: static value (text input), source field (picker), or "Build expression..." (opens inline mini-builder).
- Else branch: same options as Then, plus "Add else-if condition" option that nests another `ConditionalModeBuilder` recursively.
- **5-level else-if cap:** The form allows up to 5 else-if levels (6 total branches). When the cap is reached, the "Add else-if condition" button is replaced with an info message: "For more than 5 conditions, consider using a Value Map or switch to Editor mode."
- Inline mini-builder for branches: a compact version of the Value mode (source picker + transform pipeline) rendered inline within the branch section.
- Wire expression generation via `generateExpressionFromState()`.
- Component tests.

### Out of Scope

- Value mode (T-03/T-04).
- Value Map mode (T-06).
- Live Expression/Result (T-07).
- Condition groups deeper than 3 levels of nesting (visual complexity concern — support 2 levels of group nesting in v1).

## Change Requirements

**`ConditionalModeBuilder.tsx`:**

- Props:
  - `state: ConditionalModeState` (the conditional portion of `ExpressionBuilderState`)
  - `onStateChange: (state: ConditionalModeState) => void`
  - `parsedSourceSchema: ParsedSchema | null`
- Renders:
  - "IF" label + condition section.
  - "THEN" label + then branch value selector.
  - "ELSE" label + else branch value selector (with else-if option).
  - When else-if is selected, renders a nested `ConditionalModeBuilder` within the else section (indented/nested visually).

**`ConditionRow.tsx`:**

- Props:
  - `condition: ConditionRow`
  - `onChange: (updated: ConditionRow) => void`
  - `onRemove?: () => void`
  - `parsedSourceSchema: ParsedSchema | null`
- Renders:
  - Left operand: dropdown/input that can be "Source field" (shows field picker) or "Value" (shows text input).
  - Comparison operator: `<select>` dropdown with human-readable labels.
  - Right operand: same as left operand (dropdown + input). For `isNull`/`isNotNull`, the right operand is hidden (unary operators).
  - Remove button (x) for compound condition rows (not the first row).

**Compound conditions:**

- Each condition group enforces a **single logical operator** (AND or OR), selected via a toggle/segmented control above the condition rows.
- [+ Add condition] appends a new `ConditionRow` within the current group (shares the group's operator).
- [+ Add nested group] creates a nested `ConditionGroup` within the current group's condition list. The nested group has its own operator toggle.
- This produces clean, unambiguous DSL: `and(condA, condB, or(condC, condD))`.
- Visual: nested groups indent and show a border-left to indicate nesting level.
- Allow up to 2 levels of group nesting in the form (primary group + 1 nested group). If users need more complexity, they should use Editor mode.

**Else-if nesting cap:**

- The "Add else-if condition" button tracks the current nesting depth.
- At depth 5 (5 else-if levels = 6 total branches), the button is hidden and replaced with an info message: "For more than 5 conditions, consider using a Value Map or switch to Editor mode."
- The depth counter is passed as a prop to nested `ConditionalModeBuilder` instances.

**`BranchValueSelector.tsx`:**

- Props:
  - `branch: BranchValue`
  - `onBranchChange: (branch: BranchValue) => void`
  - `parsedSourceSchema: ParsedSchema | null`
  - `allowElseIf?: boolean` — only true for else branch
- Renders:
  - Radio/segmented options: "Static value" | "Source field" | "Build expression..." | (if allowElseIf) "Else-if condition"
  - Static value: text input.
  - Source field: single-select field picker.
  - Build expression: inline mini-builder (compact UnifiedExpressionBuilder in Value mode only, or a simplified Source + Transform view).
  - Else-if condition: renders nested `ConditionalModeBuilder`.

**Operator mapping (display -> DSL):**

| Display Label | DSL Function |
|---|---|
| equals | `eq(left, right)` |
| not equal | `neq(left, right)` |
| greater than | `gt(left, right)` |
| less than | `lt(left, right)` |
| greater or equal | `gte(left, right)` |
| less or equal | `lte(left, right)` |
| contains | `contains(left, right)` |
| is null | `isNull(left)` |
| is not null | `not(isNull(left))` |

**Integration into `UnifiedExpressionBuilder`:**

- When `activeMode === 'conditional'`, render `ConditionalModeBuilder` in the main content area.
- On state change, generate expression via `generateExpressionFromState()` and fire `onExpressionChange`.

## Blockers / Risks

- Recursive rendering of nested conditionals needs careful state management to avoid infinite re-renders. Use key-based identity and limit visual nesting depth display (e.g., indent with a left border).
- The inline mini-builder for branches adds complexity. If scope becomes too large, consider deferring the inline mini-builder to a follow-up and only supporting static/source for branches initially (note this in open questions).

## Notes

- The existing `ConditionBuilder.tsx` component provides some reference patterns, but the new implementation is substantially different (form-based vs. the existing raw-text approach). Create new components rather than refactoring the old one.
- Visual design: use an "if/then/else" block layout with clear visual separation. The condition section should feel like a form row: [left] [operator] [right]. Branches should be indented and labeled.
- For the inline mini-builder in branches, render a simplified version (no mode tabs, just source + transforms) since the branch is always a value expression.
- `data-testid` pattern: `conditional-builder`, `condition-row-{index}`, `condition-operator`, `condition-left`, `condition-right`, `branch-then`, `branch-else`, `add-condition-btn`, `add-else-if-btn`.
