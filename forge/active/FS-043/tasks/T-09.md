## Summary

Implement the cross-array lookup guided helper as a leaf-level logic option available within the item template layer. The helper generates `default(get(find(source("lookupArray"), eq(item("matchField"), parent("compareField"))), "returnField"), fallback)` DSL patterns through a structured form, providing a user-friendly alternative to manually composing nested function calls.

---

## Scope

### In Scope

- `CrossArrayLookupEditor.tsx` — guided form for configuring cross-array lookups
- Integration as a leaf-level logic option in `ItemFieldRow` / `ItemTemplateEditor` (alongside Transformation, Condition, Value Map)
- Form fields:
  - Lookup array — picker showing root-level array fields from source schema
  - Match field — field from the lookup array's item type
  - Compare against — current item field or parent item field (scope-aware)
  - Return field — field from the lookup array's item type
  - Default fallback — optional static value input
- Expression generation from lookup state → DSL
- Expression decomposition: detect `default(get(find(...), ...), ...)` pattern and hydrate `CrossArrayLookupState`
- Integration with `ItemFieldMapping` discriminated union (lookup kind)

### Out of Scope

- Non-equality-based lookups (range, fuzzy, regex)
- Multiple match conditions (AND/OR)
- Multi-level lookup chaining

## Notes

- The "compare against" field is scope-aware: if the lookup is inside a single-level `map()`, the compare value uses `parent()` (the `find()` creates a second array context, so the outer map's item becomes `parent()`). If the lookup is inside a nested `map()`, only the immediately enclosing array context's item is available as `parent()`.
- This scope behavior follows DSL rules: inside `find()`, `item()` refers to the lookup candidate, and `parent()` refers to the enclosing map's current element.
