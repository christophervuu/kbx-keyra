## Summary

Build the item template layer of the Array Builder — the UI for mapping individual fields within array items. This layer reuses the scalar chain builder (`ChainBuilder.tsx`) for leaf field mapping, adapting it to operate in array scope (where `item()` and `parent()` are available alongside `source()`). The item template renders below the collection layer and presents target item fields derived from the target schema.

---

## Scope

### In Scope

- `ItemTemplateEditor.tsx` — list of target item fields with per-field editing
- `ItemFieldRow.tsx` — single item field row: target name, type badge, mapped status, expand/collapse
- Integration with `ChainBuilder` for leaf field chain editing, scoped to array context
- Array-scoped source references: `item("field")`, `parent("field")`, `source("field")`, `static("value")`
- Source scope selector within array context (item field, root source, parent item, static value)
- Target item schema derivation: extract item fields from array target schema
- Per-field completion tracking (mapped / unmapped / error)
- Compact collapsed state for mapped fields (shows expression summary)
- Integration with `useArrayBuilderState()` for field mapping state management
- Leaf-level logic options: Transformation, Condition, Value Map, Cross-array Lookup (placeholder for T-09), Advanced expression

### Out of Scope

- Cross-array lookup helper implementation (T-09 — render placeholder/option here)
- Nested array handling within item template (T-10)
- Validation display (T-11)

## Change Requirements

- `ItemTemplateEditor.tsx`:
  - Derives target item fields from the target schema's array item type
  - Renders a list of `ItemFieldRow` components
  - Supports single-expansion: only one field's chain editor is expanded at a time (accordion model matching `ChainBuilder.tsx` pattern)
  - Shows "Item fields" section header with mapped/total count badge
  - Object fields in the item schema render as expandable groups; leaf fields are directly mappable
  - Nested array fields show a marker/button for opening nested array context (wired in T-10)
- `ItemFieldRow.tsx`:
  - Target field name + type badge + required indicator
  - Status indicator: unmapped (gray circle), mapped (green check), error (red circle)
  - Collapsed: one-line expression summary (reuse `summarizeChain()` pattern)
  - Expanded: inline `ChainBuilder` instance scoped to array context
- Array-scoped `ChainBuilder` integration:
  - When `ChainBuilder` is used inside the item template, the source entry must offer array-scope options:
    - "Item field" — generates `item("path")` references
    - "Root source" — generates `source("path")` references
    - "Parent item" — generates `parent("path")` references (only when in nested array context)
    - "Static value" — generates literal values
  - The source field picker must show item-level fields (from the source array item schema) when "Item field" is selected, and root-level fields when "Root source" is selected
  - This may require passing a `scope` or `contextMode` prop to `ChainBuilder` or wrapping it with a scope-aware source adapter
- Update `useArrayBuilderState()`:
  - `setFieldMapping(targetPath, mapping: ItemFieldMapping)` — set/update mapping for an item field
  - `removeFieldMapping(targetPath)` — clear mapping for an item field
  - `expandedItemField: string | null` — tracks which field's chain editor is expanded

## Blockers / Risks

- Adapting `ChainBuilder` to work in array scope (item/parent/source context) may require a non-trivial wrapper or prop extension. If `ChainBuilder` needs modification, keep changes minimal and backward-compatible with its scalar field usage.

---

## Notes

- The key integration challenge is making `ChainBuilder` scope-aware without breaking its existing usage in `ScalarFieldBuilder`. Consider a `sourceContext` prop that defaults to `'root'` (existing behavior) and can be set to `'arrayItem'` or `'nestedArrayItem'` to enable scoped source options.
- The item template should adapt its field list based on the target schema's array `items` definition. For JSON Schema, this is `targetSchema.items.properties` for object arrays.
- Parent item scope option should only appear when the array builder knows it's inside a nested array context (controlled by T-10).
