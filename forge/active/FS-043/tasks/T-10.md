## Summary

Implement nested array support within the Array Builder's item template layer. When an item template contains a target field that is itself an array, clicking it opens a separate focused Array Builder panel that replaces the outer builder, with a clear "Back to parent" action at the top. The outer draft state is preserved. The nested context provides scope-aware references (root source, current item, parent item, static). The UI clearly displays the current nesting context and limits depth to one parent level per v1 constraints.

---

## Scope

### In Scope

- Focused panel nested Array Builder: replaces the outer builder when entering a nested array
- "Back to parent" action at top of nested panel to return to outer array builder
- Outer draft state preservation while editing nested array
- Scope context display: "Editing: orders[].items[] — inside orders[]"
- Available scopes in nested context: root source (`source()`), current item (`item()`), parent item (`parent()`), static
- `parent()` scope option in ChainBuilder when editing nested array leaf fields
- Recursive `ArrayBuilderState` handling: outer item template's `nestedArrays` map stores inner `ArrayBuilderState`
- Navigation between nesting levels (enter nested / return to parent via focused panel swap)
- Depth limit: 2 explicit nesting levels (outer + inner). Deeper nesting falls back to custom expression.

### Out of Scope

- Named scopes (future DSL extension)
- Triple-nested arrays in structured mode (falls back to custom expression)
- Multi-level `parent()` addressing

## Change Requirements

- `ItemTemplateEditor.tsx` / `ItemFieldRow.tsx`:
  - Detect target item fields that are array-type
  - Show array-type indicator badge and "Configure nested array" action button
  - Clicking opens the nested array context
- `ArrayBuilder.tsx` nested context (focused panel model):
  - When `activeNestedPath` is set, replace the outer `ArrayBuilder` panel with a nested `ArrayBuilder` for the nested array's `ArrayBuilderState`
  - Show "Back to parent" action at the top of the nested panel (click returns to outer builder)
  - Show context breadcrumb: "Editing: orders[].items[] — inside orders[]"
  - Show scope context label: "Parent item fields available via parent()"
  - Pass `nestingDepth` prop to inner builder to enforce depth limit
  - At `nestingDepth >= 2`: array-type fields in the inner item template show "Use custom expression for deeper nesting" instead of opening a third level
  - Outer builder state is fully preserved while the nested panel is active
- ChainBuilder scope extension:
  - When `nestingDepth >= 1`, add "Parent item" source scope option to ChainBuilder
  - "Parent item" source generates `parent("field")` references
  - Parent item field picker shows fields from the outer array's item schema (passed as prop)
- `useArrayBuilderState()`:
  - `enterNestedArray(targetPath)` — sets `activeNestedPath`, creates nested `ArrayBuilderState` if not exists
  - `exitNestedArray()` — clears `activeNestedPath`, returns to outer level
  - Nested state stored in `itemTemplate.nestedArrays` map
  - Expression generation recurses into nested states for the full expression

## Notes

- The nested builder uses a focused panel model (resolved Q5): clicking a nested array field replaces the outer builder entirely with a nested builder panel, and a "Back to parent" action at the top returns to the outer builder. Outer draft state is preserved throughout. This avoids the cramped layout of an inline nested approach.
- The `nestedArrays` map in `ItemTemplateState` uses the target field path as the key, allowing the state to be persisted and restored across navigation.
