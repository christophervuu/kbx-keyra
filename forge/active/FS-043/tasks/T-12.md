## Summary

Implement the Custom Expression mode as an advanced escape hatch for array expressions that don't fit the structured builder modes. Wire the expression decomposer (T-03) into the Array Builder's initialization path so existing array expressions are loaded into the appropriate structured mode or fall back to Custom Expression mode. Support round-trip from structured to custom and back when possible.

---

## Scope

### In Scope

- `CustomExpressionEditor.tsx` — raw DSL editor surface for array expressions
- Visual separation of Custom Expression as an "Advanced" option in the mode selector
- Expression decomposer integration on builder initialization:
  - Load existing expression → attempt `decomposeArrayExpression()` → load structured or raw mode
- Banner for unrecognized expressions: "This expression uses a pattern not supported by the structured builder."
- Round-trip: Custom → structured when expression matches recognized pattern
- "Restore previous structured draft" option when returning from Custom Expression (wired in T-08 state, this task builds the UI)
- Backward compatibility: all valid existing array DSL expressions load without error

### Out of Scope

- Building the structured modes (T-04, T-05, T-06 — already done)
- Mode switching state logic (T-08 — already done)
- General raw DSL editor improvements (autocomplete, enhanced syntax highlighting)

## Change Requirements

- `CustomExpressionEditor.tsx`:
  - Renders `RawDslEditor` for raw DSL editing
  - Shows expression parse status (valid/invalid) via engine `parse()`
  - Shows banner when loaded from unrecognized expression: "This expression uses a pattern not supported by the structured builder. Edit here or reset to use a structured mode."
  - "Reset to structured mode" action: clears raw expression and returns to mode selector
  - When returning from structured mode (via T-08): shows best-effort generated DSL
- Array Builder initialization:
  - On mount or when `targetPath` changes:
    - Check for existing expression via `getDraftExpression(targetPath)` or from saved rules
    - If expression exists: call `decomposeArrayExpression(expression)`
    - If decomposition succeeds: load structured state from decomposed result
    - If decomposition fails: load Custom Expression mode with raw expression
  - If no expression exists: show mode selector (first-time flow)
- Return from Custom Expression to structured mode:
  - Attempt `decomposeArrayExpression()` on current raw expression
  - If recognized: load structured state
  - If not recognized and `previousStructuredDraft` exists: offer three options:
    - "Restore previous draft" — reload in-session structured draft
    - "Reset" — fresh structured mode
    - "Stay in Custom" — remain in raw editor
  - If not recognized and no previous draft: offer "Reset" or "Stay in Custom"
- Visual distinction: Custom Expression mode card in `ArrayModeSelector` is visually separated from structured modes (e.g., divider line, "Advanced" label, muted styling)

## Blockers / Risks

## Notes

- This task is the integration point for backward compatibility. Ensure that the following existing DSL patterns from the old array builder are loadable:
  - `map(source("x"), {...})` — Map mode
  - `map(filter(source("x"), ...), {...})` — Filter + Map mode
  - `array(...)` — Build from Values mode
  - `merge(map(...), map(...))` — Merge Branches mode
  - `concat(source("a"), source("b"))` — legacy merge pattern; may need special handling in decomposer or map to Custom mode
  - Any other valid DSL — Custom Expression mode fallback
