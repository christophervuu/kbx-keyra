## Summary

Implement the Filter + Map and Build from Values collection-layer UI components within the Array Builder. Filter + Map extends the Map mode with a simplified boolean-focused filter predicate editor (not the full chain model) with a raw expression fallback for complex predicates. Build from Values provides a multi-entry builder for constructing arrays from individual fields or static values, with optional null filtering and drag-and-drop + keyboard reorderable entries.

## Change Requirements

- `FilterMapCollectionEditor.tsx`:
  - Reuses source array selection from `MapCollectionEditor`
  - Adds a filter predicate section below the source selection
  - Shows "Filter: [predicate summary]" in collapsed state
- `FilterPredicateEditor.tsx`:
  - Simplified boolean-focused builder (not the full chain model):
    - Field comparison: `gt(item("field"), value)`, `eq(item("field"), value)`, `lt(item("field"), value)`, `gte(...)`, `lte(...)`, `neq(...)`
    - Null check: `not(isNull(item("field")))`, `isNull(item("field"))`
  - Raw expression fallback toggle for complex predicates (AND/OR, nested logic)
  - Left operand defaults to an item field picker
  - Operator dropdown: equals, not equals, greater than, less than, greater or equal, less or equal, is null, is not null
  - Right operand: static value input or source field
  - Generates boolean DSL expression
- `BuildFromValuesEditor.tsx`:
  - Ordered list of value entries, reorderable via drag-and-drop with keyboard move controls (up/down arrows)
  - `[+ Add Entry]` button to add new entries
  - Per-entry remove button
  - Drag handle on each entry for reordering (order is semantically meaningful in `array()`)
  - Keyboard accessibility: up/down arrow buttons or keyboard shortcuts to move entries
  - Null filtering toggle: "Filter out entries with null values" — generates `filter(array(...), not(isNull(item("field"))))`
  - For object-shaped target items: each entry is an object template with per-field source/static inputs
  - For primitive target items: each entry is a single source/static input
- `ValueEntryEditor.tsx`:
  - Renders fields matching target item schema
  - Each field can be: source field reference, static value, or raw expression
  - Compact layout for inline editing
- Update `useArrayBuilderState()`:
  - `setFilterPredicate(predicate: FilterPredicateState)` action
  - `addValueEntry()`, `removeValueEntry(index)`, `updateValueEntry(index, entry)`, `reorderValueEntry(fromIndex, toIndex)` actions
  - `setNullFiltering(enabled: boolean)` action

## Notes

- The filter predicate editor is intentionally simplified — a boolean-focused builder, not the full chain model (resolved Q2). It supports single field comparisons and null checks. Complex predicates (AND/OR, nested conditions) use a raw expression fallback toggle. Full multi-condition visual AND/OR filter building is a possible future enhancement.
- Build from Values entries are reorderable via drag-and-drop with keyboard move controls (resolved Q3). Order matters because `array()` preserves element order.
- Build from Values entries should adapt their shape based on the target item schema — if the target expects objects, render object field editors; if primitives, render single-value inputs.
