## Summary

Implement the mode switching state machine for the Array Builder with draft state preservation rules. Compatible mode switches (e.g., Map ↔ Filter + Map) preserve state silently. Incompatible switches (e.g., Build from Values → Map) show a confirmation dialog explaining what will be kept and what will be discarded. Switching to Custom Expression preserves the previous structured draft in-session for potential return.

## Change Requirements

- `switchMode(newMode)` in `useArrayBuilderState()`:
  - If `isCompatibleModeSwitch(currentMode, newMode)`:
    - Apply preservation rules per `getModePreservationRules(currentMode, newMode)`
    - Map → Filter + Map: add empty filter, keep sourceArrayPath + itemTemplate
    - Filter + Map → Map: remove filter, keep sourceArrayPath + itemTemplate
    - Map/Filter + Map → Merge: wrap current setup as Branch 1, add empty Branch 2
    - Merge → Map/Filter + Map (1 branch): convert single branch to Map mode
  - If not compatible:
    - Set `pendingModeSwitch` state to trigger confirmation dialog
    - On confirm: apply switch with appropriate state reset
    - On cancel: clear `pendingModeSwitch`
  - If switching to Custom Expression:
    - Store current state in `previousStructuredDraft`
    - Generate best-effort DSL from current state
    - Set mode to Custom Expression with generated DSL as `rawExpression`
  - If switching from Custom Expression to structured mode:
    - Attempt to decompose raw expression via `decomposeArrayExpression()`
    - If decomposition succeeds and matches target mode: load decomposed state
    - If decomposition fails and `previousStructuredDraft` exists: offer "Restore previous" option
    - If neither: require reset confirmation
- `ModeSwitchConfirmDialog.tsx`:
  - Props: `fromMode`, `toMode`, `preservedItems: string[]`, `discardedItems: string[]`, `onConfirm`, `onCancel`, `onRestorePrevious?`
  - Shows: "Switching from [X] to [Y]"
  - Lists what will be kept and what will be discarded
  - Confirm / Cancel buttons; optional "Restore previous draft" when returning from Custom Expression
- `ArrayBuilder.tsx`:
  - Show mode selector with current mode highlighted
  - Mode selector triggers `switchMode` for subsequent changes (not `selectMode`)
  - Render `ModeSwitchConfirmDialog` when `pendingModeSwitch` is set
- `ArrayModeSelector.tsx`:
  - When a mode is already selected, show it as active/selected with a "Change mode" affordance
  - Other modes shown as options; clicking triggers switch flow

## Notes

- The `pendingModeSwitch` pattern mirrors the `useBlocker` approach used for route navigation guards — it prevents the switch from happening until the user confirms.
- The "Restore previous" option when returning from Custom Expression is session-scoped — it is lost on navigation away from the field. This is intentional and does not need persistence.
