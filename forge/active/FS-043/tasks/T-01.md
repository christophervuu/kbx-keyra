## Summary

Define the complete type system for the redesigned array builder, including `ArrayBuilderState`, `CollectionState` (discriminated union by mode), `ItemTemplateState`, `ItemFieldMapping`, mode-specific sub-states, `CompletionStatus` derivation, and factory functions. This is the foundational module that all other array builder tasks depend on.

---

## Scope

### In Scope

- `ArrayBuilderMode` union type: `'map' | 'filterMap' | 'buildFromValues' | 'mergeArrayBranches' | 'customExpression'`
- `ArrayBuilderState` top-level type: mode, collectionState, itemTemplate, completionStatus, previousStructuredDraft
- `CollectionState` discriminated union: `MapCollectionState`, `FilterMapCollectionState`, `BuildFromValuesState`, `MergeBranchesState`, `CustomExpressionState`
- `FilterPredicateState` type for filter configuration
- `ValueEntry` type for build-from-values entries
- `MergeBranch` type for merge branch configuration
- `ItemTemplateState` type with `ItemFieldMapping[]` and `nestedArrays` map
- `ItemFieldMapping` type linking target field path to a `ChainState` or cross-array lookup state
- `CrossArrayLookupState` type for the lookup helper state
- `CompletionStatus` type and `deriveCompletionStatus()` function
- Factory functions: `createEmptyArrayBuilderState()`, `createCollectionStateForMode()`, `createEmptyItemTemplate()`, `createEmptyMergeBranch()`, `createEmptyValueEntry()`, `createEmptyCrossArrayLookup()`
- Type guards for discriminated unions
- Mode compatibility helpers: `isCompatibleModeSwitch(from, to)`, `getModePreservationRules(from, to)`

### Out of Scope

- Expression generator (T-02)
- Expression decomposer (T-03)
- React components (T-04+)
- Hook logic (T-04+)

## Change Requirements

- Create `ui/src/features/mappings/lib/array-builder-state.ts` with all types, factory functions, type guards, and completion derivation
- Reuse `ChainState` from `chain-builder-state.ts` for leaf field mappings inside `ItemFieldMapping` — do not duplicate chain types
- `deriveCompletionStatus(state: ArrayBuilderState)` must return:
  - `'notStarted'` when no mode is effectively configured (mode may be set but collection source is not)
  - `'inProgress'` when mode is configured but item template is incomplete
  - `'complete'` when collection logic is valid and all required item fields are satisfied
  - `'hasErrors'` when validation errors exist at any level
- `isCompatibleModeSwitch(from, to)` must classify all 20 directional mode pairs as compatible (no confirmation needed) or incompatible (confirmation needed) per the spec's mode-switch state transition table
- All types must follow TypeScript strict mode conventions (no `any`, proper readonly modifiers)
- Export all types and functions from the module

## Notes

- This task establishes the type system only. No hooks, components, or expression logic. Keep it pure data + functions.
- The `ItemFieldMapping` type should accommodate both scalar chain states and cross-array lookup states via a discriminated union on a `kind` field.
- The `FilterPredicateState` should be expressive enough to support future complex filter UIs while starting with a simple approach for v1 (possibly a raw expression string with optional structured overlay).
