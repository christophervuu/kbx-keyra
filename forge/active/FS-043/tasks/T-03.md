## Summary

Implement a pure function that decomposes an existing DSL expression string into `ArrayBuilderState`, enabling the array builder to hydrate from previously saved array expressions. The decomposer analyzes the AST to detect supported structural patterns (map, filter+map, build from values, merge branches), extracts configuration, and delegates leaf-level field decomposition to the existing `decomposeToChain()` from the scalar chain decomposer.

---

## Scope

### In Scope

- `decomposeArrayExpression(expression: string): DecomposeArrayResult` main decomposer function
- `DecomposeArrayResult` type: `{ success: true, state: ArrayBuilderState } | { success: false, reason: string, rawExpression: string }`
- Pattern detection for:
  - `map(source(...), {...})` → Map mode
  - `map(filter(source(...), ...), {...})` → Filter + Map mode
  - `array(...)` and `filter(array(...), ...)` → Build from Values mode
  - `merge(...)` with `map()` branches → Merge Branches mode
- Item template field extraction from object templates
- Per-field decomposition delegating to `decomposeToChain()` for leaf field chains
- Cross-array lookup pattern detection: `default(get(find(...), ...), ...)` → `CrossArrayLookupState`
- Nested array detection within item templates
- Graceful fallback to Custom Expression mode for unrecognized patterns

### Out of Scope

- UI components
- Modifying the scalar `decomposeToChain()` function
- Supporting every possible DSL permutation (decomposer is best-effort)

## Blockers / Risks

- The decomposer is inherently best-effort — complex or unusual DSL structures will fall through to Custom Expression mode. This is by design and not a risk.

---

## Notes

- Pattern detection should be structured as a series of matchers tried in order: merge → filter+map → map → build-from-values → custom fallback. Merge is checked first because `merge(map(...), map(...))` contains `map()` calls that would otherwise match the map pattern.
- For round-trip testing, semantic equivalence means the generated expressions produce the same output when executed, not necessarily identical string representation.
