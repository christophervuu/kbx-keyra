## Summary

Update Schema Detail to enforce strict CDM read-only behavior, expose only allowed CDM actions, and align detail-level loading/error/re-sync feedback with the shared CDM UX contract.

---

## Scope

### In Scope

- Ensure CDM detail disables/removes inline metadata edits.
- Ensure CDM detail disables/removes edit mode, replace-file flow, remove, publish/sync-to-github, and promote actions.
- Keep View and Re-sync available for CDM.
- Ensure Unlink is not rendered in Schema Detail (project-context action only).
- Align SchemaGitStatus and SchemaActions messaging with canonical CDM copy.

### Out of Scope

- Non-CDM editing model redesign.
- Full page layout redesign.

## Change Requirements

- CDM read-only policy must be enforced at both control rendering and handler execution boundaries.
- CDM action list in detail must match FS-078 allowed/disallowed policy exactly.
- Detail state copy for loading/error/re-sync should be consistent with Project Overview/Schema Library.

---

## Verification Requirements

- Unit/component tests for CDM vs non-CDM action matrix.
- Tests proving CDM edit flows cannot be entered/executed.
- Tests for status and error copy consistency in detail-level status/action areas.
- Typecheck/lint for touched UI files.

---

## Acceptance Checks

- CDM Schema Detail is non-editable end-to-end.
- CDM disallowed actions are unavailable/non-executable.
- CDM View + Re-sync remain available and labeled consistently.
- Detail-level loading/error/re-sync messaging is standardized.
- Tests, typecheck, and lint pass.
