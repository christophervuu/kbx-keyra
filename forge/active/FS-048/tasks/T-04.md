## Summary

Create staleness detection utilities and integrate them with the workspace hook so that persisted suggestions are automatically marked `stale` when the underlying rules change after generation. Staleness is checked when the workspace is entered and when the user returns from editing.

---

## Scope

### In Scope

- Create `ui/src/features/mappings/lib/auto-map-staleness.ts` with:
  - `detectStaleSuggestions(items, currentRules)` — compares each item's `existingExpressionAtGeneration` against the current rule for the same target path
  - Returns a list of `targetPath` values that should be marked stale
- Staleness conditions:
  - The saved or draft expression for the target path differs from `existingExpressionAtGeneration`
  - A rule was manually added for a target that was `isNew === true` at generation time
- Integrate staleness detection into `useAutoMapWorkspace`:
  - Check on workspace entry (when `sectionPath` is set and persisted data is loaded)
  - Check when `rules` prop changes while workspace is active (via effect)
  - Call `markStale(targetPath)` for each detected stale item
- Stale items get a visual indicator (status badge) — visual rendering is in T-06

### Out of Scope

- Source schema staleness (deferred)
- Target schema staleness (deferred)
- Sample payload staleness (does not affect suggestion validity)
- Staleness based on source context changes
- UI rendering of stale state (T-06)

## Change Requirements

- `detectStaleSuggestions` must:
  - Accept `items: PersistedSuggestionItem[]` and `currentRules: readonly MappingRule[]`
  - For each item, find the rule with matching `target` path
  - Compare rule's `expression` with item's `existingExpressionAtGeneration`
  - If they differ and item is in `suggested` or `dismissed` status, mark as stale candidate
  - If item was `isNew === true` and a rule now exists for that target, mark as stale candidate
  - `accepted` and `edited` items are never marked stale (terminal states)
- Integration with hook:
  - Run detection on initial hydration from persistence
  - Run detection when `rules` changes (debounced or in effect cleanup to avoid excess re-renders)
  - Update item status to `stale` and persist updated state
- Staleness is idempotent — running detection on already-stale items does not change their status
