## Summary

Create the `ui/src/features/projects/` feature directory with component and hook barrels, feature-local types, and the folder structure needed by all subsequent tasks. Also apply the Q1-resolved domain type changes: make `sourceSchemaRef`/`targetSchemaRef` optional on `MappingConfig` and `CreateMappingInput`, make `sourceSchemaId`/`targetSchemaId` optional on `MappingMetadata`, and update `LocalStorageAdapter` and `useMappingEditor` with `?.` guards. This establishes the organizational pattern consistent with existing features and the type foundation for schema-optional mappings.

## Change Requirements

Create the following structure:

```
features/projects/
  index.ts            Feature barrel — re-exports types, hooks, components
  types.ts            Feature-local types
  components/
    index.ts          Components barrel (empty initially)
  hooks/
    index.ts          Hooks barrel (empty initially)
  lib/
    index.ts          Lib barrel (empty initially)
```

Types to define in `types.ts`:

- `SchemaScope`: `'global' | 'project-level'`
- `ProjectLoadState`: discriminated by status
- `SchemaCardData`: `{ schemaId, name, format, origin, scope: SchemaScope, fieldCount, syncStatus, isInferred }`
- `MappingRowData`: `{ mappingId, name, sourceSchemaName, targetSchemaName, ruleCount, coverage, status, devDeploy, qaDeploy, prodDeploy, updatedAt }`
- `CreateProjectFormData`: `{ name: string, description: string, tags: string[] }`
- `CreateMappingFormData`: `{ name: string, sourceSchemaId: string | null, targetSchemaId: string | null }`
- `CreateMappingStep`: `'name' | 'source-schema' | 'target-schema' | 'confirm'`

**Domain type changes (Q1 resolution):**

Update `ui/src/lib/types/domain.ts`:
- `MappingConfig.sourceSchemaRef`: change from `SchemaRef` to `SchemaRef | undefined` (i.e., `readonly sourceSchemaRef?: SchemaRef`)
- `MappingConfig.targetSchemaRef`: same
- `CreateMappingInput.sourceSchemaRef`: change from `SchemaRef` to `SchemaRef | undefined`
- `CreateMappingInput.targetSchemaRef`: same
- `MappingMetadata.sourceSchemaId`: change from `string` to `string | undefined` (i.e., `readonly sourceSchemaId?: string`)
- `MappingMetadata.targetSchemaId`: same

Update `ui/src/lib/api/local-storage-adapter.ts`:
- `createMapping()`: use `input.sourceSchemaRef` with `?.` — when undefined, omit from config; set `sourceSchemaId: input.sourceSchemaRef?.schemaId ?? ''` (or omit if MappingMetadata field is optional)
- `updateMapping()`: use `config.sourceSchemaRef?.schemaId` and `config.targetSchemaRef?.schemaId`

Update `ui/src/features/mappings/hooks/use-mapping-editor.ts`:
- In the schema loading block (~line 179-181), guard with:
  ```typescript
  const schemaPromises = [
    mappingConfig.sourceSchemaRef ? adapter.getSchema(mappingConfig.sourceSchemaRef.schemaId) : Promise.reject('no source schema'),
    mappingConfig.targetSchemaRef ? adapter.getSchema(mappingConfig.targetSchemaRef.schemaId) : Promise.reject('no target schema'),
  ];
  const [sourceResult, targetResult] = await Promise.allSettled(schemaPromises);
  ```
  This preserves the existing `allSettled` graceful-failure pattern while avoiding a pointless API call.

Update `ui/src/lib/engine/index.ts`:
- In `toEngineMappingConfig()`, when `sourceSchemaRef`/`targetSchemaRef` are undefined, provide a fallback for the engine type (which requires them):
  ```typescript
  const DEFAULT_SCHEMA_REF = { schemaId: '', type: 'local' as const };
  // ...
  sourceSchemaRef: config.sourceSchemaRef ? { ... } : DEFAULT_SCHEMA_REF,
  targetSchemaRef: config.targetSchemaRef ? { ... } : DEFAULT_SCHEMA_REF,
  ```

## Blockers / Risks

- The domain type change (`sourceSchemaRef?`, `targetSchemaRef?`) touches code from FS-008 and FS-010. TypeScript will surface all breakages via `tsc --noEmit` — fix each consumer with `?.` guards or conditional checks.

Do NOT change the engine type — the engine is a separate concern and its config validation should remain strict.
