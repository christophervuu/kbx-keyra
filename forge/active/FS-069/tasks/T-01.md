## Summary

Harden the `explain-rule` backend endpoint so it consistently executes through the shared AI runtime using prompt registry resolution and structured output validation. Ensure request validation and error mapping produce useful, normalized failures, including invalid DSL cases.

---

## Scope

### In Scope

- Align `src/lambda/ai/explain-rule.ts` request validation and response mapping with current canonical conventions.
- Ensure explain invocation uses shared runtime prompt-resolution path (no handler-local prompt text/logic).
- Enforce structured output validation before success response.
- Normalize invalid DSL / invalid payload / runtime failure behavior into canonical error semantics.

### Out of Scope

- UI presentation/copy updates.
- New AI endpoints or new model-provider behavior.
- Prompt-authoring workflows.

---

## Relevant Areas

- `src/lambda/ai/explain-rule.ts`
- `src/lib/ai/invoke-ai.ts`
- `src/lib/ai/output-parser.ts`
- `src/lib/ai/prompt-registry.ts`
- `src/lambda/shared/response.ts`
- `src/lambda/shared/errors.ts`

---

## Change Requirements

- Explain-rule handler must remain thin and delegate orchestration to shared runtime.
- Handler/runtime path must use prompt-registry lookup for explain prompt ID.
- Success responses must only be emitted from schema-validated structured output.
- Invalid inputs and invalid DSL conditions must return deterministic, user-useful failure responses.
- No write operations to mapping persistence/state are introduced in this path.

---

## Verification Requirements

- Add/update backend unit tests for explain success, invalid payload, invalid DSL path, prompt-not-found/config failure, and structured-output parsing failures.
- Verify status and error envelopes remain canonical.
- Run `pnpm typecheck` and targeted backend test suite for explain-rule.

---

## Acceptance Checks

- Explain-rule endpoint returns structured success for valid inputs (`AE-01`, `AE-05`).
- Invalid DSL path yields graceful explanation or useful normalized failure (`AE-02`).
- Tests prove prompt registry + structured output contract path is used (`AE-05`).
- No persistence/mutation side effects are introduced in explain-rule backend flow.
- `pnpm typecheck` passes for touched backend areas.
