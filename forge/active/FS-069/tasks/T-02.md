## Summary

Update and/or harden Mapping Editor explain surfaces so a selected rule can display concise AI-generated explanation text with clear assistance labeling. Ensure explain lifecycle interactions do not alter rule expressions, draft status, or persisted mapping content.

---

## Scope

### In Scope

- Explain trigger wiring from selected rule context via `ApiAdapter.explainRule`.
- Explain lifecycle state UX (loading/success/error/retry/dismiss as applicable) in existing explain hook/component surfaces.
- Explicit UI labeling/disclaimer that explanation is generated assistance and not persisted mapping content.
- Guardrails/tests proving explain operations do not mutate rule expression/draft/persistence state.

### Out of Scope

- Redesign of Mapping Editor layout.
- New AI capabilities (suggest/smart-fix/auto-map changes).
- Prompt or model tuning.

## Change Requirements

- Explain action must operate on selected rule and render response in existing explain UI surface.
- UI copy must clearly distinguish explanation as generated assistance.
- Success and failure explain flows must preserve current rule text and draft state exactly.
- Hook/component behavior must remain adapter-based and transport-agnostic.

---

## Verification Requirements

- Add/update UI tests for:
  - successful explanation rendering and labeling;
  - error and retry behavior;
  - non-mutation guarantees pre/post explain invocation.
- Run targeted UI tests and `pnpm typecheck`.

---

## Acceptance Checks

- Selected rule explain flow renders concise explanation (`AE-01`).
- Explain panel/section clearly labels AI-generated assistance (`AE-04`).
- Pre/post explain assertions confirm no rule content/order/state mutation on success/failure (`AE-03`).
- Targeted explain UI tests pass and touched areas typecheck cleanly.
