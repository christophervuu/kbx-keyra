## Summary

Implement the `parseInferredSchema()` function that takes sample JSON or XML data, infers the schema structure (field names, types, nesting), and produces a `ParsedSchema` with all nodes flagged as `inferred: true`. This enables users to explore schemas derived from sample data even without a formal schema definition.

---

## Scope

### In Scope

- `parseInferredSchema(content: string, format: 'json' | 'xml'): ParsedSchema` implementation
- JSON sample inference: recursively traverse object keys, infer types from values
- XML sample inference: parse with DOMParser, infer structure from element hierarchy
- Type inference rules: string, number, boolean, null, array, object
- Array element type inference (examine first N elements for consistent typing)
- Recursive traversal for nested objects/arrays
- All nodes marked with `inferred: true`
- `isRequired` set to `false` for all inferred nodes (cannot be determined from sample)
- Parse timing measurement
- Error handling for invalid JSON/XML sample data
- Unit tests covering AE-07 scenario

### Out of Scope

- Multi-sample inference (comparing multiple documents to refine types)
- Schema generation (outputting JSON Schema or XSD from inference — only produces `SchemaTreeNode` tree)
- Inference confidence scores
- Date/datetime string detection (strings stay as 'string')
- XML attribute inference (only elements are inferred)

## Change Requirements

Implement `parseInferredSchema()` with the following behavior:

1. **Input handling**:
   - If `format === 'json'`: parse with `JSON.parse()`. If invalid, throw `SchemaParseError`.
   - If `format === 'xml'`: parse with `DOMParser`. If invalid, throw `SchemaParseError`.

2. **JSON inference**:
   - Object keys become nodes with fieldName = key
   - Infer type from JavaScript `typeof` and special cases:
     - `typeof === 'string'` → `'string'`
     - `typeof === 'number'` → `'number'`
     - `typeof === 'boolean'` → `'boolean'`
     - `value === null` → `'null'`
     - `Array.isArray(value)` → `'array'`, set `isArray = true`
     - `typeof === 'object'` → `'object'`, recurse into properties
   - For arrays: examine items to infer element type. If items are objects, create child nodes from the first object's keys. If items are primitives, note the element type.
   - Recurse into nested objects to build full tree

3. **XML inference**:
   - Child elements become nodes
   - Elements with child elements → type `'object'`
   - Elements with only text content → type `'string'` (conservative default)
   - Repeated sibling elements with same tag → parent is `'array'`
   - Recurse into nested elements

4. **Node construction**:
   - All nodes get `inferred: true`
   - All nodes get `isRequired: false` (sample data cannot determine requiredness)
   - Paths built with dot-notation, same as other parsers
   - Depth, parentPath, childCount set correctly

5. **Performance**: Track start time, compute `parseTimeMs`.

6. **Error handling**: Invalid input throws `SchemaParseError`. Null/undefined values within the sample data are handled gracefully (type = 'null' or 'any').

## Blockers / Risks

- Type inference from a single sample is inherently imprecise (a field might be `null` in the sample but normally a string). This is acceptable — the "⚠ Inferred from sample data" indicator communicates this to users.

---

## Notes

- The inferred schema parser is the simplest of the three parsers since it doesn't need to handle schema-definition constructs (refs, types, required, etc.). It only needs to traverse data structure.
- For JSON arrays with mixed types (e.g., `[1, "hello", true]`), infer as `'any'` element type.
- For XML, only element nodes matter — text nodes are values, not schema structure. Attributes are ignored in Phase 0 inference.
