## Summary

Add virtualized rendering to `<SchemaTreeView />` so that only visible nodes are in the DOM at any time. This ensures schemas with 1,000–23,000+ fields render without performance degradation. Implement lazy expansion (children rendered only when parent is expanded) and ensure scrolling is smooth with appropriate overscan. Choose and integrate a virtualization approach (e.g., `@tanstack/react-virtual` or a custom implementation) suitable for variable-depth tree structures.

## Change Requirements

**Flattened tree computation:**

Create a `useFlattenedTree(nodes: SchemaTreeNode[], expandedPaths: Set<string>)` hook (or utility function) that:
- Takes the root node array and current expand state
- Returns a flat array of `SchemaTreeNode` objects in display order (DFS traversal, only including nodes whose ancestors are all expanded)
- Memoized with `useMemo` — recomputes only when `nodes` or `expandedPaths` change
- This flat list is the input to the virtualizer

**Virtualization integration:**

- Use `@tanstack/react-virtual` (recommended for its lightweight API and React 18 compatibility) or implement a custom virtualizer
- Configure with:
  - `count`: length of flattened visible nodes array
  - `getScrollElement`: ref to the scrollable container
  - `estimateSize`: fixed row height (e.g., 32px per row)
  - `overscan`: 10–20 rows above/below viewport
- Render only the rows within the virtual window
- Each row is positioned absolutely or with transform to maintain correct scroll position

**Lazy expansion:**
- Children are not included in the flat list until their parent is in `expandedPaths`
- When a parent is expanded, its children are added to the flat list on next render
- When collapsed, children are removed from the flat list

**Scroll-to-node:**
- Export a `scrollToNode(path: string)` utility or expose it via a ref/callback
- Used by search (T-07) to scroll to first match
- Used by selection (T-08) to ensure selected node is visible
- Used by keyboard nav (T-09) to keep focused node in view

**Container setup:**
- The tree container must have a fixed or max height with `overflow-y: auto`
- The inner container has height = total rows * row height (for correct scrollbar sizing)
- Rows are positioned within this inner container at their computed offset

## Notes

- The key insight is separating the tree's logical model (hierarchical `SchemaTreeNode[]`) from the render model (flat array of currently visible nodes). The virtualizer operates on the flat array.
- The `useFlattenedTree` hook is the bridge between tree expand state and virtualization input. It should be performant for 23,000+ total nodes even when only a fraction are visible.
- For the `estimateSize`, a fixed 32px row height is recommended. All tree rows should be the same height (field name + icon + badge on one line). This simplifies virtualization significantly.
- The `overscan` value (10–20) ensures smooth scrolling without visible blank areas during fast scrolling.
