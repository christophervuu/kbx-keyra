## Summary

Add common validation and execution-limit enforcement (timeout/token caps) to the shared invocation layer so feature handlers inherit consistent guardrails without duplicating logic.

---

## Scope

### In Scope

- Shared pre-invocation payload/profile validation.
- Shared timeout budget and token-cap enforcement hooks.
- Deterministic failure generation for limit/config violations.
- Unit tests for limit and validation edge behavior.

### Out of Scope

- Endpoint-level handler migration.
- Telemetry schema finalization.

---

## Relevant Areas

- `src/lib/ai/invoke-ai.ts`
- `src/lib/ai/config.ts`
- `src/lib/ai/model-client.ts`
- `src/lib/ai/*` (validation/limit utility modules as needed)
- `tests/lib/ai/*`

---

## Change Requirements

- Validation behavior must be shared and reusable across all AI endpoint invocations.
- Timeout/token enforcement must be profile-driven (tier/feature aware).
- Limit-related failures must map into normalized shared-layer failure outputs.

---

## Verification Requirements

- Unit tests for invalid payload/profile failure semantics.
- Unit tests for timeout/token cap enforcement behavior.
- Targeted tests for deterministic handling across tiers.

---

## Acceptance Checks

- [ ] Shared validation module/logic is integrated into invocation path.
- [ ] Timeout/token caps are enforced by shared layer, not handlers.
- [ ] Limit/validation failure paths are covered by tests.
