## Summary

Implement a common telemetry/logging contract for all shared AI invocations so success/failure diagnostics are consistent across endpoints and support operational monitoring.

---

## Scope

### In Scope

- Define structured telemetry field set for AI invocations.
- Emit telemetry/logs from shared invocation path for start/result/failure events.
- Include correlation/request identifiers and invocation metadata (feature, tier, model, limits, duration, outcome).
- Add tests validating telemetry payload shape and required fields.

### Out of Scope

- External observability platform integration specifics.
- UI telemetry changes.

---

## Relevant Areas

- `src/lib/ai/invoke-ai.ts`
- `src/lib/ai/types.ts`
- `src/lambda/shared/*` (correlation-id utilities if needed)
- `tests/lib/ai/*`

---

## Change Requirements

- Telemetry contract must be endpoint-agnostic and generated by shared AI layer.
- Failure events must include normalized error classification fields.
- Logs must be structured and consistent for both success and failure.

---

## Verification Requirements

- Unit tests that assert telemetry field coverage and invariants.
- Validation that both successful and failed invocations produce expected telemetry events.
- Lint/typecheck coverage for new telemetry types/utilities.

---

## Acceptance Checks

- [ ] Shared telemetry schema/contract exists and is documented in code types.
- [ ] Shared invocation emits required telemetry fields for success/failure paths.
- [ ] Tests assert telemetry structure/invariants for representative invocations.
- [ ] `pnpm typecheck` and `pnpm lint` pass for touched areas.

---

## Blockers / Risks

- Inconsistent requestId propagation from handlers can reduce telemetry quality unless normalized at shared layer boundary.

---

## Notes

- Prefer additive telemetry fields to preserve backwards compatibility with existing log consumers.
