## Summary

Establish the foundational shared AI invocation interfaces and centralized Tier 1/Tier 2 routing profiles under the backend AI runtime so all AI handlers can rely on one canonical contract.

---

## Scope

### In Scope

- Define shared invocation request/response profile types.
- Define centralized feature-to-tier/model routing configuration.
- Define per-tier execution defaults (timeouts/token caps) as contract-level configuration.
- Implement hybrid routing behavior: code defaults/fallbacks with registry metadata override when valid.
- Implement allowlisted feature-override table contract for model/limits.
- Add tests verifying deterministic profile resolution and fallback behavior.

### Out of Scope

- Handler adoption changes.
- Telemetry implementation details.
- Error normalization wiring.

---

## Relevant Areas

- `src/lib/ai/types.ts`
- `src/lib/ai/config.ts`
- `src/lib/ai/invoke-ai.ts`
- `src/lib/ai/*` (new profile/routing modules as needed)
- `tests/lib/ai/*`

---

## Change Requirements

- Routing policy must be centralized and feature-addressable.
- Tier/model/limits resolution must not depend on handler-local constants.
- Code defaults must win when registry overrides are missing/invalid.
- Initial defaults must be explicit: Tier 1 `openai/gpt-4.1-mini` (20s, 1200 output tokens), Tier 2 `openai/gpt-4.1` (45s, 2500 output tokens).
- Feature-specific overrides must come only from allowlisted shared config table.
- Contracts must be explicit enough for reuse by explain-rule, suggest-expression, smart-fix, AI validation, and auto-map.

---

## Verification Requirements

- Unit tests for feature profile resolution and tier/model mapping.
- Unit tests for missing/invalid registry override fallback semantics.
- Unit tests for allowlisted override acceptance/rejection behavior.
- Typecheck/lint pass for touched AI runtime modules.

---

## Acceptance Checks

- [ ] Shared invocation and routing contract types/config are implemented in `src/lib/ai/`.
- [ ] Centralized Tier 1/Tier 2 routing exists and resolves deterministically per feature key.
- [ ] Hybrid routing fallback behavior is implemented: invalid/missing registry override falls back to code defaults.
- [ ] Tier defaults are encoded exactly as Rev 2 decisions (Tier 1 20s/1200, Tier 2 45s/2500 with specified models).
- [ ] Feature-specific overrides are controlled via allowlisted shared config table only.
- [ ] Tests validate profile resolution behavior and edge/error cases.
- [ ] `pnpm typecheck` and `pnpm lint` pass for touched areas.

---

## Blockers / Risks
