## Summary

Update engine lookup behavior and DSL/function contracts to support explicit `exact` and `ignore-case` match modes without breaking existing `valueMap()` behavior, and add deterministic collision diagnostics by direction/match mode.

---

## Scope

### In Scope

- Engine type updates for match mode on reusable map defaults and usage overrides.
- `valueMap`/`valueTable` lookup normalization logic for ignore-case string matching.
- Validation updates for duplicate normalized keys and direction-specific collisions.
- DSL specification/version updates and function registry/diagnostics alignment.

### Out of Scope

- Backend persistence and migration execution.
- UI implementation.

## Change Requirements

- Preserve backward compatibility for existing signatures:
  - `valueMap(value, mappings)`
  - `valueMap(value, mappings, fallback)`
- Extend inline signature to `valueMap(value, mappings, fallback?, matchMode?)` while preserving existing signatures.
- Keep reusable project/global value-map lifecycle details in rule binding metadata; do not encode those lifecycle details into DSL arguments.
- Use deterministic locale-independent `String.prototype.toLowerCase()` normalization on string lookup keys only.
- Do not trim, fold accents, remove punctuation, normalize locale, or cast types as part of ignore-case matching.
- Implement one shared normalization function used by validation and runtime lookup paths.
- Keep non-string behavior unchanged except where existing contract already coerces values.
- Add/extend stable diagnostics for normalized-key collisions.

---

## Verification Requirements

- Unit tests for exact and ignore-case behavior, including non-string and null inputs.
- Validation tests for collisions by direction and match mode.
- Fixtures for ASCII, accented characters, Turkish `I/İ`, and `ß` across browser/Lambda parity suites.
- Fixture parity tests confirming existing exact behavior remains unchanged.

---

## Acceptance Checks

- Existing expressions execute unchanged under default exact mode.
- Ignore-case mode matches string keys regardless of casing and preserves output value casing.
- Duplicate normalized keys are blocked deterministically for active direction/match-mode combination.

---

## Blockers / Risks

- Risk: hidden locale-dependent behavior divergence between browser and Lambda.
