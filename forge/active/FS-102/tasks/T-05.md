## Summary

Add project-level APIs for linked global maps, overlay CRUD, effective-map resolution, update review/accept workflows, orphan handling, and unlink guardrails when maps are in use.

---

## Scope

### In Scope

- Project value-map list/detail/link/unlink endpoints.
- Overlay update endpoint with override/add/exclude operations.
- Update review and accept endpoints including conflict/orphan detection.
- Effective resolution output used by Builder/runtime prep.

### Out of Scope

- Global library management endpoints.
- UI implementation.

## Change Requirements

- Support behavior of required routes:
  - `GET /projects/:projectId/value-maps`
  - `POST /projects/:projectId/value-maps/link`
  - `GET /projects/:projectId/value-maps/:id`
  - `PUT /projects/:projectId/value-maps/:id/overlay`
  - `POST /projects/:projectId/value-maps/:id/review-update`
  - `POST /projects/:projectId/value-maps/:id/accept-update`
  - `DELETE /projects/:projectId/value-maps/:id/link`
- Keep compatibility aliases for existing `/value-tables` project surfaces where applicable via canonical service routing.
- Block accept-update while unresolved conflicts/orphans remain.
- Block unlink while referenced by project mappings and return usage details.
- Add mapping dependency state transitions:
  - `current` / `needs-review` / `invalid`.
- New global revision publication sets project link `update available` only.
- Accepting linked revision update or effective overlay/default changes marks affected mappings `needs-review` without auto-version creation.
