## Summary

Extend Mapping Builder to configure and preview value-map direction, match mode defaults/overrides, fallback behavior, and effective-row provenance with pre-save validation surfacing.

---

## Scope

### In Scope

- Builder controls for direction, text matching, and fallback options.
- Support for linked global/customized/project-only map selection.
- Effective-row summary and detail preview linking to project map detail.
- Validation messaging for collisions and invalid config combinations.

### Out of Scope

- Backend resolve/update API behavior.

---

## Relevant Areas

- `ui/src/routes/pages/MappingEditor.tsx`
- `ui/src/features/mappings/**/*`
- `ui/src/lib/data/dsl-functions.ts`
- builder/decomposer/generator modules in `ui/src/features/mappings/lib/*`
- corresponding UI/unit tests

---

## Change Requirements

- Preserve existing expression compatibility while persisting explicit resolved runtime behavior metadata.
- Support inline `valueMap(value, mappings, fallback?, matchMode?)` while preserving existing expression signatures.
- Keep reusable map lifecycle details in binding metadata (id/revision/overlay/direction/match/fallback), not in DSL arguments.
- Update Builder decomposition/generation and function/help metadata in lockstep with the finalized DSL contract.
- Surface pre-save blocking diagnostics from backend/engine validation.

---

## Verification Requirements

- Builder unit/component tests for mode selection, expression generation/decomposition, validation blocks.
- Regression tests for legacy expressions without explicit match mode.

---

## Acceptance Checks

- Builder supports map default vs explicit match-mode override.
- Direction/match/fallback selections are persisted in saved mapping config contract.
- Invalid collision configurations cannot be saved.

---

## Blockers / Risks

- Risk: mismatch between builder-generated DSL and backend-resolved metadata representation.

---

- Coordinate closely with T-02 for canonical DSL/metadata representation.
