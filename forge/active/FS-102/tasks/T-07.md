## Summary

Create global library routes and screens for searching/filtering/sorting global value maps, editing rows into immutable revisions, viewing revision history, and showing usage context.

---

## Scope

### In Scope

- New global navigation entry and routes (`/value-mappings`, `/value-mappings/:valueMapId`).
- Library list/cards/table with metadata and actions.
- Global detail page with rows, revision history, and usage section.
- Save confirmation language for immutable revision creation.

### Out of Scope

- Project linking/customization UI.
- Mapping Builder integration.

---

## Relevant Areas

- `ui/src/routes/*`
- `ui/src/features/*` (new global value-mapping feature surfaces)
- `ui/src/lib/api/*`
- `ui/src/lib/types/*`
- UI tests under `ui/src/**/__tests__` or route tests

---

## Change Requirements

- Surface required metadata: name, description, current revision, row count, default match mode, project usage, mapping usage, updated date, status.
- Support archive action and duplicate action per global map rules.
- Include revision history with added/changed/removed summary.

---

## Verification Requirements

- UI tests for create/edit/archive/list/filter/sort and revision history rendering.
- Manual verification for responsive behavior and route navigation.

---

## Acceptance Checks

- Users can create and revise global maps from dedicated library routes.
- Prior revisions remain inspectable and immutable in UI.
- Usage visibility appears in detail view.

---

## Blockers / Risks

- Risk: route-level state drift if library and project pages use divergent view models.

---

## Notes

- Preserve existing app-shell visual language and navigation patterns.
