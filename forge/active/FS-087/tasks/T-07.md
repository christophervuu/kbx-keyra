## Summary

Ensure mapping create/edit schema selectors can choose from all schemas in the shared library, while preserving explicit schema references and optionally linking selected non-linked schemas to the current project.

---

## Scope

### In Scope

- Update Create Mapping and Mapping Editor schema picker logic to shared-library availability.
- Preserve explicit source/target schema reference IDs in mapping configs.
- Highlight or default linked schemas for relevance without restricting availability.
- Define and implement behavior when selecting non-linked schema (auto-link or guided link).

### Out of Scope

- Backend migration scripts.
- Schema Library visual redesign beyond picker/list interactions.

- Schema pickers must no longer be filtered by project/global/local scope.
- Source/target references remain explicit and stable per selected schema IDs.
- Selecting non-linked schema should preserve project relevance model (linking behavior aligned with spec decisions).

- Implemented shared-library schema availability in Create Mapping flow:
  - Source/target selectors now load from `listSchemas()` (shared library), not project-linked-only schema refs.
  - Selector options are grouped by relevance (`Linked schemas` first, then `Other available schemas`) while preserving full availability.
  - Format labels in selector options normalized to shared terminology (`JSON`, `XSD`, etc.).

  - Source/target mapping refs are derived from selected schema IDs and source metadata (`github` refs keep commitSha, upload-backed refs use `published`).

- Implemented project relevance preservation when selecting non-linked schemas:
  - On submit, selected schema IDs not already linked are best-effort linked to project via `updateProject({ linkedSchemaIds })` before mapping create.
  - Link update failure is non-blocking to mapping creation so explicit mapping refs remain canonical.
