## Summary

Adjust project-level schema workflows so Add Schema means link existing shared schema or upload new shared schema and link it to the project; unlink removes project relevance only.

---

## Scope

### In Scope

- Update Add Schema entry points and interactions from Project Overview context.
- Ensure upload-from-project path creates shared schema and links to current project.
- Ensure linked schema list behavior reflects project relevance only.
- Wire unlink interactions to non-destructive link removal semantics with hard-block when mapping dependencies exist.

### Out of Scope

- Backend API contract changes.
- Mapping schema picker behavior (handled by T-07).

## Change Requirements

- Add Schema workflow presents link-existing and upload-new semantics aligned to shared library model.
- Uploaded schema from project context is linked back to project after creation.
- Unlink action never implies global deletion and is blocked when schema is mapping-referenced in that project; dependent mappings are surfaced.

---

## Verification Requirements

- Integration/component tests for add/upload/link/unlink project schema flows.
- Manual validation in Project Overview for linked schema counts/list behavior.

---

## Acceptance Checks

- Project linked-schema interaction shows relevance list only.
- Upload from project results in shared schema + project link.
- Unlink behavior removes link only when safe; when mappings depend on schema, unlink is blocked and schema remains in library.
