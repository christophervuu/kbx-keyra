## Summary

Introduce canonical `RecipeValue` usage objects (`input|fixed|constant`) with per-value steps and move away from transforms stored on raw tray inputs. Ensure transform scope is exactly per-value and final-result.

---

## Scope

### In Scope

- Recipe value type definitions and conversion helpers.
- Per-value step attach/edit/clear mechanics in state helpers.
- Legacy transform migration rules (lossless only; otherwise Advanced fallback marker).

### Out of Scope

- Full UI redesign of all editors.

---

## Relevant Areas

- `ui/src/features/mappings/lib/smart-builder-state.ts`
- `ui/src/features/mappings/lib/smart-builder-expression-generator.ts`

## Change Requirements

- Raw tray input no longer canonical owner of transform chains.
- Reused tray input can have different transforms per usage.
- Final-result steps remain separate from recipe-value steps.

---

## Verification Requirements

- Unit tests for per-value vs result-step separation.
- Hydration migration tests for legacy transform shapes.

---

## Acceptance Checks

- Dual-ownership transform model removed from canonical path.
- Reused input with distinct per-use transforms generates distinct DSL wrapping.

---

## Blockers / Risks
