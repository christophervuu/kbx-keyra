## Summary

Implement the "Constants" section within the ConfigurationPanel. This section manages `config.constants` — a key-value map referenced in rules via `constant("KEY_NAME")`. Users can add new constants (key + value with type inference), edit existing constants inline, and delete constants with a confirmation warning about potential rule breakage.

---

## Scope

### In Scope

- `ConstantsSection` component
- Display: table of key-value pairs with type badge (string, number, boolean)
- Add constant: key input (uppercase convention suggested via placeholder) + value input + add button
- Value type inference: numeric strings → number, "true"/"false" → boolean, else → string
- Type badge display next to value (subtle, informational)
- Edit constant: click to enter inline edit mode for key or value
- Delete constant: X button with confirmation message: "This constant may be referenced by rules. Removing it will cause validation errors."
- Duplicate key prevention: show inline error "Key already exists" if key matches existing entry
- Empty key prevention: add button disabled until key is non-empty
- Empty state: "No constants defined" message
- Calls `onUpdateConfig({ constants: updatedRecord })` on add/edit/delete

### Out of Scope

- Validating constant values against usage in rules (engine handles this)
- Complex value types (objects, arrays) — values are scalar only in Phase 0
- Bulk import/export of constants
- Sorting or filtering the constants table

## Change Requirements

After this task:

- `ConstantsSection` accepts:
  - `constants: Readonly<Record<string, unknown>>` (current constants, may be undefined → treat as `{}`)
  - `onUpdate: (constants: Record<string, unknown>) => void` (calls `onUpdateConfig({ constants: {...} })`)
- Renders a table/list of existing constants:
  - Column 1: Key (monospace, clickable for inline edit)
  - Column 2: Value (clickable for inline edit) + type badge
  - Column 3: Delete (X) button
- Add row at bottom:
  - Key input (placeholder: "CONSTANT_NAME")
  - Value input (placeholder: "value")
  - Add button (disabled when key is empty or duplicate)
- Type inference logic:
  - `/^-?\d+(\.\d+)?$/` → store as `number`
  - `"true"` or `"false"` (case-insensitive) → store as `boolean`
  - everything else → store as `string`
- Inline edit mode:
  - Click on key or value cell enters edit mode
  - Enter or blur commits the edit
  - Escape cancels the edit
  - Key edit: if new key conflicts with existing, show error and revert
- Delete flow:
  - Click X → confirmation dialog with warning about rule references
  - Confirm → remove key from constants record → call `onUpdate`
  - Cancel → no change

## Notes

For the type badge, use a small colored pill:
- "string" → gray
- "number" → blue
- "boolean" → purple

The key input should visually suggest uppercase convention (via placeholder text "CONSTANT_NAME") but not enforce it — users may use any valid string key.

The inline edit pattern: use a controlled input that replaces the display text on click. This avoids needing a separate edit modal. Keep the edit state local to the row.
