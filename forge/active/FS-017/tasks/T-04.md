## Summary

Implement the "Null-out Subtrees" section within the ConfigurationPanel. This section manages `config.nullSubtrees` — an array of target path prefixes whose entire subtrees should be set to null during execution. Users can add subtree roots (with autocomplete from target schema object-type nodes), remove entries with confirmation, and see the child field count for each path.

---

## Scope

### In Scope

- `NullSubtreesSection` component
- Add subtree: text input with autocomplete suggestions from `parsedTargetSchema`
- Autocomplete filters to object-type nodes only (nodes with children)
- Remove subtree: X button on each entry with confirmation dialog
- Display: list of current subtree roots with path and child field count
- Duplicate prevention: if path already in list, show inline error
- Calls `onUpdateConfig({ nullSubtrees: updatedArray })` on add/remove
- Confirmation dialog for remove: "Remove subtree null-out for '{path}'?"
- Integration into `ConfigurationPanel` section slot

### Out of Scope

- Implementing the engine's null-subtree execution behavior (already exists)
- Validating that the path is a "correct" path (allow manual entry of paths not in schema)
- Nested autocomplete (just flat path strings from schema tree)

## Notes

To derive autocomplete paths from `ParsedSchema`:
- Walk the `SchemaTreeNode` tree recursively
- Collect paths of nodes where `node.type === 'object'` (nodes that have `children`)
- Build dot-notation paths (e.g., `Order.Header.ShipTo`)
- This utility could be a small helper function in `lib/` or co-located with the component

For child field count: count the number of leaf nodes under the selected object node in the schema tree. If schema is not available, show "—" or omit the count.

Reuse the existing `ConfirmDialog` component from `ui/src/features/mappings/components/ConfirmDialog.tsx`.
