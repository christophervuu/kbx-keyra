## Summary

Create the `ConfigurationPanel` component that serves as the structural container for all config sections in Panel 7. It defines the section layout (unmapped targets, null subtrees, constants, external sources), the settings inheritance indicator pattern, and scroll behavior within the constrained panel slot. Individual section content components are plugged in by subsequent tasks.

---

## Scope

### In Scope

- `ConfigurationPanel` component with props for config state and actions
- Section container pattern (collapsible or static sections with headers)
- `InheritanceIndicator` sub-component: "Using project default" (gray) or "Custom" (blue badge)
- "Reset to project default" action button per section (visible but non-functional beyond clearing to undefined in Phase 0)
- Scrollable panel body to handle overflow in the constrained Panel 7 slot
- Section placeholder slots for T-03 through T-06 to fill
- Panel header with "Configuration" title

### Out of Scope

- Implementing the actual content of each section (Unmapped Targets, Null Subtrees, Constants, External Sources) — those are T-03 through T-06
- Wiring into MappingEditorPage (that's T-07)
- Project settings resolution logic (Phase 1)

## Notes

The sections will initially render placeholders. T-03 through T-06 will replace them with full section implementations. The section structure should make it easy to slot in child components without modifying the ConfigurationPanel shell.

Keep the section layout simple — no tabs/accordion needed. A single scrollable column with clearly separated sections works well for the constrained Panel 7 space. Each section header should be visually distinct (e.g., border-b separator or slight background difference).
