## Summary

Implement the "Unmapped Targets Strategy" section within the ConfigurationPanel. This is a radio group (or dropdown) that lets users select what happens to target fields with no mapping rule: "null" (set to null), "omit" (exclude from output), or "error" (produce validation errors). The selection writes to `config.unmappedTargets` and triggers validation.

---

## Scope

### In Scope

- `UnmappedTargetsSection` component
- Radio group with three options: null (default), omit, error
- Option labels with brief descriptions:
  - `null` — "Set unmapped fields to null in output (default)"
  - `omit` — "Exclude unmapped fields from output entirely"
  - `error` — "Produce validation errors for unmapped fields"
- Calls `onUpdateConfig({ unmappedTargets: value })` on selection change
- Reflects current selection from `configOptions.unmappedTargets` (undefined treated as "null")
- Accessible radio group (proper fieldset, legend, aria labels)
- Integration into `ConfigurationPanel` section slot

### Out of Scope

- Implementing the validation logic itself (engine handles this)
- Displaying which specific fields are unmapped (that's Panel 3/6 diagnostics)
- Project-level default resolution (Phase 1)
