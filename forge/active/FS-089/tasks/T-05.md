## Summary

Implement Schema Library list/table view optimized for larger schema sets, with required columns, CDM badge/name handling, actions, and sort integration.

---

## Scope

### In Scope

- Add list/table renderer with columns: Name, Status, Format, Fields, Used By, Updated, Actions.
- Ensure name column includes CDM badge and duplicate-name disambiguator.
- Wire list view into shared filter/sort/view state.
- Respect ownership-based action availability in Actions column.

### Out of Scope

- Card renderer redesign.
- Backend pagination redesign.
- New advanced table features (column pinning, virtualization) unless already present.

---

## Relevant Areas

- `ui/src/features/schemas/components/**/*`
- `ui/src/features/schemas/hooks/**/*`

---

## Change Requirements

- List view must use same canonical status and format semantics as cards.
- Sort behavior must be consistent between card and list modes.
- CDM and user-created action rules must remain consistent across views.

---

## Verification Requirements

- UI tests for list column rendering, sorting, and action availability.
- Manual check for view-toggle parity between card and list.

---

## Acceptance Checks

- List view renders required columns with expected schema metadata.
- CDM badge appears left of name in list rows for CDM schemas.
- Sorting works for major columns in list view.
- Actions column respects read-only CDM restrictions.

---

## Blockers / Risks

- Shared state bugs between card/list mode can cause filter/sort divergence.

---

## Notes

- Reuse card/list shared formatting helpers for status, dates, and field count text.
