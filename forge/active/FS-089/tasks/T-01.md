## Summary

Refactor shared schema metadata contracts across backend/persistence/adapter layers to separate ownership, data format, source kind, and readiness status. Remove scope/sync/publish UI-driving semantics from canonical read models while keeping compatibility handling for legacy records.

---

## Scope

### In Scope

- Update schema metadata types and normalization paths to support:
  - `ownership: cdm | user`
  - `dataFormat: json | xml`
  - `sourceKind: json_schema | xsd | inferred_from_json | inferred_from_xml`
  - `status: ready | processing | needs_review | error`
  - `isCdm`, `readonly`, and optional disambiguator fields
- Add compatibility mapping from legacy fields (`scope`, legacy origin aliases, sync fields) into new read model.
- Ensure adapters expose stable payloads for schema library and selector consumers.

### Out of Scope

- Schema Library rendering changes.
- Add Schema modal UX updates.
- CDM seed/bootstrap data loading implementation.

## Change Requirements

- Canonical schema read model must expose ownership/format/source-kind/status as separate fields.
- Legacy `scope` and sync/publish semantics must not be required by UI surfaces.
- Data format presentation contract must derive JSON/XML from source kind correctly.
- Existing records must remain readable via compatibility normalization.

---

## Verification Requirements

- Unit tests for metadata normalization and source-kind → dataFormat mapping.
- Adapter-level tests for schema list/detail payload shape.
- Typecheck/lint pass for touched backend/UI contract files.

---

## Acceptance Checks

- Shared schema metadata type definitions include ownership, dataFormat, sourceKind, status, isCdm, readonly.
- Legacy records with scope/origin aliases normalize into canonical read model without runtime errors.
- No canonical UI contract path requires Global/Local/Published/sync fields.
- Tests covering AE-08 and AE-12 mapping behavior pass.
- Lint and typecheck pass for touched modules.
