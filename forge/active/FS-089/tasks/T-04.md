## Summary

Update schema cards to the new content hierarchy with CDM badge placement, status prominence, format/field count separation from source kind, and contextual display for duplicates and zero-field states.

---

## Scope

### In Scope

- Card layout updates:
  - CDM badge left of schema name
  - status directly below name
  - format + field count row
  - used-by and updated rows
- Remove derivation/source-kind from primary card metadata.
- Implement duplicate-name disambiguator display.
- Implement contextual 0-field display behavior.
- Update card action availability based on ownership/read-only state.

### Out of Scope

- List/table renderer changes.
- Add Schema modal changes.
- Backend disambiguator generation strategy decisions beyond current contract fields.

---

## Relevant Areas

- `ui/src/features/schemas/components/**/*`
- `ui/src/features/schemas/hooks/**/*`
- `ui/src/lib/types/domain.ts`

---

## Change Requirements

- Card must show JSON/XML format labels only (never “Inferred” as format).
- CDM cards must not expose edit/delete/replace actions.
- Error/needs-review/processing statuses must be visually distinguishable.

---

## Verification Requirements

- Component tests for card rendering by ownership/status/source-kind combinations.
- Tests for duplicate name disambiguator rendering and zero-field contextual copy.
- Manual visual regression review in schema library card view.

---

## Acceptance Checks

- Card metadata rows match required hierarchy and content.
- CDM badge appears at left of schema name for CDM only.
- Source-kind is not used as card format label.
- 0-field states render contextual messaging tied to status.
- CDM cards do not expose edit/replace/delete actions.

---

## Blockers / Risks

- Disambiguator source field may vary by data availability.
