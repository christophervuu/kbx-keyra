## Summary

Implement the baseline CDM bootstrap/seed behavior so CDM schemas are present automatically in default schema list APIs/adapters. Use the resolved hybrid strategy: startup metadata bootstrap for all CDM schemas with lazy full payload/tree loading, and keep behavior consistent for Create Mapping selectors.

---

## Scope

### In Scope

- Add/adjust CDM seed manifest/fixture loading in current runtime path:
  - backend mode canonical source: versioned `cdm-manifest.json` with seeded DynamoDB/S3 records,
  - local/demo mode fallback: bundled read-only fixtures.
- Ensure list schemas responses include seeded CDM records without manual link steps.
- Preserve CDM record read-only semantics and ownership markers.
- Bootstrap metadata at startup for all CDM entries; lazy-load full schema payload/tree on demand.
- Ensure selector-facing list queries include CDM by default.

### Out of Scope

- Schema Library UI card/list rendering.
- Add Schema modal behavior.
- CDM governance/admin remove flows.

---

## Relevant Areas

- `src/lambda/schema/list-schemas.ts`
- `src/lib/persistence/schema-metadata.ts`
- `ui/src/lib/api/local-storage-adapter.ts`
- `ui/src/lib/api/http-adapter.ts`
- schema seed fixtures/manifests under `src/` or `ui/` as appropriate

---

## Change Requirements

- Default schema list behavior must include CDM records without add/link operations.
- Seed path must support current local/demo mode while preserving backend-replaceable contract.
- Seeded CDM records must include required canonical metadata (ownership/status/readonly).

---

## Verification Requirements

- Fixture/seed tests asserting CDM presence in default schema list.
- Selector-level test coverage showing CDM entries available for mapping selection.
- Typecheck/lint for touched backend/adapter paths.

---

## Acceptance Checks

- Default schema list contains CDM entries in fresh runtime state.
- Create Mapping selectors can load CDM entries without prior Add Schema action.
- Seeded CDM records are marked as read-only CDM ownership.
- Tests for CDM default presence pass.

---

## Blockers / Risks

- Manifest/fixture parity risk between backend and local/demo modes if contracts diverge.

---

## Notes

- Favor a contract-stable implementation so backend seed-job replacement in later phase does not require UI contract changes.
