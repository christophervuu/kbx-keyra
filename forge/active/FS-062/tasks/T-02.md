## Summary

Add all five Phase 1 DynamoDB table resource definitions to the SAM template with correct key schemas, GSIs, and on-demand billing. Table definitions must exactly match the schemas documented in `forge/architecture/persistence-model.md`.

---

## Scope

### In Scope

- `AWS::DynamoDB::Table` resources for: Projects, Mappings, SchemaMetadata, SchemaNodes, MappingVersions
- Key schemas (PK, SK) for each table
- GSI definitions: `projectId-index` on Mappings, `fieldName-index` and `parentPath-index` on SchemaNodes
- `BillingMode: PAY_PER_REQUEST` on all tables
- Stage-prefixed table names via `!Sub`
- DeletionPolicy: Retain for prod, Delete for dev (conditional)

### Out of Scope

- Table data or seed records
- Persistence module TypeScript code (FS-058)
- Additional attribute definitions beyond key attributes (DynamoDB is schemaless beyond keys)

---

## Relevant Areas

- `template.yaml` (modify — add resources)
- `forge/architecture/persistence-model.md` (reference)

## Change Requirements

Add to `template.yaml` Resources section:

1. **ProjectsTable** (`AWS::DynamoDB::Table`)
   - TableName: `!Sub '${Stage}-keyra-projects'`
   - KeySchema: `projectId` (HASH)
   - AttributeDefinitions: `projectId` (S)
   - BillingMode: PAY_PER_REQUEST

2. **MappingsTable** (`AWS::DynamoDB::Table`)
   - TableName: `!Sub '${Stage}-keyra-mappings'`
   - KeySchema: `mappingId` (HASH)
   - AttributeDefinitions: `mappingId` (S), `projectId` (S)
   - GSI `projectId-index`: KeySchema `projectId` (HASH), Projection ALL
   - BillingMode: PAY_PER_REQUEST

3. **SchemaMetadataTable** (`AWS::DynamoDB::Table`)
   - TableName: `!Sub '${Stage}-keyra-schema-metadata'`
   - KeySchema: `schemaId` (HASH)
   - AttributeDefinitions: `schemaId` (S)
   - BillingMode: PAY_PER_REQUEST

4. **SchemaNodesTable** (`AWS::DynamoDB::Table`)
   - TableName: `!Sub '${Stage}-keyra-schema-nodes'`
   - KeySchema: `schemaId` (HASH), `path` (RANGE)
   - AttributeDefinitions: `schemaId` (S), `path` (S), `fieldName` (S), `schemaIdPath` (S), `parentPath` (S)
   - GSI `fieldName-index`: KeySchema `fieldName` (HASH), `schemaIdPath` (RANGE), Projection ALL
   - GSI `parentPath-index`: KeySchema `schemaId` (HASH), `parentPath` (RANGE), Projection ALL
   - BillingMode: PAY_PER_REQUEST
   - Note: `schemaIdPath` is a concatenated attribute `{schemaId}#{path}` — application code must populate this attribute on write

5. **MappingVersionsTable** (`AWS::DynamoDB::Table`)
   - TableName: `!Sub '${Stage}-keyra-mapping-versions'`
   - KeySchema: `mappingId` (HASH), `version` (RANGE)
   - AttributeDefinitions: `mappingId` (S), `version` (N)
   - BillingMode: PAY_PER_REQUEST

Update Globals.Function.Environment.Variables to use `!Ref` for each table logical ID.

## Notes

- The `fieldName-index` GSI uses a concatenated sort key attribute `schemaIdPath` containing `{schemaId}#{path}`. This keeps the index simple and avoids filter-based queries. Application-level code (persistence module in FS-058) is responsible for populating this attribute on every write.
- DynamoDB does not require defining non-key attributes. Only key attributes (used in PK, SK, or GSI keys) need to appear in AttributeDefinitions.
