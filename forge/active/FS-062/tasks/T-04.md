## Summary

Define the API Gateway REST API resource and all 20+ Lambda function resources in the SAM template, with correct routes, Lambda proxy integrations, CORS preflight configuration, IAM roles, and per-function environment variables. This is the largest infrastructure task and wires together the entire API surface.

---

## Scope

### In Scope

- `AWS::Serverless::Api` resource with CORS, stage name, and binary media types
- `AWS::Serverless::Function` resources for all 20 handlers from backend-api.md route table
- Lambda function properties: Handler, CodeUri, Runtime, MemorySize, Timeout, Policies, Events (API event)
- IAM policies: DynamoDB CRUD on relevant tables, S3 read/write on storage bucket, Step Functions StartExecution (for schema ingest), OpenSearch HTTP access (for schema query)
- Per-function memory overrides for performance-critical functions (schema ingestion: 512MB, schema query: 512MB)
- CORS preflight via SAM `Cors` property or explicit OPTIONS methods

### Out of Scope

- Lambda handler application code (FS-056, FS-057, FS-058)
- Custom authorizers or API keys
- Request/response models or validators in API Gateway
- Usage plans or throttling configuration
- WAF integration

## Change Requirements

Add to `template.yaml`:

**KeyraApi** (`AWS::Serverless::Api`)
- StageName: `!Ref Stage`
- Cors:
  - AllowOrigin: `'*'`
  - AllowMethods: `'GET,POST,PUT,DELETE,OPTIONS'`
  - AllowHeaders: `'Content-Type,Authorization'`

**Lambda Functions** (one per route from backend-api.md Section 2):

Project domain (5 functions):
- CreateProjectFunction: POST /projects → `src/lambda/project/create-project.ts`
- ListProjectsFunction: GET /projects → `src/lambda/project/list-projects.ts`
- GetProjectFunction: GET /projects/{id} → `src/lambda/project/get-project.ts`
- UpdateProjectFunction: PUT /projects/{id} → `src/lambda/project/update-project.ts`
- DeleteProjectFunction: DELETE /projects/{id} → `src/lambda/project/delete-project.ts`

Mapping domain (9 functions):
- CreateMappingFunction: POST /mappings → `src/lambda/mapping/create-mapping.ts`
- GetMappingFunction: GET /mappings/{id} → `src/lambda/mapping/get-mapping.ts`
- UpdateMappingFunction: PUT /mappings/{id} → `src/lambda/mapping/update-mapping.ts`
- DeleteMappingFunction: DELETE /mappings/{id} → `src/lambda/mapping/delete-mapping.ts`
- DuplicateMappingFunction: POST /mappings/{id}/duplicate → `src/lambda/mapping/duplicate-mapping.ts`
- ListMappingsFunction: GET /projects/{projectId}/mappings → `src/lambda/mapping/list-mappings.ts`
- ListVersionsFunction: GET /mappings/{mappingId}/versions → `src/lambda/mapping/list-versions.ts`
- GetVersionFunction: GET /mappings/{mappingId}/versions/{version} → `src/lambda/mapping/get-version.ts`
- SaveVersionFunction: POST /mappings/{mappingId}/versions → `src/lambda/mapping/save-version.ts`

Schema domain (5 functions):
- CreateSchemaFunction: POST /schemas → `src/lambda/schema/create-schema.ts`
- ListSchemasFunction: GET /schemas → `src/lambda/schema/list-schemas.ts`
- GetSchemaFunction: GET /schemas/{id} → `src/lambda/schema/get-schema.ts`
- DeleteSchemaFunction: DELETE /schemas/{id} → `src/lambda/schema/delete-schema.ts`
- QuerySchemaNodesFunction: POST /schemas/{id}/query → `src/lambda/schema/query-schema-nodes.ts`

Schema ingestion workers (2 functions):
- ProcessBatchFunction: (no API event — invoked by Step Functions)
- OrchestrationTasksFunction: (no API event — invoked by Step Functions)

Each function needs:
- Events: Api event with path and method referencing `!Ref KeyraApi`
- Policies: minimum-privilege IAM (e.g., project functions only need Projects table access)
- Environment: Inherits Globals + any function-specific additions (e.g., schema functions need `OPENSEARCH_ENDPOINT`, `STATE_MACHINE_ARN`)

## Notes

- SAM uses `Events` property on `AWS::Serverless::Function` to implicitly create API Gateway integrations. This is preferred over explicit `AWS::ApiGateway::Method` resources for simplicity.
- The `{id}` path parameter syntax in SAM/API Gateway is `{id}` (not `:id` like Express). Translate from backend-api.md's `:id` notation.
- Step Functions worker functions (ProcessBatch, OrchestrationTasks) are invoked directly by Step Functions, not via API Gateway. They should have no `Events` but still need appropriate IAM policies.
- Consider grouping IAM policies into shared policy documents to reduce template verbosity.
