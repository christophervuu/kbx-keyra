## Summary

Define the Step Functions state machine resource in the SAM template with correct IAM permissions, timeout configuration, and reference to the ASL definition file. The state machine orchestrates large schema ingestion (>= 500 fields) by coordinating parse, batch process, aggregate, and metadata update Lambda tasks.

---

## Scope

### In Scope

- `AWS::Serverless::StateMachine` resource in `template.yaml`
- ASL (Amazon States Language) definition file at `src/lambda/schema/step-functions/schema-ingestion.asl.json`
- IAM policy: invoke ProcessBatch and OrchestrationTasks Lambda functions
- IAM policy: read/write S3 batch files
- State machine timeout: 15 minutes
- Map state with MaxConcurrency: 10
- Error handling: Catch-all routing to error handler state
- `STATE_MACHINE_ARN` environment variable on CreateSchemaFunction

### Out of Scope

- Lambda handler application logic (FS-056)
- Step Functions execution monitoring or dashboards
- Custom retry policies beyond what's defined in the ASL

## Change Requirements

Add to `template.yaml` Resources section:

**SchemaIngestionStateMachine** (`AWS::Serverless::StateMachine`)
- Name: `!Sub '${Stage}-keyra-schema-ingestion'`
- DefinitionUri: `src/lambda/schema/step-functions/schema-ingestion.asl.json`
- DefinitionSubstitutions:
  - `ProcessBatchFunctionArn`: `!GetAtt ProcessBatchFunction.Arn`
  - `OrchestrationTasksFunctionArn`: `!GetAtt OrchestrationTasksFunction.Arn`
  - `StorageBucket`: `!Ref StorageBucket`
- Policies:
  - LambdaInvokePolicy for ProcessBatchFunction
  - LambdaInvokePolicy for OrchestrationTasksFunction
  - S3CrudPolicy for StorageBucket (batch file read/write)

Create `src/lambda/schema/step-functions/schema-ingestion.asl.json`:
- States:
  1. **ParseSchema**: Task state, invoke OrchestrationTasks with `action: 'parse'`
  2. **ProcessBatches**: Map state, MaxConcurrency 10, invoke ProcessBatch per batch item
  3. **AggregateResults**: Task state, invoke OrchestrationTasks with `action: 'aggregate'`
  4. **UpdateMetadata**: Task state, invoke OrchestrationTasks with `action: 'updateMetadata'`
  5. **HandleError**: Task state, invoke OrchestrationTasks with `action: 'handleError'`
- All task states have Catch routing to HandleError
- TimeoutSeconds: 900 (15 minutes) at state machine level
- Comment describing the flow

Update CreateSchemaFunction environment:
- Add `STATE_MACHINE_ARN: !Ref SchemaIngestionStateMachine`

## Notes

- The ASL definition uses `${ProcessBatchFunctionArn}` and `${OrchestrationTasksFunctionArn}` as substitution variables that SAM replaces via `DefinitionSubstitutions`.
- The OrchestrationTasks function is a single Lambda that handles multiple actions (parse, aggregate, updateMetadata, handleError) differentiated by input payload. This is simpler than separate Lambdas for each orchestration step.
- Per schema-ingestion.md, the Map state iterates over batch manifests written to S3 by the ParseSchema step. The iterator receives a batch file S3 key as input.
