## Summary

Extend `array-expression-generator.ts` to emit deterministic canonical `map(filter(map(array(...))))` expression structure for `objectFields` mode, preserving ordered key list, null filtering semantics, reusable item template mapping, and optional user inclusion condition.

---

## Scope

### In Scope

- Add generator branch for `objectFields` mode.
- Build deterministic `array("k1", "k2", ...)` from configured key order.
- Build intermediate `{ day, value }` records via `get(source(parentPath), item(""))`.
- Apply default `not(isNull(item("value")))` filtering before final template mapping.
- Integrate optional additional inclusion predicate.
- Ensure item template generation references `item("day")` and `item("value")` contexts correctly.

### Out of Scope

- Decomposer changes.
- UI component interactions.

---

## Relevant Areas

- `ui/src/features/mappings/lib/array-expression-generator.ts`
- `ui/src/features/mappings/lib/array-expression-generator.test.ts`

---

## Change Requirements

- Generated expression uses only existing DSL functions (`array/map/filter/get/source/item/not/isNull` plus existing scalar DSL).
- Generator must not emit lazy-`if` placeholder object generation pattern for this mode.
- Output string is deterministic for same state input.
- Parent-missing behavior resolves to empty result through canonical pipeline semantics (non-fatal).

---

## Verification Requirements

- Add unit tests for:
  - one field and seven ordered fields,
  - missing/null child skip semantics,
  - `IsOpen: false` included,
  - missing child inner fields retained as item nulls,
  - fixed values,
  - root and enrichment references,
  - additional inclusion condition,
  - deterministic expression stability.
- Parse validity assertions via engine parse helper.

---

## Acceptance Checks

- Generator emits canonical nested structure for objectFields mode.
- Order follows configured key order exactly.
- Missing/null child keys are filtered before item template mapping.
- Existing modes’ generator output remains unchanged.

## Blockers / Risks
