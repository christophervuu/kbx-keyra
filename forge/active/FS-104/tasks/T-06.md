## Summary

Add objectFields-specific validation rules and preview summary presentation for configured/included/skipped/generated counts, including parent-missing and schema-drift unresolved-child handling.

---

## Scope

### In Scope

- Extend `array-validation.ts` for objectFields mode checks:
  - missing parent object path,
  - no selected keys,
  - duplicate key selection,
  - invalid/removed schema child key handling (preserve unresolved entry),
  - item recipe completeness/required target warnings.
- Extend preview rendering (`ArrayResultPreview` and/or `BuilderFeedbackArea` integration) to display required summary counts and output order metadata for objectFields runs.
- Ensure default semantics skip absent/null child keys and include `IsOpen: false` objects.

### Out of Scope

- Engine-level new diagnostics codes (unless absolutely required by implementation evidence).

- `ui/src/features/mappings/lib/array-validation.ts`

- related component/lib tests

---

## Change Requirements

- Preview must communicate:
  - configured properties count,
  - included properties count,
  - skipped properties count,
  - generated items count,
  - final output order.
- Parent-missing should not produce noisy per-child warning spam in preview summary.
- Unresolved removed schema child keys are preserved and marked repair-needed.

---

## Verification Requirements

- Unit/component tests for validation states and preview summary counts.
- Tests for parent missing, missing child, explicit null child, and `IsOpen: false` inclusion.

---

## Acceptance Checks

- Validation catches objectFields configuration errors deterministically.
- Preview summary shows correct counts for complete and missing-day samples.
- Parent missing case yields empty output with non-fatal warning behavior.

---

## Blockers / Risks

- Count derivation can drift from actual expression output if not tied to execution result structure.

---

## Notes

- Prefer deriving counts from evaluated intermediate pipeline outputs where feasible for accuracy.
