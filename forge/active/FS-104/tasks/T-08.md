## Summary

Add parity-focused tests that execute canonical objectFields-generated expressions through both browser engine integration and runtime/Lambda handler harnesses to confirm identical outputs and required missing-value behavior.

---

## Scope

### In Scope

- Add/extend engine integration tests for objectFields canonical expression scenarios.
- Add/extend runtime execute handler tests with same payload/config fixtures to assert parity with browser-side execution outcomes.
- Include cases:
  - full weekly input (7 outputs ordered),
  - missing day key (6 outputs),
  - parent missing/null (empty array),
  - `IsOpen: false` retained.

### Out of Scope

- Changing runtime handler API contracts.
- Non-objectFields parity expansion.

---

## Relevant Areas

- `tests/engine/functions/arrays-integration.test.ts`
- `tests/engine/functions/arrays.test.ts`
- `tests/lambda/runtime/runtime-handlers.test.ts`
- supporting fixtures in `tests/**`

---

## Change Requirements

- Same canonical expression and source payloads should be used for both execution paths.
- Assertion includes output ordering and object contents.
- No cloud-specific behavior branch is introduced.

---

## Verification Requirements

- Run targeted engine and lambda test suites.
- Ensure no regression in existing runtime execute tests.

---

## Acceptance Checks

- Browser-side and Lambda-side outputs match for canonical objectFields cases.
- Missing parent object yields empty array without execution failure.
- `IsOpen: false` entries remain present.

## Blockers / Risks

## Notes
