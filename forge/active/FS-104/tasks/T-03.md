## Summary

Update item-template authoring for `objectFields` so each scalar field uses current Smart Builder semantics with canonical context access to property name (`day`) and property value (`value`) while preserving root source/enrichment/fixed-value behavior.

---

## Scope

### In Scope

- Extend item-field authoring context wiring (`ItemTemplateEditor`/`ItemFieldRow` and related helper state) for objectFields mode:
  - property-name source option,
  - property-value object source option,
  - existing source/enrichment contexts.
- Ensure one reusable item recipe applies across selected keys.
- Preserve transforms/defaults/conditions/value-maps/refine/advanced fallback behavior.

### Out of Scope

- Collection editor interactions.
- Canonical DSL generation implementation details.

---

- `ui/src/features/mappings/components/ItemTemplateEditor.test.tsx`
- `ui/src/features/mappings/lib/chain-expression-generator.ts` (if context placeholder normalization updates are required)

---

## Change Requirements

- Item recipe context must support mapping examples:
  - `operationDayValue` ← property name
  - `beginTime/endTime/isOpen` ← property value child fields
  - fixed literals
- No requirement to author seven separate mappings.
- Existing non-objectFields array modes remain unchanged.

---

## Verification Requirements

- Component tests for selecting property-name and property-value contexts.
- Tests for fixed values and transform/default chains in objectFields recipe rows.
- Regression tests for existing item field contexts (`item`, `parent`, `source`, static).

---

## Acceptance Checks

- Item recipe field can map from property name context.
- Item recipe field can map from property value context.
- Existing root source and enrichment references remain available.
- Reusable recipe applies uniformly (single configuration path) in UI state.

---

## Blockers / Risks

- Context disambiguation in UI labels may confuse users if not clearly named.

---

## Notes

- Do not introduce a second scalar-transformation implementation; reuse existing Smart Builder pathways.
