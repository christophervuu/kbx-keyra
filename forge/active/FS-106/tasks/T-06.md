## Summary

Implement artifact packaging as a self-contained runtime bundle with deterministic canonical serialization and stable artifact identity/hash behavior across deploy/promote/rollback.

---

## Scope

### In Scope

- Bundle builder for manifest + runtime content payload.
- Canonical serializer and hash computation.
- Artifact identity rules (`artifactId` bound to hash).
- Validation checks at runtime ingest/activation.

### Out of Scope

- Retention cleanup process.

---

## Relevant Areas

- `src/lib/deployment/*artifact*` (new/refactor)
- `src/lambda/deployment/deploy-mapping.ts`
- `src/lambda/deployment/promote-deployment.ts`
- `src/lambda/runtime/*ingest*` (if present/new)
- `src/lib/persistence/s3/deployment-snapshot.ts`
- `tests/lib/deployment/*`

---

## Change Requirements

- Ensure metadata (actor/reason/environment/time) is excluded from artifact hash input.
- Promotion transfers identical bundle bytes/hash.
- Rollback never rebuilds artifacts.

---

## Verification Requirements

- Unit tests for canonical serialization determinism.
- Integration tests confirming same bytes/hash through promotion path.

---

## Acceptance Checks

- Same artifact ID/hash always maps to same bytes.
- Promotion and rollback preserve immutable artifact identity.
- Runtime ingest rejects hash/content mismatch.

---

## Blockers / Risks

- Canonical serialization drift can cause false identity changes.
