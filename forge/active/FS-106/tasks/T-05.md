## Summary

Implement one-operation-at-a-time locking per mapping/environment plus scheduled reconciliation for timed-out/stuck operations and runtime/projection mismatch repair.

---

## Scope

### In Scope

- Lock acquisition/release/expiry/recovery.
- Expected-active-artifact concurrency checks.
- Runtime status and active-pointer reconciliation path.
- Scheduled reconciliation execution and metrics/audit output.

### Out of Scope

- UI polling/resume behavior.

## Change Requirements

- Enforce lock scope `(mappingId, targetEnvironment)`.
- Return deterministic conflict contracts for concurrent mutations.
- Reconcile timed-out operations from runtime authority.
- Repair projection on reconciliation when drift is detected.

---

## Verification Requirements

- Unit tests for lock conflicts and expiry recovery.
- Integration tests for timeout and projection-failure reconciliation.

---

## Acceptance Checks

- Conflicting operations cannot silently overwrite each other.
- Timed-out operations are recoverable/finalizable by reconciliation.
- Projection/runtime mismatches are repaired within reconciliation window.

---

## Blockers / Risks

- Incorrect lock TTL settings can cause false conflicts or overlap.

---

## Notes

- Runtime active pointer remains authoritative in all conflict resolution paths.
