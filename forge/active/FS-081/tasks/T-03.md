## Summary

Build/adjust sandbox-side orchestration endpoints that create/resolve immutable artifacts and coordinate deploy/promote actions into runtime accounts using relay semantics without cross-account role assumption.

---

## Scope

### In Scope

- Control-plane API flow for deploy to runtime environment.
- Control-plane API flow for promote between runtime environments while preserving artifact identity.
- Artifact manifest construction (`artifactId`, hash, source provenance, engine version, schema refs).
- Canonical transfer mechanism: direct payload push (artifact in request body) from sandbox to runtime deploy API.
- Runtime endpoint invocation + retry/error handling contract.

### Out of Scope

- Runtime account local storage activation internals (T-04).
- Authn/authz hardening.

## Change Requirements

- Deploy orchestration creates or resolves immutable artifact once, then relays to target runtime endpoint.
- Promote orchestration forwards same artifact identity to next environment (no regeneration).
- Runtime deploy requests enforce configured max payload size; oversize requests return deterministic actionable diagnostics.
- Artifact hash/integrity metadata included in transfer contract.
- Retry semantics are client-driven idempotent retry keyed by `artifactId`/`snapshotId`.
- Control plane records outcome metadata for auditing/provenance.

---

## Verification Requirements

- Contract/integration tests for deploy + promote success and failure paths.
- Tests confirm same artifact identity promoted upward.
- Tests confirm no cross-account role-assumption dependency in orchestration path.

---

## Acceptance Checks

- Deploy to Dev from Sandbox produces artifact and successfully relays to runtime endpoint.
- Promote Dev→Preprod preserves exact artifact identity.
- Oversize artifact payloads are rejected with deterministic payload-size diagnostics and remediation guidance.
- Failure in runtime activation does not report false success from control-plane API.
- Integration tests cover relay retry + deterministic error envelope behavior.

---

## Blockers / Risks

- Runtime endpoint size limits must be configured and surfaced clearly to avoid opaque API Gateway/Lambda failures.
