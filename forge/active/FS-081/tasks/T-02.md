## Summary

Update deployment-domain types, enums, and persistence/API contracts so runtime environment values are DEV, PREPROD, PROD and control-plane context is represented separately from runtime deployment targets.

---

## Scope

### In Scope

- Update backend deployment environment enums/types/constants.
- Replace runtime QA references with PREPROD in deployment-related backend code and tests.
- Ensure SANDBOX is not treated as runtime deploy target in runtime-plane code paths.
- Add migration compatibility handling where legacy QA data may exist (read/translate strategy or explicit migration path scaffolding).

### Out of Scope

- Full deployment endpoint behavior changes (handled in later tasks).
- UI rendering changes.

## Change Requirements

- Runtime environment contract becomes `DEV | PREPROD | PROD`.
- Canonical enum becomes `SANDBOX | DEV | PREPROD | PROD` with runtime deploy targets restricted to `DEV | PREPROD | PROD`.
- QA-specific runtime references are normalized at domain/presentation boundaries: raw historical `QA` is preserved for audit, normalized as `PREPROD` for behavior/UI.
- Validation and error messages reflect PREPROD naming.
- Staleness/current response contracts remain consistent after enum update.

---

## Verification Requirements

- Unit/integration tests updated for environment enums and route behavior assumptions.
- Typecheck/lint pass for backend touched areas.
- Regression tests verify no accidental introduction of SANDBOX as runtime deploy target.

## Acceptance Checks

- Backend deployment domain no longer uses QA as runtime environment value.
- PREPROD is accepted everywhere QA previously was used for runtime deployment semantics.
- Existing deployment history/read paths have deterministic behavior for any legacy QA records (raw preserved + normalized PREPROD behavior).
- Typecheck and targeted deployment test suites pass.
