## Summary

Build an Express mock server at `tests/e2e/mock-server/` that implements all CRUD endpoints matching the FS-057 route table, with an in-memory store, deterministic behavior, and test control endpoints (`/test/seed`, `/test/reset`, `/test/health`) for E2E test isolation. The server is started and stopped by Playwright's `webServer` config (from T-01).

---

## Scope

### In Scope

- Mock server implementing all routes from `forge/architecture/backend-api.md` section 2:
  - Projects: POST/GET/GET/:id/PUT/:id/DELETE/:id
  - Mappings: POST/GET/:id/PUT/:id/DELETE/:id/POST/:id/duplicate, GET /projects/:projectId/mappings
  - Schemas: POST/GET/GET/:id/DELETE/:id, POST/:id/query
  - Versions: GET/:mappingId/versions, GET/:mappingId/versions/:version, POST/:mappingId/versions
- In-memory store (plain JS objects/maps) for all entities
- Test control endpoints:
  - `POST /test/seed` — accepts `{ projects: [], mappings: [], schemas: [] }` and bulk-loads
  - `POST /test/reset` — clears all data
  - `GET /test/health` — returns 200 for readiness checks
- Response shapes matching `ui/src/lib/types/domain.ts` exactly
- Error responses matching `backend-api.md` section 4 envelope (`{ error: { code, message, statusCode, retryable } }`)
- CORS headers matching `backend-api.md` section 10
- Server startup script (`tests/e2e/mock-server/index.ts`) that listens on port 4100 — invoked by Playwright `webServer` config
- TypeScript implementation with shared types imported from UI domain

### Out of Scope

- AI, GitHub, deployment, template, search, activity, or preview endpoints
- Persistent storage (data lives in memory only)
- Authentication/authorization logic
- Rate limiting or throttling simulation
- Real S3/DynamoDB interaction

## Change Requirements

- Mock server must provide immediate read-after-write consistency (no async delays)
- All entity IDs must be generated deterministically when not provided in seed data (e.g., UUID v4 or sequential)
- Timestamps (`createdAt`, `updatedAt`) must be set to current time on create/update
- Delete operations must return 404 if entity doesn't exist
- List endpoints must return full arrays (no pagination)
- `POST /test/reset` must be synchronous and complete before responding
- Mock server must log requests minimally (method + path) for debugging
- Server must gracefully handle unknown routes with 404

---

## Verification Requirements

- Server starts on configured port without error
- `GET /test/health` returns 200
- `POST /test/seed` with valid data returns 200 and subsequent GETs return seeded data
- `POST /test/reset` clears all data; subsequent list endpoints return `[]`
- CRUD operations return correct status codes (201 for create, 200 for get/update, 204 for delete)
- Error envelope is returned for 400/404/409 scenarios
- TypeScript compiles cleanly

---

## Acceptance Checks

- Mock server starts and responds to health check
- All CRUD routes from backend-api.md route table are implemented
- Seed and reset control endpoints work correctly
- Response shapes are type-compatible with domain types
- CORS headers are present on all responses
- No dependency on real AWS services or external systems
- Server can be started/stopped programmatically for Playwright integration

---

## Blockers / Risks

- Keeping mock response shapes in sync with domain types requires discipline; type imports help
- Mock server must handle concurrent requests without race conditions (in-memory store is single-threaded in Node, so naturally safe)

---

## Notes

- The mock server does NOT need to implement business logic beyond basic CRUD (no referential integrity enforcement beyond what's needed for tests)
- Consider exporting the server as a module (not just a CLI script) so Playwright global setup can start/stop it
- Port 4100 is chosen to avoid conflicts with common dev ports (3000, 3001, 5173, 8080)
- Reference `forge/architecture/backend-api.md` section 2 for the complete route table
