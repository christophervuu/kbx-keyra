## Summary

Update AI Lambda handlers to consume shared runtime outcomes and consistently map prompt/output validation failures into canonical backend error envelopes.

---

## Scope

### In Scope

- Align AI handler status/code mapping for prompt-not-found and invalid structured output failures.
- Ensure invalid structured output maps to HTTP 500 with semantic code `INVALID_MODEL_OUTPUT`.
- Ensure handlers return success only when runtime returns validated output payloads.
- Add/adjust handler tests for failure-path contract behavior.

### Out of Scope

- Non-AI Lambda handlers.
- Frontend adapter/UI changes.

---

## Relevant Areas

- `src/lambda/ai/explain-rule.ts`
- `src/lambda/ai/suggest-expression.ts`
- `src/lambda/ai/auto-map.ts`
- `src/lambda/shared/errors.ts`
- `src/lambda/shared/response.ts`
- `tests/lambda/ai/*`

---

## Change Requirements

- Handlers must remain thin and not re-implement parser/registry logic.
- Prompt-not-found and invalid-output failures must map to stable backend error envelope fields.
- Invalid-output failures specifically use `INVALID_MODEL_OUTPUT` with HTTP 500.
- Response contracts must remain machine-readable for UI consumers.

---

## Verification Requirements

- Handler unit tests for success + prompt-not-found + invalid-structured-output paths.
- Regression checks for existing AI handler status/code behavior.
- Typecheck/lint for touched handler modules.

---

## Acceptance Checks

- [ ] AI handlers only return success for runtime-validated structured outputs.
- [ ] Prompt-not-found and invalid-output paths map to canonical error envelope behavior (`INVALID_MODEL_OUTPUT` on HTTP 500 for invalid output).
- [ ] Handler tests cover new/updated failure semantics.
- [ ] `pnpm typecheck` and `pnpm lint` pass for touched areas.
