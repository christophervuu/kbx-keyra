## Summary

Standardize per-capability response schema declaration and enforce strict structured-output parsing/validation in shared AI runtime.

---

## Scope

### In Scope

- Define shared mapping from capability/prompt to expected response schema contract.
- Wire model invocation and output parser to use declared schemas consistently.
- Normalize invalid/malformed output failures at runtime boundary with semantic code `INVALID_MODEL_OUTPUT`.

### Out of Scope

- Feature-specific UI rendering of AI outputs.
- Prompt-content tuning.

---

## Relevant Areas

- `src/lib/ai/types.ts`
- `src/lib/ai/model-client.ts`
- `src/lib/ai/output-parser.ts`
- `src/lib/ai/invoke-ai.ts`
- `tests/lib/ai/*`

---

## Change Requirements

- Structured schema declaration must be centralized, not handler-local.
- Output validation must run before success result is returned.
- Invalid output must never be surfaced as successful payload.

---

## Verification Requirements

- Unit tests for schema-valid success parsing.
- Unit tests for malformed JSON and schema mismatch failures.
- Typecheck/lint for touched runtime modules.

---

## Acceptance Checks

- [ ] Shared schema declaration contract exists for in-scope AI capabilities.
- [ ] Runtime enforces schema validation before success response emission.
- [ ] Invalid structured outputs return normalized failure results and are tested.
- [ ] `pnpm typecheck` and `pnpm lint` pass for touched areas.

---

## Blockers / Risks

- Existing prompt records may contain schema drift versus runtime declarations.

---

## Notes

- Keep parser failure details safe for API consumers while preserving debug utility in logs.
