## Summary

Ensure the External value entry option in ScalarFieldBuilder's entry mode selector uses consistent disabled/coming-soon styling matching the conventions used elsewhere in the builder system. Conduct a final visual spacing and typography audit across both builders to verify all alignment goals are met.

---

## Scope

### In Scope

- Verify and adjust the External value card in `ScalarEntryModeSelector` to use consistent disabled/coming-soon styling:
  - Muted visual treatment (reduced opacity or desaturated colors)
  - Non-interactive (no hover effects, no click response, no selection)
  - Tooltip: "External data sources — available in a future release"
  - Cursor: `not-allowed` or `default` (not pointer)
- Visual audit of both builders side by side, verifying:
  - Question heading typography matches (`text-xs font-semibold uppercase tracking-wide text-slate-400`)
  - Card styling matches (border, padding, selected/unselected states, blue dot indicator)
  - Divider treatment matches (`h-px bg-slate-700/60`)
  - Scrollable content spacing matches (`space-y-4 px-4 py-4`)
  - Header row spacing and alignment matches
  - Footer action row treatment matches
- Fix any remaining visual inconsistencies found during audit

### Out of Scope

- Functional changes to either builder
- External data source implementation
- New component creation (unless discovered during audit)
- Changes to BuilderFeedbackArea or ValidationSummaryRow internals
