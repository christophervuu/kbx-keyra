## Summary

Add a Builder/Editor mode toggle and an overflow menu (⋮) to the ArrayBuilder header (matching ScalarFieldBuilder's header pattern), remove the Custom Expression strategy card from ArrayModeSelector, and wire RawDslEditor rendering for editor mode. This resolves the biggest interaction inconsistency between the two builders: raw DSL editing becomes a header-level mode switch in both builders instead of being a strategy card in the array builder.

---

## Scope

### In Scope

- Add `ModeToggle` component to ArrayBuilder header row 1 (right-aligned after target path)
- Add overflow menu (⋮) to ArrayBuilder header row 1 (right-aligned after ModeToggle), matching ScalarFieldBuilder's `HeaderOverflowMenu` pattern; include "Remove mapping" action (same as scalar builder)
- Add `mode` state (`'builder' | 'editor'`) to ArrayBuilder (or extend `useArrayBuilderState`)
- Remove `customExpression` option from `ArrayModeSelector` — remove the mode card and the "Advanced" separator divider
- Render `RawDslEditor` in the scrollable content area when mode is `'editor'`
- Pre-fill RawDslEditor with the current generated expression when switching to Editor
- On Editor→Builder switch: attempt decomposition via `decomposeArrayExpression()` — on success hydrate structured state, on failure show warning banner and stay in Editor mode
- Preserve unrecognized expression banner behavior: when a saved expression cannot be decomposed on field selection, default to Editor mode with banner
- Migrate CustomExpressionEditor's core rendering (parse status badge, error list) into the ArrayBuilder's editor-mode rendering path
- Preserve "Restore previous draft" and "Reset to structured mode" action equivalents in the editor-mode surface
- Wire draft detection to work in both modes (expression from RawDslEditor text in editor mode, generated expression in builder mode)

## Blockers / Risks

- The `customExpression` mode is currently deeply integrated into `useArrayBuilderState` — the mode enum, state transitions, and expression generation all reference it. Removing it as a selectable mode while preserving the raw DSL editing capability requires careful state management refactoring.
- Decomposition-back from raw DSL to structured array mode may need adjustments to handle expressions that were previously only reachable via Custom Expression mode.

## Notes

- Reference ScalarFieldBuilder's `ModeToggle` component (lines ~162-195) for the exact toggle implementation pattern. Consider extracting it as a shared component if it isn't already.
- The CustomExpressionEditor's "Restore previous draft" action maps to "the builder state that was in memory before switching to Editor" — this is already the behavior in ScalarFieldBuilder's Editor→Builder switch.
- The "Reset to structured mode" action maps to clearing the raw expression and initializing an empty builder state — equivalent to starting fresh in Builder mode.
