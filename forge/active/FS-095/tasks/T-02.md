## Summary

Update action application flow so guided actions are applied through one normalized parameter payload path rather than bespoke per-action assembly. This ensures deterministic mutation behavior and safe fallback when expression hydration cannot reconstruct parameters.

---

## Scope

### In Scope

- Refactor `applySmartActionToDraft` to accept normalized parameter payloads from shared lifecycle state.
- Migrate existing parameterized actions to shared apply contracts.
- Enforce apply blocking when parameter validation fails.
- Preserve advanced fallback behavior for non-decomposable expressions.
- Add unit/integration regressions for draft mutation and no-op on invalid apply.

### Out of Scope

- New Smart Builder visual editor controls.
- Action picker/search availability behavior changes.
- Layout changes unrelated to parameter application.

---

- `ui/src/routes/pages/MappingEditor.tsx`

- `ui/src/features/mappings/lib/smart-builder-state.test.ts`

## Change Requirements

- Apply pipeline must treat parameterized and non-parameterized actions through a common interface.
- Invalid parameter drafts must not mutate expression or recipe state.
- Hydration logic must avoid unsafe guessed parameter reconstruction and route to Advanced fallback when needed.
- Existing fixed-template actions must continue to work without regressions.

---

## Verification Requirements

- Tests for successful parameterized apply DSL output and unsaved-state updates.
- Tests that invalid parameter states block apply and keep draft unchanged.
- Tests for non-decomposable parameterized hydration fallback behavior.
- Lint/typecheck pass for touched modules.

---

## Acceptance Checks

- `applySmartActionToDraft` consumes normalized parameter payloads.
- Parameterized action apply paths update recipe + DSL deterministically when valid.
- Invalid parameter apply attempts are blocked with no expression mutation.
- Hydration fallback behavior for ambiguous expressions remains safe and explicit.

---

## Blockers / Risks
