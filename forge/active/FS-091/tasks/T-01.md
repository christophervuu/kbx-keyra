## Summary

Introduce a shared schema retrieval interface and wire AI/schema-query runtime entry points through mode-based retriever selection (`dynamodb|opensearch|shadow`). This creates the migration seam needed for phased rollout without breaking handler contracts.

---

## Scope

### In Scope

- Define `SchemaRetriever` contract and retrieval result types.
- Add runtime retriever-mode configuration parsing/validation.
- Route AI handlers and schema query path through abstraction.
- Implement deterministic primary/secondary execution policy for `shadow` mode.

### Out of Scope

- Full Dynamo retrieval scoring implementation.
- OpenSearch decommission.

## Change Requirements

- All retrieval-calling surfaces use retriever abstraction rather than direct OpenSearch calls.
- Retriever mode is environment-driven and fails closed on invalid values.
- `shadow` mode executes comparison retrieval as non-blocking side path.

---

## Verification Requirements

- Unit tests for mode parsing/routing.
- Handler-level tests asserting retriever abstraction usage and non-breaking response shapes.
- Lint/typecheck/test for touched modules.

## Acceptance Checks

- AI and schema-query code paths no longer hard-code OpenSearch client usage.
- `dynamodb`, `opensearch`, and `shadow` modes are selectable and test-covered.
- Shadow secondary-path failures do not fail primary response.
