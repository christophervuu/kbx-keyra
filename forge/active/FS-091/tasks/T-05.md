## Summary

Modify schema ingestion outputs and add backfill support so all schemas (new and existing) contain retrieval-ready lexical/token/embedding fields required by Dynamo-only retrieval.

---

## Scope

### In Scope

- Extend node persistence writes with normalized lexical retrieval fields.
- Add/adjust token index persistence model if selected by retrieval strategy.
- Add backfill workflow for existing schemas.
- Ensure ingestion status/reporting includes retrieval-field population outcomes.

### Out of Scope

- Removal of OpenSearch infra resources.
- AI handler mode routing logic.

## Change Requirements

- Ingestion writes enough retrieval metadata to operate without OpenSearch index.
- Embeddings are persisted per-node in DynamoDB in this phase; include size/throughput telemetry needed to evaluate hybrid S3 fallback trigger.
- Backfill path is idempotent and safe to rerun.
- Missing retrieval fields are detectable via metrics/logging.

---

## Verification Requirements

- Unit/integration tests for ingestion outputs and backfill idempotency.
- Tests for large-schema paths (Step Functions) where applicable.
- Lint/typecheck/test for touched modules.

---

## Acceptance Checks

- Newly ingested schemas are queryable via Dynamo retrieval without OpenSearch.
- Backfilled legacy schemas become queryable via Dynamo retrieval path.
- Backfill re-run does not create duplicate or inconsistent index state.

---

## Blockers / Risks

- Backfill runtime and throughput on very large schema inventory.

---

## Notes

- Keep migration-safe behavior when some schemas are partially backfilled during rollout.
