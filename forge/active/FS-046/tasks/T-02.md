## Summary

Create the `useAutoMapReview` hook that manages the full Auto-Map suggestion review lifecycle — from triggering the request, through receiving and processing results, to tracking per-suggestion review status and applying accepted suggestions via the editor's draft API.

## Change Requirements

### Hook contract

```ts
interface UseAutoMapReviewParams {
  adapter: ApiAdapter;
  projectId: string;
  mappingId: string;
  rules: readonly MappingRule[];
  updateDraft: (targetPath: string, expression: string) => void;
  setSelectedTargetPath: (path: string) => void;
  parsedSourceSchema?: ParsedSchema | null;
}

interface UseAutoMapReviewResult {
  // State
  status: 'idle' | 'loading' | 'success' | 'error';
  items: readonly SuggestionReviewItem[];
  summary: AutoMapReviewSummary;
  error: string | null;
  sectionPath: string | null;

  // Actions
  triggerAutoMap: (sectionPath: string) => Promise<void>;
  acceptSuggestion: (targetPath: string) => void;
  editSuggestion: (targetPath: string) => void;
  dismissSuggestion: (targetPath: string) => void;
  undoDismiss: (targetPath: string) => void;
  acceptAllValid: () => void;
  reset: () => void;

  // Drawer control
  isDrawerOpen: boolean;
  openDrawer: () => void;
  closeDrawer: () => void;
}
```

### `triggerAutoMap(sectionPath)` behavior

1. Set `status` to `'loading'`, store `sectionPath`
2. Build `AutoMapSectionInput`:
   - `projectId`, `mappingId` from params
   - `sectionPath` from argument (the `selectedTargetPath` when the user triggers from an object node)
   - `sourceContext` derived from `parsedSourceSchema` (if provided) — format source fields as text lines (`"- {path} ({type})"`) limited to 200 lines, same pattern as FS-042
3. Call `adapter.autoMapSection(input)` with abort semantics (ignore stale responses if a new request is triggered)
4. On success:
   - Deduplicate suggestions by target path (first occurrence wins; log duplicates)
   - Look up `currentExpression` for each suggestion from `rules` array
   - Derive `isNew` flag (no matching rule exists)
   - Initialize all `reviewStatus` to `'pending'`
   - Compute summary
   - Set `status` to `'success'`, open drawer
5. On error:
   - Map error to user-friendly message
   - Set `status` to `'error'`, store error message

### Action handlers

**`acceptSuggestion(targetPath)`:**
- Find the item with matching target
- Call `updateDraft(targetPath, item.suggestion.expression)`
- Update `reviewStatus` to `'accepted'`
- Recompute summary

**`editSuggestion(targetPath)`:**
- Find the item with matching target
- Call `updateDraft(targetPath, item.suggestion.expression)` to pre-load suggestion
- Call `setSelectedTargetPath(targetPath)` to navigate editor
- Update `reviewStatus` to `'edited'`
- Recompute summary

**`dismissSuggestion(targetPath)`:**
- Update `reviewStatus` to `'dismissed'`
- No call to `updateDraft`
- Recompute summary

**`undoDismiss(targetPath)`:**
- Find the item with matching target where `reviewStatus === 'dismissed'`
- Update `reviewStatus` back to `'pending'`
- No call to `updateDraft`
- Recompute summary (pending count increases, dismissed count decreases)
- No-op if the item is not in `'dismissed'` state

**`acceptAllValid()`:**
- For all items where `reviewStatus === 'pending'` AND (`validation?.valid === true` OR `validation` is undefined):
  - Call `updateDraft(targetPath, expression)`
  - Set `reviewStatus` to `'accepted'`
- Recompute summary
- Return count of accepted items

**`reset()`:**
- Clear all state back to `idle`
- Close drawer

### Summary computation

```ts
function computeSummary(items: SuggestionReviewItem[]): AutoMapReviewSummary {
  return {
    total: items.length,
    pending: items.filter(i => i.reviewStatus === 'pending').length,
    accepted: items.filter(i => i.reviewStatus === 'accepted').length,
    edited: items.filter(i => i.reviewStatus === 'edited').length,
    dismissed: items.filter(i => i.reviewStatus === 'dismissed').length,
    validCount: items.filter(i => i.suggestion.validation?.valid === true).length,
    warningCount: items.filter(i => hasWarnings(i.suggestion)).length,
    invalidCount: items.filter(i => i.suggestion.validation?.valid === false).length,
    highConfidence: items.filter(i => i.suggestion.confidence === 'high').length,
    mediumConfidence: items.filter(i => i.suggestion.confidence === 'medium').length,
    lowConfidence: items.filter(i => i.suggestion.confidence === 'low').length,
  };
}
```

A suggestion "has warnings" when `validation.valid === true` but `validation.diagnostics` contains warning-severity entries.

### Abort semantics

- Use a ref-based stale-run check (incrementing `requestId` ref) consistent with `useSuggestExpression` (FS-042)
- On unmount: ignore any in-flight response
- New `triggerAutoMap` call cancels/supersedes any in-flight request

## Notes

- The `sourceContext` derivation mirrors FS-042's `SuggestExpressionInline` pattern: format source schema leaf fields as text lines, limited to 200 lines. This is a temporary showcase mechanism — when the backend adds RAG retrieval, `sourceContext` becomes optional/ignored.
- Drawer open/close state is managed within the hook to keep the drawer lifecycle co-located with the review state. Components consume `isDrawerOpen` / `openDrawer` / `closeDrawer` from the hook.
- The hook calls `adapter.autoMapSection()` (new method from T-01), not the existing `adapter.autoMap()`. This keeps the section-level and full-schema contracts separate.
- The `undoDismiss` action only transitions items from `'dismissed'` → `'pending'`. It is intentionally a no-op for items in any other state.
