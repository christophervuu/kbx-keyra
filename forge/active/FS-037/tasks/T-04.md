## Summary

Create the `useEnvironmentComparison` hook that orchestrates two-sided comparison execution. This is the core comparison engine: it manages mode selection, executes both sides (client-side for "Current" variants, server-side for environment variants), computes the diff between outputs, and exposes the full `ComparisonState`. This hook wires together `useServerPreview` and `useDeploymentContext` with client-side execution logic. It loads the saved config fresh on each run (Q1) and fires both sides in parallel with stale-request cancellation (Q4).

## Scope

### In Scope

- Create `ui/src/features/mappings/hooks/use-environment-comparison.ts`
- Implement `useEnvironmentComparison` hook:
  - Inputs: `mappingId`, `config` (working MappingConfig), `sourceSchemaDetail`, `targetSchemaDetail`, `sourceDataRaw` (string | null)
  - Outputs: `{ state, mode, setMode, runComparison, canRun, modeAvailability }`
- Client-side execution for "Current (Working)": uses `executeMapping()` with the in-memory working config
- Client-side execution for "Current (Saved)": loads last-saved config via `adapter.getMapping()` on each comparison run (not cached at page load) and executes with `executeMapping()`
- Server-side execution: delegates to `useServerPreview` for environment sides; for dual-server modes (DEV vs QA, QA vs PROD), both requests fire in parallel
- Stale request cancellation: track a run ID (incrementing counter) and discard results from superseded runs when mode or source data changes mid-flight
- Diff computation via `computeDiff()` after both sides complete
- `ComparisonState` management: idle → executing → complete/partial-error
- `canRun` gating: false when sourceDataRaw is null, or when selected mode is unavailable
- Mode availability derived from `useDeploymentContext`
- Add unit tests

### Out of Scope

- UI components (those are T-05, T-06, T-07, T-08)

## Change Requirements

The hook must:

1. **Accept mode selection** via `setMode(mode: ComparisonMode)` — validates mode is available before accepting
2. **Execute left side** based on mode config:
   - `client` context with no environment → execute working config via `executeMapping()`
   - `client` context for "saved" → load saved config fresh via `adapter.getMapping(mappingId)` on each run, then execute
   - `server` context → delegate to `useServerPreview`
3. **Execute right side** using the same dispatch logic
4. **Run both sides** when `runComparison()` is called:
   - Parse `sourceDataRaw` as JSON
   - Execute left and right in parallel via `Promise.allSettled` (both start simultaneously)
   - Track a `runId` counter; increment on each `runComparison()` call
   - When a side completes, check if `runId` still matches; discard results from stale runs
   - As each side completes (for the current run), update `ComparisonState` progressively
   - When both complete, compute diff via `computeDiff(leftOutput, rightOutput)`
5. **Build metadata** for each side:
   - Client/working: version from config, `hasUnsavedChanges` flag, client engine version
   - Client/saved: version from loaded config, saved timestamp
   - Server: metadata from `ServerPreviewResult.metadata`
6. **Handle partial failures**: if one side errors, the other side's result is still displayed; diff shows "Cannot compute diff" message
7. **`canRun`**: `false` when `sourceDataRaw` is null, mode is unavailable, or already executing
8. **Reset state** when mode changes

## Notes

- The "Current (Saved)" side calls `adapter.getMapping(mappingId)` on each comparison run to get the latest persisted config. This is a per-run async call, not a page-load cache. This ensures freshness if the mapping was saved elsewhere between comparison runs.
- Engine version for client-side execution can be a build-time constant or imported from the engine package. Check if `@keyra/engine` exports a version string; if not, use a placeholder `"client"`.
- Both sides execute in parallel using `Promise.allSettled` to ensure one side's failure doesn't prevent the other from completing.
- Stale request cancellation uses an incrementing `runId` ref pattern: each `runComparison()` increments the counter, and result handlers check `currentRunId === myRunId` before applying state. This prevents race conditions from slow prior requests overwriting newer results.
