## Summary

Add the foundational TypeScript types for environment comparison workflows to the domain model and feature types. These types define comparison modes, side results, metadata shapes, comparison state, and a separate `ComparisonSnapshot` record for storing comparison results linked to test cases. All subsequent tasks depend on these types.

---

## Scope

### In Scope

- Add `ComparisonMode` union type to `ui/src/lib/types/domain.ts`:
  ```ts
  type ComparisonMode = 'current-vs-saved' | 'current-vs-dev' | 'current-vs-qa' | 'dev-vs-qa' | 'qa-vs-prod';
  ```
- Add `ComparisonSideMetadata` interface to `ui/src/lib/types/domain.ts`
- Add `ComparisonSideResult` interface to `ui/src/lib/types/domain.ts`
- Add `ComparisonState` interface to `ui/src/lib/types/domain.ts`:
  ```ts
  interface ComparisonState {
    mode: ComparisonMode;
    left: ComparisonSideResult;
    right: ComparisonSideResult;
    diffEntries: DiffEntry[] | null;
    overallStatus: 'idle' | 'executing' | 'complete' | 'partial-error';
  }
  ```
- Add `ComparisonSnapshot` interface to `ui/src/lib/types/domain.ts`:
  ```ts
  interface ComparisonSnapshot {
    id: string;
    testCaseId: string;
    mappingId: string;
    mode: ComparisonMode;
    leftResult: ComparisonSideResult;
    rightResult: ComparisonSideResult;
    diffEntries: DiffEntry[];
    capturedAt: ISODateString;
  }
  ```
- Add `ComparisonModeConfig` type to feature types (`ui/src/features/mappings/types.ts`) defining left/right side configuration per mode (label, execution context, environment)
- Export all new types from `ui/src/lib/types/index.ts` barrel
- Add type-level tests verifying importability and structural correctness

## Change Requirements

Add the following types to `domain.ts`:

- `ComparisonMode`: union of the five comparison mode identifiers
- `ComparisonSideMetadata`: captures execution context (`client` | `server`), optional environment, config version, optional snapshot version, optional deployment timestamp, engine version, optional saved-at timestamp, optional unsaved-changes flag
- `ComparisonSideResult`: captures label, output (nullable), diagnostics array, metadata, status (`idle` | `executing` | `success` | `error`), optional error string
- `ComparisonState`: aggregates mode, left result, right result, nullable diff entries, overall status
- `ComparisonSnapshot`: separate record storing comparison results, linked to a test case by `testCaseId` and scoped to a mapping by `mappingId`. Contains mode, both side results, diff entries, and captured-at timestamp. This is a standalone record, not an extension of `TestCase`.

Add `ComparisonModeConfig` to feature types:

- Maps each `ComparisonMode` to a left/right side definition: `{ leftLabel, rightLabel, leftContext: 'client' | 'server', rightContext: 'client' | 'server', leftEnvironment?: Environment, rightEnvironment?: Environment }`
- Export a `COMPARISON_MODES` constant record mapping each mode to its config
- User-facing labels must follow the canonical definitions: Current = working config with unsaved changes, Saved = latest persisted version, DEV/QA/PROD = currently deployed snapshot

All types must use `readonly` modifiers consistent with existing domain type conventions.
