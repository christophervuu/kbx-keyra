## Summary

Compose all comparison components into a `CompareTab` component and integrate it into the Test Lab page tab bar. This is the main integration task that wires the comparison mode selector, side panels, diff display, and comparison hook into a cohesive tab experience. The Compare tab shares source data with the other tabs via the existing `PreviewProvider` (Q5 resolution) and enforces the guardrail that no deploy/promote/rollback actions exist.

---

## Scope

### In Scope

- Create `ui/src/features/mappings/components/comparison/CompareTab.tsx`
- Create `ui/src/features/mappings/components/comparison/index.ts` (barrel export)
- Add "Compare" to the Test Lab tab bar (the 5th tab)
- Compose inside `CompareTab`:
  - `ComparisonModeSelector` at the top
  - Two `ComparisonSidePanel` components in a side-by-side layout (50/50 split)
  - `ComparisonDiffDisplay` below the side panels
  - "Run Comparison" button
- Wire `useEnvironmentComparison` hook to the CompareTab
- Connect `sourceDataRaw` from the shared Test Lab state to the comparison hook — the Compare tab reads source data from the same state as the other tabs via `PreviewProvider`, maintaining a single source-of-truth payload (Q5 resolution). No separate compare-only source data state.
- Ensure no deploy/promote/rollback actions exist in the Compare tab DOM
- Update the Test Lab tab type to include `'compare'`
- Add component tests for CompareTab composition
- Add integration test for the full Compare tab within the Test Lab page

### Out of Scope

- Comparison result storage (that's T-09)
- Changes to existing tabs (Output, Diagnostics, Trace, Diff)
- Changes to the left panel (source data input, test case manager)

## Change Requirements

`CompareTab` props:

```ts
interface CompareTabProps {
  mappingId: string;
  config: MappingConfig | null;
  sourceSchemaDetail: SchemaDetail | null;
  targetSchemaDetail: SchemaDetail | null;
  sourceDataRaw: string | null;
}
```

Layout:

```
┌──────────────────────────────────────────────────┐
│ ComparisonModeSelector  [Run Comparison]          │
├───────────────────────┬──────────────────────────┤
│ ComparisonSidePanel   │ ComparisonSidePanel       │
│ (left)                │ (right)                   │
│                       │                           │
│                       │                           │
├───────────────────────┴──────────────────────────┤
│ ComparisonDiffDisplay                             │
└──────────────────────────────────────────────────┘
```

Test Lab page integration:

- Add `'compare'` to the `TabId` union type
- Add `{ id: 'compare', label: 'Compare' }` to the `TABS` array
- Render `<CompareTab>` when `activeTab === 'compare'`
- Pass shared `sourceDataRaw` (from the same state provider as other tabs), `config`, schema details, and `mappingId` to CompareTab

"Run Comparison" button:

- Disabled when `!canRun` (no source data, mode unavailable, or already executing)
- Shows spinner during execution
- Tooltip explains why disabled

Guardrails:

- No deploy/promote/rollback buttons or links in CompareTab
- This is enforced by simply not including any such elements — verified by test

Test IDs: `compare-tab`, `compare-run-btn`, `compare-layout`

## Notes

- The side-by-side layout should use CSS Grid or Flexbox with a 50/50 split. On smaller screens (near 1024px minimum), consider a stacked layout fallback, but this is desktop-first so side-by-side is the primary layout.
- The tab bar in the Test Lab page is currently a simple array of `{ id, label }` objects. Adding a 5th entry is straightforward.
- Make sure the comparison state is isolated to the Compare tab — switching away and back should preserve the last comparison result (don't reset on tab switch).
