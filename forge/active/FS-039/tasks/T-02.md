## Summary
Implement a new `generateExpressionFromChain(chain: ChainState): string` function that walks a `ChainState` tree and produces the equivalent DSL expression string. This replaces the role of `pipeline-expression-generator.ts` and `source-card-expression-generator.ts` for the new chain model. The generator must handle `OperandValue` types in condition predicates, including the `currentValue` kind which substitutes the accumulated chain expression at that point.

## Change Requirements
Create `chain-expression-generator.ts` with `generateExpressionFromChain()`. The function must recursively walk the chain: start with source expression, then for each step in order, wrap the accumulator.

**Step expression generation:**
- TransformSteps produce `functionName(accumulator, ...args)`
- ConditionSteps produce `if(predicateExpr, thenChainExpr, elseChainExpr)` where predicate expressions use comparison operators
- ValueMapSteps produce `valueMap(accumulator, { "input1": output1, ... }, defaultExpr)`
- Empty chains (source kind: none, no steps) return empty string

**OperandValue expression generation (critical for conditions):**
- `{ kind: 'currentValue' }` → The generator must track the accumulated expression at each step. When a condition's left operand is `currentValue`, the generator substitutes the chain accumulator expression computed up to (but not including) the current condition step. Example: if chain is `source("name") → upper() → IF(currentValue = "ADMIN")`, the `currentValue` resolves to `upper(source("name"))`.
- `{ kind: 'field'; path }` → generates `source("path")`
- `{ kind: 'static'; value }` → generates the literal DSL representation
- `{ kind: 'expression'; dsl }` → passes through the raw DSL string unchanged

**Predicate expression generation:**
- Each predicate has `left: OperandValue`, `operator: string`, `right: OperandValue`
- Generator resolves both operands, then wraps in operator: `eq(leftExpr, rightExpr)`
- AND-combined predicates within a clause: `and(pred1, pred2, ...)`

## Notes
This generator replaces the existing `generateExpressionFromState()` and source-card generator for the new chain model. Keep old generators in place — they'll be removed when all consumers migrate.

The `currentValue` substitution is the most complex part of this task. The generator must maintain an "accumulator" variable as it walks the steps array. Before processing each step, the accumulator holds the expression produced by all prior steps. When a condition step's predicate references `{ kind: 'currentValue' }`, the generator uses the current accumulator value — NOT the final chain output. This is what makes conditions test "the value at this point in the chain."
