## Summary
Update the navigation guard to use the new `hasUnsavedChanges` from the draft model. Ensure field-to-field navigation within the editor auto-stores drafts without showing a dialog. Ensure route-level navigation shows a confirmation dialog only when unsaved draft changes exist.

---

## Scope

### In Scope
- Field-to-field navigation: auto-store draft expression in draftRules map (no dialog)
- Route navigation guard: show dialog when `hasUnsavedChanges === true`
- Dialog text: "You have unsaved changes to N field(s). Discard and leave?"
- Confirm: clear all drafts, navigate
- Cancel: stay, preserve drafts
- Remove old unapplied-changes detection logic
- Remove old `isDirty` comparison against `lastAppliedExpression`

### Out of Scope
- View unsaved changes overlay (T-10)
- ScalarFieldBuilder changes (T-05 handles the component-level changes)

## Change Requirements
The composition layer (`MappingEditor.tsx`) wires field navigation to auto-commit the current field's draft via `commitDraft(currentTargetPath)` before hydrating the new field. No dialog is shown for field navigation — this is seamless. Route-level navigation uses `useBlocker` with `hasUnsavedChanges` as the gate. The old `lastAppliedExpression` comparison and unapplied-changes dialog are removed. The new dirty detection is purely based on `draftRules` map content vs saved rules.
