## Summary
Implement a new `decomposeToChain(expression: string): { chain: ChainState } | { error: string }` function that parses a DSL expression and attempts to reconstruct a `ChainState` from it. This is the inverse of T-02's generator and enables hydrating the Builder from saved expressions.

---

## Scope

### In Scope
- New function `decomposeToChain(expression: string): DecomposeChainResult`
- Parse the DSL expression using the engine's `parse()` function
- Walk the AST to identify chain structure: outermost function calls unwrapped as steps, innermost `source()` call as chain source
- Recognize condition patterns: `if(predicate, then, else)` → ConditionStep
- Recognize value map patterns: `valueMap(source, mappings, default)` → ValueMapStep
- Recognize chainable transform patterns (reuse `CHAINABLE_TRANSFORMS` set)
- Recognize static/literal values as ChainSource
- Return error with reason string when expression cannot be represented as a chain
- Unit tests for all decomposition paths including failure cases

### Out of Scope
- Component wiring (T-06)
- Removing old decomposers

## Change Requirements
Create `chain-decomposer.ts` with `decomposeToChain()`. The function uses the engine `parse()` to get an AST, then recursively walks it to build a `ChainState`. For each AST node: (1) `source("path")` → ChainSource field, (2) literal → ChainSource static, (3) `if(pred, then, else)` → ConditionStep with recursive branch decomposition, (4) `valueMap(expr, mappings, default)` → ValueMapStep, (5) chainable function with first arg being a deeper chain → TransformStep. Non-chainable multi-arg functions that don't match known patterns return an error result.
