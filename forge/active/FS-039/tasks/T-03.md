## Summary
Implement a new `decomposeToChain(expression: string): { chain: ChainState } | { error: string }` function that parses a DSL expression and attempts to reconstruct a `ChainState` from it. This is the inverse of T-02's generator and enables hydrating the Builder from saved expressions. The decomposer must reconstruct `OperandValue` types in condition predicates, defaulting condition left operands to `{ kind: 'currentValue' }` when the left operand expression matches the accumulated chain expression at that point.

## Scope

### In Scope
- New function `decomposeToChain(expression: string): DecomposeChainResult`
- Parse the DSL expression using the engine's `parse()` function
- Walk the AST to identify chain structure: outermost function calls unwrapped as steps, innermost `source()` call as chain source
- Recognize condition patterns: `if(predicate, then, else)` → ConditionStep with OperandValue reconstruction
- Recognize value map patterns: `valueMap(source, mappings, default)` → ValueMapStep
- Recognize chainable transform patterns (reuse `CHAINABLE_TRANSFORMS` set)
- Recognize static/literal values as ChainSource
- **OperandValue reconstruction in conditions:**
  - When a condition predicate's left operand matches the accumulated chain expression, decompose it as `{ kind: 'currentValue' }` (this is the default/expected case)
  - When the left operand is a different `source("path")` call, decompose as `{ kind: 'field'; path }`
  - When the left operand is a literal, decompose as `{ kind: 'static'; value }`
  - Fallback: decompose as `{ kind: 'expression'; dsl }` for unrecognized patterns
- Return error with reason string when expression cannot be represented as a chain
- Unit tests for all decomposition paths including failure cases and OperandValue reconstruction

## Change Requirements
Create `chain-decomposer.ts` with `decomposeToChain()`. The function uses the engine `parse()` to get an AST, then recursively walks it to build a `ChainState`.

**AST node handling:**
- `source("path")` → ChainSource field
- Literal → ChainSource static
- `if(pred, then, else)` → ConditionStep with recursive branch decomposition
- `valueMap(expr, mappings, default)` → ValueMapStep
- Chainable function with first arg being a deeper chain → TransformStep
- Non-chainable multi-arg functions that don't match known patterns → error result

**OperandValue reconstruction (critical for condition round-tripping):**
The decomposer must reconstruct `OperandValue` types when decomposing condition predicates. The key insight: when a condition appears within a chain, its left operand is often the "current value" (accumulated chain expression up to that point). The decomposer must detect this pattern:

1. Track the accumulated chain expression as it unwraps steps (same as generator does)
2. When decomposing a condition predicate, compare the left operand expression to the accumulator
3. If they match → `{ kind: 'currentValue' }` (the default case, most common)
4. If left operand is a different `source("path")` → `{ kind: 'field'; path }`
5. If left operand is a literal → `{ kind: 'static'; value }`
6. Otherwise → `{ kind: 'expression'; dsl: rawExprString }` (fallback)

This ensures round-trip fidelity: expressions generated with `currentValue` left operands decompose back to `currentValue`, and expressions generated with explicit `field` left operands decompose back to `field`.

## Notes
The decomposer and generator (T-02) should be developed in tandem. Round-trip testing is critical: `generate(decompose(expr)) === expr` for all supported patterns.

The `currentValue` detection heuristic is the most nuanced part: the decomposer must track what the "accumulated expression" would be at each step position, then check if a condition's left operand matches it. If a user manually wrote `if(eq(upper(source("name")), "ADMIN"), ...)` and `upper(source("name"))` IS the accumulated chain expression, the decomposer should recognize this as `currentValue`. If they wrote `if(eq(source("type"), "VIP"), ...)` and `source("type")` does NOT match the accumulator, it should be decomposed as `{ kind: 'field', path: 'type' }`.
