## Summary
Define the new `ChainState`, `ChainSource`, `ChainStep`, `TransformStep`, `ConditionStep`, `ValueMapStep`, `DraftFieldState`, and related types in `expression-builder-state.ts`. These types replace the existing `ExpressionBuilderState` discriminated union with a unified chain model. Also define the `DraftRulesMap` type used by `useMappingEditor`.

---

## Scope

### In Scope
- New type definitions: `ChainState`, `ChainSource` (field/static/none), `ChainStep` (union of TransformStep/ConditionStep/ValueMapStep), `ConditionStep` (with required else), `ValueMapStep` (with required default), `DraftFieldState`, `DraftValidationState`
- `DraftRulesMap` type definition (Map&lt;string, string&gt;)
- Preserve existing types needed by other consumers (backward compat exports)
- Type-level tests verifying the new type structure

### Out of Scope
- Expression generation from ChainState (T-02)
- DSL decomposition into ChainState (T-03)
- Component changes (T-05+)
- Removing old types (defer until all consumers migrate)

---

## Relevant Areas
- `ui/src/features/mappings/lib/expression-builder-state.ts`
- `ui/src/features/mappings/types.ts`

---

## Change Requirements
Add the new chain model types alongside existing types. The `ChainState` type must support: source selection (field path or static value or none), ordered steps array, each step being a transform (function + args), condition (predicates + then chain + else chain), or value map (rows + default chain). `ConditionStep` must structurally enforce required else branch (non-optional `elseBranch: ChainState` field). `ValueMapStep` must structurally enforce required default (non-optional `defaultValue: ChainState` field). Export all new types from the feature barrel.

- Type-level tests verify ChainState can represent: simple source, source+transforms, source+condition, source+valueMap, nested condition branches with chains
