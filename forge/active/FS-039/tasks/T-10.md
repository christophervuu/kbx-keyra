## Summary
Implement the "View unsaved changes" overlay that displays a diff between draft rules and saved rules. Each changed field shows its saved and draft expressions, change type (modified/added/removed), and per-field revert action. Clicking a field path navigates to that field in the Builder.

---

## Scope

### In Scope
- `UnsavedChangesOverlay` component (modal or drawer)
- Change list grouped by type: Modified, Added, Removed
- Each entry: target field path, saved expression (or "unmapped"), draft expression (or "will be removed")
- Per-entry "Revert" button wired to `revertDraft(targetPath)`
- Click field path to navigate to that field (close overlay, set `selectedTargetPath`)
- Empty state: "No unsaved changes" (should not be reachable since trigger is hidden when clean)
- Count header: "N unsaved changes"
- Close button / backdrop dismiss

### Out of Scope
- EditorTopBar trigger button (T-11)
- Styling details (visual design is not this spec's concern)

---

## Relevant Areas
- `ui/src/features/mappings/components/UnsavedChangesOverlay.tsx` (new)
- `ui/src/features/mappings/hooks/use-mapping-editor.ts` (consumes `getUnsavedChangeSummary()`)

## Change Requirements
Create `UnsavedChangesOverlay.tsx`. Props: `changes: UnsavedChangeSummary[]`, `onRevert: (targetPath: string) => void`, `onNavigate: (targetPath: string) => void`, `onClose: () => void`. The component groups entries by change type and renders them in a scrollable list. Each entry displays the field path (clickable), saved vs draft expression text, and a "Revert" button. Reverting removes the entry from the list (component receives updated props from parent). Navigating closes the overlay and sets `selectedTargetPath` in the parent.

---

## Verification Requirements
- Component renders change list with correct grouping
- Modified entries show both saved and draft expressions
- Added entries show draft expression and "unmapped" for saved
- Removed entries show saved expression and "will be removed" for draft
- Revert button calls `onRevert` with correct targetPath
- Field path click calls `onNavigate` with correct targetPath
- Close button calls `onClose`
- TypeScript compiles, lint passes
