## Summary

Implement the AI validation report presentation surface that displays categorized/severity-tagged issues, recommendations, and issue-to-rule links while explicitly distinguishing AI advisory guidance from deterministic diagnostics.

---

## Scope

### In Scope

- Add/update report components in mapping UI for AI validation findings.
- Render issue category, severity badges, affected-rule references, and recommendations.
- Render/report only canonical V1 categories (`correctness | completeness | maintainability | risk`) and severities (`info | warning | error`).
- Implement clickable issue-to-rule navigation/highlighting for resolvable references.
- Render explicit advisory labeling and visual separation from deterministic diagnostics.
- Add UI tests for rendering, linking behavior, fallback handling, and distinction messaging.

### Out of Scope

- Backend generation logic.
- Auto-fix/auto-apply behavior.
- Full diagnostics panel redesign unrelated to AI validation.

## Change Requirements

- Report UI displays structured AI issues and summary metrics.
- Issue references navigate to corresponding rules when resolvable.
- Unresolvable references degrade gracefully (non-click fallback, no crash).
- AI report presentation explicitly states advisory/additive status.
- Deterministic diagnostics remain present and not conflated with AI findings.

---

## Verification Requirements

- Component tests for issue rendering and category/severity display using canonical V1 enum values.
- Component tests for issue-link to rule navigation and stale-link fallback.
- Component tests for advisory-vs-authoritative labeling presence.
- Typecheck for touched UI files.

---

## Acceptance Checks

- UI report includes category, severity, recommendation, and affected-rule linkage.
- AI findings and deterministic diagnostics are clearly distinct semantically/visually.
- Stale/unresolvable issue references do not break UI.
