## Summary

Replace `HttpAdapter` AI placeholders with canonical backend API calls for explain-rule, suggest-expression, auto-map, smart-fix, and validate-mappings. Ensure request/response typing and error handling align with existing HTTP adapter conventions, remove scoped `NOT_IMPLEMENTED` behavior for these methods, and standardize temporary capability unavailability as `FEATURE_NOT_ENABLED`.

---

## Scope

### In Scope

- Implement `HttpAdapter` methods: `explainRule`, `suggestExpression`, `autoMap`, `autoMapSection`, `smartFix`, `validateMappings`.
- Map each method to canonical `/ai/*` route path with correct HTTP method and payload shape.
- Ensure adapter responses conform to domain types in `ui/src/lib/types/domain.ts`.
- Add/update adapter unit tests for route mapping and success/error propagation.

### Out of Scope

- UI component redesign or copy changes.
- Backend Lambda business-logic implementation details beyond endpoint contract assumptions.
- Unrelated non-AI adapter methods.

---

## Relevant Areas

- `ui/src/lib/api/http-adapter.ts`
- `ui/src/lib/api/http-adapter.test.ts`
- `ui/src/lib/api/types.ts`
- `ui/src/lib/types/domain.ts`

---

## Change Requirements

- `HttpAdapter` no longer throws `AdapterMethodNotImplementedError` for scoped AI methods.
- AI method route mappings are explicit, deterministic, and test-covered.
- Payload mapping supports both section-scoped and whole-mapping auto-map invocation semantics.
- `autoMap(input)` response mapping always returns `rules` and preserves optional `diagnostics`, `warnings`, and `retrievalMeta` when present.
- Temporary unavailability for not-yet-enabled backend capabilities surfaces `FEATURE_NOT_ENABLED` semantics (not generic errors).
- Existing HTTP client normalization behavior remains the only transport/error mechanism used.

---

## Verification Requirements

- Unit tests assert all scoped AI methods call expected `/ai/*` paths with expected bodies.
- Unit tests cover temporary capability-unavailable behavior as standardized `FEATURE_NOT_ENABLED` mapping.
- Unit tests cover non-2xx propagation through normalized HTTP client behavior.
- Typecheck for adapter + tests remains clean.

---

## Acceptance Checks

- `HttpAdapter` implements all scoped AI methods without `NOT_IMPLEMENTED` throws.
- Tests cover `explainRule`, `suggestExpression`, `autoMap`, `autoMapSection`, `smartFix`, and `validateMappings` route contracts, including `FEATURE_NOT_ENABLED` transitional behavior.
- `pnpm --filter @keyra/ui test -- http-adapter` (or equivalent targeted suite) passes.
- `pnpm --filter @keyra/ui typecheck` passes for touched areas.

---

## Blockers / Risks

- Backend endpoint contract drift (especially smart-fix/validate-mappings) could require adapter payload tweaks.

---

## Notes

- Prefer stable endpoint naming matching existing handler conventions (`/ai/explain-rule`, `/ai/suggest-expression`, `/ai/auto-map`) and align new methods consistently.
