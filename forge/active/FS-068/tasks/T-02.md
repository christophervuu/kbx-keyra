## Summary

Formalize unsupported AI behavior in offline mode (`LocalStorageAdapter`) for all scoped Phase 2 AI methods and lock the behavior with deterministic tests. This task ensures local mode behavior is explicit policy rather than incidental implementation.

---

## Scope

### In Scope

- Define consistent offline error semantics for `autoMap`, `autoMapSection`, `suggestExpression`, `explainRule`, `smartFix`, and `validateMappings`.
- Update local adapter implementation as needed to match the policy.
- Add/expand tests in local adapter test suite for all methods.

### Out of Scope

- HTTP mode behavior or route mapping.
- UI messaging changes outside what existing hooks already derive from adapter errors.

---

## Relevant Areas

- `ui/src/lib/api/local-storage-adapter.ts`
- `ui/src/lib/api/local-storage-adapter.test.ts`
- `ui/src/lib/api/types.ts`

---

## Change Requirements

- All scoped AI methods in local adapter follow one deterministic unsupported behavior contract.
- Contract is documented in code comments/tests for maintainability.
- Tests cover all scoped methods and assert exact failure behavior.

---

## Verification Requirements

- Unit tests for each scoped AI method in local mode.
- Confirm deterministic error message/code semantics expected by existing hook error mappers.

---

## Acceptance Checks

- Local adapter AI methods all follow the same offline unsupported policy.
- Local adapter tests include full scoped method coverage and pass.
- `pnpm --filter @keyra/ui exec vitest run src/lib/api/local-storage-adapter.test.ts` (targeted suite) passes.

---

## Blockers / Risks

- If policy changes from string-message errors to structured errors, hook error mapping may need coordinated updates.
