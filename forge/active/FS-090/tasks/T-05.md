## Summary

Modernize Schema Detail field work area with explicit type labels, simplified toolbar controls, and save/cancel edit mode semantics while enforcing CDM read-only restrictions.

---

## Scope

### In Scope

- Render explicit type labels (`STR`, `NUM`, `BOOL`, `ARR`, `OBJ`) as primary indicator.
- Remove depth dropdown and keep search/expand/collapse/show-issues controls.
- Add persistent edit banner with local-change copy.
- Replace re-sync edit CTA patterns with Save/Cancel controls.
- Enforce edit entry blocking for CDM schemas.

### Out of Scope

- Sample payload add/diff experience.
- Usage/action menu repositioning.

---

## Relevant Areas

- `ui/src/features/schemas/components/SchemaTreeView.tsx`
- `ui/src/features/schemas/hooks/use-schema-editor.ts`
- `ui/src/features/schemas/components/SchemaDetailPage.tsx`

---

## Change Requirements

- Icons cannot be the sole type indicator.
- Save pipeline call remains local-edit until explicit save; cancel reverts local edits.
- CDM paths never render editable controls.

---

## Verification Requirements

- UI tests for label rendering and depth-control absence.
- UI tests for edit banner/save/cancel behavior.
- UI tests proving CDM read-only prevents edit mode.

---

## Acceptance Checks

- Field rows show explicit type labels in view/edit contexts.
- Depth dropdown is removed while required toolbar controls remain.
- Save/Cancel local-edit model is active for user schemas and blocked for CDM.

---

## Blockers / Risks

- Existing tree virtualization layout may need adjustments for new label/chip width.

---

## Notes

- Keep compatibility with existing schema parser outputs across JSON/XSD/inferred.
