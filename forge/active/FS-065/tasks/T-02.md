## Summary

Using the inventory from T-01, identify and document all architecture drift, bypasses, and loop risks relative to the Phase 1 backend architecture. Produce a drift list that ties each issue to authoritative architecture references and impacted code paths.

---

## Scope

### In Scope

- Compare current AI paths against `ai-runtime.md`, `backend-api.md`, `phase-1-readiness.md`, `schema-ingestion.md`, and `persistence-model.md`.
- Identify non-canonical adapter/API/handler/runtime/query routing.
- Identify deprecated or conflicting integration patterns still active in code.
- Identify gaps from mandatory canonical `HttpAdapter` implementations for `autoMap`, `suggestExpression`, `explainRule`, `smartFix`, `validateMappings`.
- Classify schema retrieval drift against OpenSearch-first target and degraded fallback constraints (PK-scoped + gated + instrumented).
- Create a drift matrix artifact under FS-065.

### Out of Scope

- Final keep/replace/retire decisions.
- Code remediation.

## Change Requirements

- Each drift item must include: finding, conflicting architecture rule/doc, impacted path(s), and risk level.
- Drift list must explicitly call out loops/bypasses that can mislead future implementation.
- Distinguish “must-fix for reconciliation” vs “documented defer with guardrails”.
- Drift list must include feature-gating conformance for deferred non-core/experimental methods (`FEATURE_NOT_ENABLED`).

---

## Verification Requirements

- Architecture cross-check review confirms references are accurate and current.
- Every high-risk drift item is traceable to one or more concrete files and runtime paths.
