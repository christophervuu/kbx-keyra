## Summary

Update shared TypeScript domain/API types and adapter behavior (HTTP + LocalStorage) to support enrichment metadata and input-set payloads for preview/test execution while retaining compatibility with existing single-source data.

---

## Scope

### In Scope

- Update mapping-related types (`CreateMappingInput`, `MappingMetadata`, `MappingDetail`, `MappingConfig`, preview inputs).
- Update `HttpAdapter` request/response mapping for enrichment fields.
- Update `LocalStorageAdapter`, fixtures, and mock data for enrichment-aware records.
- Ensure preview input set structures support named enrichment payloads with versioned input-set shape.

### Out of Scope

- Mapping Editor component behavior changes.
- Backend handler implementation details (handled in backend tasks).

---

## Relevant Areas

- `ui/src/lib/types/domain.ts`
- `ui/src/lib/api/types.ts`
- `ui/src/lib/api/http-adapter.ts`
- `ui/src/lib/api/local-storage-adapter.ts`
- related adapter/type tests and fixtures

---

## Change Requirements

- Type contracts must represent mapping enrichment metadata and runtime/preview input set shape.
- Type contracts must codify canonical `enrichmentSources` plus derived compatibility handling for `config.externalSources`.
- HTTP adapter must send/receive enrichment fields without dropping unknown existing fields.
- Local storage mode must load/save enriched and non-enriched mappings safely.
- Legacy single-source samples must migrate/load as input sets with empty `externalSources`.

---

## Verification Requirements

- Adapter unit tests for serialization/deserialization and backward compatibility.
- Typecheck/lint across UI data layer.
- Fixture/mock updates validated by affected tests.

---

## Acceptance Checks

- Shared type contracts compile and support enrichment metadata + input sets.
- HTTP and LocalStorage adapters both support enriched mappings.
- Existing single-source fixtures and flows remain valid via input-set migration defaults.

---

## Blockers / Risks

- Existing fixtures may encode assumptions about singular source payloads and require broad updates.

---

## Notes

- Keep contract naming aligned with decisions finalized in T-01.
