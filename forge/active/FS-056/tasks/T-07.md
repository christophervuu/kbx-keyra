## Summary

Define the AWS Step Functions state machine (ASL) for orchestrating large schema ingestion. The state machine coordinates parsing the full schema, chunking nodes into batches, fanning out parallel batch processors, aggregating results, and updating schema metadata on completion or failure. The definition is an Amazon States Language (ASL) JSON file that can be deployed manually or via IaC.

---

## Scope

### In Scope

- Step Functions state machine definition in ASL (JSON)
- States:
  1. **ParseSchema** — Lambda task: parse full schema from S3, produce node batches, write batch manifests to S3
  2. **ChunkNodes** — Pass/Choice state: split parsed nodes into batch references
  3. **ProcessBatches** — Map state (parallel): invoke worker Lambda per batch
  4. **AggregateResults** — Lambda task: merge batch results, compute totals
  5. **UpdateMetadata** — Lambda task: set SchemaMetadata to `ready` with final field count
  6. **HandleError** — Catch state: set SchemaMetadata to `error` on any failure
- Input: `{ schemaId: string, s3Key: string, format: SchemaFormat }`
- Output: `{ schemaId: string, status: "ready" | "error", fieldCount: number }`
- Error handling: Catch on all task states, transition to HandleError
- Map state configuration: max concurrency 10 (avoid DynamoDB/OpenSearch throttling)
- Timeout: 10 minutes overall, 2 minutes per batch Lambda

### Out of Scope

- Worker Lambda implementation (T-08)
- Parse Lambda implementation (reuses T-02 parser, orchestration in T-08)
- Infrastructure deployment of the state machine
- IAM role definitions

## Change Requirements

- ASL definition must be valid Amazon States Language
- Map state must use `ItemsPath` pointing to batch references from the parse step
- Each batch reference includes: `{ batchIndex: number, s3Key: string, schemaId: string, nodeCount: number }`
- Error handling at each task state with `Catch` → `HandleError`
- `HandleError` state invokes a Lambda that sets SchemaMetadata `status: "error"` and includes error details
- `ResultPath` used correctly to pass data between states
- Max concurrency on Map state prevents infrastructure overwhelming
- Overall timeout (`TimeoutSeconds`) set on state machine
- Per-task timeouts (`TimeoutSeconds`) set on Lambda invocations

## Verification Requirements

- ASL definition passes AWS Step Functions linter / validator (use `statelint` or equivalent)
- State flow validates:
  - Happy path: ParseSchema → ProcessBatches (Map) → AggregateResults → UpdateMetadata
  - Error path: any state failure → HandleError
- Map state correctly references batch items
- Timeout values are reasonable (10 min overall, 2 min per batch)
- Max concurrency is set to prevent throttling
- README documents deployment steps and IAM requirements

## Notes

The parse step for a 23,000-field schema needs sufficient Lambda memory (recommended: 1024–2048MB) and timeout (recommended: 120 seconds). These are configured in the task state's `Resource` parameters or in the Lambda configuration itself.

Batch size target: ~500 nodes per batch. A 23,000-field schema produces ~46 batches. With max concurrency 10, processing completes in ~5 waves.
