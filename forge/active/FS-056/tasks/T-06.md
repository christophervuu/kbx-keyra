## Summary

Implement the `ingestSchema` Lambda handler that receives schema upload requests, determines whether to process inline or delegate to Step Functions, and orchestrates the full inline ingestion path for small schemas (< 500 fields). For schemas >= 500 fields, it starts a Step Functions execution and returns immediately. This is the primary entry point for all schema uploads.

---

## Scope

### In Scope

- Lambda handler at `src/lambda/schema/ingest-schema.ts`
- Request validation (name, content, format required)
- Schema format detection from content if format not explicitly provided
- Field count determination (quick pre-parse or parse + count)
- Inline path (< 500 fields):
  1. Create SchemaMetadata with `status: "ingesting"`
  2. Store original in S3
  3. Parse schema into SchemaNode[]
  4. Batch-write SchemaNodes to DynamoDB
  5. Bulk-index to OpenSearch
  6. Store processed content in S3
  7. Update SchemaMetadata to `status: "ready"` with `fieldCount`
  8. Return complete SchemaMetadata
- Step Functions path (>= 500 fields):
  1. Create SchemaMetadata with `status: "ingesting"`
  2. Store original in S3
  3. Start Step Functions execution with `{ schemaId, s3Key, format }`
  4. Return `{ schemaId, status: "ingesting", executionArn }`
- Error handling: catch parse/write failures, set `status: "error"`, return error response
- `schemaId` generation (UUID v4)

### Out of Scope

- Step Functions state machine definition (T-07)
- Step Functions worker implementation (T-08)
- Query endpoint (T-09)
- Authentication
- Rate limiting

## Change Requirements

- Handler signature follows existing Lambda pattern: `export async function handler(event: APIGatewayProxyEvent): Promise<APIGatewayProxyResult>`
- Parse request body: `{ name: string, content: string, format?: SchemaFormat, origin?: SchemaOrigin }`
- Generate `schemaId` via `crypto.randomUUID()`
- Format detection: if `format` not provided, detect from content (JSON with `$schema`/`properties`/`type` → `json-schema`; XML with `xs:schema`/`xsd:schema` → `xsd`)
- Threshold check: parse the schema, count fields, compare against `getInlineFieldThreshold()` (configurable via `SCHEMA_INLINE_FIELD_THRESHOLD` env var, default 500). Fields < threshold → inline; >= threshold → Step Functions.
- For inline path: orchestrate T-02 parser, T-03 S3, T-04 DynamoDB, T-05 OpenSearch in correct sequence
- For Step Functions path: use `@aws-sdk/client-sfn` `StartExecutionCommand`
- State machine ARN from environment variable (`INGESTION_STATE_MACHINE_ARN`)
- Return appropriate HTTP status codes:
  - 201 for successful inline ingestion
  - 202 for Step Functions delegation (accepted, processing)
  - 400 for validation errors
  - 500 for unexpected failures
- If OpenSearch indexing fails but DynamoDB succeeds: still return success with a warning flag (non-blocking per spec)
