## Summary

Implement the OpenSearch indexing module that creates the `keyra-schema-nodes` index mapping and bulk-indexes SchemaNode documents. The module handles index creation (if not exists), document construction from SchemaNode records, bulk indexing in batches of 500, and idempotent upserts using `{schemaId}#{path}` as document IDs.

---

## Scope

### In Scope

- `ensureIndexExists(): Promise<void>` — create index with correct mapping if it doesn't exist
- `bulkIndexSchemaNodes(nodes: SchemaNode[]): Promise<{ indexed: number, failed: number }>` — bulk index in batches of 500
- `deleteSchemaDocuments(schemaId: string): Promise<void>` — delete all documents for a schema (for re-ingestion support)
- Index mapping definition matching product spec's OpenSearch schema:
  - `schemaId` (keyword), `path` (text + keyword), `fieldName` (text + keyword)
  - `embeddingText` (text — BM25), `embedding` (knn_vector 1536 — defined but empty)
  - `type` (keyword), `depth` (integer), `parentPath` (keyword), `isArray` (boolean)
- Document ID format: `{schemaId}#{path}`
- Bulk API batch size: 500 documents per request
- OpenSearch endpoint from environment variable (`OPENSEARCH_ENDPOINT`)
- `wait_for` refresh on final batch

### Out of Scope

- Vector embedding population (deferred to AI/RAG spec)
- Query/search operations (separate task T-09)
- OpenSearch collection/domain creation (infrastructure)
- Authentication to OpenSearch (IAM role-based, handled by SDK)

## Change Requirements

- Use `@opensearch-project/opensearch` client (add as dependency if not present)
- OpenSearch client instantiated once per module with AWS SigV4 signing for Serverless
- Index mapping must define all fields from the product spec's OpenSearch schema
- `knn_vector` field defined with `dimension: 1536` and `engine: "nmslib"` (or `faiss` per OpenSearch Serverless requirements)
- `bulkIndexSchemaNodes` must:
  - Construct bulk request body (action + document pairs)
  - Use `index` action with explicit `_id` for idempotent upserts
  - Split into batches of 500
  - Track indexed vs failed counts from bulk response
  - Set `refresh: "wait_for"` on final batch only
- Document construction: map SchemaNode fields to OpenSearch document fields (same names, `embedding` field left as empty array or null)
- Error handling: individual document failures don't fail the entire batch; report counts

## Notes

OpenSearch Serverless uses IAM-based access control (no username/password). The client must be configured with AWS SigV4 signing. Reference the AWS documentation for `@opensearch-project/opensearch` with Serverless.

The `embedding` field is defined in the mapping but will contain empty values (empty array or null) until the AI/RAG spec populates it. This avoids needing to re-create the index later.
