## Summary

Extend `src/lambda/shared/` to generate a UUID `requestId` at the start of every handler invocation, include it in all error responses via the error envelope, and return it in a `x-request-id` header on success responses. Ensure all error constructor functions (`notFound`, `conflict`, `validationError`, `internalError`, `serviceUnavailable`) consistently produce the canonical error envelope shape including `requestId`.

---

## Scope

### In Scope

- Add `requestId` generation (UUID v4) to the shared handler utilities
- Extend `errorResponse()` to accept and include `requestId` in the error envelope body
- Extend `jsonResponse()` to include `x-request-id` header
- Add a new `TIMEOUT` error constructor for 504 responses
- Update all existing error constructors to include `requestId` parameter
- Add/update unit tests for the shared error utilities

### Out of Scope

- Modifying individual handler business logic
- CloudWatch/logging infrastructure
- Request tracing across services (distributed tracing)
- Auth-related error codes (401/403)

---

## Relevant Areas

- `src/lambda/shared/errors.ts` — error constructors
- `src/lambda/shared/response.ts` — response builders
- `src/lambda/shared/types.ts` — shared types
- `tests/lambda/unit/shared/` — unit tests

---

## Change Requirements

- `src/lambda/shared/response.ts`: `jsonResponse()` must accept optional `requestId` and include it as `x-request-id` header. `errorResponse()` must include `requestId` in the error envelope body.
- `src/lambda/shared/errors.ts`: All error factory functions must accept `requestId` as a parameter. Add new `timeout(requestId, message?)` factory returning 504 with `retryable: true`.
- Create a `src/lambda/shared/request-id.ts` module exporting `generateRequestId(): string` using UUID v4 (or crypto.randomUUID if available in Lambda runtime).
- Error envelope shape must be:
  ```json
  {
    "error": {
      "code": "ERROR_CODE",
      "message": "...",
      "statusCode": number,
      "retryable": boolean,
      "requestId": "req-..."
    }
  }
  ```
- All existing handler tests must continue to pass (error shape is backward-compatible since `requestId` is additive).

## Notes

- Use `crypto.randomUUID()` which is available in Node.js 18+ Lambda runtime. No external dependency needed.
- The `requestId` prefix `req-` is optional/cosmetic — a plain UUID is acceptable.
