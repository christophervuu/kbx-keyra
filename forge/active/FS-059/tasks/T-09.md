## Change Requirements

- Section 4 addition — Request Correlation ID:
  - All handlers generate `requestId` (UUID) at invocation start
  - Included in error envelope body (`error.requestId`)
  - Included in success response header (`x-request-id`)
  - Purpose: diagnostic correlation between UI error display and backend logs
- Section 4 addition — `TIMEOUT` error code:
  - Code: `TIMEOUT`, HTTP 504, retryable: true
  - Used when Lambda execution exceeds timeout or downstream service times out
- New Section (after Section 4 or as Section 4.x) — Error Resilience Flow:
  - Diagram or description: Handler → errorResponse() → API Gateway → HttpAdapter.httpClient → retryWithBackoff → toAppError() → AsyncState error status → ErrorBanner → retry action
  - Document which errors auto-retry vs surface immediately
  - Document that retry is bounded (3 attempts, exponential backoff 500ms base)
  - Document optimistic update rollback contract (snapshot → apply → confirm/rollback)
- Update INDEX.md `Last Updated` for `backend-api.md`
