## Summary

Implement backend persistence contracts for ActiveSnapshots and DeploymentHistory tables plus S3 snapshot/schema key strategies needed by deploy, rollback, execute, and status handlers.

---

## Scope

### In Scope

- Add/update persistence types and DAO methods for active-pointer and append-only history records.
- Add S3 key builder utilities for immutable snapshots and schema payload paths.
- Implement idempotent snapshot-write semantics for repeated deploy calls with same snapshot identity.
- Provide read helpers for execute/status paths.

### Out of Scope

- API routing/handler wiring.
- UI changes.

---

- `src/lib/persistence/types.ts`
- `src/lib/persistence/deployments.ts`
- `src/lib/persistence/config.ts`

- `tests/lib/persistence/**/*.test.ts`

---

## Change Requirements

- Active pointer model supports O(1) lookup by mappingId.
- History model is append-only and supports rollback event representation.
- Snapshot writes are immutable and hash-aware.
- Persistence APIs return deterministic not-found/idempotent outcomes for handler consumption.

---

## Verification Requirements

- Persistence unit tests cover deploy append, rollback append, pointer update semantics, idempotent deploy behavior, and unknown snapshot rollback target.
- Typecheck/lint pass.

---

## Acceptance Checks

- ActiveSnapshots and DeploymentHistory persistence contracts map to FS-082 table design.
- Snapshot key strategy follows required prefixes and immutability constraints.
- Tests verify pointer-only rollback semantics and immutable artifact behavior.
- Touched persistence tests and typecheck pass.
