## Summary

Implement thin internal deploy/rollback handlers that validate payload integrity, persist immutable artifacts, update active pointers, append history, and return deterministic error envelopes.

---

## Scope

### In Scope

- Implement `POST /internal/deploy` handler logic.
- Implement `POST /internal/rollback` handler logic.
- Input validation and integrity checks (snapshotId/hash constraints).
- Idempotent behavior for repeated deploys of same snapshot identity.
- Error classification using shared backend error envelope conventions.

### Out of Scope

- Runtime execute logic.
- Auth/security controls.

---

## Relevant Areas

- `src/lambda/deployment/*`
- `src/lambda/shared/*`
- `src/lib/persistence/deployments.ts`
- `src/lib/persistence/s3/*`
- `tests/lambda/deployment/**/*.test.ts`

---

## Change Requirements

- Deploy handler rejects hash mismatch and avoids pointer mutation on failure.
- Deploy success persists artifacts + pointer + history consistently.
- Rollback repoints pointer only to existing local snapshot and appends rollback event.
- Success and failure responses include request correlation metadata.

---

## Verification Requirements

- Handler unit/integration tests for success and failure paths.
- Tests for idempotent repeated deploy and deterministic rollback-not-found behavior.
- Typecheck/lint pass.

---

## Acceptance Checks

- Deploy route satisfies immutable snapshot + active pointer + history behavior.
- Rollback route satisfies pointer-only + append-only history behavior.
- Failure scenarios do not leave partial active-pointer changes.
- Deployment handler test suite and typecheck pass.

---

## Blockers / Risks

- Safe handling of partial persistence failures requires clear compensation/error semantics.

---

## Notes

- Keep handlers thin and push storage logic into persistence modules.
