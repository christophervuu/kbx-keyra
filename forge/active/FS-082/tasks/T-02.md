## Summary

Add/adjust SAM template resources, parameters, and outputs so each runtime account can be bootstrapped with the same `template.yaml` while preserving data resources during updates.

---

## Scope

### In Scope

- Define runtime API, deploy/execute/status Lambdas, DynamoDB tables, S3 bucket, and log groups in `template.yaml`.
- Add parameterization for environment naming, prefixes, and retention settings.
- Wire Lambda environment variables and IAM permissions.
- Add/verify stack outputs required by control-plane callers.
- Apply non-destructive update controls (`Retain`, update-replace strategy) for persistent data resources.

### Out of Scope

- Handler business logic implementation.
- CI/CD workflow automation.

## Change Requirements

- Resources and names follow FS-082 naming strategy.
- Template supports deployment to `dev`, `preprod`, `prod` with parameter overrides.
- Outputs expose API URL/ID, table names, bucket name, and function ARNs.
- Table and bucket resources are protected from accidental destructive updates.

---

## Verification Requirements

- `sam validate` passes.
- Template diff/review confirms required resources and outputs exist.
- Deploy smoke in one target environment confirms resources created with expected names.

---

## Acceptance Checks

- `template.yaml` defines all required runtime bootstrap resources from FS-082.
- Lambda env var wiring includes table names, bucket name, prefixes, and environment.
- Stack outputs required by spec are present and non-empty post-deploy.
- Data resources survive no-op/non-destructive stack update in smoke verification.

---

## Blockers / Risks

- Existing template complexity may require careful logical-ID naming to avoid accidental replacement of current resources.
