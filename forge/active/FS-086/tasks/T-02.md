## Summary

Add an on-demand linked schemas interaction triggered from project summary text so schema visibility remains available without occupying default page real estate. Use the app’s canonical existing modal/dialog primitive first, then existing accessible wrapper, and fallback to minimal inline expansion only if no modal primitive exists. Ensure schema rows are compact and user-facing labels are simplified.

---

## Scope

### In Scope

- Make `{N} linked schemas` summary text interactive in Project Overview header/summary region.
- Implement linked schemas interaction using this order:
  1. existing shared Dialog/modal component,
  2. existing accessible third-party/wrapper already used in app,
  3. minimal inline expansion fallback only if no modal primitive exists.
- Render compact schema list rows with name, origin, simplified format label, field count, and usage count.
- Apply simplified format labels (`JSON`, `XML`, `XSD`, `Inferred JSON`, `Inferred XML`) and avoid `JSON Schema` wording.
- Add Add Schema action in the lightweight surface only if straightforward; if included, wire to existing Add Schema behavior.
- Provide empty state for zero linked schemas with path to existing Add Schema flow.

### Out of Scope

- Rebuilding schema management workflows or schema model.
- Introducing new backend schema endpoints.
- Redesigning Schema Library / Schema Detail screens.

## Change Requirements

- Linked schema count element must be clearly interactive and keyboard accessible.
- Lightweight surface must open/close predictably and preserve current page context.
- Modal/dialog implementation (if used) must follow existing accessibility behavior patterns: focus trap, Escape to close, keyboard-reachable actions, accessible title/label, and focus return to linked-schemas trigger on close.
- Backdrop close behavior should follow whichever existing modal primitive is reused.
- Schema rows must be compact text/list style, not large card grid style.
- Formatting labels must use simplified user-facing terms; do not display technical scope labels (Project/Global/Local) in this interaction.
- Add Schema trigger (if present in surface) must call same handler/flow as header Add Schema action.
