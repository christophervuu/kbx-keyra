## Summary

Adjust mapping list/table presentation to exploit full-width layout and improve row readability while preserving required status-based row actions and deploy navigation behavior. This task ensures Project Overview remains operationally focused after layout simplification.

---

## Scope

### In Scope

- Adjust mappings section/table column sizing and overflow behavior to improve readability with full-width layout.
- Ensure Source → Target column has meaningful width and avoids aggressive wrapping where possible.
- Ensure Actions column remains visible/usable across common desktop widths.
- Preserve/confirm row action gating:
  - Draft: Open only, no Deploy
  - Ready: Open + Deploy
  - Has Errors: prefer Fix primary only if already supported/reusable; otherwise Open as accepted fallback; no Deploy
- Preserve Deploy as navigation to Mapping Deployment page (no inline deployment).
- Preserve Create Mapping action availability from page/header and mapping section context as currently designed.

### Out of Scope

- New deploy execution capabilities.
- Rewriting mapping status model or backend deployment metadata model.
- Mapping Editor redesign.

## Change Requirements

- Table layout should prioritize mapping scanability under full-width page composition.
- Column definitions should continue to include Name, Source → Target, Rules, Coverage, Status, Deployment, Last Modified, Actions.
- Row action rendering must align exactly with spec gating and avoid disabled Deploy buttons in overview.
- Do not add new diagnostics deep-linking behavior for Fix in this spec unless existing simple reuse already exists.
- Deploy action handler must route to existing Mapping Deployment page and not trigger inline deployment side effects.
