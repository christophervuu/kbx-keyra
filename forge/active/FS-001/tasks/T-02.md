## Summary

Define all core TypeScript types and interfaces that the mapping engine exposes to consumers and uses internally. These types form the contract between the engine and its callers (UI and Lambda) and are the foundation all subsequent engine modules reference.

---

## Scope

### In Scope

Types and interfaces to define in `src/engine/types/`:

- `MappingConfig` — full mapping configuration document (name, version, engineVersion, sourceSchemaRef, targetSchemaRef, config block, rules array)
- `MappingRule` — individual rule (target, type, expression, description?)
- `RuleType` — union type for rule type field (`"string" | "number" | "boolean" | "array" | "object"`)
- `SchemaRef` — schema reference (schemaId, type: "local" | "github", commitSha?)
- `MappingConfigBlock` — config sub-object (unmappedTargets, nullSubtrees, constants, externalSources)
- `UnmappedTargetStrategy` — `"null" | "omit" | "error"`
- `ExecutionResult` — engine execute output (output data, diagnostics, trace?)
- `ValidationResult` — engine validate output (valid boolean, diagnostics, coverage?)
- `Diagnostic` — individual diagnostic entry (code, severity, message, ruleIndex?, targetPath?, expression?, location?)
- `DiagnosticSeverity` — `"error" | "warning" | "info"`
- `DiagnosticLocation` — location within an expression (function name, argumentIndex?)
- `TraceEntry` — execution trace entry (ruleIndex, targetPath, expression, inputValue, outputValue, diagnostics?)
- `EngineOptions` — options passed to validate/execute (trace enabled, max recursion depth, etc.)
- `Environment` — enum for deployment environments (`DEV | QA | PROD`)
- `FunctionSignature` — describes a registered function's parameters and return type
- `FunctionParameter` — individual parameter definition (name, type, required, variadic?)
- `FunctionImplementation` — the callable implementation type
- `RegisteredFunction` — complete registration entry (name, signature, implementation)
- `ValueType` — union of DSL value types (`"string" | "number" | "boolean" | "null" | "array" | "object"`)

All types exported from `src/engine/types/index.ts` and re-exported from `src/engine/index.ts`.

### Out of Scope

- Error code constant values (T-03)
- Function registry logic (T-04)
- API stub implementations (T-05)
- Any implementation logic in the types themselves

## Change Requirements

After this task completes:

- All types listed in scope exist as named exports from `src/engine/types/index.ts`
- All types are re-exported from `src/engine/index.ts`
- No type uses `any` — all fields have explicit types
- Types match the shapes defined in the DSL specification (§5.3 Diagnostic Object Structure, §6 Mapping Config Format)
- TypeScript strict mode passes with all types
- Types are organized into logical files within `src/engine/types/`

Type shape reference (from DSL spec):

**MappingConfig** must include: `name: string`, `version: number`, `engineVersion: string`, `sourceSchemaRef: SchemaRef`, `targetSchemaRef: SchemaRef`, `config: MappingConfigBlock`, `rules: MappingRule[]`

**MappingRule** must include: `target: string`, `type: RuleType`, `expression: string`, `description?: string`

**Diagnostic** must include: `code: string`, `severity: DiagnosticSeverity`, `message: string`, `ruleIndex?: number`, `targetPath?: string`, `expression?: string`, `location?: DiagnosticLocation`

**ExecutionResult** must include: `output: unknown`, `diagnostics: Diagnostic[]`, `trace?: TraceEntry[]`

**ValidationResult** must include: `valid: boolean`, `diagnostics: Diagnostic[]`

## Notes

- Split types into logical files for maintainability (config types, result types, registry types, option types) but export everything from a single `index.ts` barrel.
- The `FunctionImplementation` type should be a generic callable: `(args: unknown[], context: ExecutionContext) => unknown` or similar — but keep it simple for the scaffold. The exact shape may be refined in the function implementation spec.
- `ExecutionContext` (or similar) may be needed for array scope access — define a placeholder if useful, or defer to the execution spec.
- Use `readonly` arrays and objects where mutation is not intended in the public API.
