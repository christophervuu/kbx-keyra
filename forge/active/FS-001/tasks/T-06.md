## Summary

Configure Vitest as the test runner, write unit tests covering the public API stubs, function registry, and error codes, create the fixture directory structure for future integration tests, and validate the entire scaffold builds cleanly (build, typecheck, lint, tests all pass green).

---

## Scope

### In Scope

- Vitest configuration (`vitest.config.ts`)
- Test directory structure:
  - `tests/engine/` — engine tests root
  - `tests/engine/validate.test.ts` — tests for validate() stub
  - `tests/engine/execute.test.ts` — tests for execute() stub
  - `tests/engine/registry.test.ts` — tests for function registry
  - `tests/engine/diagnostics.test.ts` — tests for error codes and message formatter
  - `tests/engine/fixtures/` — empty directory for future integration test fixtures
  - `tests/engine/dsl/` — empty directory (`.gitkeep`) for future DSL tests
  - `tests/engine/execute/` — empty directory (`.gitkeep`) for future execution tests
  - `tests/engine/validate/` — empty directory (`.gitkeep`) for future validation tests
- Add `vitest` to devDependencies in `package.json`
- Update `test` script in `package.json` to run vitest
- A `tsconfig` path for tests (either a separate `tsconfig.test.json` or include tests in the main config for type checking)

Unit tests to write:

1. **validate.test.ts**:
   - `validate()` returns `{ valid: true, diagnostics: [] }` for a minimal config
   - Return type matches `ValidationResult` shape

2. **execute.test.ts**:
   - `execute()` returns `{ output: {}, diagnostics: [] }` without trace option
   - `execute()` returns `{ output: {}, diagnostics: [], trace: [] }` with trace enabled
   - Return type matches `ExecutionResult` shape

3. **registry.test.ts**:
   - `registerFunction()` makes function retrievable
   - `hasFunction()` returns correct boolean
   - `listFunctions()` returns registered names
   - Duplicate registration throws
   - `createRegistry()` produces isolated instances

4. **diagnostics.test.ts**:
   - All expected KEYRA-E### codes exist
   - All expected KEYRA-W### codes exist
   - Each code has correct severity
   - `formatDiagnosticMessage()` interpolates parameters correctly
   - Total code count matches spec (verify no codes are missing)

### Out of Scope

- Integration tests (no logic to integrate yet)
- Coverage thresholds (premature for a scaffold)
- CI/CD test pipeline
