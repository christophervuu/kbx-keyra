## Summary

Add a resolver that discovers and fetches relative `$ref` dependencies for CDM schemas while strictly enforcing allowed source folders and rejecting disallowed or unresolved references.

---

## Scope

### In Scope

- Resolve relative `$ref` targets from a root CDM schema file.
- Permit only valid targets within `JSONSchemas/CoreSchemas/`, `JSONSchemas/Definitions/`, and `JSONSchemas/Events/`.
- Add path normalization and traversal protection (no escape from allowed roots).
- Add cycle/depth protections and deterministic failure errors.

### Out of Scope

- Full re-ingestion write pipeline.
- UI changes.

---

## Relevant Areas

- `src/lib/schema/parser/**/*.ts`
- `src/lib/schema/**/*.ts` (new resolver module?)
- `src/lambda/schema/**/*.ts` ?
- `tests/lib/schema/**/*.test.ts`

---

## Change Requirements

- Dependency resolution must be transitive for nested relative refs.
- Resolution must fail with explicit reason when any required dependency is disallowed or missing.
- `JSONSchemas/Sample Payloads/` must never be considered dependency source.

---

## Verification Requirements

- Unit tests for allowed/disallowed path cases.
- Unit tests for nested references, cycles, and depth guard behavior.
- Tests for Events-folder references when present.

---

## Acceptance Checks

- Relative refs into CoreSchemas/Definitions/Events resolve when valid.
- Disallowed/missing refs fail with deterministic resolution error.
- Resolver cannot traverse into excluded roots such as Sample Payloads.
- Targeted resolver tests pass.

---

## Blockers / Risks

- Ref format variability (`./`, `../`, fragments) may require robust normalization strategy.

---

## Notes

- Keep resolver reusable by re-sync pipeline and possible future ingestion tooling.
