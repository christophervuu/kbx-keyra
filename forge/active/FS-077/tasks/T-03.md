## Summary

Update CDM sync orchestration so changed commits execute full schema re-ingestion (parse, nodes, embeddings, OpenSearch re-index), unchanged commits return no-op, and failures preserve prior active state.

---

## Scope

### In Scope

- Commit SHA comparison gate for re-sync entrypoint.
- Changed-path orchestration into full ingestion/indexing pipeline.
- Unchanged-path short-circuit no-op behavior.
- Atomic/rollback-safe write sequencing to avoid partial active-state corruption.
- Step Functions routing integration for large schema re-ingestion where applicable.

### Out of Scope

- Diff summary field classification logic (handled separately).
- New UI components.

---

## Change Requirements

- On changed commit, full rebuild must refresh SchemaNodes, embedding text/embeddings, and OpenSearch docs.
- On unchanged commit, return deterministic no-op with no parse/index writes.
- On failure at any rebuild phase, terminal result is failed and prior ready state remains intact.

---

## Verification Requirements

- Integration tests for changed commit success path.
- Integration tests for unchanged commit no-op path.
- Failure-path tests proving no partial active-state corruption.

---

## Acceptance Checks

- Changed commit runs full ingestion + index rebuild and updates commit SHA.
- Unchanged commit returns no-op without rebuild side effects.
- Failed rebuild returns explicit failure and does not corrupt active schema/index state.
- Retrieval/query path observes refreshed schema nodes after successful update.

---

## Blockers / Risks

- Atomicity guarantees across DynamoDB, S3, and OpenSearch require careful sequencing and verification.

---

## Notes

- Reuse existing ingestion modules where possible; avoid duplicating parse/index logic.
