## Summary

Add best-effort diff summary computation between previous and refreshed schema representations so successful re-sync responses report added, removed, and modified fields.

---

## Scope

### In Scope

- Define deterministic diff input baseline (pre-sync vs post-sync schema node set).
- Compute and attach `added`, `removed`, and `modified` lists in re-sync result.
- Keep algorithm stable and bounded for large schemas.

### Out of Scope

- UI visualization redesign for diffs.
- Historical diff storage beyond immediate response payload.

---

## Relevant Areas

- `src/lib/schema/**/*.ts` (diff utility module)
- `src/lambda/schema/**/*.ts`
- `tests/lib/schema/**/*.test.ts`
- `tests/lambda/schema/**/*.test.ts`

---

## Change Requirements

- Diff summary must be present on `status=updated` responses.
- Modified detection uses **path + structural fingerprint** (type, isArray, depth) — nodes at same path with differing fingerprint are classified as modified.
- Modified algorithm must be best-effort and documented by chosen heuristic (path + structural fingerprint per Rev 2 decision).
- Output ordering should be deterministic for stable testing.

---

## Verification Requirements

- Unit tests for added/removed/modified classification.
- Tests for no-change and large-schema stability.
- Contract tests for response payload shape.

---

## Acceptance Checks

- Updated re-sync responses include deterministic `diffSummary` payload.
- Added/removed/modified lists classify representative schema changes correctly.
- Diff generation remains bounded and passes targeted tests.

---

## Blockers / Risks

- Structural fingerprint fields: type, isArray, depth — any change triggers `modified` classification.

---

## Notes

- Heuristic is path + structural fingerprint (type, isArray, depth) per FS-077 Rev 2 Q1 resolution.
- Capture chosen heuristic in task notes/tests for architecture doc handoff.
