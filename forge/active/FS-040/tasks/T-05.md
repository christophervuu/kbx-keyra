## Summary

Implement a per-target-property unsaved diff capability in the Builder panel. Create a `useUnsavedDiff` hook that compares the current draft expression against the last-saved rule for the selected target, and an `UnsavedDiffPanel` component that renders a human-readable stacked comparison with a "Revert to saved" action.

---

## Scope

### In Scope

- Implement `useUnsavedDiff` hook in `ui/src/features/mappings/hooks/use-unsaved-diff.ts`:
  - Accepts: `targetPath`, `currentExpression`, `savedRules` (from `useMappingEditor`), and optionally `savedConfig` (the last-persisted mapping config for baseline).
  - Returns: diff state including `status` (`'new' | 'modified' | 'removed' | 'unchanged' | 'no-mapping'`), `savedExpression`, `currentExpression`, `hasUnsavedChanges`.
- Implement `UnsavedDiffPanel` component in `ui/src/features/mappings/components/UnsavedDiffPanel.tsx`:
  - Inline expandable panel triggered by a "View unsaved changes" button.
  - Shows stacked comparison: "Last saved" section + "Current draft" section + status badge.
  - "Revert to saved" button when a saved baseline exists and the current draft differs.
  - "No unsaved changes" message when expressions are identical.
  - "New mapping" status when no saved rule exists for the target.
- Integrate `UnsavedDiffPanel` into `ScalarFieldBuilder` between the Pinned Feedback Area and the Expression Area (collapsible, triggered by button).
- Expose a `getSavedRuleForTarget(targetPath): MappingRule | null` accessor from `useMappingEditor` (or equivalent mechanism to access the last-saved config).
- Wire "Revert to saved" to restore the expression from the saved rule, triggering builder state re-decomposition.

### Out of Scope

- Full mapping-level diff (comparing all rules, not just the selected field).
- Version history integration (FS-018 version diff is separate).
- Global "View all unsaved changes" in `EditorTopBar`.

## Change Requirements

### `useUnsavedDiff` hook

1. Inputs:
   - `targetPath: string`
   - `currentExpression: string`
   - `savedRules: readonly MappingRule[]` (or a `getSavedRuleForTarget` function)
   
2. Logic:
   - Find the saved rule where `rule.target === targetPath`.
   - If no saved rule and current expression is empty → `status: 'no-mapping'`.
   - If no saved rule and current expression is non-empty → `status: 'new'`.
   - If saved rule exists and expressions are identical → `status: 'unchanged'`.
   - If saved rule exists and expressions differ → `status: 'modified'`.
   - If saved rule exists and current expression is empty → `status: 'removed'`.

3. Outputs:
   ```typescript
   interface UnsavedDiffState {
     status: 'new' | 'modified' | 'removed' | 'unchanged' | 'no-mapping';
     savedExpression: string | null;
     currentExpression: string;
     hasUnsavedChanges: boolean;  // true for 'new', 'modified', 'removed'
   }
   ```

### `UnsavedDiffPanel` component

1. Props:
   - `diffState: UnsavedDiffState`
   - `targetPath: string`
   - `isExpanded: boolean`
   - `onToggle: () => void`
   - `onRevert: () => void`
   - `className?: string`

2. Rendering:
   - Trigger: a button/link labeled "View unsaved changes" with a change indicator badge when `hasUnsavedChanges`.
   - Expanded content:
     - "Last saved" section: syntax-highlighted saved expression, or "No mapping" placeholder.
     - "Current draft" section: syntax-highlighted current expression, or "No mapping" placeholder.
     - Status badge: "New mapping" (blue), "Modified" (amber), "Mapping removed" (red), "No changes" (green/muted).
   - "Revert to saved" button: visible when `status === 'modified'` or `status === 'removed'`. Clicking fires `onRevert`.
   - `aria-expanded` on trigger button.
   - Panel content labeled with `aria-labelledby`.
   - `data-testid="unsaved-diff-panel"`
   - `data-testid="unsaved-diff-trigger"`

3. Visual design:
   - Bordered section, slightly inset, with a subtle background tint to distinguish it from the main expression area.
   - Expressions displayed in monospace with syntax highlighting via `tokenizeDsl`.

### `useMappingEditor` changes

- Expose the last-saved rules baseline. Options:
  - Add `savedRules: readonly MappingRule[]` to the hook's return value, representing the rules as they were at the last `save()` call.
  - Implementation: snapshot `rules` into a `savedRulesRef` on each successful save. Initialize `savedRulesRef` from the adapter-loaded rules on mount.
- This is a lightweight addition — no structural changes to the save flow.

### `ScalarFieldBuilder` integration

- Add local `isDiffExpanded` state.
- Render `UnsavedDiffPanel` between the feedback area and the expression area (conditionally when `isDiffExpanded`).
- Wire "Revert to saved" to:
  1. Set expression to `savedExpression ?? ''`.
  2. Trigger builder state re-decomposition (may need to update `currentExpression` prop or trigger a re-key).

## Blockers / Risks

- The baseline for "last saved" depends on `useMappingEditor` maintaining a snapshot of saved rules. If the hook's current implementation does not easily support this, the snapshot mechanism needs careful placement to avoid stale data after save operations.
- "Revert to saved" needs to trigger re-decomposition of the reverted expression into builder state. This uses the same path as target selection hydration (FS-025 T-01). Ensure the re-decomposition flow is reliable for this use case.

---

## Notes

- The diff is per-target-field, not a full mapping diff. This is intentional to keep the scope manageable and aligned with the per-field Builder workflow.
- The diff compares normalized expression strings. Whitespace differences are not meaningful.
- The diff does not show a visual character-level diff (like git). It shows a simple side-by-side/stacked display of old vs. new expression. A character-level diff utility can be added later if user feedback indicates it's valuable.
