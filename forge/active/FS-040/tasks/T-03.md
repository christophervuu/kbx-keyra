## Summary

Replace the current `isValid`-based Apply button gating in `ScalarFieldBuilder` with `useBuilderValidation`'s `canApply` and wire `canSave` (output type validation) into the save flow. Remove the `suggestSourceFields` import and all remaining Suggested Sources references that T-02 did not already clean up.

---

## Scope

### In Scope

- Update `ScalarFieldBuilder` to:
  - Call `useBuilderValidation` with the necessary inputs (builder state, expression, target type, mode, parse result, parse validity).
  - Replace the existing `canSave` derivation (`isDirty && expression.trim().length > 0 && isValid && !isValidating && !isApplied`) with logic that uses `builderValidation.canApply` plus the existing `isDirty` and `!isApplied` conditions.
  - Pass `builderValidation.canSave` upward (or use it locally) to gate the Save flow. The composition layer / `useMappingEditor` may need a callback or flag to prevent save when output type is invalid.
- Ensure Apply button is disabled and shows appropriate state when `canApply` is false.
- Ensure the Apply button's gating message (if any tooltip is shown) reflects the first structural issue or parse error.
- Remove any remaining `suggestSourceFields` imports, `suggestions` state, `handleSuggestionSelect`, `SuggestionPill` sub-component, and `MATCH_KIND_LABEL` constant from `ScalarFieldBuilder` if not already removed in T-02.
- Update existing tests that rely on the old `isValid` gating to use the new validation model.

### Out of Scope

- The feedback area rendering (T-02).
- Action row button redesign (T-04).
- Unsaved diff (T-05).
- Changes to `useMappingEditor.save()` internals — only the gating condition at the call site.

## Change Requirements

1. `ScalarFieldBuilder` must call `useBuilderValidation` and use its `canApply` output to gate the Apply button.

2. The `canSave` variable in `ScalarFieldBuilder` must be:
   ```
   canSave = isDirty && builderValidation.canApply && !isApplied && !isValidating
   ```
   Note: `builderValidation.canApply` already includes structural + parse validity checks.

3. The Apply button tooltip should show the first validation issue message when `canApply` is false and expression is non-empty (to help the user understand *why* Apply is blocked).

4. For output type validation gating of Save:
   - Option A: `ScalarFieldBuilder` fires `onApply` with an additional `outputTypeValid` flag, and the parent composition layer prevents save when any applied rule has an output type mismatch.
   - Option B: `onApply` remains unchanged, and the save gating is handled at the `useMappingEditor` level by re-running output type checks at save time.
   - **Recommended: Option A** — surface `outputTypeValid` in the applied rule metadata so the composition layer can gate Save. This can be as simple as adding an optional `warnings` array to the apply callback.
   - The simplest initial implementation: if `outputTypeValid` is false, the Apply button remains enabled but a warning is shown. The Save button in `EditorTopBar` should be gated by checking all applied rules for output type validity. This may require passing a `hasOutputTypeWarnings` flag upward.

5. Clean up all remaining Suggested Sources artifacts from `ScalarFieldBuilder`:
   - Remove `suggestSourceFields` import
   - Remove `SuggestionPill` sub-component (if still in file)
   - Remove `suggestions` useMemo
   - Remove `handleSuggestionSelect` handler
   - Remove `MATCH_KIND_LABEL` constant
   - Remove the `suggested-sources-section` DOM block (if T-02 didn't remove it)
