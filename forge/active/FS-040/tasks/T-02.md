## Summary

Create the `BuilderFeedbackArea` component that persistently displays Expression, Result, and Validation Status rows at the top of the Builder panel. Remove `LiveExpressionDisplay` and `LiveResultDisplay` from inside `UnifiedExpressionBuilder` and render them within this new feedback area in `ScalarFieldBuilder`. The feedback area is always visible regardless of Builder/Editor mode.

---

## Scope

### In Scope

- Create `BuilderFeedbackArea` component in `ui/src/features/mappings/components/BuilderFeedbackArea.tsx`.
- The component renders three rows:
  1. **Expression** — syntax-highlighted DSL expression (reuse `LiveExpressionDisplay` rendering or inline the tokenizer logic).
  2. **Result** — evaluated result value (reuse `LiveResultDisplay` rendering logic with `useExpressionPreview`).
  3. **Validation** — two inline status badges: Structure (✓/✗) and Output Type (✓/✗).
- Integrate `BuilderFeedbackArea` into `ScalarFieldBuilder` between the Header and the Expression Area.
- Remove `LiveExpressionDisplay` and `LiveResultDisplay` from `UnifiedExpressionBuilder`'s render output (they are now rendered in the feedback area).
- Pass `BuilderValidationState` from T-01 to the feedback area for validation badge rendering.
- Validation badges:
  - Structure valid: green check icon + "Structure" label.
  - Structure invalid: red X icon + first issue message.
  - Structure N/A (Editor mode): neutral/hidden badge.
  - Output type valid: green check icon + "Output type" label.
  - Output type mismatch: amber warning icon + mismatch message.
  - Neutral (no expression): muted text or no badges.
- Ensure `role="region"`, `aria-label="Expression feedback"` on the container.
- Ensure `aria-live="polite"` on Expression and Result regions for screen reader updates.
- Ensure validation badges have `role="status"` and appropriate `aria-label`.

### Out of Scope

- Gating Apply/Save buttons (T-03).
- Action row changes (T-04).
- Unsaved diff panel (T-05).
- Changes to `LiveExpressionDisplay` or `LiveResultDisplay` file exports (other consumers, if any, should still be able to import them).

## Change Requirements

`BuilderFeedbackArea` component:

1. Props:
   - `expression: string`
   - `sourceData: unknown | null`
   - `validationState: BuilderValidationState`
   - `mode: 'builder' | 'editor'`
   - `className?: string`

2. Expression row:
   - Renders syntax-highlighted expression using the `tokenizeDsl` utility.
   - Empty state: italic muted text "No expression yet".
   - `data-testid="feedback-expression"`

3. Result row:
   - Calls `useExpressionPreview({ expression, sourceData })` internally.
   - Renders formatted result, evaluating state, error state, or "Load test data" prompt.
   - `data-testid="feedback-result"`

4. Validation row:
   - Renders two inline badges side by side.
   - Structure badge: `data-testid="validation-structure-badge"`
     - Valid: `CheckCircle2` (green) + "Structure"
     - Invalid: `XCircle` (red) + first issue message (truncated if long)
     - N/A (Editor mode): hidden or muted "—"
   - Output Type badge: `data-testid="validation-output-type-badge"`
     - Valid: `CheckCircle2` (green) + "Output type"
     - Mismatch: `AlertTriangle` (amber) + mismatch message
     - Unknown/neutral: muted "—"
   - `data-testid="feedback-validation"`

5. Container:
   - `data-testid="builder-feedback-area"`
   - `role="region"` + `aria-label="Expression feedback"`
   - Visual: bordered section with `border-b border-slate-700`, `px-4 py-3`

`ScalarFieldBuilder` changes:
- Remove the Suggested Sources section (the `suggestions.length > 0 && (...)` block).
- Remove `suggestSourceFields` import and related state/handlers.
- Add `BuilderFeedbackArea` between Header and Expression Area.
- Pass the appropriate props (expression, sourceData from PreviewContext, validation state from `useBuilderValidation`).

`UnifiedExpressionBuilder` changes:
- Remove the `LiveExpressionDisplay` and `LiveResultDisplay` sections from its render output.
- These components are no longer rendered inside the builder content — they are in the feedback area.
- Do not delete the component files — they may still be imported by `BuilderFeedbackArea` or other consumers.

## Notes

- The feedback area replaces the Suggested Sources row in the layout. This is a deliberate design choice to promote continuous validation feedback over heuristic suggestions (the Suggest AI action is the future replacement for heuristic suggestions).
- `useExpressionPreview` is called inside `BuilderFeedbackArea`, not passed as a prop. This keeps the component self-contained and consistent with how `LiveResultDisplay` currently works.
- The Expression row in the feedback area is read-only (no click-to-edit behavior, unlike `LiveExpressionDisplay` inside the builder). If click-to-edit is desired, the `onClickToEdit` callback can be added later.
