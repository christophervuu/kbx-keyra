## Summary

Create Lambda handlers for the five deployment API routes: deploy, promote, rollback, list deployments, and get current deployments. Enforce deployability rules (revision→DEV only, version→any, promotion requires version).

---

## Scope

### In Scope

- `POST /mappings/:id/deploy` handler with sourceType+environment validation
- `POST /mappings/:id/promote` handler with version-backed enforcement
- `POST /mappings/:id/rollback` handler
- `GET /mappings/:id/deployments` handler with optional environment filter
- `GET /mappings/:id/deployments/current` handler
- SAM template route additions
- Input validation and error codes (`REVISION_NOT_DEPLOYABLE_TO_ENV`, `PROMOTION_REQUIRES_VERSION`, `SOURCE_NOT_FOUND`, `SNAPSHOT_INTEGRITY_ERROR`)
- Integration tests

### Out of Scope

- Persistence layer internals (T-01)
- UI consumption (T-05/T-06)
- Staleness computation in response (T-03 provides the module, but listing current deployments returns raw data)

## Change Requirements

- Deploy handler: validate `sourceType` against `environment` rules, verify source exists (revision or version), call `deployments.create()`
- Promote handler: read current deployment in `fromEnvironment`, verify `sourceType=version`, create deployment in `toEnvironment` with `promotedFrom` field
- Rollback handler: read referenced deployment by SK, create new deployment with `rollbackOf` field using the same `configS3Key`
- List handler: call `deployments.listHistory()` with optional environment filter
- Current handler: call `deployments.getCurrentAll()` and return per-environment status
- All handlers follow existing Lambda conventions (shared response helpers, error envelope)
