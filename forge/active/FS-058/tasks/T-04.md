## Summary

Implement `src/lib/persistence/schema-metadata.ts` with typed CRUD operations for the SchemaMetadata DynamoDB table: create, get, list, update-status, and delete. This module handles schema lifecycle metadata without touching schema content (S3) or tree nodes.

## Change Requirements

- Implement `schemaMetadata.create(input: CreateSchemaMetadataInput): Promise<SchemaMetadataItem>`:
  - Generate UUID `schemaId`
  - Set `createdAt`, `updatedAt`
  - Default `status: 'ingesting'` if not provided
  - Default `syncStatus: 'not-synced'` if not provided
  - Write to DynamoDB with `PutCommand`
  - Return `SchemaMetadataItem`

- Implement `schemaMetadata.get(schemaId: string): Promise<SchemaMetadataItem | null>`:
  - `GetCommand` by `schemaId`
  - Return item or null

- Implement `schemaMetadata.list(): Promise<SchemaMetadataItem[]>`:
  - `ScanCommand` on SchemaMetadata table
  - Return all items

- Implement `schemaMetadata.updateStatus(schemaId: string, status: string, fieldCount?: number): Promise<SchemaMetadataItem>`:
  - `UpdateCommand` setting `status`, optionally `fieldCount`, always `updatedAt`
  - Return updated item (`ReturnValues: 'ALL_NEW'`)

- Implement `schemaMetadata.delete(schemaId: string): Promise<void>`:
  - `DeleteCommand` by `schemaId`
  - Idempotent

- Export all functions

## Notes

- The `SchemaMetadataItem` type must include `scope`, `syncStatus`, `inferred`, and `description` fields that are present in the UI's `SchemaMetadata` type but absent from the product spec's table definition. These were added during Phase 0 UI development and must be persisted.
- `updateStatus()` is the primary mutation path used by the ingestion pipeline (FS-056) to transition schemas from `ingesting` → `ready` or `error`.
