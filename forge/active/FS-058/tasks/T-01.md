## Summary

Create the foundational persistence module at `src/lib/persistence/` with TypeScript item type definitions for all 5 DynamoDB tables, DynamoDB Document Client and S3 Client singletons configured from environment variables, table/bucket name constants, and the barrel `index.ts` export. This establishes the shared infrastructure that all subsequent entity modules build on.

---

## Scope

### In Scope

- `src/lib/persistence/types.ts` — TypeScript interfaces for `ProjectItem`, `MappingItem`, `SchemaMetadataItem`, `SchemaNodeItem`, `MappingVersionItem`
- `src/lib/persistence/clients.ts` — DynamoDB Document Client + S3 Client singletons, env var config (`PROJECTS_TABLE`, `MAPPINGS_TABLE`, `SCHEMA_METADATA_TABLE`, `SCHEMA_NODES_TABLE`, `MAPPING_VERSIONS_TABLE`, `STORAGE_BUCKET`, `AWS_REGION`)
- `src/lib/persistence/config.ts` — table name constants and S3 key-pattern helpers
- `src/lib/persistence/index.ts` — barrel exports
- Type compatibility checks ensuring item types align with `ui/src/lib/types/domain.ts`
- Unit tests for config/client initialization

### Out of Scope

- Entity-specific CRUD operations (T-02 through T-07)
- Integration test infrastructure (T-08)

## Change Requirements

- Create `src/lib/persistence/types.ts` with interfaces:
  - `ProjectItem` — all fields from DynamoDB Projects table definition in spec
  - `MappingItem` — all fields from Mappings table, including `configS3Key`
  - `SchemaMetadataItem` — all fields from SchemaMetadata table, including `scope`, `syncStatus`, `inferred`, `description`
  - `SchemaNodeItem` — all fields from SchemaNodes table
  - `MappingVersionItem` — all fields from MappingVersions table, including `configS3Key`
  - Input types: `CreateProjectInput`, `CreateMappingInput`, `CreateSchemaMetadataInput`, `UpdateProjectInput`, `UpdateMappingInput`
  - Converter functions (or type utilities) to map item types to domain types: `toProjectMetadata()`, `toMappingMetadata()`, `toSchemaMetadata()`

- Create `src/lib/persistence/clients.ts`:
  - Export `dynamoClient` — `DynamoDBDocumentClient` singleton, configured from `AWS_REGION` env var (default: `us-east-1`), with optional endpoint override via `DYNAMODB_ENDPOINT` for local development
  - Export `s3Client` — `S3Client` singleton, configured similarly with optional `S3_ENDPOINT` override

- Create `src/lib/persistence/config.ts`:
  - Export `TABLE_NAMES` object reading from env vars with sensible defaults (e.g., `keyra-projects`)
  - Export `BUCKET_NAME` reading from `STORAGE_BUCKET` env var
  - Export S3 key builder functions:
    - `schemaOriginalKey(schemaId, ext)` → `schemas/{schemaId}/original.{ext}`
    - `schemaContentKey(schemaId)` → `schemas/{schemaId}/content.json`
    - `mappingConfigKey(mappingId)` → `mappings/{mappingId}/config.json`
    - `mappingVersionKey(mappingId, version)` → `mappings/{mappingId}/versions/v{N}.json`

- Create `src/lib/persistence/index.ts` — barrel export of types, clients, config

## Notes

- Follow the pattern established by `src/lib/ai/` for AWS SDK client creation (look at `prompt-registry.ts` for DynamoDB client patterns).
- The `DYNAMODB_ENDPOINT` and `S3_ENDPOINT` env vars enable pointing to DynamoDB Local / LocalStack during development.
