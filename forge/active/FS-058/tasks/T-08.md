## Summary

Create an integration test suite that validates all persistence modules against real DynamoDB Local and LocalStack S3 instances. This includes a docker-compose configuration for test infrastructure, table creation scripts, and end-to-end tests covering create/read/update/delete cycles for all entities.

---

## Scope

### In Scope

- `docker-compose.test.yml` (or similar) with DynamoDB Local + LocalStack S3
- Table creation script/utility for test setup
- Integration test files for all entity modules
- Test lifecycle (create tables before, clean up after)
- Environment variable setup for local endpoints

### Out of Scope

- CI pipeline integration (documented but not automated)
- Performance benchmarks
- Load testing

## Change Requirements

- Create `docker-compose.test.yml` at project root:
  - DynamoDB Local on port 8000
  - LocalStack (S3) on port 4566
  - Healthchecks for readiness

- Create `tests/integration/persistence/setup.ts`:
  - `createTables()` function — creates all 5 DynamoDB tables with correct key schemas and GSIs using `CreateTableCommand`
  - `deleteTables()` function — deletes all tables
  - `createBucket()` function — creates S3 bucket
  - `clearBucket()` function — empties all objects
  - Configure clients to point at local endpoints

- Create integration test files covering:
  - **Projects**: full CRUD cycle (create → get → list → update → get → delete → get returns null)
  - **Mappings**: create → get → listByProject → update (version increment) → duplicate → delete
  - **SchemaMetadata**: create → get → list → updateStatus → delete
  - **SchemaNodes**: batchWrite 75 items → listBySchema (all 75) → queryContains → deleteBySchema → listBySchema (empty)
  - **MappingVersions**: save 3 versions → list (descending) → get specific → save 51st (triggers prune) → verify count ≤ 50
  - **S3 Content**: putOriginal → putProcessed → get → getOriginal → delete → get returns null

- Add npm script or documentation for running integration tests:
  - `npm run test:integration` or equivalent
  - Requires docker-compose up first

## Blockers / Risks

- Docker must be available on the development machine. If Docker is not available, these tests won't run. Document this requirement clearly.
- DynamoDB Local has known differences from real DynamoDB (e.g., no throughput limits). Note these limitations.

## Notes

- Integration tests should use `vitest` (consistent with project test tooling) with a longer timeout setting for integration tests.
- Consider using a `beforeAll`/`afterAll` pattern per file that creates tables and cleans up.
- Each test should use unique IDs to avoid interference when tests run in parallel.
- The `setup.ts` should export a `getTestClients()` function that returns pre-configured clients pointing at local endpoints, overriding the env vars used by the persistence module.
