## Summary

Implement `src/lib/persistence/mappings.ts` with typed CRUD operations for the Mappings DynamoDB table and associated S3 config storage: create, get, list-by-project, update (with version auto-increment), delete, and duplicate. The update operation atomically increments the version counter using DynamoDB conditional expressions.

## Change Requirements

- Implement `mappings.create(input: CreateMappingInput & { config: MappingConfig }): Promise<MappingItem>`:
  - Generate UUID `mappingId`
  - Set `version: 1`, `createdAt`, `updatedAt`
  - Compute `configS3Key` using `mappingConfigKey(mappingId)`
  - Write config JSON to S3
  - Write metadata item to DynamoDB
  - Return `MappingItem`

- Implement `mappings.get(mappingId: string): Promise<MappingItem | null>`:
  - `GetCommand` on Mappings table
  - Return item or null

- Implement `mappings.listByProject(projectId: string): Promise<MappingItem[]>`:
  - `QueryCommand` on `projectId-index` GSI
  - Return all matching items

- Implement `mappings.update(mappingId: string, fields: UpdateMappingInput, config?: MappingConfig): Promise<MappingItem>`:
  - `UpdateCommand` with `SET version = version + :one` in the expression
  - Update `updatedAt`, plus any other provided fields (`status`, `ruleCount`, `coverage`)
  - If `config` provided, overwrite S3 object at `configS3Key`
  - Return updated item (`ReturnValues: 'ALL_NEW'`)

- Implement `mappings.delete(mappingId: string): Promise<void>`:
  - Read item to get `configS3Key`
  - Delete S3 object
  - Delete DynamoDB item

- Implement `mappings.duplicate(mappingId: string, newName: string): Promise<MappingItem>`:
  - Read source mapping (get item + get S3 config)
  - Generate new `mappingId`, set `version: 1`, set `name: newName`
  - Write new S3 config + new DynamoDB item
  - Return new `MappingItem`

## Notes

- The version auto-increment uses `SET version = version + :one` with `ExpressionAttributeValues: { ':one': 1 }`. This is not a conditional check — it's a simple increment (last-write-wins for Phase 1).
- The `duplicate` operation reads config from S3 to avoid requiring the caller to fetch it separately.
