## Summary

Write integration tests that prove projects created in one session are fully loadable in a fresh session — all metadata fields are durable and returned identically. Tests cover create → get, create → list, and update → get across session boundaries.

---

## Scope

### In Scope

- Integration tests for project cross-session persistence
- Test scenarios: create/get, create/list, update/get, delete/verify-gone
- Assertion on all project metadata fields: `projectId`, `name`, `description`, `slug`, `schemaRefs`, `tags`, `createdAt`, `updatedAt`
- Use of `createFreshSession()` to simulate session boundaries

### Out of Scope

- Mapping or schema persistence (T-03, T-04)
- Project referential integrity with mappings (future spec)
- Performance benchmarks

## Change Requirements

- Create `tests/lambda/integration/persistence/project-persistence.test.ts`
- Test cases:
  1. **Create in Session A, Get in Session B**: Create project with full metadata. Use fresh session to retrieve by ID. Assert deep equality on all fields.
  2. **Create in Session A, List in Session B**: Create 3 projects. Use fresh session to list. Assert all 3 appear with correct metadata.
  3. **Update in Session A, Get in Session B**: Create project, update `name` and `description`. Use fresh session to get. Assert updated fields are current, `updatedAt` has changed, `createdAt` is unchanged.
  4. **Delete in Session A, Get in Session B**: Create project, delete it. Use fresh session to get. Assert not-found response.
  5. **Schema refs and tags persist**: Create project with non-empty `schemaRefs` and `tags`. Fresh session get returns them identically.
- Each test uses deterministic but unique IDs (UUIDs from fixture helpers)
- Tests are isolated — each creates and cleans its own data

---

## Verification Requirements

- All test cases pass against DynamoDB Local
- Deep equality assertions (not just key field checks)
- Timestamps are valid ISO 8601 and logically consistent (createdAt <= updatedAt)
- Array fields (schemaRefs, tags) maintain order
- Empty arrays persist correctly (not `null` or `undefined`)
