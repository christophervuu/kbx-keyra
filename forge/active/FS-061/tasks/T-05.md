## Summary

Audit `http-adapter.ts`, `bootstrap.ts`, and related adapter files to identify and remove any reads from `localStorage` or `sessionStorage` that would create a hidden dependency on browser state for data reconstruction when the `HttpAdapter` is active. Add a lint rule or static check to prevent regressions.

---

## Scope

### In Scope

- Static analysis of `ui/src/lib/api/http-adapter.ts` for localStorage/sessionStorage reads
- Static analysis of `ui/src/lib/api/bootstrap.ts` for localStorage seeding or sync when HttpAdapter is selected
- Audit any utility files imported by HttpAdapter for indirect storage access
- Remove or guard any localStorage reads found in the HttpAdapter code path
- Add ESLint rule or grep-based CI check to prevent future regressions
- Verify that `createAdapter()` with `VITE_API_URL` set does not touch localStorage

### Out of Scope

- `LocalStorageAdapter` — it's supposed to use localStorage (that's its purpose)
- `HybridAdapter` — being replaced by HttpAdapter
- UI component localStorage usage (e.g., preferences, theme) — acceptable
- Performance caching strategies (future spec)

---

## Relevant Areas

- `ui/src/lib/api/http-adapter.ts` — primary audit target
- `ui/src/lib/api/bootstrap.ts` — adapter factory
- `ui/src/lib/api/hybrid-adapter.ts` — reference for patterns to not replicate
- `ui/src/lib/api/local-storage-adapter.ts` — reference for patterns to avoid
- `ui/src/lib/api/types.ts` — `ApiAdapter` interface (read-only reference)
- `.eslintrc.*` or `eslint.config.*` — lint rule addition
- `ui/src/lib/api/` — directory-level lint scope

---

## Change Requirements

- **Audit**: Search for all occurrences of:
  - `localStorage.getItem`
  - `localStorage.setItem`
  - `sessionStorage.getItem`
  - `sessionStorage.setItem`
  - `window.localStorage`
  - `window.sessionStorage`
  in `http-adapter.ts` and all files it transitively imports (excluding node_modules)
- **Fix**: If any storage reads exist for data reconstruction (not diagnostics/logging), either:
  - Remove them entirely, OR
  - Guard them behind a condition that ensures they only execute in `LocalStorageAdapter` context
- **Prevent regression**: Add an ESLint rule (`no-restricted-globals` or `no-restricted-properties`) scoped to `ui/src/lib/api/http-adapter.ts` and related backend-adapter files. This must be CI-enforced (not optional). Additionally, document the prohibition as a code review convention for the adapter directory.
- **Verify bootstrap**: Confirm that `createAdapter()` when `VITE_API_URL` is set:
  - Does NOT read from localStorage to seed any state
  - Does NOT migrate localStorage data to HTTP
  - Returns a clean HttpAdapter instance ready for HTTP-only operation

---

## Verification Requirements

- `grep -r "localStorage\|sessionStorage" ui/src/lib/api/http-adapter.ts` returns zero data-access matches (logging/diagnostic mentions acceptable if clearly guarded)
- `bootstrap.ts` does not call localStorage when HttpAdapter path is taken (verified by code inspection or unit test)
- Lint rule or CI check is in place and would fail if someone adds `localStorage.getItem()` to `http-adapter.ts`
- Unit test (optional but preferred): mock `localStorage` to throw, instantiate HttpAdapter, call a CRUD method — should succeed without touching storage

## Acceptance Checks

- Zero localStorage/sessionStorage reads in HttpAdapter code path for data reconstruction
- ESLint rule added and CI-enforced — would fail build if someone adds `localStorage.getItem()` to `http-adapter.ts`
- `bootstrap.ts` verified clean for HttpAdapter selection path
- If any fixes were needed, they are minimal and do not change adapter behavior
- `forge/architecture/project-structure.md` updated if new files/scripts created
