## Summary

Create explicit mutation-to-query impact rules and wire all major UI mutation flows to either write canonical mutation responses directly into cache or trigger targeted invalidation. Ensure delete flows remove stale detail caches and list memberships.

---

## Scope

### In Scope

- Define mutation impact matrix in code for:
  - projects,
  - mappings,
  - schemas,
  - deployments,
  - settings,
  - value-table resources.
- Apply matrix to current mutation callsites and success handlers.
- Prefer direct cache writes when mutation response is complete canonical and sufficient.
- Merge only formally documented patch-response fields.
- Use targeted invalidation + refetch when response is partial/metadata-only/incomplete.
- Cancel relevant in-flight reads before optimistic/canonical cache updates.
- For delete operations, remove exact detail/dependent queries and invalidate affected collections/summaries.
- Include backend/adapter context clearing pathways.

### Out of Scope

- UI redesign of mutation interactions.
- New backend endpoint contracts.

## Change Requirements

- Every supported mutation has explicit cache impact rules.
- Mapping save path avoids redundant immediate GET when complete canonical response is already available.
- Deletes remove detail caches and corresponding list entries.
- Invalidation boundaries support item/list/family targeting.
- No generic merge helper treats omitted fields as unchanged unless endpoint contracts explicitly guarantee that behavior.

---

## Verification Requirements

- Mutation-focused integration tests with request spies confirming no unnecessary follow-up GETs where avoidable.
- Tests validating dependent screens update after each mutation type.
- Tests proving metadata-only responses invalidate canonical detail queries instead of speculative merges.

---

## Acceptance Checks

- Project mutation cache impacts match matrix and keep dashboard/project views coherent.
- Mapping mutation cache impacts refresh summary/deployment-context dependencies correctly.
- Schema mutation impacts update detail/list/usage and dependent project surfaces.
- Deployment mutation impacts refresh deployment badges/context/history and related overviews.
- Backend context changes clear incompatible cache.
- Metadata-only update paths invalidate canonical detail queries and refetch instead of guessing merged resources.

---

## Blockers / Risks

- Some mutation responses may not carry enough canonical fields for safe direct write-through.

---

## Notes

- Where canonical payload is incomplete, document and consistently apply targeted invalidation fallback.
