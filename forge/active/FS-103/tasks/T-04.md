## Summary

Adopt shared query caching for schema library/detail/usage and deployment context/history pages, including operationally sensitive manual refresh controls and window-focus refresh policy for deployment data.

---

## Scope

### In Scope

- Migrate schema hooks:
  - `use-schema-library.ts`
  - `use-schema-detail.ts`
  - `use-schema-usage.ts`
- Migrate deployment hook:
  - `use-deployment-page.ts`
- Introduce per-resource refresh trigger policy:
  - deployment data focus-refresh enabled,
  - schema content avoids unnecessary aggressive refresh.
- Keep deployment-progress polling in dedicated deployment workflow hooks only.
- Ensure manual refresh actions reuse canonical query paths and keep content visible.

### Out of Scope

- Mapping Editor unsaved-state boundary changes.
- Full mutation invalidation matrix implementation outside schema/deployment domains.
- Moving generic query definitions to interval polling.

## Change Requirements

- Schema pages support cached return rendering and stale background refresh.
- Deployment pages support background refresh with subtle status indicators.
- Manual refresh keeps content visible and reports non-blocking errors when cached data exists.
- Focus-triggered stale refresh is scoped to deployment-sensitive resources.
- Active-operation polling is isolated to dedicated deployment hooks, runs only for transitional states, stops on terminal/unmount, and keeps `refetchIntervalInBackground` false by default.

---

## Verification Requirements

- Integration tests for schema and deployment cached return behavior.
- Tests for deployment manual refresh and refresh-error UX.
- Adapter parity verification for both adapters.

---

## Acceptance Checks

- Schema and deployment pages render cached content on return navigation.
- Deployment refresh actions do not blank page content.
- Refresh failures with cache render non-blocking warning states.
- Deployment mutation actions refresh badges/context/history consistently.
- Behavior is verified under both `HttpAdapter` and `LocalStorageAdapter` modes.
- Ordinary deployment context/history queries do not poll solely due to stale status.

---

## Blockers / Risks

- Deployment flows have rapidly changing states; stale policy tuning must avoid misleading status lag.

---

## Notes

- Preserve existing deployment-in-progress special polling semantics separately from generic query refresh rules.
