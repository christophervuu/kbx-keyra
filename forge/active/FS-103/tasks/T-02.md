## Summary

Create a centralized typed key factory and query-definition registry that encodes deterministic keys, backend/adapter rebootstrap semantics, and resource-specific cache policy defaults. This becomes the only supported key construction mechanism for page queries.

---

## Scope

### In Scope

- Define structured key namespaces for projects, mappings, schemas, deployments, settings, and value-table resources.
- Include filters/pagination parameters and required identifiers in key models.
- Recreate or clear `QueryClient` when backend URL or adapter identity changes.
- Include DEV/QA/PROD in keys only where resource data is environment-specific.
- Define exact resource-group stale/gc defaults from FS-103 Rev 2.

### Out of Scope

- Full migration of existing pages/hooks to new keys.

---

## Relevant Areas

- `ui/src/lib/*` (new query key/definition modules)
- `ui/src/lib/api/bootstrap.ts`
- `ui/src/lib/api/types.ts`
- `ui/src/features/**/*` (touchpoints where ad hoc keys might emerge)

---

## Change Requirements

- Query keys must be deterministic and serializable.
- Prevent arbitrary page-local key array construction by convention and usage.
- Resource categories have explicit stale/gc policy constants documented in code with FS-103 Rev 2 exact defaults.
- Support targeted invalidation granularity (item/list/family).
- Do not include transport configuration such as API base URL in every domain key.

---

## Verification Requirements

- Unit tests for key determinism and parameter coverage.
- Unit tests for invalidation-scope helpers (item/list/family).
- Type-level tests or compile checks for key factory signatures.

---

## Acceptance Checks

- Query key factory exists with typed methods per resource family.
- Key output includes required IDs/filter/pagination dimensions.
- Backend/adapter boundary is enforced via QueryClient rebootstrap/clear behavior.
- Environment-specific key dimensions are present only for truly environment-scoped resources.
- Resource-specific stale/gc defaults are centrally defined with exact initial values.
- No new feature code constructs ad hoc string-array keys.

---

## Blockers / Risks

- Incomplete resource parameter modeling can cause accidental key collisions.
