## Summary

Refactor Home dashboard and Project Overview hooks/components to use shared query definitions so return navigation uses cached data immediately, stale data refreshes in background, and refresh errors become non-blocking when cached content exists.

---

## Scope

### In Scope

- Replace effect-driven fetch orchestration in:
  - `use-dashboard-data.ts`
  - `use-project-overview.ts`
- Keep current Home activity-feed loading behavior unchanged in FS-103 (no activity query-cache migration in this task).
- Preserve existing page UX while introducing clear initial-load vs background-refresh state behavior.
- Reduce duplicate sequential/N+1 patterns where safe, including coordinated parallel requests with dedup.
- Maintain existing mutation behavior in Project Overview while integrating query invalidation hooks.

### Out of Scope

- Mapping editor and deployment page migration.
- Full mutation matrix implementation for all domains.
- Activity-feed ownership/merge redesign.

## Change Requirements

- First load shows existing skeleton when no cache.
- Return visits render cached content without full skeleton replacement.
- Background refresh indicators are subtle and non-blocking.
- Refresh failures with cache show warning/last-updated/retry affordance.
- Shared query dedupe prevents duplicate same-key adapter calls across simultaneous consumers.

---

## Verification Requirements

- Hook integration tests for initial vs cached return behavior.
- Request spy assertions for dedupe and reduced duplicate calls.
- UI tests for non-blocking refresh error state.

---

## Acceptance Checks

- Dashboard and Project Overview render immediately from cache on return navigation.
- No full-page skeleton appears on cached return visits.
- Stale revalidation runs in background and updates data when changed.
- Failed refresh preserves content and exposes retry + last-success timestamp.
- There are no concurrent duplicate adapter requests for the same canonical query key.
- Home activity-feed behavior remains unchanged.

---

## Blockers / Risks

- Existing derived dashboard totals may depend on chained requests and require careful memoized recompute.

---

## Notes

- Keep UI composition largely unchanged; focus on data-layer behavior and state transitions.
