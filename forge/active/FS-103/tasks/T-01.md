## Summary

Add TanStack Query to the UI workspace and wire a root `QueryClientProvider` in app bootstrap so all pages can use a shared in-memory query cache. Define base client defaults and cache-clear hooks needed for adapter/backend boundary changes.

---

## Scope

### In Scope

- Add `@tanstack/react-query` dependency.
- Create app-level query client module and provider wiring in `ui/src/main.tsx` (or app-shell equivalent).
- Define global baseline defaults (retry policy baseline, gc, focus/reconnect behavior baseline) to be overridden per resource group.
- Add cache reset utility entry point for backend/adapter changes and dev manual reset.

### Out of Scope

- Migrating specific pages/hooks to query APIs.
- Final per-resource stale/gc policy tuning.

---

- `ui/package.json`

- `ui/src/lib/api/bootstrap.ts`
- `ui/src/lib/api/types.ts`
- `ui/src/lib/*` (new query bootstrap modules)

---

## Change Requirements

- Application renders under both `AdapterProvider` and `QueryClientProvider` with stable initialization order.
- Query cache is memory-only for this phase (no persistence plugin/hydration).
- Introduce a centralized cache reset function callable when adapter/backend context changes.
- Ensure base configuration does not force global refetch-every-focus behavior.

---

## Verification Requirements

- Unit tests for query client factory defaults and cache reset behavior.
- App bootstrap test proving provider composition initializes without regressions.
- Typecheck/lint/build clean.

---

## Acceptance Checks

- `@tanstack/react-query` is installed and used by app bootstrap.
- App starts in both `localStorage` and `httpBackend` modes with no provider/runtime errors.
- Query client initialization is centralized and reusable.
- Manual cache reset utility exists and clears query cache deterministically.
- No query persistence plugin is introduced.
