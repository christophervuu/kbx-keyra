## Summary

Extend `SchemaMetadata` with `scope`, `description`, `updatedBy`, `inferred`, and `syncStatus` fields. Create `UpdateSchemaInput` type. Add `updateSchema(id, input)` method to the `ApiAdapter` interface and implement it in `LocalStorageAdapter`. This provides the data layer foundation all other FS-015 tasks depend on, and also satisfies FS-016's metadata requirements.

---

## Scope

### In Scope

- Add `scope: 'global' | 'project'` field to `SchemaMetadata` (default: `'global'` for backward compatibility)
- Add `description?: string` field to `SchemaMetadata`
- Add `updatedBy?: string` field to `SchemaMetadata`
- Add `inferred?: boolean` field to `SchemaMetadata` (set at creation time when schema is inferred from sample data)
- Add `syncStatus: 'synced' | 'not-synced' | 'local-changes'` field to `SchemaMetadata` (default: `'not-synced'` for Phase 0)
- Create `UpdateSchemaInput` type in `ui/src/lib/types/domain.ts`:
  - `name?: string`
  - `description?: string`
  - `scope?: 'global' | 'project'`
  - `content?: Record<string, unknown> | string`
  - `fieldCount?: number`
  - `format?: SchemaFormat`
- Add `updateSchema(id: string, input: UpdateSchemaInput): Promise<SchemaMetadata>` to `ApiAdapter` interface
- Implement `updateSchema` in `LocalStorageAdapter`:
  - Find schema by ID (throw NOT_FOUND if missing)
  - Merge input fields into existing metadata/detail
  - Update `updatedAt` timestamp
  - Set `updatedBy` to `'local-user'`
  - Persist to localStorage
  - Return updated `SchemaMetadata`
- Update `CreateSchemaInput` to optionally accept `scope` and `description`
- Update `createSchema` in `LocalStorageAdapter` to store `scope` (default `'global'`) and `description`
- Export new types from `ui/src/lib/types/index.ts`

### Out of Scope

- UI components consuming these types (handled in T-02+)
- Schema editing logic or tree manipulation
- Any changes to the SchemaTreeView component

## Change Requirements

- `SchemaMetadata` gains five new fields: `scope` (required with default), `description` (optional), `updatedBy` (optional), `inferred` (optional boolean), `syncStatus` (required with default `'not-synced'`).
- `SchemaScope` type alias: `'global' | 'project'`.
- `SchemaSyncStatus` type alias: `'synced' | 'not-synced' | 'local-changes'`.
- `UpdateSchemaInput` is a new exported interface.
- `ApiAdapter.updateSchema` method added to the interface.
- `LocalStorageAdapter.updateSchema` implementation does partial merge: only defined fields in the input overwrite existing values. `updatedAt` is always refreshed. If `content` is provided, both `detail.content` and `metadata` fields (fieldCount if provided) are updated. If content is updated on a synced schema, `syncStatus` changes to `'local-changes'`.
- Existing `createSchema` must populate `scope: input.scope ?? 'global'`, `description: input.description ?? ''`, `inferred: input.inferred ?? false`, and `syncStatus: input.syncStatus ?? 'not-synced'`.
- All existing tests must continue to pass (no breaking changes to existing schema CRUD).

## Notes

This task is foundational — all other FS-015 tasks depend on it, and FS-016 (Schema Library) also depends on the `inferred` and `syncStatus` fields added here. Keep the changes minimal and non-breaking. The `scope` field defaults to `'global'` and `syncStatus` defaults to `'not-synced'` so existing stored schemas (without these fields) still work correctly when read back.
