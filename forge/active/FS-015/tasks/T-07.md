## Summary

Build the Actions section of the Schema Detail page with context-dependent action buttons. Actions vary based on schema origin, scope, and format. Includes confirmation modals for destructive actions, blocking logic for remove when mappings reference the schema, and placeholder buttons for Phase 0 deferred features (GitHub sync, AI auto-describe).

---

## Scope

### In Scope

- Create `ui/src/features/schemas/components/SchemaActions.tsx` component
- Action buttons with visibility rules:
  - **Edit** (non-CDM, json-schema only): activates edit mode (calls `startEditing` from T-04)
  - **Auto-describe fields** (non-CDM): placeholder with tooltip "AI-generated field descriptions available in a future release"
  - **Sync to GitHub** (local or edited published): placeholder with tooltip "GitHub sync available when backend is connected"
  - **Re-sync from GitHub** (CDM or published): placeholder with tooltip "Re-sync available when backend is connected"
  - **Promote to Global** (scope === 'project'): changes scope from project to global
  - **Replace file** (non-CDM): triggers file upload flow (implemented in T-08)
  - **Remove** (non-CDM): deletes schema from storage
  - **View Raw**: shows raw content (implemented in T-08)
- Confirmation modals:
  - **Promote to Global:** "This will make the schema available to all projects. This action cannot be undone." → confirm calls `adapter.updateSchema(id, { scope: 'global' })`
  - **Remove (no blockers):** "Are you sure you want to remove this schema? This action cannot be undone." → confirm calls `adapter.deleteSchema(id)` → redirect to Schema Library
  - **Remove (blocked):** Shows "Cannot remove this schema because it is referenced by:" + list of mapping names. Remove button disabled or blocked state.
- Create reusable `ConfirmModal` component in `ui/src/components/` if one doesn't exist
- Integrate into `SchemaDetailPage`
- Wire "Edit" button to `startEditing()` from `useSchemaEditor` (T-04)
- Consume usage data from `useSchemaUsage` (T-06) for remove blocking check

### Out of Scope

- Replace file upload flow (T-08)
- View Raw modal content (T-08)
- Actual GitHub sync operations (Phase 3)
- Actual AI operations (Phase 2)
- Schema editing operations (T-05)

## Change Requirements

- `SchemaActions` component:
  - Props: `schema: SchemaDetail`, `parsedSchema: ParsedSchema | null`, `onEdit: () => void`, `onReplace: () => void`, `onViewRaw: () => void`, `usage: { mappings: UsageMapping[] }`, `isEditing: boolean`
  - Conditionally renders buttons based on `schema.metadata.origin`, `schema.metadata.scope`, `schema.metadata.format`, and `isEditing` state
  - Placeholder buttons are visually distinct (muted/outlined) with tooltips explaining deferred availability
  - When editing is active: shows "Save" and "Cancel" instead of "Edit" (or hides Edit)

- Promote to Global flow:
  - Show `ConfirmModal` with warning text
  - On confirm: call `adapter.updateSchema(schemaId, { scope: 'global' })`
  - Update local state to reflect new scope
  - Toast or inline confirmation of success

- Remove flow:
  - Check `usage.mappings.length > 0` → show blocked state with mapping names
  - If no mappings reference it: show `ConfirmModal` with deletion warning
  - On confirm: call `adapter.deleteSchema(schemaId)`
  - Navigate to `/schemas` (Schema Library)

- `ConfirmModal` shared component (if new):
  - Props: `open`, `title`, `message`, `confirmLabel`, `cancelLabel`, `variant` ('danger' | 'warning' | 'info'), `onConfirm`, `onCancel`
  - Accessible (focus trap, ESC to close, aria labels)
  - Tailwind-styled overlay + centered modal
