## Summary

Build three remaining features for the Schema Detail page: (1) inferred schema banner with per-schema dismiss persistence, (2) View Raw modal showing syntax-highlighted schema content with copy button, and (3) Replace file flow that allows uploading a new file to replace schema content entirely.

---

## Scope

### In Scope

- **Inferred schema banner:**
  - Displayed when `ParsedSchema.inferred === true`
  - Text: "⚠ This schema was inferred from sample data and may be incomplete. Review and refine the structure before using it in mappings."
  - "Dismiss" button hides banner for current session
  - Dismissal persisted in localStorage key: `keyra:schema-banner-dismissed:{schemaId}`
  - On page load: check localStorage for dismissal before showing

- **View Raw modal:**
  - Create `ui/src/features/schemas/components/ViewRawModal.tsx`
  - Shows raw JSON Schema or XSD content in a code block
  - Syntax highlighting (JSON: colored keys/values/brackets; XSD: colored tags/attributes)
  - Lightweight implementation — no heavy library (use `<pre>` with CSS class coloring or a minimal JSON/XML formatter)
  - Copy button: copies raw text to clipboard (using `navigator.clipboard.writeText`)
  - Read-only (no editing)
  - Modal with close button, scrollable content area

- **Replace file flow:**
  - Create `ui/src/features/schemas/components/ReplaceFileDialog.tsx`
  - Triggered by "Replace file" action button (T-07 provides `onReplace` callback)
  - Shows confirmation: "This will replace the current schema content. Existing mappings will need re-validation."
  - On confirm: opens file picker (accept `.json`, `.xsd`)
  - Reads file content
  - Re-parses with appropriate parser (`parseJsonSchema` or `parseXsd`)
  - Calls `adapter.updateSchema(schemaId, { content, fieldCount, format })`
  - Updates page state with new schema data
  - If parse fails: shows error, does not save

- Integrate all three into `SchemaDetailPage`

### Out of Scope

- Schema validation of replaced content
- Syntax highlighting with external libraries (Monaco, highlight.js, Prism)
- Editing within the View Raw modal
- Multiple file upload

## Change Requirements

- **InferredSchemaBanner:**
  - Props: `schemaId: string`, `inferred: boolean`
  - If `inferred === false` or localStorage has dismissal key: render nothing
  - Otherwise: render warning banner with dismiss button
  - Dismiss writes `keyra:schema-banner-dismissed:{schemaId}` = `'true'` to localStorage
  - Styled as amber/yellow warning banner with ⚠ icon

- **ViewRawModal:**
  - Props: `open: boolean`, `onClose: () => void`, `content: string | object`, `format: SchemaFormat`
  - If content is object: `JSON.stringify(content, null, 2)` for display
  - JSON syntax highlighting: regex-based coloring of keys, strings, numbers, booleans, null
  - XSD syntax highlighting: regex-based coloring of tags, attributes, values
  - Copy button using `navigator.clipboard.writeText(rawString)`
  - Success feedback on copy (brief "Copied!" indicator)
  - Modal overlay, max-height with scroll, monospace font

- **ReplaceFileDialog:**
  - Props: `open: boolean`, `onClose: () => void`, `schemaId: string`, `currentFormat: SchemaFormat`, `onReplaced: (newDetail: SchemaDetail) => void`
  - Step 1: confirmation message
  - Step 2: file input (hidden input triggered by button, accept appropriate extensions)
  - Reads file as text
  - Infers format from extension (`.json` → json-schema, `.xsd` → xsd)
  - Parses with `parseJsonSchema` or `parseXsd`
  - On parse success: calls `adapter.updateSchema(schemaId, { content, fieldCount, format })` then `onReplaced()`
  - On parse failure: shows inline error, does not close

## Blockers / Risks

---

## Notes

The banner dismissal uses direct localStorage access (not through the adapter) because this is a UI preference, not domain data. This is consistent with the principle that `LocalStorageAdapter` handles domain data while simple UI preferences can use localStorage directly.
