## Summary

Ensure every generated Auto-Map suggestion receives mapping-engine validation enrichment prior to API response, with normalized diagnostics and valid/invalid state for UI-safe review.

---

## Scope

### In Scope

- Parse/validation invocation for each candidate expression.
- Normalization of validation diagnostics into stable response shape.
- Validation flags used by suggestion list payload.
- Tests for valid and invalid expression enrichment.

### Out of Scope

- Workspace UI rendering behavior.
- Retrieval/chunk planning updates.
- Deterministic engine diagnostic taxonomy redesign.

---

## Relevant Areas

- `src/lambda/ai/auto-map.ts`
- `src/engine/dsl/*`
- `tests/lambda/ai/auto-map.test.ts`

---

## Change Requirements

- Every suggestion includes validation payload before returning to client.
- Invalid expressions carry normalized diagnostics and are clearly marked invalid.
- Validation failures in one suggestion do not crash entire response processing.

---

## Verification Requirements

- Unit tests for valid expression diagnostics (`valid=true`).
- Unit tests for invalid expression diagnostics (`valid=false` + normalized messages).
- Regression tests for mixed valid/invalid suggestion sets.
- Typecheck for touched files.

---

## Acceptance Checks

- No suggestion is returned without validation status.
- Invalid suggestion diagnostics are stable and reviewable.
- Tests mapped to `AE-04` pass.

---

## Blockers / Risks

- Engine parser behavior changes could affect normalization assumptions.

---

## Notes

- Keep validation enrichment additive; do not reinterpret deterministic validation authority.
