## Summary

Ensure `LiveResultDisplay` inside `ScalarFieldBuilder` → `UnifiedExpressionBuilder` receives `sourceData` from `PreviewContext`, enabling real-time field-level result display while the user builds expressions. When no test data is loaded, the component should show the empty-state message.

---

## Scope

### In Scope

- Identify how `sourceData` flows from `PreviewContext` to `LiveResultDisplay` in the `ScalarFieldBuilder` rendering path
- Wire `sourceData` from `PreviewContext` through to `UnifiedExpressionBuilder` → `LiveResultDisplay` props
- If `sourceData` is stored as a raw JSON string in `PreviewContext`, parse it before passing to `LiveResultDisplay`
- Verify empty-state message renders correctly when `sourceData` is null
- Verify result updates when expression changes (debounced via `useExpressionPreview`)

### Out of Scope

- Changes to `useExpressionPreview` hook logic
- Changes to `LiveResultDisplay` component rendering (already correct per current implementation)
- Changes to `PreviewContext` API/shape
- Adding new test data loading mechanisms
- Changes to `InlinePreviewStrip` or `BottomArea` preview surfaces

---

## Change Requirements

- In `ScalarFieldBuilder` (or its parent composition), access `sourceData` from `PreviewContext` using the appropriate hook (`usePreviewContext()` or `useContext(PreviewContext)`).
- If `sourceData` from PreviewContext is a raw JSON string, parse it to produce the `unknown` value that `LiveResultDisplay` expects. Handle parse failure gracefully (treat as null).
- Pass parsed `sourceData` as a prop through to `UnifiedExpressionBuilder` → `LiveResultDisplay`.
- If `UnifiedExpressionBuilder` already accepts a `sourceData` prop and passes it to `LiveResultDisplay`, verify the prop is actually being provided by `ScalarFieldBuilder`.
- If `UnifiedExpressionBuilder` does NOT accept `sourceData` as a prop, add it to the component's props interface and thread it to `LiveResultDisplay`.
- Ensure `LiveResultDisplay` receives the current expression string from builder state (already wired via `expression` prop).

## Blockers / Risks

- `PreviewContext` may store source data as a string (the user types raw JSON into the source textarea). If so, parsing is needed before passing to `useExpressionPreview`. Parse failures should result in null sourceData (triggering empty state), not an error.
- `ScalarFieldBuilder` renders inside `MappingEditorPage` which should already be wrapped in `PreviewProvider`. If not, the context read will return null — this is already handled by the empty state.

## Notes

- `LiveResultDisplay` already handles the no-data case (lines 56-59 of LiveResultDisplay.tsx show the italic "Load test data to see live results." message when `sourceData === null || sourceData === undefined`).
- The primary task is ensuring the `sourceData` prop is actually threaded through from the context rather than being left as `null` or `undefined`.
- Check the `PreviewContext` shape to determine whether it exposes raw string or parsed object. The `ConnectedInlinePreviewStrip` may already perform this parsing — reuse its pattern.
