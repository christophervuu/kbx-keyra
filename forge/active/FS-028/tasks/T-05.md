## Summary

Ensure all diagnostic description surfaces consistently wrap text instead of truncating, and use the `ExpandableText` component for long messages. Remove any remaining `truncate` or `line-clamp` CSS on diagnostic descriptions across `InlinePreviewStrip` and related components.

---

## Scope

### In Scope

- Audit all diagnostic description rendering in `InlinePreviewStrip` (collapsed bar summary + expanded diagnostics list)
- Remove any CSS `truncate`, `text-ellipsis`, `overflow-hidden`, or `line-clamp-*` classes from diagnostic description elements
- Apply `ExpandableText` component (already defined in `InlinePreviewStrip.tsx`) to all diagnostic description renders
- Ensure severity icons, error codes, and rule navigation links remain visible and are not displaced by wrapped text
- Verify the 150-character threshold for expand/collapse works correctly
- If diagnostic descriptions appear in `BottomArea` Diagnostics tab, apply the same treatment there

### Out of Scope

- Changes to `ExpandableText` threshold value (keep 150 chars unless testing reveals it's problematic)
- Changes to diagnostic data structure or severity levels
- Changes to error codes or diagnostic generation logic
- Changes to `ScalarFieldBuilder` or builder-level inline diagnostics
- Adding new diagnostic display surfaces

---

## Relevant Areas

- `ui/src/features/mappings/components/InlinePreviewStrip.tsx`
- `ui/src/features/mappings/components/BottomArea.tsx` (diagnostics tab)
- `ui/src/features/mappings/types.ts` (PreviewDiagnostic type)

---

## Change Requirements

- In `InlinePreviewStrip` collapsed bar: if diagnostic descriptions are shown in the summary, replace any truncation with either a short summary or `ExpandableText`.
- In `InlinePreviewStrip` expanded diagnostics list: ensure all `<span>` or `<p>` elements rendering `diagnostic.message` or `diagnostic.description` use `ExpandableText` if they could exceed 150 characters, or at minimum use `break-words whitespace-pre-wrap` classes.
- In `BottomArea` Diagnostics tab: apply the same pattern. If diagnostic rows there use separate components, update those as well.
- Ensure the diagnostic row layout accommodates multi-line content:
  - Severity icon/badge and error code should be on the first line or in a fixed-width left column
  - Description area should be the flexible content area that wraps
  - Rule link/navigation button should remain accessible (not pushed off-screen by long text)
- Extract `ExpandableText` to a shared utility if it's needed in `BottomArea` as well (or import from `InlinePreviewStrip` if co-located).
