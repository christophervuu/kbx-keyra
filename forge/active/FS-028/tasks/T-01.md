## Summary

Change `SchemaUploadDialog` paste mode to run `analyzePasteContent` on input change (debounced 300ms) instead of exclusively on blur. This makes the content info panel (format badge, field count, parse validation) appear immediately after paste without requiring the user to tab out.

---

## Scope

### In Scope

- Add debounced call to `analyzePasteContent` inside `handlePasteTextChange`
- Remove or downgrade the `handlePasteBlur` call to a fallback (keep it for edge cases but not as the primary trigger)
- Implement a 300ms debounce using `useRef` + `setTimeout` pattern (no external debounce library)
- Ensure `pasteInfo` state is set by the debounced analysis, triggering the `ContentInfoPanel` render
- Cancel pending debounce on each new keystroke and on dialog close

### Out of Scope

- Schema Name inference logic (T-02)
- Changes to file upload mode
- Changes to `parseContentInfo` function itself
- Changes to the `ContentInfoPanel` visual rendering

- `ui/src/features/projects/components/SchemaUploadDialog.tsx`
- `ui/src/features/projects/components/__tests__/SchemaUploadDialog.test.tsx`

## Change Requirements

- In `SchemaUploadDialog`, add a `useRef<ReturnType<typeof setTimeout>>` for the debounce timer.
- In `handlePasteTextChange`, after existing logic, schedule `analyzePasteContent(text)` with a 300ms delay. Cancel any previously scheduled timeout first.
- Clear the debounce timer in the `useEffect` cleanup that resets state when `open` becomes `false`.
- `handlePasteBlur` should remain as a fallback (if the debounced analysis hasn't fired yet, blur triggers it immediately by clearing the timeout and calling `analyzePasteContent` synchronously).
- The existing immediate `title` extraction in `handlePasteTextChange` (lines 361-372) remains untouched — it provides the fast-path for Schema Name before the full analysis completes.

## Notes

- The existing `handlePasteTextChange` already clears `pasteInfo` on content change (line 356-358). The debounced analysis will re-set it after the delay. This creates a brief flash where the info panel disappears during typing — this is acceptable UX (consistent with debounce pattern).
