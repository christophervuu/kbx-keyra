## Summary

Implement the canonical schema-family lifecycle state machine in persistence/services, including single active draft, draft revisions with no-change behavior, immutable versions with monotonic numbering, and UUID-backed version identity.

---

## Scope

### In Scope

- Add schema family lifecycle entities/fields:
  - current draft,
  - draft revisions,
  - immutable versions,
  - `basedOnVersion`.
- Implement no-change draft-revision save semantics.
- Implement no-change version creation semantics.
- Implement version numbering invariants and failure atomicity.

### Out of Scope

- UI flows.
- Migration of legacy records.

---

## Relevant Areas

- `src/lib/persistence/types.ts`
- `src/lib/persistence/schema-metadata.ts`
- `src/lib/persistence/schema-nodes.ts`
- `src/lib/persistence/s3/schema-content.ts`
- schema-domain service modules under `src/lib/schema/*`

---

## Change Requirements

- Use UUID-backed `schemaVersionId` separate from deterministic `contentHash`.
- Enforce uniqueness on `(schemaId, version)`.
- Preserve clean draft state after successful version creation.

---

## Verification Requirements

- Unit tests for lifecycle transitions and no-change behavior.
- Integration tests for monotonic version allocation and failed-version non-consumption.

---

## Acceptance Checks

- One active draft per family is enforced.
- Save-draft no-change does not create revision.
- Create-version no-change returns `noChange` and allocates no new number.
- Failed/cancelled version operation does not consume visible version number.

---

## Blockers / Risks

- Transaction boundaries must be correct to avoid race-based version gaps.
