## Summary

Extend mapping backend contracts and services so mappings pin immutable schema versions across source/target/enrichment, impact extraction uses parsed DSL structures (not text search), and upgrade preview/apply flows remain explicit, guarded, and revision-based.

---

## Scope

### In Scope

- Mapping schema reference model update to include immutable identity bundle:
  - `schemaId`,
  - `schemaVersion`,
  - `schemaVersionId`,
  - `contentHash`.
- Role-aware impact computation by source/target/enrichment usage.
- AST/parsed mapping usage extraction for path/field references.
- Upgrade endpoints equivalent to:
  - `POST /mappings/:id/schema-upgrade/preview`
  - `POST /mappings/:id/schema-upgrade/apply`
- Preview invalidation semantics when base mapping/schema selection changes.
- Explicit suggestion acceptance + confirmation gates.
- Mapping revision creation semantics only on explicit save/apply.
- Archived-schema warning semantics for existing mappings.

### Out of Scope

- UI rendering and controls for upgrade flow.

## Change Requirements

- Prohibit auto-upgrade, auto-DSL rewrite, and auto-deploy behavior.
- Preserve execution/deployability of existing pinned mappings when updates are available.
- Keep deployment staleness semantics distinct from schema-update availability statuses.

---

## Verification Requirements

- Unit/integration tests for role-aware impact classification.
- Endpoint tests for upgrade preview/apply safety guards, preview invalidation, and revision behavior.
- Tests ensuring old revision immutability and explicit confirmation requirement.
- Tests proving impact extraction is parser-based and not vulnerable to string-literal false positives.

---

## Acceptance Checks

- Mapping refs persist explicit immutable schema version identity and hash.
- New schema versions do not auto-change existing mappings.
- Upgrade preview reports affected rules and breaking/non-breaking counts by role.
- Upgrade apply requires explicit action and yields new mapping revision only.
- Archived schemas are warned/blocked per FS-105 rules without mutating existing mapping refs.

---

## Blockers / Risks

- Complex edge cases around rename/move heuristics and stable identity alignment.
