## Summary

Implement `fieldId` sidecar identity storage using schema-version + JSON Pointer mapping, with deterministic lifecycle semantics across rename/move/duplicate/delete-readd/restore operations.

---

## Scope

### In Scope

- Add sidecar persistence model for node identity.
- Ensure IDs are not silently injected into user raw schema content.
- Implement identity transform behavior across supported edits.
- Expose identity mapping needed by diff/impact services.

### Out of Scope

- UI display changes.

---

## Relevant Areas

- `src/lib/persistence/types.ts`
- `src/lib/persistence/schema-nodes.ts`
- `src/lib/schema/*diff*`

---

## Change Requirements

- Use canonical JSON Pointer for structural mapping.
- Preserve ID on rename/move/type/required/description changes.
- Create new IDs for duplicate and delete/readd cases.

---

## Verification Requirements

- Unit tests for each identity lifecycle rule.
- Integration test for restore behavior preserving historical IDs.

---

## Acceptance Checks

- Identity sidecar exists per version and is queryable.
- Rename/move preserves `fieldId`; duplicate/delete-readd creates new IDs.
- Raw schema content remains free of implicit internal ID insertion unless explicitly configured.

---

## Blockers / Risks

- Incorrect identity propagation can corrupt diff/impact lineage.
