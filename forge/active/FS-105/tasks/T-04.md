## Summary

Implement `createSchemaVersion` request semantics with exact draft-revision capture, OCC, idempotency keys, and transactional monotonic allocation under concurrency.

---

## Scope

### In Scope

- Request contract support for:
  - `expectedDraftRevision`,
  - `idempotencyKey`,
  - optional `changeSummary`.
- Ensure version captures exact expected draft revision.
- Enforce single visible allocation under concurrent requests.
- Ensure retry with same idempotency key returns same result/job.

### Out of Scope

- UI form interactions.

---

## Relevant Areas

- `src/lambda/schema/*versions*`
- `src/lib/schema/*`
- `src/lib/persistence/*`

---

## Change Requirements

- Use conditional writes/transactions to prevent duplicate allocation.
- Prevent exposing partially committed versions.
- Preserve active newer draft revisions while older revision versioning job completes.

---

## Verification Requirements

- Concurrency integration tests with parallel version create calls.
- Idempotent retry tests including partial-failure retry paths.

---

## Acceptance Checks

- Concurrent version creation allocates at most one next version number.
- Same idempotency key does not create duplicates.
- Captured content exactly matches `expectedDraftRevision`.
- Partial failure does not expose incomplete selectable version.

---

## Blockers / Risks

- Race-condition risk is high without strict transaction design.
