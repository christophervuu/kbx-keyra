## Summary

Replace lossy reconstruction saves with a lossless AST/document edit engine that applies typed patch commands against JSON Pointer targets and blocks unsupported unsafe edits.

---

## Scope

### In Scope

- Patch-command model for guided edits.
- JSON Pointer target resolution and guarded edit checks.
- Lossless preservation guarantees for untouched/unsupported content.
- Unsupported-operation detection for restricted constructs.

### Out of Scope

- UI form/dialog changes.

---

## Relevant Areas

- `src/lib/schema/*`
- `src/lambda/schema/update-schema.ts`
- `ui/src/features/schemas/lib/tree-to-json-schema.ts` (deprecate high-risk full-save usage)
- tests in `tests/lib/schema/*` and `tests/lambda/schema/*`

---

## Change Requirements

- Preserve semantic equivalence of untouched unsupported subtrees.
- Allow reformatting but disallow lossy key/value drops.
- Enforce add-field validation before mutation application.

---

## Verification Requirements

- Unit tests for unsupported keyword preservation and unsafe-operation rejection.
- Regression tests for existing supported edits.

---

## Acceptance Checks

- Unrelated edits do not remove untouched unsupported content.
- Unsupported edits return deterministic unsupported-operation error.
- Add-field invalid input is blocked before persistence.

---

## Blockers / Risks

- If legacy full-rebuild path remains active, lossless guarantees can be violated.

---

## Notes

- Guided operations should be represented independently from display dot-paths.
