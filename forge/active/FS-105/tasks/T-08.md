## Summary

Update `ApiAdapter`, `HttpAdapter`, and `LocalStorageAdapter` to support FS-105 schema/version contracts, separated readiness statuses, sample update/default flows, and mapping upgrade endpoints while retiring user-schema publish/sync behavior from canonical paths.

---

## Scope

### In Scope

- Extend adapter contract types for:
  - draft/revision/version operations,
  - separated status surfaces (`versionStatus`, `indexStatus`, `impactStatus`, `sampleValidationStatus`),
  - diff/impact responses,
  - sample CRUD/default and fallback metadata,
  - mapping-upgrade preview/apply operations.
- Implement `HttpAdapter` route wiring for canonical endpoints.
- Implement `LocalStorageAdapter` semantic parity for core FS-105 behavior in local mode.
- Remove/deprecate user-schema publish/sync actions from active adapter usage paths.

### Out of Scope

- UI integration of new adapter methods.

## Change Requirements

- Add explicit sample update operation (no delete-recreate requirement).
- Ensure mapping schema refs include immutable version identifiers in returned models.
- Keep deprecated compatibility fields only for migration windows, not as active behavior drivers.

---

## Verification Requirements

- Adapter unit tests for new methods and parity assertions.
- Contract tests for status-separation semantics.
- Contract tests for removed/retired publish-surface behavior in user-schema contexts.

## Acceptance Checks

- Adapter interface includes FS-105 lifecycle, status, and upgrade operations.
- Http/local adapters pass parity tests for key schema lifecycle semantics.
- User-schema publish/sync actions are not required by canonical adapter workflows.
- Adapter consumers can distinguish indexing/impact failure from immutable version readiness.
