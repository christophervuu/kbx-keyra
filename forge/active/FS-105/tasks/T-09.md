## Summary

Redesign schema UI surfaces to support complete schema-family lifecycle: creation options, safe draft editing flows, version selector/history/actions, sample CRUD/default behavior with precedence rules, archive behavior, and removal of legacy publish/sync semantics for user schemas.

---

## Scope

### In Scope

- Schema Library enhancements:
  - creation options list,
  - schema card/list metadata expansions,
  - lifecycle-aware filters replacing legacy scope/published filters,
  - archive visibility behavior.
- Schema Detail enhancements:
  - version selector and draft indicator,
  - draft edit actions and safe add-field UX (no auto `newField` placeholders),
  - version actions (view/compare/restore/duplicate/download/deprecate/create),
  - sample CRUD/default controls and compatibility display,
  - sample fallback precedence messaging,
  - affected mappings access panel,
  - CDM read-only wording/actions.
- Remove/retire user-schema publish/sync UI actions and statuses.

### Out of Scope

- Backend endpoint creation.
- Migration execution.

---

---

## Change Requirements

- Guided add-field flow must collect required inputs and validate before insertion.
- Destructive action dialogs must summarize descendant removal + affected mapping counts.
- Immutable versions must never be directly editable.
- XSD structural edit-unavailable messaging must be explicit.

---

## Verification Requirements

- Component/hook tests for lifecycle controls and validation behavior.
- Interaction tests for version selector/actions and default sample deletion rules.
- Tests covering fallback precedence behavior in detail view.

---

## Acceptance Checks

- Schema Library shows new lifecycle metadata and filters without legacy scope/publish filters.
- Schema Detail supports draft/version/sample/archive lifecycle controls.
- Add-field dialog enforces validation before adding node.
- User-owned schema publish/sync actions are absent from canonical UI.
- Sample/default fallback messaging reflects FS-105 precedence rules.

---

## Blockers / Risks

- UI complexity can introduce regression in existing schema detail interactions.

---

## Notes

- Reuse existing schema component architecture; avoid introducing parallel editor surfaces.
