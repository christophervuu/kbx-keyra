## Summary

Create a `BreadcrumbContext` and `useBreadcrumbLabel` hook that allows page components to register human-readable labels for dynamic URL segments. Update the `Breadcrumbs` component to read from this context and display registered labels instead of raw route parameter values. Apply the pattern in `ProjectOverviewPage` so that the project name appears in the breadcrumb instead of the project UUID.

---

## Scope

- New `BreadcrumbContext` React Context + Provider in `ui/src/components/layout/`
- New `useBreadcrumbLabel(segmentValue: string, label: string | undefined)` hook

## Change Requirements

### BreadcrumbContext (`BreadcrumbContext.tsx`)

Create a React Context that stores a `Map<string, string>` mapping URL segment values to display labels:

- `BreadcrumbLabels` type: `Map<string, string>`
- `BreadcrumbContext` provides `{ labels: BreadcrumbLabels, setLabel: (segment: string, label: string) => void, removeLabel: (segment: string) => void }`
- `BreadcrumbProvider` component wraps children and manages the labels map state

### `useBreadcrumbLabel` Hook

- Signature: `useBreadcrumbLabel(segmentValue: string, label: string | undefined): void`
- On mount and when `label` changes: calls `setLabel(segmentValue, label)` if label is defined, or `setLabel(segmentValue, 'Loading...')` if label is undefined
- On unmount: calls `removeLabel(segmentValue)` to clean up
- Uses `useEffect` for lifecycle management
- When `segmentValue` is empty/falsy, the hook is a no-op

### `Breadcrumbs.tsx` Updates

- Import and read from `BreadcrumbContext`
- In the `formatSegment` function (or equivalent): check if `labels.has(segment)` and return `labels.get(segment)` if so, otherwise fall back to the existing behavior (raw segment value)
- No visual or structural changes to the breadcrumb component itself

### `AppLayout.tsx` Updates

- Wrap the `<Outlet />` (or the full layout content) in `<BreadcrumbProvider>`
- Ensure `Breadcrumbs` is rendered inside the provider so it can read from context

### `ProjectOverviewPage.tsx` Updates

- In the inner `ProjectOverviewPageInner` component (which has access to `projectId` and loaded project data):
  - Call `useBreadcrumbLabel(projectId, project?.name)` where `project` is the loaded project detail
  - When project is loading: `project` is undefined → hook registers "Loading..."
  - When project is loaded: hook registers the project name
  - When project fails to load or is not found: `project` is undefined → hook registers "Loading..." which then stays as the fallback (or could be enhanced to show raw ID — see notes)

### Fallback Behavior

- If the project fails to load (error/not-found state), the breadcrumb label for the project segment should fall back to the raw `projectId` rather than staying as "Loading..."
- This requires the page component to detect the error state and either:
  - Not call `useBreadcrumbLabel` (so no override is registered, and Breadcrumbs shows raw value)
  - Or call `useBreadcrumbLabel(projectId, projectId)` explicitly as a fallback

## Blockers / Risks

- Ensure `BreadcrumbProvider` placement does not cause unnecessary re-renders of the entire layout tree. The context value should be memoized or use a stable reference pattern. If the Map-based approach causes too many re-renders, consider using `useRef` + `forceUpdate` pattern or splitting the context into a stable setter context and a read-only labels context.
- **Q1 resolution guardrails**: keep the provider narrowly scoped (layout subtree only), keep the context value small and stable, expose focused setters rather than bundling breadcrumb state with broader layout state, and ensure route screens set their label in an effect and reset on unmount.

## Notes

- This task establishes infrastructure that other pages can adopt without further Breadcrumbs changes. For example, a future spec could add `useBreadcrumbLabel(mappingId, mapping?.name)` to the Mapping Editor page.
- The "Loading..." label is intentionally not localized in Phase 0.
- The hook's cleanup (`removeLabel`) on unmount prevents stale labels from persisting when navigating away from the page.
