## Summary

Enhance the mapping section to serve as the primary action surface on the Project Overview page. Update `MappingRow` with condensed deploy badges (single "Not deployed" when all environments are not-deployed), stronger status badge styling (filled backgrounds for ready/has-errors), and a Test Lab action link. Add a "recently edited mapping" affordance at the top of the `MappingListSection` that shows the most recently edited mapping in this project, derived from `keyra:recent-activity` localStorage data.

## Change Requirements

### MappingRow Deploy Badge Enhancement

Currently, `MappingRow` renders three separate `<td>` cells for DEV, QA, and PROD, each always showing "Not deployed". Change to:

- If all three deploy statuses (`devDeploy`, `qaDeploy`, `prodDeploy`) are `'not-deployed'`:
  - Render a single `<td>` spanning 3 columns (or equivalent) with a muted "Not deployed" label
- If any deploy status is different from `'not-deployed'`:
  - Render individual DEV/QA/PROD cells with their respective status badges:
    - `deployed` — green badge
    - `stale` — amber badge
    - `not-deployed` — muted gray badge
    - `deploying` — blue badge with optional spinner
- Deploy badges (and the condensed label) should be clickable and navigate to the mapping's deployment page (`/projects/:projectId/mappings/:mappingId/deploy`)

### MappingRow Status Badge Enhancement

Update the status badge rendering to use filled backgrounds:
- `ready` — green filled background, white/dark text
- `has-errors` — red filled background, white text
- `draft` — slate/gray filled background

### MappingRow Test Lab Action

Add a "Test" action to the row actions (alongside Edit, Deploy, Duplicate, Delete):
- Renders as a link to `/projects/:projectId/mappings/:mappingId/test-lab`
- Uses a test tube or beaker icon (e.g., `FlaskConical` from Lucide)
- Positioned near the Edit and Deploy actions

### Recently Edited Mapping Affordance

Add a `RecentlyEditedCard` (or inline element) at the top of the `MappingListSection`, above the table:

**Data Source:**
- Import `useRecentActivity` from `ui/src/features/home/hooks/use-recent-activity`
- Call `getRecentItems()` to get recent activity entries
- Filter for entries where `type === 'mapping'` and the mapping's `projectId` matches the current project
- Cross-reference with the current `mappings` array to verify the mapping still exists
- Take the first (most recent) match

**Rendering:**
- If a match is found: render a compact card showing:
  - "Continue where you left off" label (preferred copy — reflects user workflow, not data state; see Q2 resolution)
  - Mapping name
  - Relative timestamp (e.g., "2 hours ago")
  - "Resume" link navigating to the Mapping Editor (`/projects/:projectId/mappings/:mappingId`)
  - `data-testid="recently-edited-mapping"`
- If no match: render nothing (the card is hidden, not an empty state)

**Props/Integration:**
- `MappingListSection` receives `projectId` and `mappings` as existing props
- The recently-edited logic can be internal to `MappingListSection` or extracted to a small component

### Mapping Section Heading

Update the `MappingListSection` heading to use a slightly bolder/larger treatment than the schemas section heading to reinforce its primary status. This can be achieved through heading size (`text-xl` vs `text-lg`) or weight (`font-semibold` vs `font-medium`).

## Notes

- The condensed deploy badge pattern mirrors what was implemented in FS-049 for `ProjectCard`. Reuse the same logic pattern.
- The `MappingListSection` table header row will need column count adjustments if the deploy columns are conditionally rendered as 1 vs 3 cells. Use `colSpan={3}` for the condensed cell to maintain table alignment.
- `useRecentActivity` stores entries with `{ type, id, projectId?, name, timestamp }`. Filter by `type === 'mapping'` and compare `projectId` if available, or cross-reference against the mappings array by `id === mappingId`.
- The recently-edited affordance is similar to the Home Dashboard's "Continue Where You Left Off" (FS-049) but shows only one item and is scoped to a single project.
- Q2 resolution: use `useRecentActivity` because it reflects user workflow (what the user was editing) rather than `updatedAt` (what changed). Frame the label as "Continue where you left off" rather than "Recently edited" — the signal source is navigation behavior, not data modification timestamps.
