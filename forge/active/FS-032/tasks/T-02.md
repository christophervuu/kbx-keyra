## Summary

Extend the layout branching in `AppLayout.tsx` to recognize the Test Lab route as a focused workspace route alongside the Mapping Editor. When either route matches, breadcrumbs are suppressed and the content renders in the full-bleed `<main>` without padding or max-width constraints.

---

## Scope

### In Scope

- Add a second `useMatch()` call in `AppLayout.tsx` for the Test Lab route pattern (`/projects/:projectId/mappings/:mappingId/test-lab`)
- Introduce a combined boolean (e.g., `isFocusedWorkspace`) that is true when either the Mapping Editor or Test Lab route matches
- Replace `isMappingEditorRoute` with `isFocusedWorkspace` in the breadcrumb suppression and layout branching logic
- Update the comment explaining why breadcrumbs are suppressed to mention Test Lab alongside the Mapping Editor
- Verify that the `AdvancedTestingPage` / `TestLabPage` height calculation (`h-[calc(100vh-3.5rem)]`) still works correctly in the full-bleed layout

### Out of Scope

- Changes to any other routes or pages
- Changes to `Breadcrumbs.tsx` or `NavBar.tsx`
- Creating a generalized "workspace route registry" abstraction — keep it simple with explicit `useMatch()` calls

## Relevant Areas

- `ui/src/components/layout/AppLayout.tsx`
- `ui/src/features/mappings/components/AdvancedTestingPage.tsx` (or `TestLabPage.tsx` after T-03) — verify height calculation

## Change Requirements

After this task, `AppLayout.tsx` should look conceptually like:

```tsx
const isMappingEditorRoute = useMatch('/projects/:projectId/mappings/:mappingId') !== null;
const isTestLabRoute = useMatch('/projects/:projectId/mappings/:mappingId/test-lab') !== null;
const isFocusedWorkspace = isMappingEditorRoute || isTestLabRoute;
```

And the JSX uses `isFocusedWorkspace` where `isMappingEditorRoute` was previously used:

- `{!isFocusedWorkspace && <Breadcrumbs />}` — suppresses breadcrumbs on both routes
- `{isFocusedWorkspace ? <main className="flex-1">...</main> : <main className="flex-1 px-6 py-6">...</main>}` — full-bleed for both routes

The Mapping Editor must continue to behave identically (no regression from AE-04).
Regular pages must continue to show breadcrumbs and constrained layout (AE-05).

## Notes

- The `useMatch` pattern for the editor route is an exact match. The Test Lab route (with `/test-lab` suffix) does not conflict — `useMatch('/projects/:projectId/mappings/:mappingId')` will not match the test-lab path because of the extra segment.
- Keep the implementation simple: two explicit `useMatch()` calls combined with `||`. If more focused workspace routes emerge later, the pattern can be generalized at that point.
