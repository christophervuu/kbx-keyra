## Summary

Replace the native HTML `<select>` elements in `ValueEntryEditor` and `FilterPredicateEditor` with custom listbox dropdowns that render `SourceFieldOptionRow` for each option. Native selects cannot display rich content (badges, test data, scope) so conversion is required for visual consistency.

---

## Scope

### In Scope

- Convert the `<select>` element for source field selection in `ValueEntryEditor.tsx` to a custom dropdown (portalled, role="listbox") using the same pattern as ChainSourceCard/ItemFieldRow
- Convert the `<select>` element for right-operand source field in `FilterPredicateEditor.tsx` to a custom dropdown
- Both new custom dropdowns render options using `<SourceFieldOptionRow>`
- Wire PreviewContext for test data in both
- Implement keyboard navigation (arrow keys, Enter, Escape) consistent with other pickers
- Implement outside-click dismissal
- Implement search/filter within the dropdown (optional — include if the option count may be large)
- Preserve all existing form behavior: selected value still propagates to parent via existing callbacks
- Update component tests

### Out of Scope

- Other `<select>` elements in these components that are NOT source-field pickers (e.g., operator selects, type selects)
- Other picker components (handled in T-02, T-03, T-04)
- Changes to the component's data model or state management

## Change Requirements

### ValueEntryEditor.tsx

- Identify the `<select>` element that lists source fields for value entry selection
- Replace with a custom dropdown trigger button + portalled listbox pattern:
  - Trigger button shows currently selected value with `SourceFieldChipBadge` or inline badge + path
  - Portalled dropdown (z-50, positioned relative to trigger) with `role="listbox"`
  - Each option is `<div role="option" aria-selected={...}>` wrapping `<SourceFieldOptionRow />`
  - Search input at top of dropdown for filtering (if option count > ~10)
- Wire `PreviewContext` for test data
- Preserve: `onChange` callback fires with the selected path value, no change to parent interface

### FilterPredicateEditor.tsx

- Same pattern as ValueEntryEditor — identify source-field `<select>`, convert to custom listbox
- Preserve: right-operand selection behavior, callback interface

### Shared dropdown shell pattern

If both conversions share enough structure, extract a minimal shared dropdown shell (trigger + portalled listbox + outside-click + keyboard nav + search). This could be a local helper component or just duplicated structure — prefer extraction if >80% identical.

### Accessibility requirements

- `role="listbox"` on the option container
- `role="option"` on each option with `aria-selected`
- `aria-expanded` on the trigger button
- `aria-controls` linking trigger to listbox
- Keyboard: Arrow Up/Down to navigate, Enter to select, Escape to close
- Focus management: focus moves to listbox on open, returns to trigger on close

## Notes

This task has the highest implementation complexity per-component because it replaces native browser behavior with custom JavaScript. Use the existing portalled dropdown pattern from `ChainSourceCard` and `ItemFieldRow` as reference implementations. Consider using `createPortal` for the dropdown to avoid overflow/clipping issues in scrollable containers.
