## Summary

Integrate the shared `SourceFieldOptionRow` into the remaining custom source-field dropdowns: `ItemFieldRow`, `ConditionStepEditor`, `ArgumentSlotInput`, `ValueMapModeBuilder`, and `MergeBranchEditor`. These components have scope-aware source selection and must pass scope labels to the shared renderer.

---

- Modify `ItemFieldRow.tsx` source dropdown to render options using `SourceFieldOptionRow` with scope passed
- Modify `ConditionStepEditor.tsx` field pickers to use `SourceFieldOptionRow`
- Modify `ArgumentSlotInput.tsx` source field dropdown to use `SourceFieldOptionRow`
- Modify `ValueMapModeBuilder.tsx` source picker to use `SourceFieldOptionRow`
- Modify `MergeBranchEditor.tsx` branch source listbox to use `SourceFieldOptionRow`
- Wire PreviewContext sourceData in each component for test data resolution

- Update component tests for each modified component

## Change Requirements

### ItemFieldRow.tsx

- Currently renders dropdown options with `Database` icon + path + scope badge
- Replace with `<SourceFieldOptionRow>`, passing:
  - `path`: the field path
  - `type`: resolved from the source schema (may need to look up type from `flattenSchemaPaths` or existing `UnifiedSourceOption`)
  - `testValue`: resolved from sourceData (note: for item-scope fields, resolution path may need the array item context — see Notes)
  - `scope`: existing scope value (item/parent/source)
- Remove the inline `Database` icon import (if no longer used elsewhere in the component)
- Preserve existing `UnifiedSourceOption` model and `buildUnifiedSourceOptions` logic — just change rendering

### ConditionStepEditor.tsx

- Identify source-field picker(s) within condition operand editors
- Replace option rendering with `SourceFieldOptionRow`
- Wire PreviewContext for test data

### ArgumentSlotInput.tsx

- Identify the source-field dropdown mode
- Replace option rendering with `SourceFieldOptionRow`
- Wire PreviewContext for test data

### ValueMapModeBuilder.tsx

- Identify source picker (likely the "source" selection at the top)
- Replace option rendering with `SourceFieldOptionRow`
- Wire PreviewContext for test data

### MergeBranchEditor.tsx

- Identify branch source listbox
- Replace option rendering with `SourceFieldOptionRow`
- Wire PreviewContext for test data

### Type resolution for options

- Where options currently lack type information, look up types from `SchemaPathEntry[]` (via `flattenSchemaPaths(parsedSourceSchema)`)
- For item-scope fields where the full schema isn't directly available, derive type from item schema or pass `'any'` as fallback

## Blockers / Risks

- `ItemFieldRow` test data resolution for item-scope fields may require resolving into the array item context (e.g., `sourceData.orders[0].name` for an item-scope field `name`) — the resolution strategy must be clarified during implementation
- Some components (`ConditionStepEditor`, `ArgumentSlotInput`) may have multiple dropdown surfaces — all source-field-related ones must be converted

## Notes

This is the largest integration task by surface count. Approach methodically: start with `ItemFieldRow` (most complex, has scope), then move to the simpler pickers. If any component's test data resolution requires array-item-context awareness, document the approach and ensure `resolveFieldTestValue` supports it (or pass a pre-resolved sourceData sub-object).
