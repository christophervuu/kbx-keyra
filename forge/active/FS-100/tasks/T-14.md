## Summary

Provision/align runtime infrastructure and IAM with logical role boundaries: runtime read/execute role, deployment-writer role, and preview-invoke role, preserving environment isolation for DEV/PREPROD/PROD and closing SANDBOX runtime gaps where required.

---

## Scope

### In Scope

- Ensure logical stores exist and are parameterized: `ActiveSnapshots`, `DeploymentRecords`, `SnapshotArtifacts`, `SchemaArtifacts`.
- Implement explicit least-privilege roles:
  - `KeyRaRuntimeRole`
  - `KeyRaDeploymentWriterRole`
  - `KeyRaRuntimeInvokeRole`
- Enforce role boundaries per environment (including single-account deployments).
- Implement missing SANDBOX runtime resources if required by SANDBOX-first execution slice.
- Maintain physical names as parameters/outputs.

### Out of Scope

- Deployment page UI behavior.
- Mapping migration logic.

---

## Relevant Areas

- `template.yaml`
- environment/runtime config modules under `src/lambda/deployment/*`
- IAM/trust policy definitions in IaC

---

## Change Requirements

- Runtime role cannot write deployment records or active pointers.
- Deployment-writer role can write artifacts/records and conditionally update pointers; cannot modify runtime code or unrelated resources.
- Preview invoke role can invoke runtime Lambda only.
- No hard dependency on separate AWS accounts; works in single-account with role/resource isolation.

---

## Verification Requirements

- IaC validation and policy assertions.
- Permission smoke tests for allowed/denied actions per role.
- Runtime health/storage reachability checks by environment.

---

## Acceptance Checks

- DEV/PREPROD/PROD runtime resources and isolation are validated.
- SANDBOX runtime gap is either implemented or explicitly marked non-applicable with justification aligned to SANDBOX execution slice.
- Role permissions match trust model and least-privilege boundaries.

---

## Blockers / Risks

- Existing template may need substantial IAM refactor to separate currently implicit role scopes.

---

## Notes

- Keep logical resource naming canonical and physical naming parameterized.
