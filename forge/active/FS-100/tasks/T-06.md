## Summary

Extend deploy subsystem to support sequential promotions and environment-scoped rollback while preserving exact snapshot identity/hash and enforcing canonical path rules.

---

## Scope

### In Scope

- Promote route/path validation (SANDBOX→DEV→PREPROD→PROD).
- Target runtime compatibility checks + artifact integrity verification.
- Rollback route validation for previously deployed snapshots in same environment.
- Idempotency handling for promote and rollback operations.

### Out of Scope

- UI card layout and confirmation modals.
- Step Function fixture authoring.

---

## Relevant Areas

- `src/lambda/deployment/{promote-deployment.ts,rollback-deployment.ts}`
- `src/lambda/deployment/{runtime-deploy.ts,runtime-rollback.ts,runtime-relay.ts}`
- `src/lib/persistence/deployments.ts`
- orchestration status persistence modules

---

## Change Requirements

- Promotions must reuse source active snapshot identity (ID/hash).
- Invalid promotion paths are rejected deterministically.
- Rollback must not create new snapshots or delete newer ones.
- Active pointer updates must be atomic and conditional.

---

## Verification Requirements

- Integration tests for valid/invalid promotion paths.
- Tests proving promotion does not read latest editor state.
- Rollback tests for pointer behavior and non-deletion invariants.

---

## Acceptance Checks

- Promotion preserves artifact identity/hash across environments.
- Invalid promotion paths fail with stable error codes.
- Rollback activates prior snapshot and keeps later snapshots intact.
- Idempotency key replay is deterministic for promote/rollback.

---

## Blockers / Risks

- Cross-environment config mismatch may produce false-negative compatibility checks.

---

## Notes

- Maintain sequential promotion policy with no environment skipping.
