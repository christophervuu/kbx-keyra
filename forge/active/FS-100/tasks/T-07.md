## Summary

Update preview architecture so control-plane preview Lambda directly invokes environment-specific runtime Lambda via preview invoke role, matching Step Function runtime path decisions.

---

## Scope

### In Scope

- Preview handler invocation transport change from runtime HTTP API client to direct Lambda invoke.
- Environment-to-runtime Lambda resolution and role usage.
- Preview response mapping to canonical runtime metadata envelope.

### Out of Scope

- Browser direct runtime invocation.
- Deployment page rendering.

---

## Relevant Areas

- `src/lambda/mapping/preview-mapping.ts`
- runtime invocation utilities/config under `src/lambda/deployment/*`
- infra role wiring in `template.yaml` or related IaC

---

## Change Requirements

- Browser path remains `Browser -> control-plane API Gateway -> preview Lambda`.
- Preview Lambda directly invokes selected environment runtime Lambda.
- Preview invocation role grants invoke-only permissions (no artifact write permissions).
- Reject environments with no active deployment.

---

## Verification Requirements

- Handler tests validating direct invoke payload/response behavior.
- IAM/permission tests (or policy assertions) for invoke-only role scope.
- Failure tests for no deployment/runtime errors.

---

## Acceptance Checks

- Preview no longer depends on `/internal/preview` HTTP runtime route.
- Preview call executes runtime Lambda directly and returns canonical metadata.
- Preview role is least-privilege invoke-only.

---

## Blockers / Risks

- Runtime function ARN discovery and cross-environment role setup may require infra coordination.

---

## Notes

- Keep diagnostics and request-id traceability aligned with deployment operations.
