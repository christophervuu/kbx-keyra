## Summary

Replace the current deployment page with a SANDBOX→DEV→PREPROD→PROD pipeline view driven by aggregate deploy-context data and canonical deploy/promote/rollback action semantics, with normalized technical error presentation.

---

## Scope

### In Scope

- Four environment cards in canonical order.
- Candidate panel, change summary, readiness checks, primary action switching by selected environment.
- Combined history table with filters.
- Confirmation dialogs with artifact-focused summaries.
- UI handling of normalized backend errors (request id + expandable technical details).

### Out of Scope

- Backend route implementation.
- Runtime execution logic.

---

## Relevant Areas

- `ui/src/features/deployments/components/*`
- `ui/src/features/deployments/hooks/use-deployment-page.ts`
- `ui/src/routes/pages/MappingDeployment.tsx`
- related deployment tests in `ui/src/features/deployments/components/*.test.tsx`

---

## Change Requirements

- Remove user-facing revision-vs-version duality in primary deployment workflow where not required.
- SANDBOX card primary action: deploy saved version.
- DEV/PREPROD/PROD card primary action: promote from preceding env.
- Rollback presented as secondary action when history allows.
- Use deploy-context as primary load contract once T-10 backend contract is available.

---

## Verification Requirements

- Component/hook tests for ordering, action labels, readiness gating, history rendering.
- Error state test with technical-details expansion and request-id display.

---

## Acceptance Checks

- Four environment cards render in canonical order.
- Primary action text/behavior changes correctly by selected environment.
- Readiness blockers disable invalid actions and show actionable messages.
- History includes deploy/promote/rollback with expected metadata.
- UI consumes normalized backend errors rather than generic network-only errors.

## Blockers / Risks
