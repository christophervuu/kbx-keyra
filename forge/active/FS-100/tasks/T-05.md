## Summary

Define and apply SANDBOX infrastructure/runtime configuration needed for deployable snapshots, active pointers, runtime invocation, and baseline telemetry for the first end-to-end slice.

---

## Scope

### In Scope

- SANDBOX runtime Lambda wiring/config.
- SANDBOX artifact storage and active snapshot persistence resources.
- IAM permissions for control-plane deployment operations and runtime invocation.
- Required environment variables and log/metric baseline.

### Out of Scope

- DEV/PREPROD/PROD promotion rollout.
- Full runtime health dashboarding.

---

## Relevant Areas

- `template.yaml`
- runtime/deployment environment config modules
- IAM policy sections in infra templates

---

## Change Requirements

- SANDBOX resources must support immutable artifact writes + active pointer reads/writes.
- Runtime invocation path for Step Functions integration must be configured.
- Least-privilege IAM for deploy vs execute operations.

---

## Verification Requirements

- Infra synth/validate checks.
- Integration test invoking SANDBOX runtime with deployed snapshot.
- Permission tests for expected allow/deny boundaries where practical.

---

## Acceptance Checks

- SANDBOX deploy path has required tables/buckets/roles/functions configured.
- Runtime can be invoked and resolve active snapshot in SANDBOX.
- No broad wildcard cross-environment permissions added beyond required scope.

---

## Blockers / Risks

- Drift between template defaults and deployed environment variables.
