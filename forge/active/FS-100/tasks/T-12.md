## Summary

Create a deterministic acceptance fixture that executes the full lifecycle: migrate existing mapping, deploy SANDBOX, execute runtime, deploy changed version, rollback, promote to DEV, and verify identical snapshot identity/output after promotion.

---

## Scope

### In Scope

- Fixture mapping + payload + expected output artifacts.
- Automated orchestration test path using runtime invocation equivalent to Step Functions flow.
- Assertions for snapshot IDs/hashes and output transitions across deploy/rollback/promotion steps.

### Out of Scope

- Full business workflow design beyond runtime invocation fixture.
- Generalized test-lab UI scenarios.

---

## Relevant Areas

- `tests/e2e/**/*`
- runtime/deployment integration test harness
- fixture data under tests/fixtures (or equivalent)

---

## Change Requirements

- Fixture must include at least two mapping versions with deterministic output delta.
- Rollback must demonstrate restoration of previous output.
- DEV promotion must prove identity/output parity with SANDBOX promoted snapshot.

---

## Verification Requirements

- End-to-end test run in CI/local harness.
- Deterministic assertions with no wall-clock fragile checks.

---

## Acceptance Checks

- Full acceptance scenario steps 1–11 execute and pass in one deterministic test flow.
- Snapshot identity parity asserted between SANDBOX and DEV after promotion.
- Output assertions match expected payloads before/after update and after rollback.

---

## Blockers / Risks
