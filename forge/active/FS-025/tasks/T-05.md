## Change Requirements

**Two-Tier Save Model section updates:**

Replace (or update) the statement about post-Apply focus advance:
- Remove: "After applying, focus advances to the next unmapped field in the worklist (normal Apply behavior)."
- Add: "After applying, the builder remains on the current field in a committed state (Apply button disabled, 'Applied' indicator shown). The user manually navigates to the next field via the 'Next unmapped' button or `Ctrl+]` shortcut."

**Expression Builder Architecture section additions:**

Add a new subsection or extend existing content to cover:

1. **State Hydration on Target Selection:**
   - When `selectedTargetPath` changes, the composition layer looks up the matching rule.
   - If a rule exists, its expression is passed to `decomposeExpression()`.
   - On decomposition success: builder state is hydrated with the returned `ExpressionBuilderState`, mode auto-detected, Builder mode activated.
   - On decomposition failure: raw expression loaded into Editor mode, "Complex expression -- edit in Editor mode" warning shown.
   - If no rule exists: builder resets to default empty state (Value mode).

2. **Builder Reset on Navigation:**
   - Builder fully resets when the user navigates to a different target field.
   - Navigation guard (FS-021 AE-05) fires before reset when unapplied changes exist.
   - Recommended pattern: key `UnifiedExpressionBuilder` on `selectedTargetPath` for guaranteed state isolation.

3. **Conditional Branch Expressions:**
   - `BranchValue` discriminated union extended with `{ type: 'expression'; state: ValueModeState }`.
   - `ConditionOperand` extended with `{ type: 'expression'; state: ValueModeState }`.
   - Inline mini-builder is Value mode only (Source + Transforms); no nested conditionals/value-maps within branches.
   - Expression generation calls `generateValueExpression(state)` for expression-type branches and operands.
   - Decomposer attempts per-branch decomposition for complex branch sub-expressions.

**Hook contract update for `useExpressionBuilder`:**

Add or update:
- `loadExpression(expression: string | null): void` — triggers decomposition and state hydration (or reset for null/empty).
- Note that this is called automatically on target selection change.
- Note the relationship between `loadExpression` and the Builder/Editor mode toggle decomposition (they share the same decomposer but are triggered differently).
