## Summary

Update shared domain and API adapter contracts so Smart Fix is rule-level, validation-aware, and compatible with canonical backend endpoint behavior.

---

## Scope

### In Scope

- Update Smart Fix input/output types in UI/shared type surfaces.
- Align `ApiAdapter` and `HttpAdapter` Smart Fix method contract with backend endpoint.
- Ensure transport/error normalization behavior remains canonical.
- Add adapter tests for request payload and response mapping for valid/invalid suggestions.

### Out of Scope

- Backend handler implementation details.
- Mapping Editor UI interaction changes.
- Unrelated AI method contract changes.

## Change Requirements

- `SmartFixInput` carries rule-level context and diagnostics scope semantics (default all diagnostics on selected rule; optional single-diagnostic scope), plus `ruleVersion`/`ruleHash` snapshot fields for stale checks.
- `SmartFixResult` carries original expression, suggested expression, explanation, validation status/diagnostics, and stale-check metadata needed for apply gating/re-run behavior.
- `HttpAdapter.smartFix(...)` serializes/deserializes canonical request/response payload.
- Adapter error handling remains consistent with existing HTTP client semantics.

---

## Verification Requirements

- Unit tests for request serialization to `/ai/smart-fix` contract shape.
- Unit tests for response mapping across valid-suggestion, invalid-suggestion (no apply-anyway semantics), stale-mismatch, and error cases.
- Typecheck for touched type/adapter files.

---

## Acceptance Checks

- Adapter/domain contracts compile and match backend Smart Fix semantics.
- Smart Fix adapter no longer represents only bulk `updatedRules` output.
- Tests for Smart Fix payload/response mapping pass.
