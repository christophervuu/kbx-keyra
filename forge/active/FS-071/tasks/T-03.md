## Summary

Add/update Smart Fix frontend orchestration so rule diagnostics can trigger suggestion requests and UI state can represent loading, valid suggestion, invalid suggestion, and failure outcomes without mutating rule state.

---

## Scope

### In Scope

- Implement or update Smart Fix hook for diagnostic-driven invocation.
- Represent Smart Fix lifecycle states (idle/loading/success-invalid/success-valid/stale-mismatch/error).
- Preserve deterministic retry/dismiss/reset behavior.
- Ensure failed or dismissed Smart Fix flows do not mutate rule expression.
- Add/update hook tests covering state transitions and non-mutation guarantees.

### Out of Scope

- Final component-level interaction polish (buttons/layout copy).
- Backend contract implementation.
- Broader Mapping Editor refactors unrelated to Smart Fix.

## Change Requirements

- Hook accepts rule/diagnostic context (default all diagnostics with optional single-diagnostic scope) and calls adapter Smart Fix method with updated contract.
- Hook exposes enough state for UI to gate acceptance when suggestion validation is invalid and to block apply on stale hash/version mismatch.
- Hook distinguishes transport/runtime error from validation-invalid suggestion result.
- Hook preserves existing abort/reset behavior conventions used by nearby AI hooks.

---

## Verification Requirements

- Hook tests for successful valid suggestion path.
- Hook tests for validation-invalid suggestion path.
- Hook tests for request failure/retry path and stale-mismatch rerun-on-latest path.
- Tests/assertions confirming no rule mutation on dismiss/failure.
- Typecheck/test for touched hook files.

---

## Acceptance Checks

- Diagnostic context can trigger Smart Fix request through hook API.
- Hook state model supports invalid suggestion outcomes distinctly from transport errors.
- Dismiss/failure behavior preserves existing rule expression state.

---

## Blockers / Risks

- Existing mapping editor state orchestration may require careful integration to avoid duplicate AI state sources.

---

## Notes

- Keep state transitions explicit; do not overload generic error state for validation-invalid outcomes.
