## Objective

Write end-to-end tests covering the primary happy-path user journeys: project CRUD, schema upload, mapping creation, and basic editor interactions.

## Context

Happy-path tests exercise the most critical user workflows from start to finish. In KeyRa, the core journey is: create a project -> upload schemas -> create a mapping -> map fields. These tests provide confidence that the integrated system works for the most common use cases.

## Requirements

### Project CRUD (`tests/e2e/specs/project-crud.spec.ts`)
- Create a new project via the form
- Verify it appears in the project list
- Navigate to the project detail
- Edit the project name/description
- Verify changes persist after page reload
- Delete the project and verify it's removed from the list

### Schema Upload (`tests/e2e/specs/schema-upload.spec.ts`)
- Upload a JSON Schema file via the schema library
- Verify the schema appears in the list with correct name
- Navigate to schema detail and verify the tree renders
- Expand nested nodes and verify children appear
- Verify schema type indicators display correctly (string, number, object, array)

### Mapping Creation (`tests/e2e/specs/mapping-creation.spec.ts`)
- Seed a project with source and target schemas
- Create a new mapping within the project
- Assign source and target schemas
- Verify the mapping editor loads with both schema trees
- Verify panel slots render correctly

### Mapping Editor (`tests/e2e/specs/mapping-editor.spec.ts`)
- Seed a complete scenario (project + schemas + empty mapping)
- Select a source field in the source tree
- Select a target field in the target tree
- Verify a mapping row appears connecting the two fields
- Create multiple mapping rows
- Delete a mapping row and verify it's removed
- Verify mappings persist after page reload

### Data Persistence (`tests/e2e/specs/persistence.spec.ts`)
- Create entities through the UI (not seeded)
- Reload the page
- Verify all created entities still exist
- Verify entity details are intact after reload

## Acceptance Criteria

- [ ] 5 spec files exist covering project, schema, mapping, editor, and persistence
- [ ] Project CRUD test creates, reads, updates, and deletes a project
- [ ] Schema test uploads a file and verifies tree rendering
- [ ] Mapping test creates a mapping and verifies editor loads
- [ ] Editor test creates and deletes field mappings
- [ ] Persistence test verifies localStorage survival across page reloads
- [ ] All tests are independent — each seeds its own data
- [ ] All tests pass consistently (no flakiness)

## Notes

- Use `test.describe.serial()` only if steps within a single user journey must be ordered; prefer independent tests
- For file upload, use Playwright's `page.setInputFiles()` with a fixture JSON Schema file
- Store fixture `.json` schema files in `tests/e2e/fixtures/schemas/` for upload tests
- The mapping editor test is the most complex — start with a single mapping row before testing multiple
- Page reload tests: use `page.reload()` and wait for the app to re-render before asserting
- If the UI uses optimistic updates, wait for localStorage to be written before reloading
