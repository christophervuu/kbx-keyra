## Objective

Create the `forge/architecture/e2e-testing.md` document and register it in `INDEX.md` to establish long-term patterns for E2E test infrastructure.

## Context

E2E testing is a new subsystem in the project. An architecture document ensures consistent patterns as the test suite grows, especially when multiple contributors write tests. It codifies decisions about directory structure, page object conventions, fixture management, and test isolation.

## Requirements

### Create `forge/architecture/e2e-testing.md`
Document should cover:
- **Overview**: Purpose and scope of E2E tests in the project
- **Directory Structure**: Layout of `tests/e2e/` and where different artifacts live
- **Patterns**:
  - Page Object Model convention (classes, selectors, no assertions)
  - Extended test fixtures (custom `test` export)
  - Storage helpers for localStorage-based Phase 0 architecture
  - Test data factories and the ScenarioBuilder pattern
  - Test isolation strategy (seed → execute → teardown)
- **Selector Strategy**: `data-testid` as primary, `getByRole` as secondary, never CSS classes
- **Performance Budget**: < 60 seconds for full suite, < 10 seconds per individual test
- **Fixture Files**: Dedicated `.json` schema fixtures (small, human-readable, reusable)
- **CI Considerations**: Placeholder section noting CI is deferred to a follow-up spec; document intended approach (Chromium-only, headless, retry policy, artifact collection)
- **Phase Evolution**: How tests will adapt when Phase 1 introduces a real backend (mock server vs real backend, network interception)
