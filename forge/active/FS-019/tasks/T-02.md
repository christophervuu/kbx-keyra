## Objective

Create the shared test fixtures, storage helpers, and test data factories that all E2E tests will use.

## Context

KeyRa Phase 0 stores all data in localStorage under keys `keyra:projects`, `keyra:schemas`, and `keyra:mappings`. E2E tests need to seed and clear this data programmatically rather than navigating through the UI for setup. Test data factories ensure consistent, type-safe test objects.

## Requirements

### Storage Helpers (`tests/e2e/fixtures/storage.ts`)
- `seedStorage(page, data)` — seeds localStorage with provided projects, schemas, mappings
- `clearStorage(page)` — removes all `keyra:*` keys from localStorage
- `getStorageData(page)` — reads and returns current localStorage state for assertions
- All functions use `page.evaluate()` to interact with browser localStorage

### Test Data Factories (`tests/e2e/fixtures/test-data.ts`)
- `createTestProject(overrides?)` — returns a valid Project object with sensible defaults
- `createTestSchema(overrides?)` — returns a valid Schema object (include a small but realistic JSON Schema fixture)
- `createTestMapping(overrides?)` — returns a valid Mapping object linking source/target schemas
- All factories produce objects matching the engine's domain types

### JSON Schema Fixture Files (`tests/e2e/fixtures/schemas/`)
- `patient.schema.json` — flat-ish schema (~10 fields) for basic tests
- `order.schema.json` — moderately nested schema (~15 fields) for CRUD tests
- `address.schema.json` — deeply nested schema (3+ levels, objects + arrays) for tree interaction tests
- Keep all fixtures small (10-15 fields max) — enough for tree, search, and validation without being unwieldy
- These are real `.json` files, human-readable and reviewable, serving as documentation of "typical schemas"
- Reusable across multiple tests without copy-paste

### Invalid Fixture Files (`tests/e2e/fixtures/invalid/`)
- `not-json.txt` — plain text file for upload error tests
- `invalid-schema.json` — valid JSON but not a valid JSON Schema

### Extended Test Base (`tests/e2e/fixtures/base.ts`)
- Export `test` extended from `@playwright/test` with custom fixtures:
  - `storageHelper` — provides seed/clear functions bound to the current page
  - `testData` — provides factory functions
- Export `expect` re-exported from `@playwright/test`
- Each test automatically clears storage in fixture teardown

## Acceptance Criteria

- [ ] `tests/e2e/fixtures/storage.ts` exports `seedStorage`, `clearStorage`, `getStorageData`
- [ ] `tests/e2e/fixtures/test-data.ts` exports factories for projects, schemas, and mappings
- [ ] `tests/e2e/fixtures/base.ts` exports extended `test` and `expect`
- [ ] `tests/e2e/fixtures/schemas/` contains at least 3 `.json` schema fixture files (10-15 fields each)
- [ ] `tests/e2e/fixtures/schemas/address.schema.json` has 3+ levels of nesting
- [ ] `tests/e2e/fixtures/invalid/` contains `not-json.txt` and `invalid-schema.json`
- [ ] Factories produce objects that match engine type definitions
- [ ] Storage helpers correctly read/write localStorage via `page.evaluate()`
- [ ] Fixture teardown clears storage so tests don't leak state

## Notes

- Import types from `@keyra/engine` for factory type safety — the workspace link makes this available
- Use UUIDs (or deterministic IDs like `test-project-1`) for test object IDs
- JSON fixture files are the source of truth for "what a schema looks like" — don't generate in-memory (couples tests to implementation)
- Keep factory defaults minimal but valid — tests override only what they need
- Consider a `ScenarioBuilder` pattern if multi-entity setup becomes common:
  ```typescript
  const scenario = new ScenarioBuilder()
    .withProject()
    .withSchema('source')
    .withSchema('target')
    .withMapping()
    .build();
  ```
