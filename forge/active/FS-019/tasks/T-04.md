## Objective

Write smoke tests that verify all routes load without errors and basic navigation works.

## Context

Smoke tests are the first line of defense — they catch catastrophic failures like broken imports, routing errors, or render crashes without testing specific features. They run fast and provide immediate feedback on app health.

## Requirements

### Route Loading (`tests/e2e/specs/smoke.spec.ts`)
- Test that each route renders without console errors:
  - `/` (home/project list)
  - `/projects/new` (project creation form)
  - `/schemas` (schema library)
  - `/settings` (settings page)
- For routes requiring IDs (`/projects/:id`, `/projects/:id/mappings/:id`, `/schemas/:id`):
  - Seed a project, schema, and mapping, then verify the routes load

### Navigation
- Test that clicking each nav link navigates to the correct route
- Test browser back/forward buttons work correctly
- Test that navigating to a non-existent route shows a 404 or redirects gracefully

### App Shell
- Verify the app shell (header, navigation, main content area) renders on every route
- Verify no uncaught JavaScript errors on any route

## Acceptance Criteria

- [ ] `tests/e2e/specs/smoke.spec.ts` exists and passes
- [ ] All defined routes are tested for successful rendering
- [ ] Navigation between routes works via UI clicks
- [ ] No console errors are thrown on any route
- [ ] Tests complete in < 10 seconds total
- [ ] Tests use the extended `test` from `fixtures/base.ts`

## Notes

- Use `test.describe('Smoke Tests', () => { ... })` to group
- Seed data once in a `test.beforeAll` or per-test — keep it lightweight
- Console error checking can use Playwright's `page.on('pageerror')` event
- Consider a helper that iterates over a route list to reduce boilerplate
- If a route redirects (e.g., `/` might redirect to `/projects`), test the final destination
- These tests should be the fastest in the suite — no complex interactions
