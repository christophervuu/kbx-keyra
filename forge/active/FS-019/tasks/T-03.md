## Objective

Create page object models that encapsulate UI selectors and interactions for each primary route, making tests readable and maintainable.

## Context

Page objects abstract away DOM selectors and interaction sequences so that when the UI changes, only the page object needs updating — not every test. KeyRa uses `data-testid` attributes throughout its components, providing stable selectors.

## Requirements

### Base Page Object (`tests/e2e/pages/app.page.ts`)
- `goto(path)` — navigate to a route
- `waitForReady()` — wait until the app shell is rendered
- `nav` — accessor for navigation elements
- `navigateTo(routeName)` — click nav links to navigate
- `getCurrentPath()` — return current URL path
- `expectNoConsoleErrors()` — assert no uncaught errors in console

### Project Pages
**`tests/e2e/pages/project-list.page.ts`**
- `goto()` — navigate to projects list
- `getProjectCards()` — return all project card locators
- `getProjectByName(name)` — find specific project
- `clickCreateProject()` — click the create button
- `deleteProject(name)` — delete a project via its actions menu

**`tests/e2e/pages/project-form.page.ts`**
- `goto(mode: 'create' | 'edit', projectId?)` — navigate to form
- `fillName(name)` — fill project name
- `fillDescription(desc)` — fill description
- `submit()` — click submit button
- `getValidationError(field)` — get error message for a field
- `expectFormReset()` — verify form is in empty state

### Schema Pages
**`tests/e2e/pages/schema-list.page.ts`**
- `goto()` — navigate to schemas
- `getSchemaCards()` — return all schema card locators
- `uploadSchema(filePath)` — trigger file upload
- `getSchemaByName(name)` — find specific schema

**`tests/e2e/pages/schema-detail.page.ts`**
- `goto(schemaId)` — navigate to schema detail
- `getTreeNodes()` — return all visible tree nodes
- `expandNode(path)` — expand a tree node
- `collapseNode(path)` — collapse a tree node
- `getNodeType(path)` — return the type indicator for a node
- `searchTree(query)` — use tree search if available

### Mapping Editor Page
**`tests/e2e/pages/mapping-editor.page.ts`**
- `goto(projectId, mappingId)` — navigate to editor
- `panel(slot: number)` — get panel by slot number
- `getSourceTree()` — return source schema tree locator
- `getTargetTree()` — return target schema tree locator
- `selectSourceNode(path)` — click a source tree node
- `selectTargetNode(path)` — click a target tree node
- `getMappingRows()` — return all mapping row locators
- `getMappingRow(sourcePath, targetPath)` — find specific mapping
- `deleteMappingRow(index)` — delete a mapping row

## Acceptance Criteria

- [ ] 6 page object files exist in `tests/e2e/pages/`
- [ ] All page objects use `data-testid` selectors (not CSS classes or tag names)
- [ ] Page objects are TypeScript classes with proper typing
- [ ] Each page object has a `goto()` method for direct navigation
- [ ] MappingEditorPage supports panel slot selection via `data-testid`
- [ ] No assertions in page objects — they return locators/values, tests assert

## Notes

- Follow the convention: page objects return Playwright `Locator` objects, not resolved values
- Use `page.getByTestId()` as the primary selector strategy
- For text-based finding, use `page.getByRole()` or `page.getByText()` as fallback
- Keep page objects focused — if a page object gets too large, split into component objects
- Consider a `SchemaTreeComponent` shared between schema detail and mapping editor pages
- Methods that trigger navigation should await the navigation to settle
