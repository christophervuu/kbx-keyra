## Summary

Transform TraceDisplay from a display-only collapsible list into an interactive component that supports clicking trace entries to fire linked selection, receiving highlight state from external selection, filtering by result status (success/failure), and searching by target path. The trace step matching the current linked selection should auto-scroll into view.

---

## Scope

### In Scope

- Add `onSelect` callback prop to TraceDisplay for firing `DebugSelection` on trace entry click
- Add `selectedRuleIndex` and `selectedTargetPath` props for receiving external highlight state
- Add visual highlight styling on trace rows matching the current linked selection
- Auto-scroll the highlighted trace entry into view when selection comes from an external panel
- Add status filter chips: **Failed** (has per-step diagnostics) | **Success** (no per-step diagnostics)
- Add search input for filtering by `targetPath` (case-insensitive, debounced 200ms)
- Add count display: `{N} of {M} trace steps` when filters/search are active
- Update existing tests and add new tests

### Out of Scope

- Wiring to page-level orchestration (T-06)
- Changing the engine's `TraceEntry` type
- Adding new data to trace entries (e.g., source field info)

## Change Requirements

Extend `TraceDisplayProps`:

```typescript
interface TraceDisplayProps {
  trace: readonly TraceEntry[] | undefined;
  enabled: boolean;
  // New props:
  onSelect?: (selection: DebugSelection) => void;
  selectedRuleIndex?: number | null;
  selectedTargetPath?: string | null;
}
```

Each trace row adds a click handler:
- On click (on the row, not just the expand/collapse button): call `onSelect({ targetPath: entry.targetPath, ruleIndex: entry.ruleIndex, source: 'trace' })`
- Apply highlight class when `selectedRuleIndex === entry.ruleIndex` or `selectedTargetPath === entry.targetPath`
- When highlighted from an external source (selection.source !== 'trace'), scroll the row into view using `scrollIntoView({ behavior: 'smooth', block: 'nearest' })`

Filter UI:
- Two toggle chips above the list: **Failed** | **Success**
- Failed = entries where `entry.diagnostics && entry.diagnostics.length > 0`
- Success = entries where `!entry.diagnostics || entry.diagnostics.length === 0`
- Search input with debounce(200ms), placeholder "Filter by target path…"
- Count display: `{N} of {M} trace steps`

Preserve existing expand/collapse behavior on TraceEntryRow — click-to-select fires on the row container, expand/collapse fires on the detail toggle button (with `stopPropagation`).
