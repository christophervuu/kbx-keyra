## Summary

Enhance OutputDisplay to track JSON paths during rendering and highlight the key-value pair(s) matching a provided `highlightPath` prop. This enables the output panel to visually indicate which output field corresponds to the currently selected diagnostic, trace step, or diff entry.

---

## Scope

### In Scope

- Enhance the JSON rendering logic in OutputDisplay to track the current path during recursive rendering
- Add `highlightPath: string | null` prop
- When `highlightPath` is set, apply a highlight background style to the key-value token(s) at the matching path
- Handle the canonical dot-separated object path format used by existing result models (e.g., `Order.Header.DocumentType`)
- Array index path support (e.g., `Items[0].Name`) is deferred unless the current path format already provides it consistently and the renderer can support it without adding a separate path-resolution model
- Add `onClick` callback prop for clicking on a key in the rendered JSON to fire linked selection
- Scroll the highlighted node into view when `highlightPath` changes from an external source
- Unit tests for path tracking and highlight behavior

### Out of Scope

- Array index path support (e.g., `Items[0].Name`) — deferred unless the current path format already provides it consistently and the renderer can support it without adding a separate path-resolution model
- Modifying the JSON tokenizer for non-highlight-related changes
- Changing the color scheme of existing syntax highlighting

## Change Requirements

Extend `OutputDisplayProps`:

```typescript
interface OutputDisplayProps {
  state: PreviewExecutionState;
  // New props:
  highlightPath?: string | null;
  onPathClick?: (path: string) => void;
}
```

Rendering enhancement:
- The current OutputDisplay uses a simple JSON tokenizer to render syntax-highlighted output. Enhance the renderer to track the current path context as it renders each key-value pair in the JSON.
- Approach: modify the rendering to use a recursive component that receives the current path prefix. Each key rendered at a given nesting level produces a path `parent.key`.
- When the current path matches `highlightPath`, wrap the key-value pair (key token + colon + value tokens) in a `<span>` with a highlight background (e.g., `bg-blue-500/20 ring-1 ring-blue-500/40 rounded`).
- When `onPathClick` is provided, each key token becomes clickable. On click: `onPathClick(currentPath)`.

Auto-scroll:
- Use a `ref` on the highlighted element. When `highlightPath` changes, call `scrollIntoView({ behavior: 'smooth', block: 'nearest' })` on the ref.

Backward compatibility:
- When `highlightPath` is `null`/`undefined`, rendering is identical to current behavior (no highlight, no click handlers).

## Notes

Keep the highlight style distinct from syntax highlighting colors. Use a subtle background highlight (blue/cyan) that doesn't interfere with the existing token color scheme (green for strings, amber for numbers, etc.).
