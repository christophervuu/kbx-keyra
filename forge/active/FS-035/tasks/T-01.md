## Summary

Extend the diff type system and `computeDiff()` utility to produce fine-grained mismatch categories instead of the current coarse `added | removed | changed` classification. This enables downstream components to display why a field mismatched, not just that it did.

---

## Scope

### In Scope

- Extend `DiffChangeType` in `ui/src/lib/types/diff.ts` with new categories: `missing_field`, `extra_field`, `value_mismatch`, `type_mismatch`, `null_mismatch`, `structural_mismatch`
- Preserve backward compatibility: existing `added`, `removed`, `changed` values can be replaced by the new categories or kept as aliases — but all consumers must work with the new categories
- Update `DiffEntry` type if needed to carry additional context (e.g., `actualType`, `expectedType` for type mismatches)
- Update `computeDiff()` in `ui/src/lib/utils/json-diff.ts` to classify each diff entry into the correct new category
- Add comprehensive unit tests covering all six mismatch categories

### Out of Scope

- Changes to the engine or execution pipeline

## Change Requirements

### Type Changes

Replace or extend `DiffChangeType` to include the six categories:

```typescript
type DiffChangeType =
  | 'missing_field'      // path in expected, not in actual
  | 'extra_field'        // path in actual, not in expected
  | 'value_mismatch'     // same path, same JS type, different value
  | 'type_mismatch'      // same path, different JS types
  | 'null_mismatch'      // same path, one is null, other is not
  | 'structural_mismatch'; // same path, object/array vs primitive (or array vs object)
```

Extend `DiffEntry` to optionally carry type context for mismatches:

```typescript
interface DiffEntry {
  readonly path: string;
  readonly type: DiffChangeType;
  readonly actual?: unknown;
  readonly expected?: unknown;
  readonly actualType?: string;   // typeof actual value (for type/structural mismatches)
  readonly expectedType?: string; // typeof expected value
}
```

### Classification Logic in `computeDiff()`

When a path exists in both actual and expected but values differ, classify as:

1. If one side is `null` and the other is not → `null_mismatch`
2. If one side is an object/array and the other is a primitive (or array vs object) → `structural_mismatch`
3. If both are non-null but `typeof actual !== typeof expected` → `type_mismatch`
4. Otherwise → `value_mismatch`

When a path exists only in expected → `missing_field`
When a path exists only in actual → `extra_field`

Populate `actualType` and `expectedType` on entries where `type` is `type_mismatch`, `null_mismatch`, or `structural_mismatch`.

### DiffResult

`DiffResult.isEqual` semantics remain the same: `true` when `entries.length === 0`.

Add a convenience summary to `DiffResult`:

```typescript
interface DiffResult {
  readonly entries: readonly DiffEntry[];
  readonly isEqual: boolean;
  readonly summary: DiffSummary;
}

interface DiffSummary {
  readonly total: number;
  readonly byCategory: Record<DiffChangeType, number>;
}
```

## Verification Requirements

- Unit tests for each mismatch category:
  - `missing_field`: key in expected, not in actual
  - `extra_field`: key in actual, not in expected
  - `value_mismatch`: same key, same type, different value (string, number, boolean)
  - `type_mismatch`: same key, string vs number, number vs boolean, etc.
  - `null_mismatch`: null vs non-null in both directions
  - `structural_mismatch`: object vs string, array vs object, array vs primitive
- Unit test for nested object paths (e.g., `address.street` missing)
- Unit test for array element mismatches
- Unit test for `DiffSummary` aggregation
- Unit test for `isEqual === true` when objects match
- Unit test for mixed categories in a single diff result
- Typecheck passes (`tsc --noEmit`)
