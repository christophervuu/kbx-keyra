## Summary

Add a "Run All" batch execution capability to the Advanced Testing page that runs all saved test cases sequentially, collects results, and presents a suite-level summary. The suite summary shows total/passed/failed/errored counts and per-test result rows that can be clicked to view detailed results.

---

## Scope

### In Scope

- Create a `useBatchExecution` hook that orchestrates sequential test case execution
- Add "Run All" button to the Advanced Testing page (visible when 2+ test cases exist)
- Show execution progress indicator during batch run (e.g., "Running 3/7...")
- After batch completes, populate `testResults` map from T-05 with all results
- Create `SuiteSummary` component showing:
  - Header with total/passed/failed/errored counts
  - Per-test result rows with name, verdict icon, duration, diagnostics count
  - Clickable rows that load the test's results into the detail tabs
- Integrate suite summary into the Advanced Testing page layout
- Handle edge cases: empty source data (skip), execution errors (continue), timeouts (continue)

### Out of Scope

- Parallel execution (sequential only in Phase 0)
- Persisting batch results
- Test result export
- Changes to test case CRUD
- Cancel batch in progress (deferred — user can navigate away)

## Change Requirements

### `useBatchExecution` Hook

```typescript
interface BatchExecutionOptions {
  config: MappingConfig | null;
  sourceSchemaDetail: unknown | null;
  targetSchemaDetail: unknown | null;
}

interface BatchTestResult {
  readonly testCaseId: string;
  readonly testCaseName: string;
  readonly verdict: ExecutionVerdict;
  readonly durationMs?: number;
  readonly diagnosticCount: number;
  readonly diffResult?: DiffResult | null;
  readonly executionState: PreviewExecutionState;
}

interface UseBatchExecutionReturn {
  runAll: (testCases: readonly TestCase[]) => Promise<void>;
  isRunning: boolean;
  progress: { current: number; total: number } | null;
  results: readonly BatchTestResult[];
  reset: () => void;
}
```

Execution logic:
1. Iterate test cases sequentially
2. For each test case:
   - Skip if `sourceData` is empty/whitespace → record as skipped
   - Execute using the engine's `executeMapping()` from `ui/src/lib/engine/`
   - If test case has `expectedOutput`, compute diff
   - Derive verdict using `deriveExecutionVerdict()`
   - Record `BatchTestResult`
   - Update `progress`
3. If execution throws or times out for a test case, record as `error` and continue
4. After all tests complete, set `isRunning` to `false`

### "Run All" Button

- Location: in the top bar area of AdvancedTestingPage, next to the existing Run button
- Label: "Run All" with a play-all icon
- Disabled when: `isRunning`, no test cases saved, or fewer than 1 test case
- When clicked: calls `batchExecution.runAll(testCases)`

### Progress Indicator

While `isRunning`:
- Show a progress bar or text in the execution summary bar area: "Running 3/7..."
- Optionally show which test case is currently executing

### Suite Summary Component

`SuiteSummary` renders after batch execution completes:

Props:
```typescript
interface SuiteSummaryProps {
  results: readonly BatchTestResult[];
  onSelectTest: (testCaseId: string) => void;
}
```

Layout:
- **Header row:** "7 tests: 5 passed, 1 failed, 1 error" with color-coded counts
- **Result rows** (scrollable list):
  - Verdict icon (pass/fail/error/skipped)
  - Test case name
  - Duration badge
  - Diagnostics count badge
  - Diff mismatch count (if applicable)
  - Click handler → `onSelectTest(testCaseId)`

### Integration into AdvancedTestingPage

- When batch results exist (`batchExecution.results.length > 0`):
  - Show `SuiteSummary` above or replacing the single-test tab area
  - Clicking a test row in the suite summary:
    - Loads that test case's `executionState` into the detail tabs
    - Loads the test case's source data and expected output into the left panel
    - Updates `loadedTestCaseId` from T-05
- When the user manually runs a single test or starts a new batch, clear previous batch results
- Populate `testResults` map (from T-05) with batch results so per-test indicators update

### Edge Cases

- **Empty source data:** test case is skipped; shown with gray "Skipped" indicator in suite summary
- **Execution error/timeout:** recorded as error; batch continues with next test case
- **Single test case:** "Run All" still works; suite summary shows 1 result
- **No test cases:** "Run All" button hidden or disabled

## Notes

- The batch execution calls the engine directly rather than going through `usePreviewExecution` (which manages single-execution lifecycle). The `useBatchExecution` hook should import `executeMapping` from `ui/src/lib/engine/` and handle the execution/diff/verdict derivation inline.
- The suite summary should be visually distinct from the single-test tabs — consider a card-like container with a header that differentiates it from the tab content.
- "Run All" with a single test case is supported to avoid special-casing the button visibility. The suite summary works with 1 result.
