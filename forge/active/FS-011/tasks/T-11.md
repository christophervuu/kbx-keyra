## Summary

Wire the complete `ExpressionBuilderPanel` into the `MappingEditorPage` Panel 4 slot. Connect the expression builder to the rule editor's selected rule state, the source schema tree's node selection callback, and keyboard shortcuts. This is the final integration task that makes all expression builder sub-components work together as a coherent panel in the Mapping Editor.

---

## Scope

### In Scope

- **Panel 4 slot replacement:**
  - Replace `<PanelPlaceholder name="Expression Builder (Panel 4)" />` in `MappingEditorPage` with `<ExpressionBuilderPanel />`
  - Pass required props from `useMappingEditor()` hook result
- **Selected rule state management:**
  - Add `selectedRuleIndex` state to the MappingEditorPage (or extend `useMappingEditor`)
  - Rule list click → sets selectedRuleIndex → expression builder loads that rule's expression
  - Expression builder changes → updateRule() fires with updated expression
  - Deselect rule → expression builder shows empty state
- **Source schema tree integration:**
  - Connect `<SchemaTreeView />` (Panel 1) `onSelectNode` callback to expression builder
  - When a node is clicked in Panel 1:
    - Editor mode: insert `source("path")` at cursor position in RawDslEditor
    - Builder mode: fill current source field slot (if in Step 1 or argument slot)
  - Ensure the click-to-insert only fires when expression builder is active (rule selected)
- **Keyboard shortcuts wiring:**
  - `Ctrl+Space` / `Cmd+Space`: trigger autocomplete in raw editor (global handler scoped to Panel 4)
  - `Ctrl+Enter` / `Cmd+Enter`: explicitly apply/commit expression (if using uncommitted pattern)
  - `Escape`: close autocomplete dropdown
  - Standard text editing delegated to native browser behavior
- **Props threading:**
  - `parsedSourceSchema` from `useMappingEditor` → expression builder for autocomplete
  - `rules` and `updateRule` from `useMappingEditor` → `useExpressionBuilder`
  - Mapping config constants/externals → `useExpressionPreview`
  - Sample data context (null for now) → `useExpressionPreview`
- **Component composition:**
  - `ExpressionBuilderPanel` composes: mode toggle, RawDslEditor (with autocomplete + validation), GuidedBuilder, FunctionReferencePanel, ExpressionPreview
  - Ensure all sub-components receive their required props through the panel
- **MappingEditorPage grid adjustment (if needed):**
  - Verify Panel 4 slot has sufficient space for the expression builder
  - Adjust grid sizing if the expression builder needs more room than the placeholder

### Out of Scope

- Schema tree component implementation (FS-009 — already exists)
- Rule list component changes (FS-010 — only adds selectedRuleIndex awareness)
- Sample data loading UI (FS-012)
- Panel resizing (deferred — open question Q4)

## Change Requirements

- Update `MappingEditorPage.tsx`:
  - Add `selectedRuleIndex` local state (initially `null`)
  - Pass `selectedRuleIndex` to RuleList (for selection highlighting) and to expression builder
  - Replace Panel 4 placeholder with `<ExpressionBuilderPanel />` composed with all required hooks/props
  - Wire schema tree `onSelectNode` to expression builder insert callback
  - Accept `expressionBuilderContent` prop slot (same pattern as `ruleListContent`) OR compose inline

- Update `RuleList` component (or its parent integration):
  - Add `onRuleSelect: (index: number | null) => void` prop
  - Highlight the selected rule row
  - Click on a rule row fires `onRuleSelect(index)`
  - Click on already-selected row or empty area fires `onRuleSelect(null)` (deselect)

- Wire `useExpressionBuilder()` in page context:
  - `selectedRuleIndex` from page state
  - `rules` from `useMappingEditor().rules`
  - `updateRule` from `useMappingEditor().actions.updateRule`
  - `parsedSourceSchema` from `useMappingEditor().parsedSourceSchema`

- Wire `useExpressionPreview()` in page context:
  - `expression` from expression builder state
  - `sourceData`: null (placeholder until FS-012)
  - `constants` from loaded mapping config
  - `externalSources`: empty object (placeholder until runtime)

- Wire source schema tree integration:
  - Panel 1 renders `<SchemaTreeView>` with `onSelectNode` callback
  - Callback receives `SchemaTreeNode`
  - Calls expression builder insert function: `insertSourceField(node.path)`
  - `insertSourceField`:
    - Editor mode: insert `source("${path}")` at cursor via RawDslEditor ref
    - Builder mode: add path to selected source fields in builder state

- Wire keyboard shortcuts:
  - Register keydown listener scoped to Panel 4 container (or document with panel focus check)
  - `Ctrl+Space` / `Cmd+Space` → open autocomplete
  - `Ctrl+Enter` / `Cmd+Enter` → commit expression explicitly
  - `Escape` → close autocomplete (if open)
  - Ensure shortcuts don't conflict with existing page-level shortcuts (Ctrl+S for save)

## Blockers / Risks

- The `MappingEditorPage` currently passes `ruleListContent` as a slot prop. Adding a `selectedRuleIndex` state + callback requires careful coordination between the rule list and expression builder — both need access to the same state.
- If `useMappingEditor` is extended with selectedRuleIndex, it changes the hook interface (potential minor breaking change for existing tests)
- Panel 1 may still be a placeholder if FS-009's tree view isn't wired into the editor page yet — if so, provide a temporary mini source field picker within the expression builder as fallback
