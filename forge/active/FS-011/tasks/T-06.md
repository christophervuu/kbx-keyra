## Summary

Build Step 3 (argument configuration) and Step 4 (preview/DSL generation) of the guided expression builder. Step 3 renders argument slots for the selected function with type-aware input controls. Step 4 shows the generated DSL expression string and validates it. This completes the core guided builder flow (excluding array-specific patterns).

---

## Scope

### In Scope

- **Step 3 — Argument Configuration:**
  - Render argument slots based on selected function's `FunctionSignature.parameters`
  - Each slot shows: parameter name, expected type, required/optional indicator
  - Slot input types based on parameter type:
    - `string` → text input or source field picker
    - `number` → number input or source field picker
    - `boolean` → toggle switch or source field picker
    - `array` → source field picker (for array-typed fields)
    - `any` → free-form input (text/number/source field)
  - Source field picker within argument slot (mini version — dropdown, not full panel)
  - Literal value input toggle per slot (switch between "Source field" and "Literal value")
  - Nested function insertion: "Use function" option that recursively opens a mini transform picker → generates nested function call
  - Enum dropdown for known enum arguments (e.g., `cast` target type: `"string"`, `"number"`, `"boolean"`)
  - Variadic parameter support: "Add argument" button for variadic params (like concat's multiple strings)
  - Argument description tooltip on hover
  - Remove optional argument (clear to undefined/omit)
- **Step 4 — Preview:**
  - Display the fully generated DSL expression string
  - Syntax-highlighted rendering (reuse `dslTokenizer` from T-02)
  - "Copy expression" button
  - Inline validation result: ✓ valid or ✗ error with message
  - If sample data is loaded: show evaluated result (stub for now — T-10 provides the full preview)
- **DSL expression generation from builder state:**
  - Assemble function call string from: function name + argument values
  - Each argument value is either:
    - `source("path")` (from field selection)
    - A literal (`"string"`, `123`, `true`, `null`)
    - A nested function call (recursively generated)
  - Handle variadic arguments (comma-separated)
  - Handle optional arguments (omitted if not filled)
- **Recursive nested function support:**
  - Argument slot can contain another guided-builder mini flow
  - Limited to 2 levels of nesting in the builder UI (deeper = use raw editor)
  - Nested builder shows inline (accordion-style expandable)

### Out of Scope

- Array-specific patterns (map, filter with object templates) — T-07
- Live evaluation against sample data — T-10
- Mode toggle — T-08
- AST decomposition (loading existing expressions into builder) — T-08

## Change Requirements

- Create `ui/src/features/mappings/lib/expression-generator.ts`:
  - `generateExpression(state: BuilderState): string`
  - `BuilderState` = `{ functionName: string; arguments: BuilderArgument[] }` (or direct copy / static value state)
  - `BuilderArgument` = `{ kind: 'source' | 'literal' | 'nested-function'; value: string | number | boolean | null | BuilderState }`
  - Handles:
    - Direct copy: `source("path")`
    - Static: `static(value)` (with proper quoting)
    - Function call: `functionName(arg1, arg2, ...)`
    - Nested: recursive generation for nested BuilderState
  - String quoting: strings get `"..."`, numbers/booleans/null are unquoted

- Create `ui/src/features/mappings/components/ArgumentConfigurator.tsx`:
  - Props: `functionName: string`, `parameters: FunctionParameter[]`, `values: BuilderArgument[]`, `onChange: (values: BuilderArgument[]) => void`, `parsedSourceSchema: ParsedSchema | null`
  - Renders one `ArgumentSlot` per parameter
  - Manages variadic "Add argument" for variadic params
  - Computes enum options for known enum parameters (e.g., cast target types)

- Create `ui/src/features/mappings/components/ArgumentSlot.tsx`:
  - Props: `parameter: FunctionParameter`, `value: BuilderArgument | undefined`, `onChange: (value: BuilderArgument) => void`, `parsedSourceSchema: ParsedSchema | null`, `enumOptions?: string[]`
  - Renders:
    - Parameter label + type + required indicator
    - Mode toggle: "Source field" / "Literal" / "Function"
    - Source field mini-picker (dropdown with paths)
    - Literal input (type-appropriate: text, number, checkbox)
    - Enum dropdown (if enumOptions provided)
    - "Use function" → opens NestedFunctionBuilder
  - Tooltip with parameter description on hover

- Create `ui/src/features/mappings/components/NestedFunctionBuilder.tsx`:
  - Mini version of TransformPicker + ArgumentConfigurator for nested function calls
  - Inline/accordion-style (expands within the argument slot)
  - Limited to 1 additional nesting level (the slot itself is already nested once)
  - Generates a `BuilderState` that the parent slot wraps

- Create `ui/src/features/mappings/components/ExpressionPreviewStep.tsx`:
  - Props: `expression: string`, `isValid: boolean`, `validationError?: string`
  - Renders:
    - Syntax-highlighted expression (using `tokenizeDsl()`)
    - Validation status indicator (green check or red X with message)
    - "Copy expression" button
    - Placeholder for evaluation result ("Load sample data to see live result")

- Update `GuidedBuilder.tsx`:
  - Add Step 3 rendering with `ArgumentConfigurator`
  - Add Step 4 rendering with `ExpressionPreviewStep`
  - Call `generateExpression()` when builder state changes
  - Call `onExpressionChange` with generated expression string
  - Validate generated expression via `parse()` and show result in Step 4
