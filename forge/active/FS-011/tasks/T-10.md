## Summary

Build the expression preview area that appears below the editor/builder, showing the final DSL expression string and (when sample data is available) the evaluated result. Create the `useExpressionPreview()` hook that parses and evaluates a single expression against sample source data using the engine's `parse()` + `evaluate()` APIs.

---

## Scope

### In Scope

- `useExpressionPreview()` hook:
  - Accept: expression string, sample source data, mapping config (constants, externals), source/target schema
  - Parse expression with `parse()`
  - If parse succeeds: evaluate AST with `evaluate()` against sample data context
  - Debounce evaluation by 300ms after expression changes
  - Return: `{ result, error, isEvaluating, expressionString }`
  - Handle evaluation errors gracefully (catch, return error message)
  - Return null result when no sample data or empty expression
- `ExpressionPreview` component:
  - Always visible below the editor/builder content area
  - Shows:
    - "Expression" section: final DSL string (syntax-highlighted via tokenizer)
    - "Result" section: evaluated result (JSON-formatted if object/array, raw if primitive)
    - Loading spinner when evaluation is in progress
    - Error display: red badge with error code + message
    - No-data state: "Load sample data in the Preview panel to see live results."
  - Result formatting:
    - Strings: shown in quotes with green color
    - Numbers: orange color
    - Booleans: purple color
    - null: gray "null"
    - Objects/arrays: JSON.stringify with 2-space indent, in monospace
  - Compact layout to fit in limited panel space
- **Engine evaluation context construction:**
  - Build `EvaluationContext` from:
    - `sourceData`: sample source data object
    - `constants`: from mapping config
    - `externalSources`: from mapping config (empty in Phase 0)
    - `registry`: defaultRegistry
    - `scopeStack`: empty (top-level evaluation)
    - `options`: default engine options
  - Use engine's `evaluate()` with the parsed AST node
- **Sample data integration point:**
  - Accept sample data as a prop/context value
  - In Phase 0 before FS-012: sample data will be null (placeholder state shown)
  - After FS-012: sample data flows from the test data context

### Out of Scope

- Sample data input UI (FS-012)
- Full mapping execution (all rules) — this evaluates a single expression only
- Trace/diagnostic display for evaluation (beyond error message)
- Expression preview for array expressions with multiple iterations (show first element only or full array)

## Change Requirements

- Update `ui/src/lib/engine/index.ts` (if not done in T-01):
  - Re-export `evaluate` from `@keyra/engine`
  - Re-export `EvaluationContext` and `EvaluationResult` types
  - Re-export `resolvePath` utility (may be useful)
  - Create helper: `evaluateExpression(expression: string, sourceData: unknown, constants?: Record<string, unknown>, externalSources?: Record<string, unknown>): { value: unknown; error: string | null }`
    - Wraps parse + evaluate into a single call
    - Catches errors and returns null value + error message
    - Constructs minimal EvaluationContext from inputs

- Create `ui/src/features/mappings/hooks/use-expression-preview.ts`:
  - Hook accepts: `{ expression, sourceData, constants, externalSources }`
  - Debounces evaluation by 300ms
  - Calls `evaluateExpression()` after debounce
  - Manages state: result value, error string, isEvaluating boolean
  - Returns: `{ result, error, isEvaluating }`
  - When expression is empty or sourceData is null: returns `{ result: null, error: null, isEvaluating: false }`
  - On evaluation error: returns `{ result: null, error: errorMessage, isEvaluating: false }`

- Create `ui/src/features/mappings/components/ExpressionPreview.tsx`:
  - Props: `expression: string`, `result: unknown | null`, `error: string | null`, `isEvaluating: boolean`, `hasSourceData: boolean`
  - Layout:
    - Top section: "Expression" label + syntax-highlighted DSL string
    - Bottom section: "Result" label + formatted result or error or placeholder
  - Conditional rendering:
    - `hasSourceData === false` → "Load sample data in the Preview panel to see live results."
    - `isEvaluating === true` → spinner/loading indicator on result section
    - `error !== null` → red error display with message
    - `result !== null` → formatted result value
    - `expression === ''` → "Enter an expression above to see a preview."
  - Result value formatter:
    - Primitive: inline styled value
    - Object/Array: `<pre>` with JSON.stringify(result, null, 2) truncated to 10 lines with "..." overflow

- Update `ExpressionBuilderPanel.tsx`:
  - Mount `ExpressionPreview` below the mode-specific content area
  - Pass expression from `useExpressionBuilder` hook
  - Pass preview result from `useExpressionPreview` hook
  - Pass `hasSourceData` indicator (will be false until FS-012 integration)

## Blockers / Risks

- Constructing a proper `EvaluationContext` from UI state is non-trivial — need to match what the engine's `execute()` builds internally. The helper function should replicate the minimal context needed for single-expression evaluation.
- Engine `evaluate()` expects a fully formed `EvaluationContext` with callbacks (`evaluate`, `pushScope`, `popScope`, `addDiagnostic`) — need to provide these even for simple expressions.
