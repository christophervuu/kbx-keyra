## Summary

Create the foundational types, state management hook (`useExpressionBuilder`), and panel shell component for the expression builder. This establishes the data model, integration contract with `useMappingEditor`, mode toggle UI, and empty/active states that all subsequent tasks build upon.

---

## Scope

### In Scope

- Type definitions:
  - `ExpressionBuilderMode` = `'builder' | 'editor'`
  - `BuilderStep` = `'source' | 'transform' | 'arguments' | 'preview'`
  - `FunctionCategory` = `'String' | 'Date' | 'Math' | 'Conditional' | 'Lookup' | 'Array' | 'NullHandling' | 'TypeConversion'`
  - `FunctionCatalogEntry` interface (name, category, description, parameterCount, parameters, returnType, example)
  - `AutocompleteItem` interface (label, insertText, detail, kind)
  - `ExpressionBuilderState` interface (mode, expression, cursorPosition, builderStep, selectedSourceFields, selectedFunction, argumentValues, etc.)
- `useExpressionBuilder()` hook:
  - Accept `selectedRuleIndex`, `rules`, `updateRule`, `parsedSourceSchema` as inputs
  - Load expression from selected rule when index changes
  - Debounce expression updates back to `updateRule()` (300ms)
  - Track current mode (builder/editor) with setter
  - Expose expression string, validation state stub, canDecompose stub
  - Handle no-rule-selected state
- `ExpressionBuilderPanel` shell component:
  - Mode toggle (segmented control: "Builder" / "Editor")
  - Render children based on mode (placeholder slots for T-02 and T-05)
  - Empty state rendering when no rule selected
  - Active state with mode toggle visible
- Engine integration additions to `ui/src/lib/engine/index.ts`:
  - Re-export `parse` function from `@keyra/engine`
  - Re-export `defaultRegistry` from `@keyra/engine`
  - Re-export relevant types: `ParseResult`, `AstNode`, `FunctionCallNode`, `ParseOptions`, `FunctionRegistry`, `FunctionSignature`, `FunctionParameter`, `RegisteredFunction`
- `DSL_FUNCTION_CATALOG` static data array with all registered functions categorized (derived from engine function registry metadata)
- Barrel exports in `ui/src/features/mappings/` updated

### Out of Scope

- Raw editor implementation (T-02)
- Guided builder UI (T-05)
- Autocomplete (T-03)
- Inline validation (T-04)
- Expression preview evaluation (T-10)
- Panel integration wiring into MappingEditorPage (T-11)

## Change Requirements

- Create `ui/src/features/mappings/hooks/use-expression-builder.ts`:
  - Hook accepts `{ selectedRuleIndex, rules, updateRule, parsedSourceSchema }` and returns expression builder state + actions
  - Loads the expression from `rules[selectedRuleIndex]` whenever `selectedRuleIndex` changes
  - Maintains local `expression` string state (decoupled from rule for debounce)
  - Debounces `updateRule()` calls by 300ms after expression changes
  - Only commits syntactically valid expressions (use `parse()` to check before committing)
  - Exposes `mode`, `setMode`, `expression`, `setExpression`, `selectedRule`, `isValid`
  - Returns null/empty state indicators when no rule selected

- Create `ui/src/features/mappings/components/ExpressionBuilderPanel.tsx`:
  - Accepts expression builder hook result as props (or consumes hook internally — implementer's choice)
  - Renders mode toggle (segmented control with "Builder" and "Editor" labels)
  - Renders empty state when no rule selected: "Select a rule to edit its expression, or add a new rule."
  - Renders mode-specific content area (placeholder div with data-testid for T-02/T-05 to replace)
  - Uses Tailwind CSS 4 for styling

- Create `ui/src/features/mappings/lib/function-catalog.ts`:
  - Export `DSL_FUNCTION_CATALOG: readonly FunctionCatalogEntry[]`
  - Include all engine-registered functions with categories, descriptions, parameter info
  - Categories: String (concat, substring, upper, lower, trim, replace, replaceAll, contains, length), Date (formatDate), Math (add, subtract, multiply, divide, round, abs), Conditional (if, eq, neq, gt, gte, lt, lte, and, or, not), Lookup (valueMap), Array (map, filter, find, array, merge, flatten, first, nth, join, count, get), Null Handling (default, coalesce, isNull), Type Conversion (cast)
  - Source access functions (source, item, parent, constant, external, static) should be in a separate "Source Access" category or excluded from the picker since they're handled differently in the builder

- Update `ui/src/lib/engine/index.ts`:
  - Add re-exports for `parse` (the DSL parse function)
  - Add re-exports for `defaultRegistry` or a wrapper function `getRegisteredFunctions()`
  - Add type re-exports: `ParseResult`, `AstNode`, `FunctionCallNode`, `ParseOptions`
  - Add type re-exports: `FunctionSignature`, `FunctionParameter`, `RegisteredFunction`
