## Summary

Implement the 5 Project CRUD Lambda handlers (create, get, list, update, delete) under `src/lambda/project/`. Each handler reads from/writes to DynamoDB using the shared utilities from T-01, returns domain objects matching `ProjectMetadata` and `ProjectDetail` types, and enforces referential integrity on delete (reject if mappings exist).

---

## Scope

### In Scope

- `src/lambda/project/create-project.ts` — POST /projects handler
- `src/lambda/project/get-project.ts` — GET /projects/:id handler
- `src/lambda/project/list-projects.ts` — GET /projects handler
- `src/lambda/project/update-project.ts` — PUT /projects/:id handler
- `src/lambda/project/delete-project.ts` — DELETE /projects/:id handler
- UUID generation for `projectId` on create
- `createdAt`/`updatedAt` timestamp management
- `getProject` returns `ProjectDetail` shape with embedded `mappings` array (query Mappings `projectId-index`) and embedded `schemas` array (batch-get SchemaMetadata for each `schemaRef`)
- `listProjects` returns `ProjectMetadata[]` with computed `mappingCount` and `schemaCount`
- `deleteProject` queries for existing mappings and returns 409 if any exist
- Input validation: `name` and `slug` required on create

### Out of Scope

- Mapping or schema handler implementations
- Slug uniqueness enforcement (deferred — no unique constraint in DynamoDB without conditional writes)
- Pagination for list endpoint
- Authentication

## Change Requirements

- Each handler exports `async function handler(event: APIGatewayProxyEvent): Promise<APIGatewayProxyResult>`
- `create-project`: validate required fields (`name`, `slug`), generate UUID, set timestamps, write to DynamoDB, return 201 with `ProjectMetadata`
- `get-project`: read project from DynamoDB, query Mappings GSI for `projectId`, batch-get SchemaMetadata for each schemaRef in the project's `schemaRefs` array, assemble `ProjectDetail` with `mappings` and `schemas` arrays, return 200 or 404
- `list-projects`: scan Projects table, for each project compute `mappingCount` (query GSI count) and `schemaCount` (from `schemaRefs.length`), return 200 with `ProjectMetadata[]`
- `update-project`: read existing (404 if not found), merge input fields, update `updatedAt`, return 200 with updated `ProjectMetadata`
- `delete-project`: query Mappings GSI count for projectId, if > 0 return 409 CONFLICT, otherwise delete, return 204
- All responses use shared response utilities for consistent headers and error formatting

## Blockers / Risks

## Notes

- `ProjectDetail` extends `Project` and adds `mappings: MappingMetadata[]`. Per Q6 resolution, it also embeds `schemas: SchemaMetadata[]` resolved from `schemaRefs`. The `getProject` handler must query the Mappings table by `projectId` and batch-get SchemaMetadata for each ref.
- `schemaCount` is derived from `schemaRefs.length` on the project record — no separate table query needed for the list endpoint.
- If a `schemaRef` points to a schema that no longer exists (orphaned ref), the handler should omit it from the `schemas` array rather than failing. This is a graceful degradation for referential edge cases.
- Consider using `BatchGetItem` optimization for `listProjects` mapping counts if performance degrades (not required for Phase 1).
- The `schemas` array in `ProjectDetail` returns full `SchemaMetadata` objects (same shape as `listSchemas` returns) but does NOT include content. Content is only returned by `getSchema`.
