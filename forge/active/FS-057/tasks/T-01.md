## Summary

Create the shared utility layer under `src/lambda/shared/` that all CRUD handlers will depend on: response builders, request body parsing, input validation, standardized error formatting, and DynamoDB/S3 client wrappers. This foundation establishes consistent patterns for error envelopes, CORS headers, and AWS SDK usage across all Phase 1 handlers.

---

## Scope

### In Scope

- `src/lambda/shared/response.ts` — `jsonResponse(statusCode, body)`, `errorResponse(code, message, statusCode, retryable)`, CORS headers
- `src/lambda/shared/request.ts` — `parseBody(event)`, `parsePathParam(event, name)`, `parseQueryParam(event, name)`
- `src/lambda/shared/validation.ts` — `requireFields(body, [...fields])` returning validation result or error
- `src/lambda/shared/errors.ts` — error codes enum, `AppErrorResponse` type, `notFound(resource, id)`, `conflict(message)`, `validationError(message)`, `internalError()`, `serviceUnavailable()`
- `src/lambda/shared/dynamo.ts` — thin typed wrappers around DynamoDB DocumentClient (getItem, putItem, query, scan, deleteItem, updateItem) with retry/throttle handling
- `src/lambda/shared/s3.ts` — thin typed wrappers around S3 client (putObject, getObject, deleteObject) with error mapping
- `src/lambda/shared/types.ts` — shared types including `APIGatewayProxyEvent`, `APIGatewayProxyResult` (replacing per-handler definitions)
- `src/lambda/shared/index.ts` — barrel export

### Out of Scope

- Specific handler implementations
- DynamoDB table definitions or provisioning
- Authentication/authorization middleware
- Retry/backoff logic beyond basic DynamoDB throttle handling

## Change Requirements

- Create `src/lambda/shared/` directory structure with all files listed in scope
- Error response envelope must match the spec's defined shape:
  ```json
  { "error": { "code": "...", "message": "...", "statusCode": N, "retryable": bool } }
  ```
- All response utilities must include `Content-Type: application/json` and `Access-Control-Allow-Origin: *` headers
- `requireFields()` must return the first missing field in its error message (consistent with AE-12)
- DynamoDB wrapper must catch `ProvisionedThroughputExceededException` and `ThrottlingException` and convert to 503 `SERVICE_UNAVAILABLE` responses
- S3 wrapper must catch `NoSuchKey` and convert to 404 `RESOURCE_NOT_FOUND`
- Types must re-export `APIGatewayProxyEvent` and `APIGatewayProxyResult` so individual handlers import from `../shared/` instead of defining locally
- Must work with `@aws-sdk/client-dynamodb`, `@aws-sdk/lib-dynamodb`, and `@aws-sdk/client-s3`
