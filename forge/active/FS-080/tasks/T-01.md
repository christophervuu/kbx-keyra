## Summary

Add a backend cache for CDM GitHub file-list reads scoped to the CommonDataModels root, with configurable TTL and explicit degraded-fallback behavior when transient GitHub failures occur.

---

## Scope

### In Scope

- Add cache read/write path for CDM listings keyed by repo/branch/path.
- Add TTL configuration and expiry behavior with defaults: local 30s, dev 60s, prod 300s.
- Implement fallback-to-cache behavior for transient listing failures, including outage-only stale-cache grace window behavior (recommended up to 15 minutes in prod).
- Ensure fallback responses carry explicit degraded/cached indicator for UI.
- Add backend tests for cache hit/miss/expiry/fallback behavior.

### Out of Scope

- Retry/backoff orchestration internals for non-listing operations.
- UI rendering changes for degraded state.
- New non-CDM cache usage.

## Change Requirements

- Implement cache policy strictly for CDM read listing flow under allowed root.
- Expose deterministic response metadata indicating fresh vs cached/degraded source.
- Keep CDM root/path validation unchanged.
- Ensure cache does not override or mutate schema sync state semantics.

---

## Verification Requirements

- Test cache hit within TTL serves cached result when GitHub transiently fails (AE-01).
- Test cache miss with failure returns explicit non-crashing error contract (AE-04).
- Test expired cache and stale-grace-window behavior matches policy and does not silently hide stale state.
- Run typecheck and targeted backend tests.

---

## Acceptance Checks

- CDM listing cache is keyed by repo/branch/path and TTL-governed.
- Transient listing failure with valid cache returns cached payload marked degraded.
- Failure without usable cache returns explicit error contract (no silent success).
- Sync-state semantics remain accurate and not overwritten by listing cache fallback.
- `forge/architecture/project-structure.md` updated if new files/folders are created.

---

## Blockers / Risks

- Incorrect cache scoping could leak cross-path data.
- Ambiguous stale policy could mask outdated browse information if not signaled clearly.

---

## Notes

- Favor explicit cache metadata fields (`source: fresh|cache`, `degraded: boolean`) for UI determinism.
