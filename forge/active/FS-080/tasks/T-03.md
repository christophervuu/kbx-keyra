## Summary

Update affected CDM UI surfaces to render class-specific friendly errors, degraded cached-state indicators, and explicit retry actions while keeping screens usable during partial GitHub outages.

---

## Scope

### In Scope

- Map canonical CDM failure classes to user-friendly messaging and guidance.
- Render degraded/cached indicator for fallback browse data.
- Add retry CTA wiring for recoverable failures in browse/link/sync surfaces.
- Ensure UI remains interactive/non-crashing under CDM GitHub errors.
- Add UI tests for failure-class messaging and retry behavior.

### Out of Scope

- Backend retry/cache implementation.
- Global redesign of unrelated schema/project UI.
- New product workflows outside existing CDM surfaces.

## Change Requirements

- Define centralized UI-side mapping table from backend failureClass code -> message/recovery guidance.
- Surface retry affordances only for relevant recoverable errors.
- Render `retry-after` guidance for rate-limited failures when metadata is present.
- Display cached/degraded status distinct from normal healthy state.
- Preserve existing non-CDM behavior outside touched scopes.

---

## Verification Requirements

- Test class-specific messaging for each canonical failure class (AE-03).
- Test degraded cached browse indicator and retry action rendering (AE-01).
- Test failures do not crash affected views and navigation remains usable (AE-04).
- Test sync terminal failures remain visible with actionable retry guidance (AE-05).

## Acceptance Checks

- Friendly error copy appears for each canonical failure class.
- Degraded cached-state indicator is shown when fallback data is used.
- Retry actions are available and wired for recoverable failures.
- UI remains usable (no crash) during CDM GitHub failures.
- `forge/architecture/project-structure.md` updated if new files/folders are created.

- Overly generic error handling may hide failure-class specificity.
