## Summary

Introduce resilient retry behavior for transient GitHub read failures and a canonical error-class mapping contract for CDM browse/link/sync responses so UI can render deterministic guidance.

---

## Scope

### In Scope

- Implement/configure bounded retry policy with exponential backoff + jitter.
- Apply retry policy to transient CDM GitHub read operations within defined bounds.
- Implement deterministic failure classification contract:
  - rate-limited
  - unauthorized-forbidden
  - not-found-path-mismatch
  - timeout-transient
- Ensure terminal sync failure is explicit and never silently swallowed.
- Add backend tests for retry behavior and class mapping.

### Out of Scope

- Friendly UI copy rendering.
- Broad retry policy redesign for unrelated subsystems.
- Observability platform integrations beyond log fields emitted by handlers.

- `tests/lib/**/*.test.ts`

---

## Change Requirements

- Keep retry bounded with configurable max attempts and delay caps.
- Apply retry only to retryable/transient classes; avoid unbounded retries for auth/path failures.
- Return/emit canonical backend-owned failure taxonomy/codes in error payload context for UI consumption.
- Expose `retry-after` metadata to UI for rate-limited responses when available.
- Guarantee sync failure responses are explicit failed outcomes.

---

## Verification Requirements

- Validate automatic retry occurs for transient timeout/network/5xx and stops at max attempts (AE-02).
- Validate non-retryable class behavior for unauthorized/path mismatch is immediate or bounded per policy.
- Validate deterministic class mapping for representative error statuses/cases (AE-03).
- Validate sync failures cannot return success on terminal error (AE-05).

---

## Acceptance Checks

- Retry attempts are bounded and use exponential backoff + jitter.
- Canonical failure classes are produced deterministically for browse/link/sync failures.
- Unauthorized/path mismatch classes are not treated as endless transient retries.
- Terminal sync failures are explicit and visible in response state.
- `forge/architecture/project-structure.md` updated if new files/folders are created.

---

## Blockers / Risks

- Misclassification could produce wrong UI guidance and retry affordances.
- Overly aggressive retry policy may worsen rate-limit behavior.

---

## Notes

- Preserve compatibility with existing backend error envelope while adding class context for UI routing.
