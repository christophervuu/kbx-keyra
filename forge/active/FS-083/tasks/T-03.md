## Summary

Implement control-plane orchestration logic for deploy and promote operations that builds/resolves immutable artifacts, calls runtime deploy APIs, enforces same-artifact promotion behavior, and records deterministic orchestration status transitions.

---

## Scope

### In Scope

- Deploy orchestration path from user action to runtime acknowledgment.
- Promote orchestration path using existing source-environment active artifact identity.
- Artifact builder/resolver behavior for source revision/version snapshots.
- Idempotency key propagation and runtime response handling.
- Persistence of orchestration records and deployment history projection updates.

### Out of Scope

- Rollback orchestration.
- Server preview orchestration.
- Deployment Page UI rendering changes.

## Change Requirements

- Enforce immutable artifact construction and identity/hash generation.
- Deploy flow must call target runtime API and persist orchestration states (`queued -> in_progress -> succeeded|failed`).
- Promote flow must re-send same artifactId/hash from source environment state.
- Preserve Save != Deploy by keeping orchestration entrypoints deploy-page action bound only.

---

## Verification Requirements

- Integration tests for deploy success/failure and promote success/failure flows.
- Tests asserting same-artifact promotion (no regenerated artifact id/hash).
- Tests asserting orchestration record transitions and request correlation metadata.

---

## Acceptance Checks

- Deploy action creates/resolves immutable artifact and updates target env on success.
- Promote action reuses existing artifact identity and activates next environment.
- Save/update mapping paths do not trigger deploy/promote orchestration.
- Integration tests covering AE-01/AE-02/AE-06 pass.

---

## Blockers / Risks

- Existing deployment persistence schema may require extension for orchestration lineage fields.

## Notes

- Keep promote sequencing aligned to policy (`DEV -> PREPROD -> PROD`).
- Spec Rev 2 **D1**: Push full artifact payload on every promote — no preflight optimization. Runtime idempotency handles duplicates.
- Spec Rev 2 **D2**: Enforce 5 MB max payload; fail fast with `PAYLOAD_TOO_LARGE` before runtime call.
