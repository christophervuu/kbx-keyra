## Summary

Implement `resolvePath(obj, path)` — a standalone utility that resolves dot/bracket path strings against an object. Handles dot notation, bracket notation with single quotes, numeric array indices, empty paths, and missing intermediates. This utility is used by function implementations (source, item, parent, get) to traverse data structures.

---

## Scope

### In Scope

- `resolvePath(obj: unknown, path: string): unknown` function
- Dot notation parsing: `"a.b.c"`
- Bracket notation with single quotes: `"items['name']"`
- Numeric array indices: `"items[0]"`
- Mixed notation: `"orders[0].items['sku']"`
- Empty path returns the whole object
- Missing intermediate paths return null (no throw)
- Null/undefined intermediate values return null gracefully
- Place in `src/engine/dsl/resolve-path.ts`
- Unit tests for all path resolution cases

### Out of Scope

- Evaluator logic (T-03)
- Any DSL function implementations
- Path validation against schemas
- Bracket notation with double quotes (DSL spec uses single quotes only)

## Change Requirements

After this task:

- `resolvePath(obj: unknown, path: string): unknown` exists and is exported
- Handles the following path segment types:
  - Dot-separated identifiers: `a.b.c`
  - Bracket with single-quoted string: `['key']`
  - Bracket with numeric index: `[0]`, `[1]`
  - Mixed combinations of the above
- Edge case handling:
  - Empty string path returns `obj` unchanged
  - `null` or `undefined` input object returns `null`
  - Path traversing into null/undefined intermediate returns `null`
  - Array index out of bounds returns `undefined` (standard JS behavior)
  - Trailing dots or empty segments are handled gracefully (return null for invalid path)
- The function is pure — no side effects, no mutations
