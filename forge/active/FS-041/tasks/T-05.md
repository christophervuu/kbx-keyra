## Summary

Enable the Explain button in `ScalarFieldBuilder`, wire it to the `useExplainRule()` hook, and add an inline `ExplanationPanel` component to display the explanation result, loading state, and error state. This is the primary showcase surface for the Explain Rule feature.

---

## Scope

### In Scope

- Enable the Explain button in `ScalarFieldBuilder.tsx` (remove `disabled`, update styling)
- Disable the button only when there is no expression to explain (AE-03)
- Call `useExplainRule()` hook
- On click: call `explain({ targetPath, expression })`
- Show loading spinner/state on the button or adjacent to it while request is in flight
- Create `ExplanationPanel.tsx` component for result display
- Render `ExplanationPanel` inline below the AI action row when result is available
- Show error state inline with "Try again" action
- Dismiss explanation when user clicks close or navigates to a different field
- Reset explanation state when `selectedTargetPath` changes (AE-09)
- Component tests for the Explain flow

### Out of Scope

- ChainBuilderShell integration (T-06)
- Hook implementation (T-04 — already done)
- HTTP client or adapter changes (T-01–T-03)

## Change Requirements

### ScalarFieldBuilder.tsx

1. **Import** `useExplainRule` from hooks
2. **Call hook** at component top level: `const { state: explainState, explain, dismiss: dismissExplain } = useExplainRule();`
3. **Determine button state:**
   - Disabled when: `currentExpression` is empty/whitespace (AE-03)
   - Tooltip when disabled: "No expression to explain"
   - Tooltip when enabled: "Explain this expression using AI"
   - Loading: show a spinner icon instead of `Lightbulb`, change text to "Explaining..."
4. **Update button markup:**
   - Remove hard-coded `disabled` and `aria-disabled="true"`
   - Remove `cursor-not-allowed` and `opacity-50` classes (conditionally apply based on state)
   - Add `onClick` handler: `explain({ targetPath: selectedTargetPath, expression: currentExpression })`
   - When `explainState.status === 'loading'`: show spinner, disable button
   - When enabled: use interactive styling (hover, focus ring)
5. **Update `AI_EXPLAIN_TOOLTIP`** constant:
   - Change from "AI-powered explanation — available in a future release" to "Explain this expression using AI"
6. **Render `ExplanationPanel`** after the action row:
   - Show when `explainState.status === 'success'` or `explainState.status === 'error'`
   - Pass `explainState`, `onDismiss: dismissExplain`, `onRetry: () => explain({ ... })`
7. **Reset on field change:**
   - Add `useEffect` that calls `dismissExplain()` when `selectedTargetPath` changes

### ExplanationPanel.tsx (new)

A lightweight inline panel for displaying the explanation result.

```typescript
interface ExplanationPanelProps {
  state: ExplainRuleState;
  onDismiss: () => void;
  onRetry: () => void;
}
```

**Layout (success state):**
```
┌─────────────────────────────────────────────┐
│  💡 Explanation                        [×]  │
│                                             │
│  "This rule checks if the invoice amount    │
│   is negative. If so, it maps the document  │
│   type to 'CreditMemo'; otherwise, it maps  │
│   to 'Invoice'."                            │
└─────────────────────────────────────────────┘
```

**Styling:**
- Dark theme consistent with Mapping Editor (e.g., `bg-slate-800/80 border border-slate-700 rounded-lg`)
- `Lightbulb` icon in header
- Dismiss button (`X` icon) in top-right
- Explanation text in `text-slate-200`
- `role="status"` and `aria-live="polite"` for screen reader announcement

**Layout (error state):**
```
┌─────────────────────────────────────────────┐
│  ⚠ Explain Error                       [×]  │
│                                             │
│  "Could not reach the Explain service..."   │
│                                             │
│  [Try again]                                │
└─────────────────────────────────────────────┘
```

**Styling:**
- Error variant: amber/red border accent
- `AlertTriangle` icon
- "Try again" button: ghost button style

**Layout (loading state):**
- The panel is not shown during loading — the button itself shows the loading state
- Alternatively: a subtle skeleton/pulse placeholder can appear where the panel will render

**Accessibility:**
- `role="status"` on success panel
- `role="alert"` on error panel
- `aria-live="polite"` for non-disruptive announcement
- Close button: `aria-label="Dismiss explanation"`
- `data-testid="explanation-panel"` on the container

## Notes

The `ExplanationPanel` is intentionally a lightweight, self-contained component. It is not a modal, drawer, or popover — it renders inline in the normal document flow below the AI action row. This keeps the implementation simple and avoids portal/overlay complexity.

The same `ExplanationPanel` component will be reused by `ChainBuilderShell` in T-06.

Keep the Suggest and Fix buttons disabled with their current tooltips — only Explain is being wired in this spec.
