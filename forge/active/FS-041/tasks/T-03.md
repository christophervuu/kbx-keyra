## Change Requirements

### `hybrid-adapter.ts` (new)

```typescript
import { LocalStorageAdapter } from './local-storage-adapter';
import { explainRuleHttp } from './ai-api-client';
import type { ExplainRuleInput, ExplainRuleResult } from '@/lib/types';

export class HybridAdapter extends LocalStorageAdapter {
  private readonly apiUrl: string;

  constructor(apiUrl: string) {
    super();
    this.apiUrl = apiUrl;
  }

  override async explainRule(input: ExplainRuleInput): Promise<ExplainRuleResult> {
    return explainRuleHttp(this.apiUrl, input);
  }
}
```

This is intentionally minimal. Future AI methods can be overridden in the same pattern as they are wired to HTTP endpoints.

### `bootstrap.ts` (update)

Current:
```typescript
export function createAdapter(apiUrl = import.meta.env.VITE_API_URL): ApiAdapter {
  if (apiUrl) {
    throw new Error('HttpAdapter not implemented');
  }
  return new LocalStorageAdapter();
}
```

Updated:
```typescript
import { LocalStorageAdapter } from './local-storage-adapter';
import { HybridAdapter } from './hybrid-adapter';
import type { ApiAdapter } from './types';

export function createAdapter(apiUrl = import.meta.env.VITE_API_URL): ApiAdapter {
  if (apiUrl) {
    return new HybridAdapter(apiUrl);
  }
  return new LocalStorageAdapter();
}
```

## Notes

The `HybridAdapter` name communicates that this adapter mixes local storage (Phase 0) with HTTP (Phase 1) behavior. When full Phase 1 arrives, either:
- `HybridAdapter` grows to override all methods with HTTP, eventually becoming the real `HttpAdapter`
- Or a new `HttpAdapter` replaces both `LocalStorageAdapter` and `HybridAdapter`

Either path is clean. The `HybridAdapter` is explicitly a transitional construct.
