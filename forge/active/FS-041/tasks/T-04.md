## Summary

Create a `useExplainRule()` React hook that manages the async lifecycle for calling `adapter.explainRule()`. The hook provides loading, success, and error states, handles request cancellation on unmount or re-invocation, and produces user-friendly error messages.

## Change Requirements

### Hook API

```typescript
interface ExplainRuleState {
  status: 'idle' | 'loading' | 'success' | 'error';
  result: ExplainRuleResult | null;
  error: string | null;
}

interface UseExplainRuleReturn {
  state: ExplainRuleState;
  explain: (input: ExplainRuleInput) => void;
  dismiss: () => void;
}

function useExplainRule(): UseExplainRuleReturn
```

### Behavior

1. **Initial state:** `{ status: 'idle', result: null, error: null }`

2. **`explain(input)`:**
   - If a previous request is in flight, abort it (set abortController ref)
   - Transition to `{ status: 'loading', result: null, error: null }`
   - Call `adapter.explainRule(input)`
   - On success: `{ status: 'success', result: <ExplainRuleResult>, error: null }`
   - On error: `{ status: 'error', result: null, error: <user-friendly message> }`
   - If the component unmounts during the call, do not update state (check mounted ref or abort signal)

3. **`dismiss()`:**
   - Transition back to `{ status: 'idle', result: null, error: null }`
   - If a request is in flight, abort it

4. **Error message mapping:**
   - Error message contains "offline mode" → "Explain is not available in offline mode"
   - Error message contains "temporarily busy" or "rate limit" → pass through
   - Error message contains "Could not reach" → pass through
   - Error message contains "unexpected response" → pass through
   - Generic/unknown errors → "An unexpected error occurred. Please try again."

5. **Cleanup on unmount:**
   - Abort any in-flight request via AbortController

### Implementation pattern

Follow the canonical hook patterns from `ui-application.md`:
- Accept nullable/optional inputs
- Return strongly typed state + actions
- Isolate errors without crashing
- Use `useCallback` for stable action references
- Use `useRef` for the AbortController to avoid re-render loops

### Tests

- **Idle state**: initial state is `{ status: 'idle', result: null, error: null }`
- **Loading state**: calling `explain()` transitions to loading
- **Success state**: adapter resolves → state has result
- **Error state**: adapter rejects → state has error message
- **Dismiss**: calling `dismiss()` resets to idle
- **Re-explain**: calling `explain()` after success resets and re-fetches
- **Abort on re-explain**: calling `explain()` while loading aborts previous
- **Offline error**: adapter throws "Not available in offline mode" → user-friendly message
- **Cleanup on unmount**: abort is called

## Notes

This hook is adapter-agnostic — it calls `adapter.explainRule()` regardless of whether the adapter is `LocalStorageAdapter`, `HybridAdapter`, or a future `HttpAdapter`. The adapter implementation handles the actual transport. This means the hook can be tested with a mock adapter without any HTTP mocking.

The hook does NOT cache results. Each call to `explain()` makes a fresh request. This is intentional for the showcase — caching can be added later if needed (spec Q3).
