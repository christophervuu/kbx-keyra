## Summary

Create a pure utility function `computeVersionDiff()` that compares two `MappingConfig` objects and produces a structured diff result. Rule matching is done by target path (stable identifier). Config-level changes (unmappedTargets, nullSubtrees, constants, externalSources) are also detected. This utility is consumed by the version history UI to render diff views and generate change summaries.

---

## Scope

### In Scope

- `computeVersionDiff(oldConfig, newConfig)` function
- Rule diff by target path: added, modified, removed
- Config diff: field-level comparison for `unmappedTargets`, `nullSubtrees`, `constants`, `externalSources`
- `generateChangeSummary(diff)` helper: produces "+N added, ~M modified, -K removed" string
- Handle edge cases: empty rules, identical configs, duplicate target paths, null/undefined config fields
- Export types: `RuleDiff`, `ConfigDiff`, `VersionDiff`

### Out of Scope

- UI rendering of the diff (T-06)
- Expression-level tokenized diff (comparing entire expressions as strings only)
- Deep diff of constant values (shallow equality per key)
- Integration with React hooks or components

## Change Requirements

After this task:

**Types:**
```typescript
export interface RuleDiff {
  readonly type: 'added' | 'modified' | 'removed';
  readonly targetPath: string;
  readonly oldExpression?: string;
  readonly newExpression?: string;
  readonly oldDescription?: string;
  readonly newDescription?: string;
}

export interface ConfigDiff {
  readonly field: string;
  readonly oldValue: unknown;
  readonly newValue: unknown;
}

export interface VersionDiff {
  readonly summary: { added: number; modified: number; removed: number };
  readonly ruleDiffs: readonly RuleDiff[];
  readonly configDiffs: readonly ConfigDiff[];
}
```

**`computeVersionDiff(oldConfig: MappingConfig, newConfig: MappingConfig): VersionDiff`**

Rule matching algorithm:
1. Build a Map of target path → rule(s) for both old and new configs
2. For each target path in new but not old → `added`
3. For each target path in old but not new → `removed`
4. For each target path in both → compare expression:
   - If expression differs → `modified` (include before/after)
   - If expression same but description differs → `modified`
   - If both identical → no diff entry
5. If a target path appears multiple times in a config (duplicate targets), compare by index position within the group of same-target rules

Config diff algorithm:
1. Compare `oldConfig.config.unmappedTargets` vs `newConfig.config.unmappedTargets` (treat `undefined` as `"null"` for comparison purposes, or just compare raw values)
2. Compare `nullSubtrees` arrays (order-independent set comparison)
3. Compare `constants` records (key-by-key; report each changed/added/removed key)
4. Compare `externalSources` arrays (order-independent set comparison)
5. Only include fields in `configDiffs` where values actually differ

**`generateChangeSummary(diff: VersionDiff): string`**
- If all counts are 0: "No changes"
- Otherwise: join non-zero counts: "+2 added, ~1 modified, -1 removed"
- Exclude categories with 0 count from the string

## Notes

This is a pure utility with no React/DOM dependencies. It can be tested with pure Vitest without React Testing Library.

For duplicate target paths: the simplest approach is to group rules by target path, then compare positionally within each group. For example, if old has `[A.B, A.B]` and new has `[A.B, A.B, A.B]`, the third is "added" and the first two are compared pairwise.

The diff utility is intentionally simple for Phase 0. Token-level expression diff (highlighting which part of the expression changed) is a future enhancement — for now, the whole expression string is shown as old/new.
