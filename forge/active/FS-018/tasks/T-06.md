## Summary

Build the `VersionDiffView` component that renders rule-level and config-level differences between two versions, and the restore flow including a confirmation modal. The diff view shows color-coded sections (green for added, yellow for modified, red for removed) with target paths and expression before/after values. The restore button triggers a confirmation modal warning about unsaved changes loss, then executes the restore via the parent's orchestration.

---

## Scope

### In Scope

- `VersionDiffView` component:
  - Summary line at top: "+N added, ~M modified, -K removed"
  - Rules added section (green): target path + new expression
  - Rules modified section (yellow): target path + before/after expression
  - Rules removed section (red): target path + old expression
  - Config changes section: field name + before/after value
  - Empty diff state: "No changes between these versions"
- "Restore this version" button (disabled/hidden on current version)
- Restore confirmation modal:
  - Message: "This will restore version v{N} as a new version (v{current+1}). Your current unsaved changes will be lost."
  - "Restore" (primary/destructive) and "Cancel" buttons
  - If no unsaved changes: simplified message without the "unsaved changes" warning
- `onRestore(config: MappingConfig)` callback prop for executing the restore
- Renders inside the `VersionHistoryDrawer` when a version is selected

### Out of Scope

- Actually executing the restore save (the parent page handles calling save after receiving the config)
- Token-level expression diffs (whole expression strings compared)
- Syntax highlighting in diff expressions
- Undo restore

## Notes

For expression display in diff entries, use a monospace font and truncate long expressions with ellipsis + tooltip/expand on hover. Expressions can be quite long in complex mappings.

The `onRestore` callback receives the version number. The parent component (page-level) handles:
1. Getting the full config via `useVersionHistory.getRestoreConfig(version)`
2. Replacing the working state in `useMappingEditor`
3. Triggering a save (which creates a new version)

This separation keeps the diff view a pure presentation component.

Integrate into `VersionHistoryDrawer`: when `selectedVersion` is not null, render `VersionDiffView` in the drawer's `children` slot (or replace the list with the diff view, with a back button to return to list).
