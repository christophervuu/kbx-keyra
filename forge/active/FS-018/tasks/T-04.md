## Summary

Create the `useVersionHistory` hook that loads the version list for a mapping, computes change summaries for each entry (using the diff utility from T-02), and exposes a `restore` action. This hook is the data/logic layer for the version history UI — it handles loading, state management, and the restore flow (replace config + trigger save).

---

## Scope

### In Scope

- `useVersionHistory(mappingId, currentConfig, onRestore)` hook
- Load version list from `adapter.listMappingVersions(mappingId)` on mount
- Refresh version list after save (triggered externally or via dependency)
- Compute change summary for each version entry (diff against previous version)
- Expose selected version state and diff computation
- `restore(version: number)` action: loads target version config, calls `onRestore` callback
- Loading state while versions are being fetched
- Empty state detection (no versions or only current version)

### Out of Scope

- UI rendering (T-05, T-06)
- Drawer open/close state (page-level concern, T-07)
- Modifying the adapter or diff utility (built in T-01, T-02)

## Change Requirements

After this task:

**Hook signature:**
```typescript
interface VersionHistoryEntry {
  readonly version: number;
  readonly savedAt: string;
  readonly savedBy: string;
  readonly ruleCount: number;
  readonly summary: string; // e.g., "+2 added, ~1 modified"
}

interface UseVersionHistoryResult {
  /** Sorted version list (most recent first) with computed summaries */
  versions: readonly VersionHistoryEntry[];
  /** Whether versions are currently loading */
  isLoading: boolean;
  /** Whether no history exists (empty state) */
  isEmpty: boolean;
  /** Currently selected version for diff viewing (null = none selected) */
  selectedVersion: number | null;
  /** Select a version to view its diff */
  selectVersion: (version: number | null) => void;
  /** Computed diff between selected version and current (null if none selected) */
  selectedDiff: VersionDiff | null;
  /** Restore a version — returns the config to restore (caller handles save) */
  getRestoreConfig: (version: number) => MappingConfig | null;
  /** Refresh the version list (call after save) */
  refresh: () => void;
}

function useVersionHistory(
  mappingId: string,
  currentConfig: MappingConfig | null,
): UseVersionHistoryResult;
```

**Behavior:**
- On mount (and when `mappingId` changes): load versions via adapter
- `versions` list includes computed `summary` string per entry (derived from diff against previous version in the list)
  - v1 or first available: "Initial version — N rules"
  - Others: use `generateChangeSummary(computeVersionDiff(prevConfig, entryConfig))`
- Summary computation is lazy/memoized (only compute when versions array changes)
- `selectVersion(n)`: sets selected; triggers diff computation against `currentConfig`
- `selectedDiff`: computed via `computeVersionDiff(selectedVersionConfig, currentConfig)` — shows what changed FROM the selected version TO current
- `getRestoreConfig(version)`: finds the version entry and returns its `config` (full MappingConfig)
- `refresh()`: re-fetches version list from adapter (called after save or restore)

## Blockers / Risks

- Summary computation for each version requires loading all version configs and diffing sequentially. With max 50 versions this is fine performance-wise, but if configs are large, initial summary computation may take a moment. Mitigation: compute summaries lazily or in a `useMemo` that only recomputes when the version array reference changes.

## Notes

The `onRestore` callback pattern: rather than having this hook directly call `useMappingEditor.save()` (which would create a circular dependency), the hook exposes `getRestoreConfig()` and the page-level code handles the actual restore + save orchestration. This keeps the hook focused on version data.

For diff computation against "current": use the `currentConfig` parameter (which should be the current working config from `useMappingEditor`). This means if the user has unsaved changes, the diff shows the difference from the historical version to the current (potentially unsaved) state. This is the most useful comparison for deciding whether to restore.
