## Summary

Add version history persistence methods to the `ApiAdapter` interface and implement them in `LocalStorageAdapter`. This establishes the data layer for all version history features — storing full MappingConfig snapshots on each save, retrieving the version list, and pruning old entries when the 50-version limit is exceeded. Also add the `MappingVersionEntry` domain type.

---

## Scope

### In Scope

- Add `MappingVersionEntry` type to `ui/src/lib/types/domain.ts`
- Add three new methods to `ApiAdapter` interface:
  - `listMappingVersions(mappingId: string): Promise<MappingVersionEntry[]>`
  - `getMappingVersion(mappingId: string, version: number): Promise<MappingVersionEntry>`
  - `saveMappingVersion(mappingId: string, entry: MappingVersionEntry): Promise<void>`
- Implement all three in `LocalStorageAdapter`:
  - Storage key pattern: `keyra:versions:{mappingId}`
  - Data stored as JSON array of `MappingVersionEntry`
  - `saveMappingVersion` appends entry and prunes if > 50
  - `listMappingVersions` returns sorted (most recent first)
  - `getMappingVersion` finds by version number, throws NOT_FOUND if missing
- Export `MappingVersionEntry` from types barrel

### Out of Scope

- Calling these methods from any hook or component (T-03+ handles that)
- Building diff logic (T-02)
- UI components
- Migration of existing mappings to have version history (existing mappings simply start with empty history)

## Change Requirements

After this task:

**`MappingVersionEntry` type:**
```typescript
export interface MappingVersionEntry {
  readonly version: number;
  readonly savedAt: string; // ISO 8601 timestamp
  readonly savedBy: string; // "You" in Phase 0
  readonly ruleCount: number;
  readonly config: MappingConfig; // full snapshot
}
```

**`ApiAdapter` additions:**
```typescript
// Version History
listMappingVersions(mappingId: string): Promise<MappingVersionEntry[]>;
getMappingVersion(mappingId: string, version: number): Promise<MappingVersionEntry>;
saveMappingVersion(mappingId: string, entry: MappingVersionEntry): Promise<void>;
```

**`LocalStorageAdapter` implementation:**

- Storage key: `keyra:versions:${mappingId}` — stores a JSON array of `MappingVersionEntry[]`
- `saveMappingVersion`:
  1. Read existing versions array (or empty if none)
  2. Append new entry
  3. If array length > 50, sort by version ascending and remove entries from the front until length === 50
  4. Write back to localStorage
  5. Handle quota exceeded gracefully (throw storage error with `retryable: false`)
- `listMappingVersions`:
  1. Read versions array
  2. Sort by version descending (most recent first)
  3. Return
- `getMappingVersion`:
  1. Read versions array
  2. Find entry where `entry.version === version`
  3. If not found, throw `notFound('MappingVersion', ...)`

## Notes

The `STORAGE_KEYS` object in `local-storage-adapter.ts` uses static keys for collections (`keyra:mappings`, etc.). Version history uses dynamic keys (`keyra:versions:{mappingId}`) because it's per-mapping data. This is a new pattern for the adapter. Use a helper method like `versionKey(mappingId: string)` to build the key.

Also add a cleanup hook: when `deleteMapping()` is called, also delete the associated version history key. This prevents orphaned version data.
