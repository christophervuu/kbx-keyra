## Summary

Write comprehensive unit and integration test coverage for the HTTP client utility, `HttpAdapter` CRUD operations, error normalization, placeholder methods, and bootstrap selection. Tests use Vitest with fetch mocking to verify all acceptance examples without requiring a running backend.

---

## Scope

### In Scope

- `ui/src/lib/api/http-client.test.ts` — HTTP client utility tests
- `ui/src/lib/api/http-adapter.test.ts` — HttpAdapter CRUD + placeholder tests
- `ui/src/lib/api/bootstrap.test.ts` — bootstrap selection tests (may already exist; update if so)
- Test coverage for:
  - All HTTP methods (GET/POST/PUT/DELETE)
  - All CRUD endpoints (correct URL construction, body serialization, response typing)
  - All error normalization scenarios (4xx, 5xx, network, timeout, malformed response)
  - Placeholder method behavior (correct error type/code/retryable)
  - Bootstrap selection logic (HttpAdapter vs LocalStorageAdapter)
  - `toAppError()` integration with `HttpClientError` and `AdapterMethodNotImplementedError`

### Out of Scope

- E2E tests against a real or mock backend server (separate verification step)
- Testing component-level behavior
- Testing existing `LocalStorageAdapter` or `HybridAdapter`

## Change Requirements

After this task:

- `http-client.test.ts` exists with tests covering:
  - Successful requests for each HTTP method
  - URL construction from baseUrl + path
  - JSON body serialization
  - Timeout behavior (AbortController fires)
  - Network failure detection (TypeError → retryable error)
  - Status code → error field mapping (400/401/403/404/409/429/500/502/503)
  - Error envelope parsing (`{ success: false, error: { code, message } }`)
  - Fallback when response body is not JSON
  - `toAppError()` produces correct `AppError` for each error type
- `http-adapter.test.ts` exists with tests covering:
  - Each of the 20 CRUD methods calls correct HTTP method + URL
  - Response is correctly typed and returned
  - Void-returning methods (delete, saveMappingVersion) work with 204
  - Error propagation (HTTP client errors bubble up correctly)
  - All placeholder methods throw `AdapterMethodNotImplementedError`
- `bootstrap.test.ts` exists with tests covering:
  - Truthy `apiUrl` → `HttpAdapter`
  - Falsy/absent `apiUrl` → `LocalStorageAdapter`
