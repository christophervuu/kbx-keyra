## Summary

Complete the `HttpAdapter` class by implementing all non-CRUD methods (AI, GitHub, deployment, templates, search, activity, preview) as structured placeholder throws. Each method throws an `AdapterMethodNotImplementedError` with a descriptive message, `code: "NOT_IMPLEMENTED"`, and `retryable: false` so that the UI error model handles these gracefully without crashes or misleading retry prompts.

---

## Scope

### In Scope

- New error class `AdapterMethodNotImplementedError` (extends `Error`, carries `code` and `retryable` fields)
- Placeholder implementations in `HttpAdapter` for:
  - Templates: `listTemplates`, `getTemplate`
  - Deployment: `getDeploymentContext`, `deploy`, `promote`, `rollback`, `getDeploymentDiff`
  - GitHub CDM: `listCdmSchemas`, `linkCdmSchema`, `syncCdmSchema`
  - GitHub Published: `listPublishedSchemas`, `publishSchemaToGitHub`, `linkPublishedSchema`
  - AI: `autoMap`, `autoMapSection`, `suggestExpression`, `explainRule`, `smartFix`, `validateMappings`
  - Search: `querySchemaNodes`
  - Activity: `listActivity`
  - Preview: `previewOnServer`

### Out of Scope

- Actual HTTP implementations for any of these methods
- Modifying the CRUD methods implemented in T-02
- Changing `ApiAdapter` interface

## Notes

- The `AdapterMethodNotImplementedError` pattern is intentionally distinct from the `LocalStorageAdapter`'s `Error("Not available in offline mode")` — it carries structured fields for the error model and communicates a different semantic (method exists but backend implementation pending vs. feature disabled in offline mode).
- Consider placing `AdapterMethodNotImplementedError` in a shared `ui/src/lib/api/errors.ts` file alongside `HttpClientError` if it makes module organization cleaner.
