## Summary

Create a typed HTTP client utility module (`ui/src/lib/api/http-client.ts`) that wraps `fetch` with configurable timeout, canonical envelope parsing (`{ success, data, error }`), automatic retry with exponential backoff for transient failures, and error normalization. This module is the foundational layer that `HttpAdapter` will consume for all HTTP operations. Errors thrown must carry `statusCode`, `code`, and `retryable` properties compatible with the existing `toAppError()` utility.

---

## Scope

### In Scope

- New file `ui/src/lib/api/http-client.ts`
- Typed `HttpClientError` class (extends `Error`) with `statusCode`, `code`, and `retryable` fields
- Core `httpRequest<T>(config)` function with:
  - Method (GET/POST/PUT/DELETE)
  - URL construction from base URL + path
  - JSON body serialization for non-GET requests
  - Configurable timeout (default 10s) via `AbortController`
  - Canonical envelope parsing: 2xx → parse `{ success: true, data: T }`, return `data` as `T`
  - Error envelope parsing: parse `{ success: false, error: { code, message } }`, extract into `HttpClientError`
  - Error handling: 4xx/5xx → construct `HttpClientError` with status, code, and retryable classification
  - Network failure → `HttpClientError` with `retryable: true`
  - Abort/timeout → `HttpClientError` with `retryable: true`
- Automatic retry with exponential backoff:
  - Retried: 429, 502, 503, 504 status codes
  - Retried: network failures and timeouts for GET requests only
  - Not retried: 400, 401, 403, 404, 409 or network failures on mutations
  - Max attempts: 3 (1 initial + 2 retries)
  - Backoff: 500ms base with exponential multiplier + jitter
- Helper `trimTrailingSlash` (can reuse pattern from `ai-api-client.ts`)
- Type exports for consumer use

### Out of Scope

- Authentication header injection
- Request/response interceptors
- Caching
- Response streaming

## Change Requirements

After this task:

- `HttpClientError` extends `Error` and carries: `statusCode?: number`, `code?: string`, `retryable: boolean`
- `httpRequest<T>()` accepts a config object: `{ baseUrl: string, path: string, method: 'GET' | 'POST' | 'PUT' | 'DELETE', body?: unknown, timeout?: number, retry?: boolean }`
- On 2xx response: parses canonical envelope `{ success: true, data: T }` and returns `data` as `T`
- On success envelope with `success: false`: throws `HttpClientError` with extracted `code`/`message` from `error` field
- On 4xx (except 429): throws `HttpClientError` with status code and `retryable: false`
- On 429: throws after retry exhaustion with `retryable: true`, `statusCode: 429`
- On 502/503/504: throws after retry exhaustion with `retryable: true`
- On other 5xx: throws `HttpClientError` with status code and `retryable: true` (no retry)
- On network failure (TypeError from fetch): retries for GET, throws immediately for mutations; error has `retryable: true`
- On timeout: retries for GET, throws immediately for mutations; error has `retryable: true`
- Retry backoff: 500ms * attempt number + random jitter (0-100ms)
- `toAppError(new HttpClientError(...))` produces a valid `AppError` with matching fields
- Envelope validation: if response is 2xx but body lacks `success: true` shape, throws `HttpClientError` with `retryable: false` and malformed-response message

## Notes

- Reference `ai-api-client.ts` patterns (AbortController timeout, JSON parsing, TypeError detection) but produce a more general/reusable module.
- The canonical envelope (`{ success: boolean, data?: T, error?: { code, message } }`) is the standard contract for all backend endpoints. Parse success envelopes to extract `data`; parse error envelopes to extract `code`/`message`.
- Use `vi.stubGlobal('fetch', ...)` or similar Vitest mocking for tests.
- Use `vi.useFakeTimers()` and `vi.advanceTimersByTime()` to test retry backoff without real delays.
- The retry strategy for mutations (POST/PUT/DELETE) is intentionally conservative: retry only for server-indicated transient errors (429/502/503/504), not for network failures, to avoid accidental duplicate writes.
