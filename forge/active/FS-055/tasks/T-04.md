## Summary

Modify `createAdapter()` in `ui/src/lib/api/bootstrap.ts` to return `HttpAdapter` (instead of `HybridAdapter`) when `VITE_API_URL` is present and non-empty. The `LocalStorageAdapter` path remains unchanged. `HybridAdapter` is retained in the codebase but formally deprecated with a dev-only console warning on instantiation.

---

## Scope

### In Scope

- Modify `ui/src/lib/api/bootstrap.ts`:
  - Import `HttpAdapter`
  - Change the `if (apiUrl)` branch to return `new HttpAdapter(apiUrl)`
  - Remove (or keep as unused) the `HybridAdapter` import
- Add formal deprecation to `ui/src/lib/api/hybrid-adapter.ts`:
  - Dev-only console warning in constructor: `console.warn('[KeyRa] HybridAdapter is deprecated. Use HttpAdapter via VITE_API_URL instead.')`
  - JSDoc `@deprecated` annotation on the class
- Verify `main.tsx` bootstrap still works with no changes

### Out of Scope

- Deleting `HybridAdapter` or `ai-api-client.ts`
- Modifying any component code
- Changing `AdapterProvider` or `useAdapter()`

---

## Relevant Areas

- `ui/src/lib/api/bootstrap.ts` — modified
- `ui/src/lib/api/http-adapter.ts` — import target
- `ui/src/lib/api/hybrid-adapter.ts` — deprecation warning added (retained in codebase)
- `ui/src/main.tsx` — call site (no changes)

## Change Requirements

After this task:

- `createAdapter()` returns `HttpAdapter` when `VITE_API_URL` is truthy
- `createAdapter()` returns `LocalStorageAdapter` when `VITE_API_URL` is falsy/absent
- The return type remains `ApiAdapter` (unchanged)
- `HybridAdapter` import is removed from `bootstrap.ts` (file itself is retained)
- `HybridAdapter` constructor emits `console.warn` in development builds only (guard with `import.meta.env.DEV`)
- `HybridAdapter` class has `@deprecated` JSDoc annotation
- No other files are modified beyond `bootstrap.ts` and `hybrid-adapter.ts`
