## Summary

Hydrate Source/Builder details for selected suggestions and implement preview behavior that cleanly handles missing sample context, enrichment input requirements, and non-destructive preview errors.

---

## Scope

### In Scope

- Suggestion detail cards (source refs, target metadata, diagnostics).
- Current vs suggested preview integration.
- `No sample selected` and incomplete-input messaging paths.
- Invalid suggestion edit-entry behavior.

### Out of Scope

- Backend validation implementation.

---

## Relevant Areas

- `ui/src/features/mappings/components/*`
- `ui/src/features/mappings/hooks/use-suggestion-preview.ts`
- detail/preview tests

---

## Change Requirements

- Keep preview failures isolated per row/details pane.
- Do not block review decisions when preview unavailable.
- Respect Advanced Mode visibility for generated expressions.

---

## Verification Requirements

- Component/hook tests for selected/unselected and sample/no-sample states.
- Tests for enrichment-input-required preview paths.

---

## Acceptance Checks

- Details show source/enrichment references and diagnostics correctly.
- Preview shows `No sample selected` when applicable.
- Invalid suggestions are editable even when direct accept is blocked.

---

## Blockers / Risks

- Risk: preview context drift when user switches sample/input set mid-review.

---

## Notes

- Reuse existing client-side engine preview primitives where possible.
