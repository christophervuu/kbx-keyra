## Summary

Implement asynchronous run execution (worker or Step Functions path) with fan-out processing, progressive writes into session suggestions, terminal partial semantics, and conditional write protection against superseded late writes.

---

## Scope

### In Scope

- Retrieval/generation/validation/persist/finalize orchestration flow.
- Progressive persistence of completed work-unit results.
- Retry/backoff policy for transient failures.
- Partial terminal-state computation.
- Superseded run/session conditional-write protections.

### Out of Scope

- UI polling/rendering.

---

## Relevant Areas

- run worker/orchestration lambdas
- Step Functions definitions
- orchestration integration tests

---

## Change Requirements

- Persist no-suggestion outcomes explicitly.
- Prevent superseded run writes from mutating canonical session state.
- Maintain idempotent work-unit completion semantics.

---

## Verification Requirements

- Integration tests for progressive writes, retries, partial termination, and idempotent duplicate callbacks.
- Tests for superseded late-write rejection.

---

## Acceptance Checks

- Run reaches `completed|partial|failed|superseded` deterministically.
- Successful outputs persist even when sibling units fail.
- Superseded late writes do not alter session summary or suggestions.

---

## Blockers / Risks

- Risk: high-concurrency contention on session partition.

---

## Notes

- Executor selection (small-worker vs Step Functions) is internal and must preserve identical API semantics.
