## Summary

Deliver backend API surface for session/run creation, status retrieval, suggestion pagination, decision updates with optimistic concurrency, batch actions, failed-unit retry, and mapping-level session lookup.

---

## Scope

### In Scope

- Session bootstrap and run start endpoints.
- Mapping-level open session lookup endpoint.
- Run status endpoint.
- Suggestion list endpoint with cursor/filter normalization.
- Single-suggestion decision endpoint (`expectedVersion`).
- Batch suggestion actions endpoint.
- Retry-failed run start endpoint.
- Capability exposure contract (`executionMode`).

### Out of Scope

- UI consumption.
- Worker orchestration internals.

---

## Relevant Areas

- `src/lambda/ai/*`
- `src/lambda/mapping/*`
- `src/lib/persistence/*`
- handler/integration tests

---

## Change Requirements

- Enforce one-open-session-per-mapping-revision behavior.
- Deduplicate equivalent active run starts by request fingerprint/idempotency key.
- Enforce limit contract: default 100, min 20 normalized, max 250.
- Emit opaque cursor bound to session + normalized filter hash + sort version.
- Preserve stable error envelopes and deterministic error codes.

---

## Verification Requirements

- Handler tests for request validation and envelope consistency.
- Integration tests for deduplication, session lookup determinism, pagination, and optimistic concurrency conflicts.

---

## Acceptance Checks

- Equivalent start requests return existing active run.
- Suggestion decision updates require valid `expectedVersion` and increment version on success.
- Batch endpoint returns applied/skipped counts with reasons.
- Retry endpoint starts retry-failed runs scoped to failed work units.

---

## Blockers / Risks

- Risk: ambiguous migration behavior between legacy and async modes.

---

## Notes
