## Summary

Ensure the `LiveResultDisplay` component (already rendered inside `UnifiedExpressionBuilder`) is properly wired to evaluate the current expression against available test/preview data in real-time. Show a clear empty state when no test data is loaded.

---

## Scope

### In Scope

- Ensure `LiveResultDisplay` in `UnifiedExpressionBuilder` receives source data from `PreviewContext`
- Wire `useExpressionPreview` with current expression and available source data
- Update result as expression changes (debounced via `useExpressionPreview`)
- Show "Load test data to see live result" empty state when no source data is available
- Show error state when expression fails to evaluate

### Out of Scope

- Changes to the bottom panel preview (InlinePreviewStrip / BottomArea)
- Changes to `useExpressionPreview` hook internals
- Adding a new source data input to the builder panel
- Backend round-trip evaluation
- Moving or restructuring `LiveResultDisplay` component

## Change Requirements

- `LiveResultDisplay` is already rendered inside `UnifiedExpressionBuilder`. Ensure it receives the correct props connected to live evaluation.
- `UnifiedExpressionBuilder` (or the parent `ScalarFieldBuilder`) should invoke `useExpressionPreview({ expression: currentExpression, sourceData })` where `sourceData` comes from the `PreviewContext`.
- Thread source data from `PreviewContext` into the builder surface if not already available.
- `LiveResultDisplay` props:
  - `result`: the evaluated result (formatted as JSON or primitive)
  - `error`: evaluation error string if present
  - `isEvaluating`: loading indicator
  - `isEmpty`: show empty state text
- When `sourceData` is null/undefined: show `"Load test data to see live result"` text instead of a result.
- When expression is empty: show nothing or subtle placeholder.
- When expression is valid and data is available: show the evaluated result formatted clearly.
- When expression has an error: show error message inline (distinct from diagnostics).

## Notes

- `LiveResultDisplay` is already rendered inside `UnifiedExpressionBuilder` (FS-023 architecture). The issue is that it may not be receiving source data from PreviewContext, or its `useExpressionPreview` may not be connected to the live expression stream during building.
- Source data availability depends on whether the user has loaded test data via the inline preview strip or test case manager. Access it via `PreviewContext`.
- The debounce in `useExpressionPreview` (300ms) handles rapid typing without excessive evaluation calls.
