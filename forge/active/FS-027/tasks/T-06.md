## Summary

Add an input-type selector to Value mode in the expression builder: "Source field" and "Static value". When "Static value" is selected, show a literal input/editor instead of the source picker. Static values must produce valid KeyRa DSL literals.

---

## Scope

### In Scope

- Add `inputType: 'source' | 'static'` to the Value mode state in `ExpressionBuilderState`
- Add UI toggle/selector in `SourceChipPicker` or Value mode header for input type choice
- When `inputType === 'source'`: show existing source search/selection UI
- When `inputType === 'static'`: show a literal value input (text input for strings, number input for numbers, toggle for booleans)
- Update `pipeline-expression-generator.ts` to handle static value state
- Inline validation: disallow Apply if static value is not a valid DSL literal
- Remove any existing standalone "Static value" button/action if it exists elsewhere

### Out of Scope

- Static values in Conditional mode branches (already handled by `BranchValueSelector`)
- Complex literal types (objects, arrays as static values)
- Changes to the DSL specification or function catalog

## Change Requirements

- Extend `ValueModeState` in `expression-builder-state.ts`:
  - Add `inputType: 'source' | 'static'` (default: `'source'`)
  - Add `staticValue: string` (default: `''`)
- `SourceChipPicker` (or a new containing component): render an input-type selector (segmented control or dropdown) above the source/static area.
  - When `'source'` is selected: render existing source picker UI.
  - When `'static'` is selected: render a text input for the static literal value.
- Expression generator: when `inputType === 'static'`:
  - If value looks like a number (parseable), emit raw number literal.
  - If value is `"true"` or `"false"`, emit boolean literal.
  - Otherwise, emit quoted string literal: `"value"`.
- Decomposer: when expression is a bare literal (string/number/boolean), decompose to `inputType: 'static'` with appropriate value.
- Validate static value before allowing Apply: non-empty, produces valid DSL.
- Remove any standalone "Static value" button/action that exists as a separate top-level control.

- Unit test: expression generator produces `"hello"` for static string input "hello".

- Unit test: expression generator produces `true` for static boolean input "true".
- Unit test: decomposer decomposes `"hello"` back to static value state.
- Component test: input-type selector toggles between source picker and static input (AE-07).
- Component test: Apply is enabled when static value is valid, disabled when empty.
- Typecheck passes.

---

## Notes

- String literals in KeyRa DSL are double-quoted. The generator should wrap user input in quotes for string values.
- Number detection: use `Number(value)` check + `!isNaN`.
- Boolean detection: exact match on `"true"` / `"false"`.
- The transform pipeline should still be available after static value selection (e.g., `upper("hello")` is valid).
