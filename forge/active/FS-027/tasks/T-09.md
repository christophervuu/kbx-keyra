## Summary

Ensure clicking Apply once commits the current expression to the working session, visibly updates the UI (disabled "Applied" state, mapped indicator on target row), and correctly updates dirty/clean state. No second click should be required.

---

## Scope

### In Scope

- Apply click commits expression via `applyRule(targetPath, expression)`
- On successful apply: disable Apply button with "Applied" or "Applied ✓" label
- On successful apply: target field row shows mapped indicator (immediately, not deferred)
- On successful apply: `isDirty` becomes `false` (via `lastAppliedExpression` update from T-01)
- Re-enable Apply only when the expression subsequently changes from the applied state
- Ensure no race condition or async gap causes the first click to appear to do nothing

### Out of Scope

- Changes to the Save flow
- Auto-advance behavior (removed in FS-025 T-04)
- Changes to the "Next unmapped" button
- The unapplied-expression modal logic (handled in T-01)

---

## Relevant Areas

- `ui/src/features/mappings/components/ScalarFieldBuilder.tsx`
- `ui/src/features/mappings/hooks/use-mapping-editor.ts`
- `ui/src/features/mappings/components/TargetFieldRow.tsx` (mapped indicator)

---

## Change Requirements

- `ScalarFieldBuilder` Apply button handler:
  1. Call `applyRule(targetPath, currentExpression)`.
  2. On success: set local state `applied = true`, update `lastAppliedExpression`.
  3. Show "Applied" (or "Applied ✓") text on the button, disable it.
  4. The target row's mapped indicator must reflect the new state immediately (ensure state propagation from `useMappingEditor` to `useTargetStatus` to row rendering is synchronous within the React commit).
- Re-enable Apply when `currentExpression !== lastAppliedExpression` (expression changes from applied state).
- If `applyRule()` is already synchronous (localStorage, no async), ensure there is no `setTimeout` or deferred state update causing a second render cycle that makes the first click appear to fail.
- If there is a debounce on expression commit in `useExpressionBuilder`, ensure Apply bypasses or flushes it.
