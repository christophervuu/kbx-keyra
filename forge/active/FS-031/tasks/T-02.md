## Summary

Implement the Prompt Registry client that loads versioned prompt records from DynamoDB with in-memory caching and a 5-minute TTL. Also implement a local file-based adapter for development and testing without DynamoDB access. Both adapters conform to the `PromptRegistryAdapter` interface defined in T-01.

## Change Requirements

### DynamoPromptRegistryAdapter

- Constructor accepts `tableName: string` and optional `DynamoDBDocumentClient` (for DI in tests)
- `getLatestPrompt(promptId)`:
  1. Check in-memory cache — if entry exists and is < 5 minutes old, return cached value
  2. On cache miss or expiry: query DynamoDB with `KeyConditionExpression: 'promptId = :pk'`, `ScanIndexForward: false`, `Limit: 1`
  3. If no items returned, return `null`
  4. Map DynamoDB item to `PromptRecord`, cache it, return it
  5. On DynamoDB error, throw with meaningful message (caller will catch and map to `AIError`)

### LocalPromptRegistryAdapter

- Constructor accepts `directoryPath: string`
- `getLatestPrompt(promptId)`:
  1. Check in-memory cache (same TTL logic)
  2. On cache miss: read file at `{directoryPath}/{promptId}.json`
  3. Parse as `PromptRecord`
  4. If file not found, return `null`
  5. Cache the result

### Factory Function

- `createPromptRegistryAdapter(config)`:
  - If `config.mode === 'local'` and `config.promptRegistryLocalDir` is set: return `LocalPromptRegistryAdapter`
  - Otherwise: return `DynamoPromptRegistryAdapter` with `config.promptRegistryTable`

### Cache Implementation

- Use a `Map<string, { record: PromptRecord; fetchedAt: number }>` for each adapter instance
- TTL check: `Date.now() - entry.fetchedAt < 300_000`
- Cache stores `null` results too (to avoid repeated queries for nonexistent prompts) — cache `null` with same TTL
