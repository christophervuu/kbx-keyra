## Summary

Implement the `invokeAI()` orchestration function that serves as the single reusable entry point for all AI features. This function wires together prompt loading, DSL reference injection, prompt rendering, model invocation, and output parsing into a cohesive pipeline. It accepts a `promptId` and request-scoped variables, and returns a normalized `AIResponse<T>`.

## Change Requirements

### invokeAI Function

```typescript
async function invokeAI<T = unknown>(
  promptId: string,
  variables: Record<string, string>,
  options?: InvokeAIOptions
): Promise<AIResponse<T>>
```

**Pipeline steps:**

1. **Resolve adapters**: use `options.promptRegistry` if provided, otherwise create default via `createPromptRegistryAdapter(loadConfig())`. Same for `dslAssetLoader`.

2. **Load prompt record**:
   - Call `promptRegistry.getLatestPrompt(promptId)`
   - If `null`: return `AIError { code: 'PROMPT_NOT_FOUND', message: '...' }`
   - If adapter throws: catch and return `AIError { code: 'REGISTRY_ERROR', message: '...' }`

3. **Load DSL reference**:
   - Call `dslAssetLoader.loadDslReference()`
   - If adapter throws: catch and return `AIError { code: 'ASSET_ERROR', message: '...' }`

4. **Render messages**:
   - Merge `{ dslReference }` with caller-provided `variables`
   - Call `renderPrompt(promptRecord, mergedVariables)`

5. **Validate configuration**:
   - Check that `GITHUB_TOKEN` is available
   - If missing: return `AIError { code: 'CONFIG_ERROR', message: '...' }`

6. **Invoke model**:
   - Parse `promptRecord.responseSchema` as JSON
   - Call model client with rendered messages, model, temperature, maxTokens, and parsed response schema
   - If model client returns an error: propagate it as `AIError`

7. **Parse output**:
   - Call `parseModelOutput()` with the raw response content
   - Return the `AIResult<T>` or `AIError`

**Error isolation**: Each pipeline step is wrapped in try-catch so that errors at any stage produce a meaningful `AIError` rather than an unhandled exception.

### Default Adapter Caching

The default adapters (created when no overrides are provided) should be module-level singletons so that the cache persists across multiple `invokeAI()` calls within the same Lambda instance. Use lazy initialization:

```typescript
let defaultRegistry: PromptRegistryAdapter | null = null;
let defaultDslLoader: DslAssetLoader | null = null;

function getDefaultRegistry(): PromptRegistryAdapter {
  if (!defaultRegistry) defaultRegistry = createPromptRegistryAdapter(loadConfig());
  return defaultRegistry;
}
```
