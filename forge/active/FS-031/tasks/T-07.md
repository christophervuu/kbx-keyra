## Summary

Implement the `aiExplainRule` Lambda handler as the first consumer of the shared AI runtime. This is a thin handler that parses the API Gateway event body, validates required fields, calls `invokeAI('explain-rule', ...)`, and returns the response. It demonstrates the pattern that all future AI Lambdas will follow.

## Change Requirements

### Handler Implementation

```typescript
export async function handler(
  event: APIGatewayProxyEvent
): Promise<APIGatewayProxyResult> {
  // 1. Parse body
  // 2. Validate required fields
  // 3. Call invokeAI
  // 4. Return response
}
```

**Request validation:**
- Parse `event.body` as JSON
- If body is null/undefined or unparseable: return 400 with `{ error: 'Invalid request body' }`
- Require `targetPath` (string) and `expression` (string) in the body
- If either is missing: return 400 with `{ error: 'Missing required field: {fieldName}' }`

**Invocation:**
- Call `invokeAI('explain-rule', { targetPath, expression })`
- If `result.success === true`: return 200 with `result`
- If `result.success === false`: return 500 with `result` (or 404 if `PROMPT_NOT_FOUND`, 429 if `MODEL_RATE_LIMITED`)

**Response formatting:**
- All responses include `Content-Type: application/json` header
- All responses include CORS headers (`Access-Control-Allow-Origin: *`) for API Gateway integration
- Response body is always a JSON string

**Error status code mapping:**
- `PROMPT_NOT_FOUND` → 404
- `MODEL_RATE_LIMITED` → 429
- `VALIDATION_ERROR` → 400
- All other errors → 500

### Type Definitions

If `@types/aws-lambda` is not already available, define minimal inline types:

```typescript
interface APIGatewayProxyEvent {
  body: string | null;
  headers: Record<string, string | undefined>;
  // ... other fields as needed
}

interface APIGatewayProxyResult {
  statusCode: number;
  headers?: Record<string, string>;
  body: string;
}
```

Prefer adding `@types/aws-lambda` as a dev dependency for full type coverage.

## Notes

- This handler is intentionally minimal. It exists to prove the shared runtime pattern works and to serve as a template for future AI Lambdas.
- The handler should NOT import directly from DynamoDB, S3, or OpenAI — only from `src/lib/ai/`.
- For unit testing, mock the `invokeAI` function (e.g., using `vi.mock()`) rather than mocking all underlying adapters. This tests the handler's thin responsibilities (parsing, validation, response formatting) in isolation from the runtime.
- Consider whether to use `@types/aws-lambda` or inline types. `@types/aws-lambda` provides comprehensive types but is a dev dependency. Inline types are lighter. Either approach is acceptable.
