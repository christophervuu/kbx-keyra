## Summary

Apply the findings from T-01 to update `forge/architecture/project-structure.md` so that every documented path exists in the repository and every architecturally significant directory is documented. Remove phantom entries, add missing entries, and correct any stale descriptions.

---

## Scope

### In Scope

- Removing documented paths that do not exist in the repository
- Adding architecturally significant paths that exist but are not documented
- Correcting stale descriptions for documented paths that exist but whose purpose has changed
- Preserving the existing document structure and formatting conventions
- Updating rules/constraints sections if they no longer reflect reality
- Ensuring the document is internally consistent (no contradictions between sections)

### Out of Scope

- Adding individual component files within already-documented directories (maintain current granularity level)
- Changing the document structure or format
- Adding new sections beyond what the current format supports
- Making code changes
- Updating other architecture documents (T-05, T-06 handle those)

---

## Relevant Areas

- `forge/architecture/project-structure.md`
- T-01 audit findings (input)

---

## Change Requirements

Based on T-01 findings:

1. **Remove phantom entries**: Any path documented in `project-structure.md` that does not exist in the repository must be removed. If the documented path represents planned-but-not-yet-built work, it may be retained only with an explicit `[planned — not yet implemented]` annotation.

2. **Add missing entries**: Any architecturally significant directory that exists in the repository but is not documented must be added with an accurate description at the appropriate granularity level.

3. **Correct stale descriptions**: Any entry whose description no longer matches its actual purpose must be updated.

4. **Update rules sections**: If the Rules section contains statements that are no longer accurate (e.g., "Types shared between engine and UI are defined in `src/types/`" when that directory doesn't exist), correct them to reflect reality.

5. **Preserve conventions**: Maintain the existing formatting (code blocks for directory trees, `---` separators, bold labels, etc.).

---

## Verification Requirements

- After update, every path listed in `project-structure.md` can be confirmed to exist via filesystem traversal (or is explicitly annotated as planned/not-yet-implemented)
- After update, no architecturally significant directory in the repository is missing from the document
- The document is internally consistent (no path referenced in a rules section that isn't shown in the tree)

---

## Acceptance Checks

- `src/types/` entry is removed or corrected (known drift point from T-01)
- All T-01 "documented but missing" findings are resolved (removed or annotated)
- All T-01 "present but undocumented" findings are resolved (added to document)
- Document passes a self-consistency check (paths in rules match paths in trees)
- No formatting or structural changes beyond what is needed for accuracy
