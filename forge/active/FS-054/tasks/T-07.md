## Change Requirements

Create `forge/architecture/phase-1-readiness.md` with the following structure:

### 1. Purpose and Scope
Brief explanation: this document captures the Phase 0 → Phase 1 boundary as revealed by the reconciliation pass.

### 2. Adapter Boundary Inventory
For each `ApiAdapter` method:
- Method signature
- Current behavior (localStorage)
- Phase 1 requirement (what the backend must provide)
- Category: CRUD / compute / AI / deployment / integration
- Complexity notes (pagination needed? optimistic updates? real-time? etc.)

### 3. Phase 0 Simplifications Requiring Phase 1 Resolution
For each intentional simplification:
- What was simplified
- Why (Phase 0 scope constraint)
- What Phase 1 must do to resolve it
- Priority/urgency for Phase 1

Examples expected:
- XSD permissive stub
- localStorage data limits
- No concurrent user support
- No authentication/authorization
- No server-side validation
- No real deployment pipeline
- No real GitHub integration (placeholder methods)

### 4. Implementation Constraints on Backend Design
Current frontend implementation assumptions that constrain how the backend can be designed:
- Expected response shapes (from adapter return types)
- Expected error handling patterns
- Expected latency model (synchronous adapter calls)
- Expected data consistency model (immediate consistency, no eventual consistency)
- Schema/type contracts the backend must satisfy

### 5. AI Showcase Transition Path
- Current state: HybridAdapter routes specific AI methods to HTTP
- What exists in backend (Lambda handlers, AI runtime)
- What Phase 1 extends (broader HttpAdapter, authentication, etc.)
- Compatibility considerations

### 6. Engine Integration Points
- Where the engine is consumed today (UI-only, browser-only)
- Where Phase 1 adds engine consumption (Lambda handlers, server-side validation)
- Bundle/deployment implications
- Performance expectations documented during engine spec

### 7. Reconciliation Summary
Brief summary of what was found during reconciliation:
- What was implemented as planned
- What was intentionally simplified or changed
- What was unresolved

### 8. Open Questions for Phase 1 Planning
Numbered list of questions that must be resolved before Phase 1 spec drafting begins.
