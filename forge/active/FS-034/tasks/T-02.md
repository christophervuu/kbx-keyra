## Summary
Add a `TestRunResult` domain type and a new `useTestRunResults(mappingId)` hook that manages per-test-case run result persistence in a separate localStorage key. This separates run results from test case definitions for backward compatibility and clean data modeling.

---

## Scope

### In Scope
- Add `TestRunResult` interface to `ui/src/lib/types/domain.ts`
- Create `useTestRunResults(mappingId)` hook at `ui/src/features/mappings/hooks/use-test-run-results.ts`
- Hook API: `results`, `recordResult`, `clearResult`, `clearAll`
- localStorage key: `keyra:testresults:{mappingId}`
- Corruption handling (same pattern as `useTestCases`)
- Export from feature barrel

### Out of Scope
- Batch execution logic (separate task)
- UI rendering of results
- Modifying existing `useTestCases` hook

- `ui/src/features/mappings/hooks/use-test-run-results.ts` (new)
- `ui/src/features/mappings/hooks/use-test-run-results.test.ts` (new)

## Change Requirements
- `TestRunResult` interface: `testCaseId: string`, `status: 'pass' | 'fail'`, `errorCount: number`, `warningCount: number`, `executedAt: ISODateString`, `durationMs: number`, `outputSnapshot?: unknown`
- `useTestRunResults(mappingId)` returns:
  - `results: Readonly<Record<string, TestRunResult>>` — keyed by testCaseId
  - `recordResult(testCaseId: string, result: TestRunResult): void` — upsert and persist
  - `clearResult(testCaseId: string): void` — remove single result and persist
  - `clearAll(): void` — remove all results for the mapping
- Storage reads on mount and when `mappingId` changes (same pattern as `useTestCases`)
- Corrupted localStorage data resets to empty record with console warning
- Storage write failures are handled gracefully (same pattern)
