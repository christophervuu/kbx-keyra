## Summary

Implement the chain-model transformation step form. Each transform step operates on the current value (implicit first argument) and presents only additional parameters for user input. The UX is task-oriented: instead of showing raw function signatures, it shows plain-language descriptions and labeled parameter fields. The existing `TransformFunctionPicker` is reused for function selection.

---

## Scope

### In Scope

- Transform step form component: `TransformStepForm` (or similar name)
- Implicit current value: the first argument of the transform function is NOT shown as a user-editable field
- Additional parameter fields: rendered with labels, type hints, and input controls
  - Source parameter: source field picker
  - Literal parameter: text input with type badge
  - Expression parameter: raw DSL mini-input
- `[+ Add input]` button for variadic functions like `concat` (AE-07)
- Function selection: reuse `TransformFunctionPicker` with type-compatible filtering
- Task-oriented presentation:
  - Function name as step header
  - Plain-language description from `DSL_FUNCTION_CATALOG`
  - Parameter labels from catalog (not raw param names)
- Step removal: X button to remove a transform step from the chain
- Step reordering: optional, via drag handles (stretch goal)

### Out of Scope

- Condition steps (T-09)
- Value map steps (T-10)
- Collapsible summaries (T-11)
- Expression generation (T-02)

## Change Requirements

- Create `TransformStepForm` component:
  - Header: function name + brief description from catalog
  - Body: additional parameter fields (everything except the implicit first arg)
  - Each parameter: labeled input with type badge and placeholder
  - For variadic functions (e.g., `concat`): render existing args + `[+ Add input]` button
  - `[+ Add input]` appends a new `ArgumentSlot` to `step.args`
  - Remove button per additional arg (except minimum required)
  - Step remove button (X or trash icon)
- Parameter slot inputs should support:
  - Source field (picker or typed path)
  - Literal value (text input)
  - The slot mode (source/literal) should be switchable
- The implicit first argument offset must be applied: when rendering additional args from `TransformLogicStep.args`, the first catalog parameter is skipped (it's the current value)
- Fires `onStepChange(index: number, step: TransformLogicStep)` callback on any parameter change
- Fires `onRemoveStep(index: number)` callback on step removal
