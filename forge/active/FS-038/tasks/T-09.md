## Summary

Implement the redesigned inline Condition builder for the chain model. The condition step renders inline in the chain, requires an else branch (always present), supports full chains in then/else branches (static value, source+transforms, or raw expression), and collapses to a compact one-line summary when complete.

---

## Scope

### In Scope

- Inline condition form: IF / THEN / ELSE layout
- IF row: left operand (defaults to current accumulated value, shown explicitly), operator picker, right operand
- "Change input" affordance on the left operand: allows switching from current accumulated value to a different source field (Q1/Q6 resolved at Rev 2)
- Operator set: equals, not equals, greater than, less than, contains, starts with, is null, is not null (reuse existing `ComparisonOperator` set)
- THEN branch: static value input, source picker, or raw expression
- ELSE branch: required, always rendered, supports same options as THEN
- ELSE branch explicitly supports: null, empty string (`""`), 0, or any defined value
- `[+ Add else-if]` button: adds nested condition in else branch (up to 5 levels, consistent with FS-023)
- Compound conditions: AND/OR groups (reuse existing `ConditionGroup` pattern)
- Collapsed summary: one-line readable text (e.g., `if tier = "premium" then "VIP" else "Standard"`)
- Click-to-expand from collapsed summary
- State mapping: `ConditionLogicStep` → `ChainBranch` for then/else

### Out of Scope

- Full InlinePipelineBuilder within branches (use simplified static/source/expression branches initially — full chain branches are a stretch goal per Q5)
- Transform steps within condition branches (deferred to integration polish)
- Value map or nested condition builders in branches (beyond else-if)

## Change Requirements

- Create `ChainConditionForm` component (or similar name):
  - IF section:
    - Left operand: defaults to "current value" label (the accumulated chain expression) — shown explicitly, not hidden (Q6 resolved at Rev 2)
    - "Change input" link/button below left operand: switches from current value to a source field picker or literal input (Q1 resolved at Rev 2)
    - Operator: dropdown from `ComparisonOperator` set
    - Right operand: literal input or source picker
  - THEN section:
    - Branch value selector: Static / Source / Expression
    - Renders appropriate input for selected kind
  - ELSE section:
    - Always present (required) — pre-created with empty value
    - Same branch value selector as THEN
    - Explicit options for null, empty string, 0 as common else values
  - `[+ Add else-if]` button in else section
  - Compound condition support: `[+ Add AND condition]` / toggle AND↔OR
- Collapsed summary rendering:
  - `summarizeConditionStep(step: ConditionLogicStep): string`
  - Format: `if {left} {op} {right} then {then} else {else}`
  - Truncate long values with ellipsis
- Fires `onStepChange(index, step: ConditionLogicStep)` on any field change
- Fires `onRemoveStep(index)` on step removal
- Else branch validation: Apply is disabled when else branch value is empty

## Notes

- The condition left operand defaulting to "current value" is key to the chain model — the user is adding a condition ON the value they've been building, not switching to a separate concept. Q1 and Q6 resolved at Rev 2 confirm this default, with an explicit "Change input" escape hatch for cases where the user wants to test a different field.
- The `[+ Add else-if]` mechanism reuses the existing FS-023 pattern of nested `if()` in the else branch.
