## Summary

Wire the new chain builder into the `ExpressionBuilderPanel` used in Rules View, replacing the current `UnifiedExpressionBuilder` usage. This ensures both Target View (ScalarFieldBuilder) and Rules View (ExpressionBuilderPanel) use the same redesigned builder.

---

## Scope

### In Scope

- Replace `UnifiedExpressionBuilder` in `ExpressionBuilderPanel` with the chain builder
- Wire `ChainBuilderState` management for Rules View context:
  - Hydrate from selected rule's expression
  - Generate expression on state change
  - Debounced commit to rule store
- Preserve Builder/Editor toggle behavior
- Preserve decomposition warning for complex expressions
- Preserve `useExpressionBuilder` hook integration or adapt it for the new model

### Out of Scope

- Removing `UnifiedExpressionBuilder` component from codebase (it may still be used by other surfaces)
- Changes to `RuleList` or rule selection mechanics

---

## Relevant Areas

- `ui/src/features/mappings/components/ExpressionBuilderPanel.tsx` — primary file to modify
- `ui/src/features/mappings/hooks/use-expression-builder.ts` — may need adaptation
- `ui/src/features/mappings/components/ChainBuilderShell.tsx` (T-04)
- `ui/src/features/mappings/lib/chain-decomposer.ts` (T-03)
- `ui/src/features/mappings/lib/chain-expression-generator.ts` (T-02)

---

## Change Requirements

- Modify `ExpressionBuilderPanel` to use the chain builder in builder mode:
  - When builder mode is active: render `ChainBuilderShell` with chain builder content
  - When editor mode is active: render `RawDslEditor` (unchanged)
- Adapt `useExpressionBuilder` hook or create a new hook (`useChainExpressionBuilder`):
  - Load selected rule expression → `decomposeToChainState()` → hydrate or fall back to editor
  - On state change → `generateExpressionFromChain()` → debounced commit
  - Mode toggle orchestration
- The Rules View builder does not have a persistent target field context, so the header row should adapt:
  - Show rule target path and type if available from the selected rule
  - Or show a simplified header without target context
- Preserve source field insertion: `expressionBuilderRef.insertSourceField(path)` should work with the new builder (update source path in chain state)
