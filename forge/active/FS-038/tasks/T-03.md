## Summary

Implement a function `decomposeToChainState(expression: string): DecomposeChainResult` that parses a DSL expression string and returns the equivalent `ChainBuilderState`, or a failure reason. This is the reverse path from DSL → state. It must handle new chain-model expressions, legacy FS-023/FS-029/FS-030 expressions, and hand-written DSL.

---

## Scope

### In Scope

- New decomposer function: `decomposeToChainState(expression: string): DecomposeChainResult`
- Result type: `{ success: true; state: ChainBuilderState } | { success: false; reason: string }`
- Decomposition of source direct copy: `source("path")` → source entry, no logic steps
- Decomposition of static literals: `"hello"`, `42`, `true`, `null` → static entry, no logic steps
- Decomposition of `static("value")` wrapper → static entry (backward compat)
- Decomposition of transform chains: `upper(source("x"))` → source + transform step
- Decomposition of nested chains: `round(multiply(source("x"), 10), 2)` → source + [multiply, round] steps
- Decomposition of conditions: `if(eq(source("x"), "y"), "a", "b")` → source + condition logic step
- Decomposition of value maps: `valueMap(source("x"), {...}, default)` → source + value map logic step
- Decomposition of mixed chains: `if(gt(upper(source("x")), "M"), ...)` → source + transform + condition
- Backward compatibility with expressions generated by FS-023/FS-029/FS-030
- Graceful failure for unrecognizable expressions (return reason string)

### Out of Scope

- Modifying existing decomposers (`pipeline-decomposer.ts`, `source-card-decomposer.ts`)
- UI components or hydration logic (T-12 handles builder integration)

## Change Requirements

- Create `chain-decomposer.ts` with the public function `decomposeToChainState`
- The function must be pure (no side effects)
- Use the engine's `parse()` function to obtain AST, then walk the AST to construct `ChainBuilderState`
- Decomposition strategy:
  1. Parse expression → AST
  2. If parse fails → return failure
  3. If root is `source("path")` literal → source entry, direct copy
  4. If root is a bare literal (string/number/boolean/null) → static entry
  5. If root is `static(...)` → static entry (backward compat)
  6. If root is `if(...)` → attempt to extract source from condition operands; create condition logic step
  7. If root is `valueMap(...)` → extract source from first arg; create value map logic step
  8. If root is function call → chain-walk through first arguments (same pattern as `source-card-decomposer.ts` CHAINABLE_TRANSFORMS logic) to find source base; collect transform steps
  9. If chain-walk fails → return failure with reason
- Reuse `CHAINABLE_TRANSFORMS` from `transform-chain-utils.ts` for chain-walking decisions
- `ChainBranch` decomposition: attempt to decompose each branch expression into static/source/expression kinds
- Export from feature barrel
- Round-trip test: `decomposeToChainState(generateExpressionFromChain(state))` should return equivalent state for all well-formed states

## Notes

- The decomposer should be designed as the single entry point for DSL → chain state conversion. The integration task (T-12) will use this instead of the legacy `decomposeExpression` / `decomposeToSourceCardState` cascade.
