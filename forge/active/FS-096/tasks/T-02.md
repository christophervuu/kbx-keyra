## Summary

Extend DSL and engine behavior so `valueMap()` accepts either inline object literals or a valid `valueTable(...)` accessor tied to pinned resolved mapping data. Add static and runtime validations for table/side/direction errors while preserving full inline compatibility.

---

## Scope

### In Scope

- Update parser/AST/function signature behavior for `valueTable(tableKey, inputSideKey, outputSideKey)`.
- Update `valueMap` validation rules to accept object literal or object-producing `valueTable(...)` expression.
- Add engine validation for unknown table/side keys, same-side errors, invalid direction, duplicate input keys, missing resolved table data/revision, and fallback type mismatches.
- Update runtime lookup implementation to use resolved entries from mapping config only.
- Add diagnostics registry entries and deterministic message templates.

### Out of Scope

- Backend API implementation and persistence of value tables.
- UI management/editor flows.

---

## Relevant Areas

- `src/engine/dsl/*`
- `src/engine/functions/lookup.ts`
- `src/engine/validate/*`
- `src/engine/types/*`
- `src/engine/diagnostics/*`
- `tests/engine/**/*`

---

## Change Requirements

- Grammar changes must not break existing inline `valueMap()` syntax.
- Engine must remain I/O-free and rely exclusively on mapping-config supplied resolved table data.
- Invalid directions must never silently resolve by “first row” behavior.

---

## Verification Requirements

- Unit/integration tests for parser, validator, execute fallback modes, ambiguity handling, and inline backward compatibility.
- Diagnostics tests verify stable code+message+location payloads.
- Typecheck/lint pass for engine modules.

---

## Acceptance Checks

- `valueTable(...)` parses and validates under new DSL rules.
- `valueMap(...)` accepts inline or `valueTable(...)` mapping sources.
- Engine rejects invalid table references/directions with stable diagnostics.
- Inline `valueMap()` behavior remains fully compatible.

---

## Blockers / Risks

- High regression risk in core lookup behavior if inline path is not fully protected by tests.

---

## Notes

- Follow existing engine diagnostic and pure-function conventions in `mapping-engine.md`.
