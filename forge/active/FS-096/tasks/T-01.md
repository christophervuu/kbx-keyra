## Summary

Introduce canonical shared types for project value tables, revisions, mapping rule references, no-match policies, and usage metadata. Extend adapter contracts so UI can manage project tables and resolve/pin revisions consistently across LocalStorageAdapter and HttpAdapter.

---

## Scope

### In Scope

- Add domain types/interfaces for project value table metadata, revisions, direction support, usage entries, and diff summaries.
- Add mapping-config type extensions for pinned revision + resolved lookup entries.
- Extend `ApiAdapter` with value-table methods (list/get/create revision/archive/usage/diff/import/export/resolve before save).
- Add baseline type tests and adapter contract tests to enforce parity expectations.

### Out of Scope

- Backend handler implementation details.
- React UI component behavior.
- Engine parser/evaluator logic.

---

## Relevant Areas

- `ui/src/lib/api/types.ts`
- `ui/src/lib/types/domain.ts`
- `ui/src/lib/api/http-adapter.ts`
- `ui/src/lib/api/local-storage-adapter.ts`
- adapter test suites in `ui/src/lib/api/*.test.ts`

---

## Change Requirements

- Contracts must encode direction-neutral table definition and per-rule direction ownership.
- Mapping config model must support pinned revision and resolved entries for offline execution.
- Adapter method signatures must support optimistic UI flows and deterministic error handling.

---

## Verification Requirements

- Typecheck passes for shared model and adapter surfaces.
- Adapter contract tests cover method availability and consistent return shapes.
- New/updated fixtures validate serialization of pinned table references.

---

## Acceptance Checks

- Shared model types for value tables/revisions/rule refs are present and used by adapters.
- `ApiAdapter` includes complete value-table management and resolve/adoption contract methods.
- Local and HTTP adapters compile against the same extended interface.

---

## Blockers / Risks

- Contract drift risk if backend routes are implemented before shared types settle.

---

## Notes

- Keep additive compatibility for existing mappings with inline-only `valueMap()` rules.
