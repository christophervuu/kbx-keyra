## Summary

Add a toggle-able breadcrumb drill-down navigation mode for the Target Worklist that allows users to focus on a single subtree when working with deeply nested schemas (5+ levels). When enabled, clicking an object/array node isolates that subtree as the current view with a breadcrumb trail for navigating back up.

---

## Scope

### In Scope

- Breadcrumb mode toggle button (in Global Toolbar or Target Worklist header)
- When breadcrumb mode is active and user clicks an object/array node:
  - Worklist view isolates to show only that node's children
  - Breadcrumb trail renders above the worklist showing the navigation path
  - Clicking a breadcrumb segment navigates up to that level
  - Clicking root/home breadcrumb restores full tree view
- `BreadcrumbNav` component for rendering the navigation trail
- Breadcrumb state: `currentSubtreePath: string | null` (null = full tree)
- Integration with `TargetWorklist` to filter displayed nodes based on breadcrumb path

### Out of Scope

- Changing default tree rendering behavior (indented tree remains default)
- Modifying how field selection works (clicking fields still opens builder)
- Keyboard navigation through breadcrumbs (defer)

## Change Requirements

After this task is complete:

- Breadcrumb mode toggle button exists (e.g., "Focus mode" toggle)
- When toggled on and user clicks an object/array node, worklist isolates to that subtree
- `BreadcrumbNav` renders: `Root > parent > child > current` with clickable segments
- Clicking a breadcrumb segment sets `currentSubtreePath` to that segment's path
- The `TargetWorklist` respects `currentSubtreePath` — when set, only renders nodes within that subtree
- When breadcrumb mode is off, clicking object/array nodes behaves normally (opens summary/builder)
- Breadcrumb mode state is managed at the composition level alongside other toolbar state
- Breadcrumb trail uses `>` or `/` separator and truncates if too many segments

## Notes

- This is an additive feature on top of the default tree view. The default behavior is unchanged — users must explicitly enable breadcrumb mode.
- Useful for schemas with 5+ levels of nesting where the full tree becomes overwhelming.
- Keep the breadcrumb UI compact — it should not take significant vertical space from the worklist.
