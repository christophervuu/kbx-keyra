## Summary

Build the Global Toolbar component that sits above the three-column layout providing target field search, filter toggles (All/Unmapped/Warnings/Required/Arrays), sort options, section-level actions, and the Rules View toggle. This toolbar controls the filtering/sorting state consumed by the Target Worklist.

---

## Scope

### In Scope

- `GlobalToolbar` component with:
  - Search input: text field that filters target fields by name/path
  - Filter buttons: All (default), Unmapped, Warnings, Required, Arrays — toggleable, mutually exclusive or combinable (design decision: combinable filters)
  - Sort dropdown/toggle: Schema order (default), Unmapped first, Required first
  - Section action button: "Auto-map Section" — **disabled**, muted style (grayed icon + label), tooltip: "AI-powered auto-mapping — available in a future release"
  - View toggle: "Target View" (default, active) / "Rules View" button
- Emits state changes via callbacks:
  - `onSearchChange(query: string)`
  - `onFilterChange(filters: TargetFilter[])`
  - `onSortChange(sort: TargetSort)`
  - `onViewToggle(view: 'target' | 'rules')`
- Visual: compact horizontal bar, dark theme consistent with editor
- Active filter/sort state visually indicated (highlighted button, active badge)

### Out of Scope

- Implementing filter/sort logic on the tree (owned by T-02 `TargetWorklist`)
- Implementing Rules View content (T-12)
- Auto-map logic implementation (placeholder only)
- Keyboard shortcuts for toolbar actions

## Change Requirements

After this task is complete:

- `GlobalToolbar` renders a horizontal bar with search, filters, sort, and view toggle
- Search input accepts text and fires debounced `onSearchChange` (300ms debounce)
- Filter buttons toggle on/off and fire `onFilterChange` with current active set
- Sort toggle/dropdown changes sort mode and fires `onSortChange`
- "Auto-map Section" button renders **disabled** with muted visual style and tooltip "AI-powered auto-mapping — available in a future release". No click handler fires.
- View toggle switches between "Target View" and "Rules View" and fires `onViewToggle`
- Active states are visually distinct (e.g., highlighted background on active filter)
- Types exported: `TargetFilter = 'unmapped' | 'warnings' | 'required' | 'arrays'` and `TargetSort = 'schema' | 'unmapped-first' | 'required-first'`
