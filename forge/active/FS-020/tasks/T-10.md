## Summary

Implement the empty/first-run state for the redesigned Mapping Editor — when no rules exist yet, the right panel shows target-driven guidance text and action CTAs rather than the legacy "No rules yet" message. The target worklist renders fully with all fields showing unmapped status.

---

## Scope

### In Scope

- Right panel empty state component (`BuilderEmptyState`) showing:
  - Guidance text: "Select a target field to create its mapping"
  - CTAs: "Start with required fields" (filters worklist), "Auto-map this schema" (**disabled**, muted style, tooltip: "AI-powered auto-mapping — available in a future release"), "Select a target field" (visual pointer to worklist)
- Ensure target worklist renders all fields with unmapped markers on first load (no rules)
- Remove/replace any legacy "No rules yet. Add your first rule." messaging from the new layout
- CTAs fire appropriate callbacks:
  - "Start with required fields" → sets filter to 'required'
  - "Auto-map this schema" → **disabled** button with muted style and tooltip: "AI-powered auto-mapping — available in a future release"
  - "Select a target field" → visual hint or scroll to first field

### Out of Scope

- Auto-map implementation
- Modifying the target worklist's unmapped rendering (handled in T-02)
- Rules View empty state (legacy behavior preserved)
