## Summary

Build the `ArrayMappingBuilder` component — a dedicated multi-step guided workflow that appears in the right panel when an array target node is selected. The workflow guides users through: (1) choosing a source collection, (2) selecting a mapping pattern, (3) mapping item fields with drag-and-drop, and (4) previewing sample output. This ensures array mapping authoring has a purpose-built UX distinct from scalar field editing.

---

## Scope

### In Scope

- `ArrayMappingBuilder` component with 4-step guided workflow:
  - **Step 1 — Source Collection:** Display available source arrays from parsed source schema. User selects one.
  - **Step 2 — Pattern Selection:** Offer patterns: "1:1 map", "Filter then map", "Merge arrays", "Build from scalars", "Advanced/Custom (raw DSL)". User selects one.
  - **Step 3 — Item Field Mapping:** Show target item fields on the right, source item fields on the left. Support drag-and-drop to create field-to-field mappings. Show mapped pairs. Allow unmapping. **One level only** — nested arrays within items are not mapped in this step.
  - **Step 4 — Preview:** Show a sample output based on the configured mapping (using engine's evaluate or a static mock). Show the generated DSL expression.
- Step indicator (reuse existing `BuilderStepIndicator` component pattern)
- Navigation: Next/Back between steps, save on Step 4
- Save generates the appropriate DSL expression (e.g., `map(source("path"), template(...))`) and fires `onSave` callback
- "Advanced/Custom" pattern in Step 2 bypasses Steps 3-4 and opens raw DSL editor for the array expression
- **Nested array escape hatch:** When the target array is nested inside another array:
  - Builder still opens normally for the inner array
  - A contextual info banner displays: "This array is nested inside {parentArrayName}. The outer array mapping must be configured first." with a clickable link to select the parent array node
  - Raw DSL toggle remains available for users who want to author the full nested expression manually

### Out of Scope

- Preview display in bottom area (T-08) — Step 4 preview is inline summary only
- Source panel drag-and-drop infrastructure (T-09) — Step 3 has its own internal DnD for item fields
- **Nested array-in-array guided mapping** (deferred — one level only in v1)
- Engine execution for live preview (use static mock in v1)

## Notes

- Review `specs/KEYRA-DSL-ARRAYS.md` before implementing the expression generator to ensure generated DSL matches the array scoping model.
- Step 3 DnD can use a simpler implementation than the cross-panel DnD (e.g., HTML5 drag API or even click-to-pair as fallback).
- For v1, the "Preview" in Step 4 can show a static JSON example rather than running the engine. The generated expression is the primary deliverable.
- **One level only**: Step 3 shows only direct scalar/simple children of the array items as mappable fields. If an item contains a nested array, that nested array node appears in the list but is not draggable — it shows a "map separately" hint indicating the user should select that nested array in the target tree to map it independently.
- The nested array banner uses the `isNestedArray` detection: check if any ancestor in the target schema path is also an array type.
