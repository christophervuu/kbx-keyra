## Summary

Replace the duplicated inline `TYPE_ICON` maps and custom option row rendering in `SourceFieldPicker` and `SourceChipPicker` with the shared `SourceFieldOptionRow` component and `SourceFieldChipBadge`. Wire `PreviewContext` sourceData to resolve and display test values in dropdown options.

---

## Scope

### In Scope

- Remove `TYPE_ICON` constant from both `SourceFieldPicker.tsx` and `SourceChipPicker.tsx`
- Replace inline option row markup in both components' dropdown lists with `<SourceFieldOptionRow>`
- Replace the single-char glyph in `FieldPill` (SourceFieldPicker) and `SourceChip` (SourceChipPicker) with `SourceFieldChipBadge` (3-letter badge)
- Wire `PreviewContext` (via `useContext(PreviewContext)`) in both components to get `sourceData`
- Compute `testValue` for each option using `resolveFieldTestValue(sourceData, path)`
- Pass `testValue` to `SourceFieldOptionRow` for each option
- Update existing component tests to expect 3-letter badges instead of single-char glyphs
- Verify no behavior change in search, selection, keyboard navigation, or accessibility

### Out of Scope

- Other source-field pickers (T-03, T-04, T-05 handle those)
- Changes to the static-value toggle or static-value input UI
- Changes to `SchemaPathEntry` type
- Changes to `flattenSchemaPaths` utility

## Change Requirements

### SourceFieldPicker.tsx

- Remove the `TYPE_ICON` constant
- Import `SourceFieldOptionRow`, `SourceFieldChipBadge`, `resolveFieldTestValue` from shared utilities
- Import and consume `PreviewContext` to get `sourceData`
- In the suggestion list rendering, replace inline `<li>` content with `<SourceFieldOptionRow path={entry.path} type={entry.type} testValue={resolveFieldTestValue(sourceData, entry.path)} />`
- In `FieldPill`, replace `<span>{icon}</span>` with `<SourceFieldChipBadge type={fieldType} />`
- Preserve: `role="listbox"`, `role="option"`, `aria-selected`, keyboard handlers, search filtering, `data-testid` attributes

### SourceChipPicker.tsx

- Same changes as SourceFieldPicker: remove TYPE_ICON, use shared component, wire PreviewContext
- In `SourceChip`, replace single-char glyph with `<SourceFieldChipBadge type={fieldType} />`
- Preserve all existing behavior and accessibility attributes

### PreviewContext consumption

- Both components should gracefully handle `PreviewContext` being null (when rendered outside a `PreviewProvider`) — in that case, `sourceData` is null and test values won't render

## Verification Requirements

- Existing tests updated to expect type badge text (e.g., `str` instead of `S`) in option rows and chips
- Test that when sourceData is provided via context, option rows show resolved test values
- Test that when sourceData is null, option rows show type + path only (no test data zone)
- Test that search still filters correctly by path
- Test that keyboard navigation (Enter, Escape, arrow keys) still works
- `tsc --noEmit` passes
- ESLint passes

## Acceptance Checks

- No `TYPE_ICON` constant exists in SourceFieldPicker.tsx or SourceChipPicker.tsx
- Dropdown option rows render `SourceFieldOptionRow` with type badges (e.g., `str`, `num`, `bool`)
- Selected chips/pills show `SourceFieldChipBadge` with type codes
- Test data appears in options when PreviewContext has sourceData
- Test data is absent when PreviewContext sourceData is null
- All existing tests pass (with updated text expectations)
- TypeCheck and lint pass

## Blockers / Risks

## Notes

These two components are the most straightforward refactors since they already render type information. The main change is switching from 1-char to 3-letter badges and adding the test data column.
