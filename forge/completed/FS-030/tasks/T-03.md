## Summary

Update `source-card-decomposer.ts` to recognize nested function chains and decompose them into `SourceWithTransform` with multi-step `InlineTransform`. Implement the `CHAINABLE_TRANSFORMS` set (broader than the existing `SINGLE_INPUT_TRANSFORMS`), chain-walking algorithm, non-linear fallback, and the backward-compatibility heuristic for single-step chains. Add comprehensive round-trip tests.

## Change Requirements

**`CHAINABLE_TRANSFORMS` set:**
```ts
const CHAINABLE_TRANSFORMS = new Set([
  // String
  'upper', 'lower', 'trim', 'replace', 'replaceAll', 'length', 'substring',
  // Date
  'formatDate',
  // Math
  'add', 'subtract', 'multiply', 'divide', 'round', 'abs',
  // Type conversion
  'cast',
  // Null handling
  'default',
  // Array single-input
  'flatten', 'first', 'count',
]);
```

**Chain-walking algorithm (`tryDecomposeChain`):**

```
function tryDecomposeChain(rootNode: FunctionCallNode):
  { sourcePath: string; steps: TransformChainStep[] } | null

1. Initialize empty steps array
2. Set current = rootNode
3. Loop:
   a. If current is source("path") -> return { sourcePath: path, steps: reversed }
   b. If current is not a FunctionCall -> return null
   c. If current.name is not in CHAINABLE_TRANSFORMS -> return null
   d. Record step: { functionName: current.name, args: slotify(current.arguments.slice(1)) }
   e. If any arg fails to convert to slot -> return null
   f. current = current.arguments[0] (walk into first arg)
4. Safety limit: max 20 nesting levels (prevent infinite loops on malformed input)
```

**Top-level heuristic in `decomposeToSourceCardState()`:**

After the `source("path")` direct-copy check:
1. Attempt `tryDecomposeChain(ast)`
2. If successful and `steps.length >= 2` -> return `SourceWithTransform` with chain
3. If successful and `steps.length === 1`:
   - If the function is in `SINGLE_INPUT_TRANSFORMS` -> return `SourceWithTransform` (backward compat)
   - Otherwise -> fall through to FunctionCall path
4. If chain fails -> fall through to existing FunctionCall path

**Argument slot chain decomposition in `nodeToSlot()`:**

Currently, `nodeToSlot()` checks `SINGLE_INPUT_TRANSFORMS.has(node.name) && isSourceCall(firstArg)` for source-with-transform slots. Update this to also attempt chain-walking when the first arg is a nested function (not just `source()`). If the chain walk succeeds, produce a source slot with a multi-step transform.

Heuristic for argument slots:
- Attempt `tryDecomposeChain(node)` on any FunctionCall node
- If chain succeeds with 2+ steps -> source slot with chain transform
- If chain succeeds with 1 step AND function is in SINGLE_INPUT_TRANSFORMS -> source slot with single-step transform (existing behavior)
- Otherwise -> expression slot (existing fallback)

## Notes

The `SINGLE_INPUT_TRANSFORMS` set should be retained for the backward-compatibility single-step heuristic. `CHAINABLE_TRANSFORMS` is a superset used for multi-step chain-walking. Both sets coexist in the decomposer.

The chain-walking algorithm is similar to the existing `decomposeValuePipeline()` in the legacy `pipeline-decomposer.ts`. Refer to that implementation for structural guidance, but the new version must produce `TransformChainStep[]` instead of legacy `TransformStep[]`.
