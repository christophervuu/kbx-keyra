## Summary

Update `SourceCard.tsx` to render chained transforms as a vertical pipeline of steps. Each step shows its function name, a remove button, and its argument form (via the existing render prop pattern). An `[+ Add Step]` button at the bottom of the pipeline allows appending new transform steps. Removing all steps reverts to DirectCopy state.

---

## Scope

### In Scope

- Update `SourceCard.tsx` to iterate `transform.steps` and render each as a vertical pipeline step
- Each step renders:
  - Step number indicator and function name badge (similar to current transform badge)
  - Remove step button (X)
  - Argument form for the step's additional args (via render prop)
  - Visual connector line/arrow between steps
- `[+ Add Step]` button at the bottom of the pipeline, opening `TransformFunctionPicker`
- When a new function is selected via `[+ Add Step]`, append a new `TransformChainStep` to the chain

## Change Requirements

**Visual layout for the pipeline:**

```
┌──────────────────────────────────────┐
│ ⬡ stats.mappedFields              ✕ │  ← source path chip + remove card
├──────────────────────────────────────┤
│ Step 1: ⚡ divide                  ✕ │  ← step badge + remove step
│   [argument form for divide]         │
│ ──────── ↓ ──────────                │  ← visual connector
│ Step 2: ⚡ multiply                ✕ │
│   [argument form for multiply]       │
│ ──────── ↓ ──────────                │
│ Step 3: ⚡ round                   ✕ │
│   [argument form for round]          │
├──────────────────────────────────────┤
│ [+ Add Step]                         │  ← opens function picker
└──────────────────────────────────────┘
```

**Render prop update:**

The `renderArgumentForm` render prop signature must be extended to support per-step rendering:

```ts
renderArgumentForm?: (props: {
  functionName: string;
  transform: InlineTransform;
  sourcePath: string;
  onTransformChange: (updated: InlineTransform) => void;
  /** Index of the step in the chain (0-based). Present for chain rendering. */
  stepIndex?: number;
  /** The specific step being rendered. Present for chain rendering. */
  step?: TransformChainStep;
  /** Callback to update a specific step's args. */
  onStepArgsChange?: (stepIndex: number, args: readonly ArgumentSlot[]) => void;
}) => React.ReactNode;
```

For backward compatibility, existing render prop consumers that only use `functionName`/`transform`/`sourcePath`/`onTransformChange` continue to work. The new fields are optional.

**Step removal logic:**

- Remove step at index `i`: filter `transform.steps` to exclude index `i`
- If no steps remain: call `onStateChange(createDirectCopyState(source))` (revert to DirectCopy)
- If steps remain: call `onStateChange(createSourceWithTransformState(source, { steps: remainingSteps }))`

**Add step logic:**

- When user selects a function from the picker, append `{ functionName, args: [] }` to `transform.steps`
- Emit updated state via `onStateChange`

**Accessibility:**

- Each step has `role="listitem"` within a `role="list"` container
- Step badges have `aria-label` with function name and step number
- Remove buttons have `aria-label` including function name
- Pipeline uses `aria-label="Transform pipeline"` on the list container
- Focus management: after removing a step, focus moves to the next step's remove button (or the Add Step button if the last step was removed)

## Notes

The existing SourceCard already renders a single transform badge and argument form. The chain rendering is an extension of this pattern: instead of one badge + one form, render N badges + N forms in a vertical list with connectors between them.

The `TransformFunctionPicker` component is reused as-is for the `[+ Add Step]` button. Type filtering (T-05) will later wrap or configure it.
