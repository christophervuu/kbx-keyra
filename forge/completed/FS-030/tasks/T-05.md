## Summary

When the user clicks `[+ Add Step]` to append a new transform to a chain, the function picker must filter available functions by type compatibility with the current pipeline output type. This prevents users from selecting transforms that cannot accept the previous step's output (e.g., `upper` after a `divide` step that outputs `number`).

---

## Scope

### In Scope

- Add a utility function `getChainOutputType(steps: readonly TransformChainStep[], sourceType?: string): string` that computes the output type of the chain by looking up each step's return type in `DSL_FUNCTION_CATALOG`
- Add a utility function `getCompatibleChainableTransforms(outputType: string): readonly FunctionCatalogEntry[]` that returns catalog entries whose first parameter type is compatible with the given output type
- Type compatibility rules:
  - If output type is `any` or unknown: return all chainable transforms
  - If a function's first parameter type is `any`: it accepts all output types
  - Otherwise: first param type must match output type (exact match: `number`=`number`, `string`=`string`)
- Update `TransformFunctionPicker` to accept an optional `allowedFunctions` prop that limits the displayed functions
- Wire the `[+ Add Step]` button in `SourceCard.tsx` (from T-04) to pass `allowedFunctions` based on chain output type
- Add tests for:
  - `getChainOutputType` with various chain configurations
  - `getCompatibleChainableTransforms` filtering logic
  - Picker rendering with filtered functions (AE-02)

### Out of Scope

- Generator/decomposer changes (T-02, T-03)
- Full integration wiring (T-06)

## Change Requirements

**Output type computation:**

```ts
function getChainOutputType(
  steps: readonly TransformChainStep[],
  sourceType?: string,
): string {
  if (steps.length === 0) return sourceType ?? 'any';
  const lastStep = steps[steps.length - 1];
  const catalogEntry = DSL_FUNCTION_CATALOG.find(e => e.name === lastStep.functionName);
  return catalogEntry?.returnType ?? 'any';
}
```

**Compatibility filtering:**

```ts
function getCompatibleChainableTransforms(outputType: string): readonly FunctionCatalogEntry[] {
  const chainable = DSL_FUNCTION_CATALOG.filter(e => CHAINABLE_TRANSFORMS.has(e.name));
  if (outputType === 'any') return chainable;
  return chainable.filter(entry => {
    const firstParam = entry.parameters[0];
    if (!firstParam) return false;
    return firstParam.type === 'any' || firstParam.type === outputType;
  });
}
```

**`CHAINABLE_TRANSFORMS` set**: Use the same set defined in the decomposer (T-03). If T-03 has not been completed yet, define the set in a shared location (e.g., new file `ui/src/features/mappings/lib/transform-chain-utils.ts`) so both T-03 and T-05 can import it.

**TransformFunctionPicker update:**

Add optional prop:
```ts
interface TransformFunctionPickerProps {
  // ... existing props ...
  /** If provided, limits the displayed functions to this set. */
  allowedFunctions?: ReadonlySet<string>;
}
```

When `allowedFunctions` is provided, filter the catalog to show only matching functions. Functions not in the set are excluded from the picker UI entirely (not shown as disabled).

**SourceCard wiring:**

In the `[+ Add Step]` handler (from T-04), compute the chain output type and pass `allowedFunctions` to the picker:

```ts
const outputType = getChainOutputType(transform.steps, sourceFieldType);
const compatible = getCompatibleChainableTransforms(outputType);
const allowedFunctions = new Set(compatible.map(e => e.name));
```
