## Summary

Wire the transform chain into the full Source Card builder flow: update all `InlineTransform` consumers in `UnifiedExpressionBuilder.tsx`, `ArgumentSlotInput.tsx`, `ArgumentForm.tsx`, and `ScalarFieldBuilder.tsx` to work with the chain model. Verify that existing single-transform behavior, decomposition round-trips, and the full authoring-to-apply flow all work end-to-end.

---

## Scope

### In Scope

- Update `UnifiedExpressionBuilder.tsx` to handle chain state in `sourceCardState`:
  - Decomposition via `decomposeToSourceCardState()` (now produces chains for eligible expressions)
  - Generation via `generateExpressionFromSourceCardState()` (now handles chains)
  - Source Card rendering with chain pipeline
- Update `ArgumentSlotInput.tsx` to construct `InlineTransform` with new chain shape when adding/updating inline transforms on argument slots
- Update `ArgumentForm.tsx` where it references `InlineTransform` for per-step rendering in chain context
- Update `ScalarFieldBuilder.tsx` if it constructs or inspects `InlineTransform` objects
- Update `use-expression-builder.ts` if it references `InlineTransform` shape
- Ensure the `renderArgumentForm` render prop in `SourceCard` is correctly wired for per-step argument form rendering
- Add or update integration tests in `UnifiedExpressionBuilder.integration.test.tsx`:

  - Apply a chain expression -> re-open -> chain hydrated
- Update `UnifiedExpressionBuilder.test.tsx` assertions for new InlineTransform shape
- Fix any remaining type errors across the codebase caused by the InlineTransform shape change

## Change Requirements

**InlineTransform construction sites:**

Every location that constructs an `InlineTransform` object must be updated from `{ functionName, args }` to `{ steps: [{ functionName, args }] }` (or use `makeSingleStepTransform()` from T-01).

Key locations:
1. `SourceCard.tsx` `handleFunctionSelect` -- creates initial transform on function pick
2. `ArgumentSlotInput.tsx` -- creates inline transform on argument slot
3. `UnifiedExpressionBuilder.tsx` -- any inline transform construction
4. `ArgumentForm.tsx` -- any transform reference in argument context
5. Test files constructing InlineTransform objects

**Render prop wiring:**

`UnifiedExpressionBuilder.tsx` provides `renderArgumentForm` to `SourceCard`. This render prop must be updated to:
1. Support per-step rendering (receive `stepIndex` and `step` from T-04's extended signature)
2. Render `ArgumentForm` for each step's additional args (not the implicit first arg)
3. Handle `onStepArgsChange` to update a specific step's args within the chain

**Decomposition hydration:**

When `decomposeToSourceCardState()` returns a `SourceWithTransform` with a multi-step chain, `UnifiedExpressionBuilder` must correctly hydrate the Source Card UI with the chain visible and editable.

**Full flow verification:**

The following end-to-end flow must work:
1. User opens builder in Value mode
2. Selects a source field -> DirectCopy card appears
3. Adds a transform -> single-step chain
4. Adds another transform via [+ Add Step] -> multi-step chain
5. Expression updates live with each change
6. User applies the expression
7. User re-opens the field -> decomposer hydrates the chain
8. Chain UI is restored with correct steps
