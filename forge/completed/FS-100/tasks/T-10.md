## Summary

Document and fix the exact deployment-page request failure (route/config/backend/CORS), implement deploy-context route behavior, and guarantee normalized CORS/error envelopes across success and failure paths.

---

## Scope

### In Scope

- Capture exact failing request evidence: method/path/origin/status/body and whether preflight or actual call failed.
- Implement/repair backend contract used by deployment page (`deploy-context` and/or missing requested route parity).
- Ensure CORS headers on success and all 4xx/5xx paths (Lambda + API Gateway gateway responses).
- Normalize backend errors with request ids and structured details.
- Update HTTP client copy/behavior so UI shows normalized backend error, not generic network-only message.
- Add regression tests covering deployment-context request and error-path behavior.

### Out of Scope

- Full deployment page redesign.
- Runtime execution logic.

---

## Relevant Areas

- `template.yaml`
- deployment/mapping handlers under `src/lambda/*`
- `src/lambda/shared/response.ts`
- `ui/src/lib/api/http-client.ts`
- deployment hook/tests in UI and lambda tests

## Change Requirements

- If route mismatch is root cause, state explicitly and fix route/adapter alignment.
- Do not assume banner text alone proves CORS; root-cause evidence is mandatory.
- Preserve user-facing BA-friendly error text with optional technical details section.

---

## Verification Requirements

- Recorded discovery finding artifact with exact request/response chain.
- API tests for CORS headers on 2xx/4xx/5xx and preflight where applicable.
- Regression test for deployment-context request failure/success handling.

## Acceptance Checks

- Root cause is documented before UI completion.
- Preflight succeeds where applicable.
- Success responses include valid CORS headers.
- 4xx/5xx responses include valid CORS headers.
- UI receives/displays normalized backend error with request id.
- Regression test covers deployment-context request path.
