## Summary

Evolve runtime execute handler to canonical request/response contracts while preserving compatibility for existing callers currently using `{ mappingId, sourceData }` and legacy response expectations.

---

## Scope

### In Scope

- Accept canonical request fields (`sourceData`, optional `enrichmentInputs`, optional executionContext).
- Maintain compatibility alias for existing `externalSources` callers during transition.
- Emit canonical response envelope (`outputFormat`, `output`, `diagnostics`, `metadata`).
- Add explicit compatibility mode/adapter for legacy response consumers where required.
- Structured runtime error taxonomy and retryability metadata.

### Out of Scope

- Deployment page UI behavior.
- Deploy/promotion persistence writes.

---

## Relevant Areas

- `src/lambda/runtime/execute.ts`
- `src/lambda/shared/{request.ts,response.ts,errors.ts}`
- runtime consumers under `src/lambda/deployment/*` and preview integration
- runtime tests in `tests/lambda/runtime/*`

---

## Change Requirements

- Do not break existing `{ mappingId, sourceData }` callers.
- Do not require enrichments for mappings that do not declare them.
- Avoid permanent ambiguous response shape detection; use explicit transitional compatibility behavior.

---

## Verification Requirements

- Runtime tests for canonical and compatibility request paths.
- Response-shape tests for canonical envelope and compatibility adapter behavior.
- Error taxonomy tests for required/optional enrichment and deployment-not-found behavior.

---

## Acceptance Checks

- Canonical contract supported with metadata fields always present.
- Existing basic callers continue to work during migration window.
- Required/optional enrichment behavior matches spec.
- Compatibility behavior is explicit and documented (no hidden shape guessing).

---

## Blockers / Risks

- Existing preview/runtime relay consumers may require synchronized update.

---

## Notes

- Align transition with T-07 and T-12 so runtime and consumers migrate in lockstep.
