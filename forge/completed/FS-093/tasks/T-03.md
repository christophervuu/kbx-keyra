## Summary

Update generic mapping execution and preview server paths to consume runtime input as `mappingId + sourceData + externalSources`, resolve mapping config by ID, and enforce required enrichment runtime diagnostics without introducing external I/O.

---

## Scope

### In Scope

- Runtime request parsing and validation for source + enrichment payloads.
- Mapping lookup by `mappingId` in execution/preview path.
- Required/optional enrichment missing-data behavior implementation.
- Backward-compatible handling for legacy preview/runtime callers where possible.

### Out of Scope

- External connector execution.
- Deployment workflow redesign.

---

## Relevant Areas

- `src/lambda/mapping/*execute*` ?
- `src/lambda/mapping/*preview*` ?
- runtime utility modules resolving active mapping/snapshot
- tests under `tests/lambda/mapping/*preview*` and runtime integration suites

---

## Change Requirements

- Caller must not send mapping rules directly for generic runtime execution.
- Runtime context must pass `sourceData` as source root and `externalSources` into engine options/context.
- Missing required enrichments must produce deterministic hard preflight errors and halt execution.
- Optional missing enrichments must not hard-fail by default.

---

## Verification Requirements

- Lambda contract tests for request validation and mapping resolution.
- Integration tests for execution with no enrichments, with enrichments, and missing required enrichments.
- Lint/typecheck/tests for touched backend/runtime modules.

---

## Acceptance Checks

- Preview/runtime accept `sourceData + externalSources` and execute mapping by `mappingId`.
- Required enrichment missing condition fails in preflight with deterministic error and no continued execution.
- Legacy no-enrichment execution path continues to function.

---

## Blockers / Risks

- Runtime handler locations may differ from inferred paths and require discovery before implementation.

---

## Notes

- Keep behavior aligned with no-I/O runtime constraints.
