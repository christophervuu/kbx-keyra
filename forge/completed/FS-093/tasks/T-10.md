## Summary

Create cross-layer verification coverage to prove enriched mappings work end-to-end and do not regress single-source behavior, including CRUD serialization, editor authoring selection, preview/runtime execution, and schema dependency protections.

---

## Scope

### In Scope

- Backend integration tests for enriched mapping lifecycle and schema guards.
- Engine validation/execution regression and enrichment-specific diagnostics tests.
- Adapter-level compatibility tests for legacy and enriched records.
- Targeted UI integration checks for key enriched authoring and preview flows (where existing test harness allows).

### Out of Scope

- New full E2E framework introduction.
- Unrelated performance benchmarking.

---

## Relevant Areas

- `tests/lambda/mapping/*`
- `tests/lib/persistence/*`
- `tests/engine/*`
- `ui/src/**/*.test.tsx` (focused mapping/project surfaces)
- integration suites under existing test structure

---

## Change Requirements

- Cover both happy paths and backward-compatibility paths.
- Ensure missing-required enrichment diagnostics are test-asserted.
- Ensure no external I/O behavior appears in runtime tests.
- Cover canonical/compatibility normalization behavior (`enrichmentSources` + derived `config.externalSources`).
- Cover legacy sample-to-input-set migration path.

---

## Verification Requirements

- Run targeted and aggregate suites for touched areas.
- Run lint/typecheck and required CI-equivalent checks for modified modules.
- Document any residual gaps as explicit follow-up items.

## Acceptance Checks

- Enriched mapping flow is test-covered from create through preview/runtime.
- Single-source legacy behavior remains green under regression coverage.
- Schema usage guard for enrichment dependencies is covered.
