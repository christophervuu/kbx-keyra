## Summary

Extend mapping persistence and CRUD Lambda handlers to accept, store, validate, return, and duplicate enrichment input metadata while preserving backward compatibility for existing single-source mappings.

---

## Scope

### In Scope

- Persistence model/type updates for enrichment metadata.
- `create/get/update/list/duplicate` mapping handler updates.
- Defaulting/migration-safe read behavior for legacy mappings.
- Schema reference usage indexing/guard updates for enrichment dependencies.

### Out of Scope

- Mapping editor UI changes.
- Engine execution internals beyond contract wiring.

---

## Relevant Areas

- `src/lib/persistence/types.ts`
- `src/lib/persistence/mappings.ts`
- `src/lambda/mapping/create-mapping.ts`
- `src/lambda/mapping/get-mapping.ts`
- `src/lambda/mapping/update-mapping.ts`
- `src/lambda/mapping/list-mappings.ts`
- `src/lambda/mapping/duplicate-mapping.ts`
- `src/lambda/schema/delete-schema.ts`
- related tests under `tests/lambda/mapping/*` and `tests/lib/persistence/*`

---

## Change Requirements

- Enrichment alias uniqueness and schema presence enforced in create/update validation.
- `enrichmentSources` treated as canonical; `config.externalSources` derived/unioned for compatibility.
- List/get APIs return enrichment summary/detail fields needed by UI.
- Duplicate mapping preserves enrichment inputs.
- Schema delete guard includes enrichment references.
- Legacy records without enrichments continue to serialize and execute.
- Legacy records with only `config.externalSources` normalize to schema-less legacy enrichment aliases.

---

## Verification Requirements

- Backend unit/integration tests for CRUD, duplication, and schema-usage guards.
- Backward compatibility tests using old mapping shapes.
- Lint/typecheck/tests for touched backend modules.

---

## Acceptance Checks

- Mapping CRUD handlers round-trip enrichment metadata correctly.
- Canonical/compatibility behavior for `enrichmentSources` + `config.externalSources` is test-covered.
- Duplicate and list flows preserve enrichment definitions.
- Schema delete conflict handling includes enrichment usage references.
- Legacy mappings without enrichment metadata remain valid.

---

## Blockers / Risks

- Existing persisted `config.externalSources` semantics may require careful compatibility layering.

---

## Notes

- Keep response contract additive/backward-compatible where feasible.
