## Summary

Introduce a shared rollback selection mechanism so prompt version fallback/override can be applied through config/data policy without handler code changes.

---

## Scope

### In Scope

- Implement rollback-aware version selection extension on top of latest retrieval.
- Implement authoritative rollback representation via explicit environment-scoped active pointer record lookup.
- Define behavior for missing/inconsistent rollback target state.
- Emit selection path metadata (latest vs rollback override) for diagnostics/telemetry.

### Out of Scope

- Prompt authoring/admin workflows.
- UI controls for rollback management.

---

## Relevant Areas

- `src/lib/ai/prompt-registry.ts`
- `src/lib/ai/config.ts`
- `src/lib/ai/invoke-ai.ts`
- `tests/lib/ai/*`

---

## Change Requirements

- Rollback policy must be data/config driven and centralized.
- Active pointer record is the authoritative runtime selector; status/deployment flags are non-authoritative metadata.
- Missing rollback target must fail deterministically (no silent arbitrary fallback).
- Handler call sites must remain unchanged when rollback toggles.

---

## Verification Requirements

- Unit tests for rollback target selection and fallback rules.
- Unit tests for environment-scoped active pointer selection behavior.
- Unit tests for invalid rollback configuration behavior.
- Typecheck/lint for touched modules.

---

## Acceptance Checks

- [ ] Shared prompt selection supports environment active-pointer rollback override without endpoint code edits.
- [ ] Invalid/missing rollback target path is deterministic and tested.
- [ ] Selection metadata captures whether latest or rollback version was used.
- [ ] `pnpm typecheck` and `pnpm lint` pass for touched areas.

## Blockers / Risks
