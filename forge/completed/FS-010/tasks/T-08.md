## Summary

Ensure the complete rule list is fully accessible: keyboard navigable (arrow keys between rows, Tab to actions), ARIA live regions for validation summary and selection changes, focus management on dialogs and bulk action bar, and screen reader announcements for state changes. This is the final UI polish task that builds on all prior components.

---

## Scope

### In Scope

- Keyboard navigation: arrow keys move focus between rule rows
- Tab order within a row: checkbox → drag handle → target path (edit) → expression (edit) → actions (delete, copy, move up/down, diagnostic expand)
- Enter/Space on a row to select or activate
- ARIA roles: `role="grid"` or `role="list"` with appropriate `role="row"` / `role="listitem"` per row
- `aria-activedescendant` pattern for focused row
- ARIA live region for validation summary bar (announces changes: "2 errors, 1 warning")
- ARIA live region for bulk action bar appearance ("3 rules selected. Bulk actions available.")
- Focus trap verification on ConfirmDialog (from T-04) — confirm existing implementation or fix
- Focus returns to triggering element after dialog closes
- Keyboard shortcut discoverability: title/tooltip on drag handle actions, move buttons
- Screen reader announcement after drag-and-drop keyboard reorder (from T-05) — verify or add
- Skip-to-content link or landmark roles for editor regions

### Out of Scope

- Mobile touch accessibility (desktop-first)
- Color-blind-specific styling (Tailwind defaults + icons provide non-color indicators)
- Full WCAG 2.1 AA audit (target the interactive keyboard/screen-reader behaviors specified)

## Change Requirements

- `RuleList` container:
  - Add `role="grid"` (or `role="list"` with `role="listitem"` per row)
  - Implement roving tabindex or `aria-activedescendant` for row focus
  - ArrowUp/ArrowDown moves focus between rows
  - Home/End moves to first/last row
- `RuleRow`:
  - Each row identified with unique `id` for `aria-activedescendant`
  - Visible focus ring (Tailwind `ring-2 ring-blue-500`) on focused row
  - Tab through interactive elements within the focused row
  - Escape exits inline editing mode
- `ValidationSummaryBar`:
  - Add `aria-live="polite"` and `aria-atomic="true"`
  - When validation result changes, the region content updates and is announced
  - Announce format: "{total} rules: {valid} valid, {warnings} warnings, {errors} errors, {coverage}% coverage"
- `BulkActionBar`:
  - Add `aria-live="assertive"` (appears on selection)
  - Announce: "{N} rules selected. Actions: Delete, Duplicate, Copy."
  - When bar disappears (selection cleared), announce nothing (removal is not announced)
- `ConfirmDialog`:
  - Verify focus is trapped (Tab cycles within dialog only)
  - Initial focus on "Cancel" button (safer default per UX conventions)
  - Escape key closes dialog (equivalent to cancel)
  - On close, focus returns to the element that triggered the dialog
- `DiagnosticDetail`:
  - Expandable via Enter/Space on the validation icon
  - `aria-expanded` attribute on trigger
  - Expanded content associated via `aria-controls` / `aria-labelledby`
- Keyboard shortcuts:
  - Document all shortcuts (Ctrl+S, arrow keys, Enter/Space, Escape) in tooltips or a help overlay (placeholder acceptable)

## Blockers / Risks

- ARIA live region behavior varies by screen reader. Test with VoiceOver (macOS) at minimum.
- Roving tabindex with complex row content (multiple interactive elements) can be tricky. The `aria-activedescendant` pattern may be simpler for this use case.

## Notes

- This task is intentionally last in the UI task sequence. It requires all interactive components to exist so it can add/verify accessibility affordances.
- Focus management is especially important for the delete confirmation flow: losing focus after dialog close is a common accessibility bug.
- Consider adding `role="status"` to the save status indicator in the top bar so screen readers announce save completion.
