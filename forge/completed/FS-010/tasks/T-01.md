## Summary

Create the `ui/src/lib/engine/` integration layer that imports the mapping engine's `validate` and `execute` functions for browser consumption via a `@keyra/engine` Vite path alias. Add `description?: string` to the UI `MappingRule` type to align with the engine. Build the `useEngineValidation()` hook that debounces validation calls, provides per-rule diagnostic lookups, and computes the validation summary. This establishes the reusable pattern for FS-011 and FS-012.

---

## Scope

### In Scope

- Create `ui/src/lib/engine/index.ts` that re-exports `validate` and `execute` from the engine
- Configure Vite path alias: `@keyra/engine` → `../../src/engine/index.ts` in `vite.config.ts` (`resolve.alias`) and `tsconfig.json` (`paths`)
- Vite handles `.js` extensions in engine internal imports and TS transpilation natively — no pre-build step
- Add `description?: string` to `MappingRule` in `ui/src/lib/types/domain.ts` to align with engine type
- Create `useEngineValidation()` hook in `ui/src/features/mappings/hooks/`
- Hook accepts: `config: MappingConfig | null`, `sourceSchema: object | null`, `targetSchema: object | null`
- Hook returns: `{ result: ValidationResult | null, isValidating: boolean, diagnosticsForRule(index): Diagnostic[], coveragePercent: number, summary: { total, valid, warnings, errors } }`
- Debounce validation by 300ms after input changes
- Skip validation when config or schemas are null
- Handle engine errors gracefully (catch, return error state)
- Unit tests for hook behavior (debounce, null skip, diagnostic filtering, summary computation)
- Verify engine bundle works in Vite dev server (smoke test)

### Out of Scope

- Schema parsing (handled by FS-009 parsers — for UI tree display only)
- UI components (T-02, T-03 own rendering)
- Save/load logic (T-07)
- `execute()` integration hook (FS-012 will build that on this pattern)
- Passing `ParsedSchema` to the engine (engine builds its own SchemaTree from raw JSON Schema objects)

## Change Requirements

- `ui/src/lib/engine/index.ts` must export `validate` and `execute` such that importing them in a React component works under Vite
- Configure `@keyra/engine` path alias:
  - In `vite.config.ts`: `resolve: { alias: { '@keyra/engine': path.resolve(__dirname, '../src/engine/index.ts') } }`
  - In `tsconfig.json`: `"paths": { "@keyra/engine": ["../src/engine/index.ts"] }`
  - Vite handles `.js` extension resolution in the engine's internal imports natively (these are TypeScript module resolution conventions)
- Add `description?: string` to `MappingRule` interface in `ui/src/lib/types/domain.ts`
- `useEngineValidation()` must:
  - Accept nullable config and schemas
  - Return `null` result and show "no schemas" state when inputs are null
  - Debounce with 300ms delay (using `useRef` for timer ID to avoid stale closures)
  - Call `validate(config, sourceSchema, targetSchema)` from the engine
  - Compute `diagnosticsForRule(index)` by filtering `result.diagnostics` where `d.ruleIndex === index`
  - Compute `coveragePercent` from `result.coverage?.percentage ?? 0`
  - Compute summary: count rules in config, subtract error+warning diagnostics to get valid count
  - Set `isValidating: true` during debounce window, `false` after completion
  - Catch thrown errors and set an error state without crashing
- Verify tree-shaking: only `validate` and `execute` (and their dependencies) should end up in the bundle — not unused engine internals
- Engine self-initializes registry on first import — verify this works in browser context

## Notes

- The engine's `src/engine/index.ts` calls `registerAllFunctions(defaultRegistry)` at module load. This is side-effectful but intentional — it sets up the function registry.
- The engine `validate()` accepts raw JSON Schema objects (not strings, not ParsedSchema). The UI passes `SchemaDetail.content` directly when it's a JSON Schema (it's stored as a JSON object in localStorage). For XSD, the engine has a permissive stub adapter.
- `ValidationResult.coverage` may be `undefined` if the engine cannot compute coverage (e.g., no target schema tree). Handle gracefully.
- This task creates `ui/src/features/mappings/` directory structure. Follow project-structure.md conventions.
- The `description` field addition to `MappingRule` is backward-compatible: existing stored rules without it will still load (optional field).
