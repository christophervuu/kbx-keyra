## Summary

Build the Rule List component (Panel 3) that renders the `rules[]` array from a `MappingConfig` as a scrollable list with per-rule validation status. Includes the validation summary bar, rule type inference display, diagnostic detail expansion, and empty/missing-schema states. This is the core read-only display that other CRUD tasks build upon.

---

## Scope

### In Scope

- `ui/src/features/mappings/components/RuleList.tsx` — container component for Panel 3
- `ui/src/features/mappings/components/RuleRow.tsx` — individual rule row component
- `ui/src/features/mappings/components/ValidationSummaryBar.tsx` — summary above the list
- `ui/src/features/mappings/components/DiagnosticDetail.tsx` — expandable diagnostic panel per rule
- `ui/src/features/mappings/lib/infer-rule-type.ts` — rule type inference from expression
- Rule row display: row number, selection checkbox, target path, expression (truncated with full on hover/expand), type badge, validation icon
- Validation icons: ✓ green (valid), ⚠ yellow (warning), ✗ red (error), gray (not validated)
- Summary bar: total rules count, valid count, warning count, error count, coverage percentage
- Diagnostic detail: on click of validation icon, expand to show all diagnostics for that rule (code, severity badge, full message, expression snippet)
- Rule type inference logic: parse outermost function name → display label
- Empty state: "No rules yet. Add your first rule to start mapping." + "Add Rule" CTA + "Auto-Map with AI" placeholder
- Schemas-missing state: message "Attach source and target schemas to enable validation"
- Wire `useEngineValidation()` hook (from T-01) to drive validation status

## Change Requirements

- `RuleList` accepts props: `rules: MappingRule[]`, `validationResult: ValidationResult | null`, `schemasLoaded: boolean`, event handlers for future CRUD wiring
- `RuleList` renders `ValidationSummaryBar` at top, then scrollable list of `RuleRow` components, or empty/missing state
- `RuleRow` displays:
  - Row index (1-based display)
  - Checkbox (controlled, for future multi-select)
  - Target field path (monospace, full width allocated)
  - Expression (truncated to ~60 chars with ellipsis; title attribute with full text; expandable on click if very long)
  - Type badge using `inferRuleType(expression)` → colored pill label
  - Validation icon (green/yellow/red/gray) derived from diagnostics for that rule index
- `ValidationSummaryBar` accepts `summary` object and renders counts with colored indicators
- `DiagnosticDetail` renders when validation icon is clicked:
  - Lists all `Diagnostic` objects for that rule
  - Each shows: code (monospace), severity badge, full message, expression snippet with location
  - "Fix" button placeholder (disabled, tooltip "Coming in Phase 2")
- `inferRuleType(expression: string): string` — lightweight parser:
  - If empty → "Not configured"
  - Extract first function name before `(`
  - Map to display label per spec table
  - Unknown functions → "Transform" (safe fallback)
- Expression truncation: show first 60 characters + "..." if longer; full text on hover (title) or expand
- Empty state includes "Auto-Map with AI" button that shows tooltip "Coming soon" and is disabled

## Blockers / Risks

- Diagnostic location data may be sparse (not all diagnostics include expression/location). Handle missing fields gracefully.
- Type inference is purely cosmetic. If the expression parsing is ambiguous (nested functions), the outermost function still determines the label.
