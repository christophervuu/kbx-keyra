## Summary

Implement drag-and-drop reordering of rules in the list using `@dnd-kit/core` + `@dnd-kit/sortable`. Rules execute in config order so reordering is semantically meaningful. Provide a visual drag handle on each row. `@dnd-kit`'s built-in keyboard sensor provides the accessible alternative (Move Up / Move Down). Reordering triggers validation.

---

## Scope

### In Scope

- Drag handle visual element on each rule row
- Drag-and-drop reorder behavior using `@dnd-kit/core` + `@dnd-kit/sortable`
- Visual feedback during drag: picked-up item highlighted, drop target indicator
- Keyboard alternative via `@dnd-kit` keyboard sensor (built-in) plus explicit "Move Up" / "Move Down" buttons
- On reorder: update rules array order in state
- Validation re-runs after reorder (automatic via state change)
- Screen reader announcement of new position after keyboard reorder (provided by `@dnd-kit` accessibility announcements)
- Install `@dnd-kit/core` and `@dnd-kit/sortable` packages

### Out of Scope

- Multi-row drag (drag only one at a time)
- Drag between different panels or mappings
- Touch/mobile drag (desktop-first constraint)
- Rule list virtualization (unlikely needed at 500 rules, but if added in T-03 or later, DnD must be compatible)

## Change Requirements

- Install `@dnd-kit/core` and `@dnd-kit/sortable` via pnpm
- Each `RuleRow` renders a visible drag handle (grip icon from Lucide, e.g., `GripVertical`)
- Drag handle is the only drag-initiating surface (not the entire row, to avoid conflicts with edit/selection clicks)
- On drag start: lifted row shows visual distinction (opacity, shadow, or placeholder)
- On drag over: target position shows a drop indicator (line or highlighted gap)
- On drop: rules array reorders — move dragged item to new index
- Use `@dnd-kit` integration:
  - `DndContext` wraps the rule list
  - `SortableContext` with `verticalListSortingStrategy`
  - `useSortable()` hook per row
  - Configure `KeyboardSensor` for keyboard accessibility
  - Configure `PointerSensor` with activation constraint (distance: 8px) to avoid triggering on clicks
  - Use `arrayMove` utility from `@dnd-kit/sortable` for reorder logic
  - `@dnd-kit` provides built-in screen reader announcements via `announcements` prop on `DndContext`
- Additionally provide explicit "Move Up" / "Move Down" buttons on each row:
  - Visible on row focus/hover (or always visible as small icon buttons)
  - Buttons disabled at list boundaries (first row: no Move Up; last row: no Move Down)
  - Moving via button fires same reorder logic as DnD drop
  - After move, focus follows the moved row
  - ARIA live region announces: "Rule moved to position {N}"
- Reorder produces a new rules array reference → triggers useEngineValidation debounce

## Notes

- `@dnd-kit/core` + `@dnd-kit/sortable` is the mandated choice: well-maintained, accessibility-first, keyboard sensors built-in, ~15KB gzipped — negligible compared to React + Tailwind.
- The drag handle should be visually subtle (gray, small grip icon) to not dominate the row layout.
- Order matters for rule execution because of last-write-wins semantics and future `target()` accessor support (per DSL spec §6.1).
- `@dnd-kit`'s `announcements` prop on `DndContext` provides configurable screen reader announcements for drag start/over/end/cancel — use this for accessibility compliance.
