## Summary

Implement the data loading and save pipeline for the Mapping Editor. On mount, load the `MappingConfig` and associated schemas from `useAdapter()`. Parse schemas using FS-009 parsers for engine validation. Track unsaved changes and provide save with version increment. Handle loading/error states and `beforeunload` warning.

---

## Scope

### In Scope

- `useMappingEditor()` hook (or equivalent) that orchestrates data loading and state
- Load `MappingConfig` via `adapter.getMapping(mappingId)` on mount
- Load source and target schemas via `adapter.getSchema(schemaId)` using config's schema refs
- Parse loaded schemas using `parseJsonSchema()` or `parseXsd()` (from FS-009) for UI tree display
- Pass raw JSON Schema objects (from `SchemaDetail.content`) directly to `useEngineValidation()` for engine validation — the engine builds its own SchemaTree internally
- Note: FS-009 `ParsedSchema` is for UI tree display only; engine receives raw schema content independently
- Local editor state management (rules array, editing state) via `useReducer`
- Save: call `adapter.updateMapping(mappingId, updatedConfig)` with incremented version
- Keyboard shortcut: Ctrl+S / Cmd+S triggers save
- Unsaved changes detection: compare current rules to last-saved snapshot
- Top bar save status: "Saved" / "Unsaved changes" / "Saving..." / "Save failed"
- Browser `beforeunload` event handler when unsaved changes exist
- Loading state: skeleton/spinner while data loads
- Error state (load failure): error message with "Retry" button
- Error state (save failure): toast notification with "Retry", local state preserved
- Wire loaded data into `MappingEditorPage` → `RuleList` component tree

### Out of Scope

- Rule CRUD logic (T-04 — this task loads/saves, T-04 mutates)
- Drag-and-drop (T-05)
- Bulk actions (T-06)
- Optimistic updates / offline queue (Phase 1+)
- Conflict resolution (Phase 0 is single-user)

## Change Requirements

- Create `useMappingEditor(mappingId: string)` hook:
  - Loads mapping config on mount via `useAdapter().getMapping(mappingId)`
  - Extracts `sourceSchemaRef.schemaId` and `targetSchemaRef.schemaId`
  - Loads both schemas via `useAdapter().getSchema(id)` (parallel)
  - For UI tree display: parses schema content via `parseJsonSchema(content)` or `parseXsd(content)` based on format
  - For engine validation: passes `SchemaDetail.content` (raw JSON Schema object) directly to `useEngineValidation()` — the engine builds its own internal SchemaTree
  - Returns: `{ config, rules, schemas: { source, target }, parsedSchemas: { source, target }, loadState, saveState, actions }`
  - `actions`: `{ addRule, updateRule, deleteRule, reorderRules, save }`
  - `loadState`: `AsyncState<MappingConfig>`
  - `saveState`: `'idle' | 'saving' | 'saved' | 'error'`
- Editor state via `useReducer`:
  - State: `{ rules: MappingRule[], lastSavedRules: MappingRule[], version: number }`
  - Actions: `ADD_RULE`, `UPDATE_RULE`, `DELETE_RULE`, `REORDER_RULES`, `SAVE_SUCCESS`, `LOAD_SUCCESS`
- Unsaved changes: `hasUnsavedChanges = !deepEqual(rules, lastSavedRules)` (implement simple deep comparison for rule arrays)
- Save:
  - Build complete `MappingConfig` from current state (name, version+1, schemas, config options, rules)
  - Call `adapter.updateMapping(mappingId, newConfig)`
  - On success: update `lastSavedRules`, increment version in state, set saveState to 'saved'
  - On failure: show error, keep local state, set saveState to 'error'
- Keyboard shortcut:
  - Register global keydown listener for Ctrl+S / Cmd+S (detect via `e.metaKey || e.ctrlKey`)
  - Prevent default browser save dialog
  - Trigger save action
  - Remove listener on unmount
- `beforeunload`:
  - When `hasUnsavedChanges === true`: register `beforeunload` listener that returns a string
  - When `hasUnsavedChanges === false`: remove listener
  - Clean up on unmount
- Loading state: render skeleton placeholder (e.g., 5 skeleton rows) while config loads
- Error state (load): render error message + "Retry" button that re-triggers load
- If schema load fails: still render rules, but set schemas to null (validation skipped per AE-10)

## Blockers / Risks

- Deep equality comparison for unsaved changes could be expensive for large rule arrays. Use a simple JSON.stringify comparison for Phase 0 (acceptable for 500 rules).
- Schema parsing via FS-009 parsers must be available for UI tree display. If FS-009 is incomplete, stub with raw schema objects for validation (engine accepts them directly).
- For JSON schemas: `SchemaDetail.content` is already a JSON object — pass directly to engine.
- For XSD schemas: engine has a permissive stub adapter. Pass the raw content and let the engine handle it.
