## Summary

Implement add, edit, and delete rule operations within the Rule List. Adding a rule shows a form for target path and expression. Editing a rule opens inline edit mode. Deleting shows a confirmation dialog. All operations mutate the local rules state and trigger engine validation via the debounced hook.

---

## Scope

### In Scope

- "Add Rule" button and form component (`RuleForm.tsx`)
- Add form fields: target path (text input), expression (textarea), description (optional text input)
- New rules appended to end of rules array
- Edit mode: clicking a rule row (or edit action) transforms row into editable form or opens detail panel
- Edit fields: target path, expression (raw DSL text), description
- Delete action per row with confirmation dialog
- Confirmation dialog component (`ConfirmDialog.tsx`) — reusable, focus-trapped
- All mutations update local rules state (via parent state setter or reducer)
- All mutations trigger `useEngineValidation()` (automatic via state change → hook dependency)
- "Add Rule" CTA in empty state wired to open add form

### Out of Scope

- Drag-and-drop reorder (T-05)
- Multi-select / bulk delete (T-06)
- Save to adapter (T-07)
- Autocomplete from schema for target path (deferred to Expression Builder, FS-011)
- Expression Builder integration (FS-011)

## Change Requirements

- Add "Add Rule" button above or below the rule list (always visible, prominent)
- Clicking "Add Rule" opens `RuleForm` in "add" mode:
  - Target path: text input (required, free-text for now)
  - Expression: textarea (optional, can be empty)
  - Description: text input (optional)
  - "Save" and "Cancel" actions
  - On save: append new `MappingRule` to rules array
- Add `description` field to `MappingRule` in `ui/src/lib/types/domain.ts` if not already present (T-01 adds it — verify)
- Edit mode:
  - Clicking a rule row or explicit "Edit" icon enters edit mode for that rule
  - Row transforms to show editable fields (inline) or a side panel appears
  - Same fields as add form, pre-populated with current values
  - "Save" and "Cancel" actions
  - On save: update the rule at that index in the array
  - Only one rule editable at a time
- Delete action:
  - Each row has a "Delete" icon/button
  - Clicking opens `ConfirmDialog`: "Delete rule targeting '{target}'?"
  - On confirm: remove rule from array at that index
  - On cancel: close dialog, no change
- `ConfirmDialog` is focus-trapped (trap focus within dialog while open, return focus on close)
- All state mutations are performed via a reducer or state setter passed from the parent editor component
- Validation re-runs automatically (debounced) because the rules array reference changes
