### Adapter Pattern section

Update the HybridAdapter documentation to reflect:
- `HybridAdapter` now overrides two AI methods: `explainRule` and `suggestExpression`
- Pattern: each AI endpoint gets its own HTTP function in `ai-api-client.ts` and a one-line override in `HybridAdapter`
- Other AI methods remain as `LocalStorageAdapter` throws until their vertical slices are implemented

### AI Integration section (new subsection or extend existing)

Document:

**Showcase AI Integration Pattern:**
- AI features are wired as vertical slices: type → HTTP function → adapter override → hook → component
- Each slice adds one function to `ai-api-client.ts`, one override to `HybridAdapter`, and one feature hook
- Source field context for NL → Rule is provided directly by the UI (extracted from parsed schema) as a showcase substitute for RAG
- Future: backend retrieves context via RAG pipeline; `sourceFields` field becomes optional/ignored; no client-side change needed
- The `SuggestExpressionInput.sourceFields` field is explicitly marked as a showcase/local-first mechanism

### RAG Compatibility note

Add a brief architecture note:
- Today: `sourceContext` is a pre-formatted text block populated by the UI from the parsed source schema (max 200 leaf fields, format: `"- {path} ({type})"` per line)
- Transition: when backend RAG is available, the backend ignores `sourceContext` and retrieves its own context
- The API contract allows both paths simultaneously — `sourceContext` remains optional
- No UI change is required when the backend transitions to RAG
