## Summary

Convert the existing disabled "Auto-map" placeholder button in `EditorTopBar` (`data-testid="automap-button"`, lines 238-249) into a live button that triggers full-schema auto-map by calling `triggerAutoMap(null)`. Wire the button with loading state from `autoMapReview.status` and pass `parsedTargetSchema` to the `useAutoMapReview` hook.

## Notes

- The existing placeholder button at EditorTopBar lines 238-249 has `disabled`, `aria-disabled="true"`, `title="AI-powered auto-mapping — coming soon"`, and `data-testid="automap-button"`. All of these attributes should be updated when `onAutoMap` is provided.
- The section trigger (`ObjectSummaryPanel` → `handleAutoMapTrigger`) passes a `sectionPath` string. The header trigger passes `null`. Both use the same `autoMapReview.triggerAutoMap()` method.
- The drawer context display should differentiate: when `sectionPath` is null, the drawer header should say something like "All eligible fields" instead of a specific section name. This is a cosmetic concern that may be handled by the existing `AutoMapReviewDrawer` based on its `sectionPath` prop being null.
- The `MappingEditorPage.test.tsx` has assertions about the automap button being disabled with a specific tooltip. Those tests will need to be updated to expect the button to be interactive.
