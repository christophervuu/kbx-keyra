## Summary

Add a post-processing filter to the auto-map Lambda handler that removes AI-generated suggestions whose `target` path is not present in the `targetSection` listing provided in the request. This prevents object-type suggestions from reaching the frontend when the frontend correctly excludes object nodes from the listing.

---

## Scope

### In Scope

- Parse the `targetSection` string (format: `"- {path} ({type})\n..."`) to extract the set of valid target paths
- After suggestion enrichment, filter suggestions to only include those whose `target` matches a path from the extracted set
- Log a warning for filtered-out suggestions (for debugging)
- Only apply the filter when `targetSection` is a multi-line listing (not a plain section path)
- Preserve existing behavior when `targetSection` is a plain path string (backward compatibility)

### Out of Scope

- Changing the AI prompt
- Modifying frontend code
- Changing CORS configuration
- Adding new endpoints

## Relevant Areas

- `src/lambda/ai/auto-map.ts` — handler: add target listing parser + post-processing filter
- `tests/lambda/ai/auto-map.test.ts` — new test cases for filtering

## Change Requirements

After the Lambda handler enriches suggestions with validation data, and before returning the response:

1. **Parse target listing**: If `targetSection` contains newline-separated lines matching the pattern `- {path} ({type})`, extract all `{path}` values into a `Set<string>`.
2. **Detect listing mode**: The filter only activates when the extracted set has >= 1 entries. If `targetSection` is a plain path (e.g., `"Order.Header"`) with no listing pattern, skip filtering (backward compat).
3. **Filter suggestions**: Remove any suggestion where `suggestion.target` is not in the allowed set.
4. **Log warnings**: For each filtered suggestion, emit `console.warn('[auto-map] Suggestion target not in listing, filtered: ${target}')`.
5. **Return filtered results**: The `suggestions` array in the response contains only allowed targets.

The parsing function should be a named helper (e.g., `parseTargetListing(targetSection: string): Set<string> | null`) for testability.

## Notes

- The listing format matches what the test fixture already uses: `"- Order.Header.DocumentType (string)\n- Order.Header.DocumentDate (string)"`. The parser should handle this format reliably.
- The regex pattern for extraction: `/^- (.+?) \(.+?\)$/gm` captures the path portion.
- This is a defense-in-depth measure — the primary filtering happens on the frontend by only listing eligible targets. The backend filter catches AI hallucinations.
