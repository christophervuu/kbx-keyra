## Summary

Add an optional `targetSection` field to the `AutoMapSectionInput` interface and update `autoMapSectionHttp` to include it in the POST request body when present. Also make `sectionPath` optional to support header mode (full-schema auto-map without a section path).

---

## Scope

### In Scope

- Update `AutoMapSectionInput` in `ui/src/lib/types/domain.ts`: add `readonly targetSection?: string`; make `sectionPath` optional (`readonly sectionPath?: string`)
- Update `autoMapSectionHttp` in `ui/src/lib/api/ai-api-client.ts`: include `targetSection` in the request body when defined
- Update existing tests in `ui/src/lib/api/__tests__/ai-api-client.test.ts` to cover `targetSection` being sent
- Verify no type errors introduced in downstream consumers

### Out of Scope

- Modifying the hook (T-05)
- Modifying the backend Lambda
- Adding new adapter methods
- Changing the adapter interface signature (method name stays `autoMapSection`)

## Change Requirements

1. **Type update** in `domain.ts`:
   ```typescript
   export interface AutoMapSectionInput {
     readonly projectId: string;
     readonly mappingId: string;
     readonly sectionPath?: string;       // made optional for header mode
     readonly targetSection?: string;     // NEW: eligible target listing
     readonly sourceContext?: string;
   }
   ```

2. **HTTP client update** in `ai-api-client.ts`:
   - Add `targetSection` to the request body object when it is defined and non-empty
   - Preserve existing `sectionPath` handling (still sent when present)
   - Both fields can coexist in the same request body

3. **Test update** in `ai-api-client.test.ts`:
   - Add test case: input with `targetSection` → body includes `targetSection`
   - Add test case: input without `targetSection` → body does not include `targetSection`
   - Add test case: input without `sectionPath` (header mode) → body does not include `sectionPath`
   - Verify existing tests still pass (backward compat)
