## Summary

Refine the `SchemaManagementSection` and `SchemaCard` components to visually present schemas as a secondary resource below mappings. Enhance schema cards with clearer color-coded origin badges, scope badges, sync status indicators, and a "used by N mappings" reference count. Update the section heading to use lighter visual weight compared to the mappings section heading.

## Change Requirements

### SchemaCard Origin Badge

Update the origin badge rendering to use color-coded backgrounds:

| Origin | Badge Color | Text |
|---|---|---|
| `cdm` | Blue (`bg-blue-100 text-blue-800`) | "CDM" |
| `published` | Purple (`bg-purple-100 text-purple-800`) | "Published" |
| `local` | Gray (`bg-gray-100 text-gray-700`) | "Local" |

Currently the origin badge may be using a single style. Replace with origin-specific colors to improve scanability.

### SchemaCard Scope Badge

Display the scope as a small badge or label:

| Scope | Display | Style |
|---|---|---|
| `global` | "Global" | Outline badge or small label |
| `project` (or `project-level`) | "Project" | Outline badge or small label |

### SchemaCard Sync Status

Render sync status as a compact indicator:

| Sync Status | Icon | Color | Label |
|---|---|---|---|
| `synced` | Check circle | Green | "Synced" |
| `not-synced` | Alert triangle | Amber | "Not synced" |
| `local-changes` | Edit icon | Amber | "Local changes" |
| N/A (local origin) | — | — | No sync indicator shown |

Show sync status only for schemas with `origin !== 'local'` (local uploads have no upstream to sync against).

### "Used by N Mappings" Count

Add a small text label or badge to each schema card showing how many mappings in the current project reference this schema:

- Derive from the existing `mappings` data: count mappings where `sourceSchemaId === schemaId` or `targetSchemaId === schemaId`
- This data is already available — `SchemaManagementSection` receives `mappingsReferencingSchema(schemaId)` via props
- Display: "Used by 2 mappings" or "Not used" if 0
- This helps users understand schema importance before removal

**Integration:**
- `SchemaCard` needs a new `usageCount` prop (or `usedByMappings` label)
- `SchemaManagementSection` derives the count and passes it to each card

### Section Heading Weight

Update the `SchemaManagementSection` heading:
- Use a lighter heading size/weight than the mappings section (e.g., `text-lg font-medium` vs the mappings section's `text-xl font-semibold`)
- This visually reinforces schemas as secondary to mappings

### Design for Future Collapsibility (Q4 Resolution)

The schemas section is always visible in this spec (collapsible interaction is deferred), but the section header structure should be designed so collapsibility can be added later without redesign:

- **Title row layout**: title text + schema count badge + Upload/Link buttons, with reserved space (or a muted chevron placeholder) where a collapse toggle will eventually go
- **Clear containment**: the section content area should be a distinct container (e.g., a div with a stable class/testid) so that adding `hidden` or height-collapse behavior later is a targeted change
- Do not add the collapse interaction itself — only ensure the markup structure supports it

### Preserve Acquisition Entry Points

No functional changes to the Upload/Link buttons or their dialogs. The three acquisition paths remain:
1. **Link CDM Schema** — via "Link Schema" button → `SchemaLinkPicker` (user selects CDM-origin schema)
2. **Link Published Schema** — via "Link Schema" button → `SchemaLinkPicker` (user selects published-origin schema)
3. **Upload New Schema** — via "Upload Schema" button → `SchemaUploadDialog`

## Notes

- The `SchemaCardData` type already includes `format`, `origin`, `scope`, `fieldCount`, `syncStatus`, and `isInferred`. No type changes are needed for existing badge data.
- The `usageCount` can be derived in `SchemaManagementSection` by cross-referencing the `mappings` prop against each schema's `schemaId`. The section already receives `mappingsReferencingSchema` function via props — use this to get the count (it returns mapping names, so `.length` gives the count).
- Color choices (blue/purple/gray) should use Tailwind's color palette consistently with the rest of the app. Adjust shades if needed for contrast.
