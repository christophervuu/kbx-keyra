## Summary

Restructure the Project Overview page layout to promote mappings as the primary content area above schemas, consolidate project identity and primary actions into a refined header pattern, and redistribute the current `ProjectActionsSection` content into the header's primary actions and overflow menu. This task changes the page skeleton and section ordering without altering the internal behavior of individual sections.

---

## Scope

- Restructure `ProjectOverviewPage.tsx` section ordering: Header → Summary Row (placeholder slot) → Mappings → Schemas → (optional compact footer)
- Consolidate `ProjectMetadataSection` + `ProjectActionsSection` into a unified header area:
  - Title row: project name (inline-editable) + primary action buttons (Create Mapping, Add Schema)
  - Metadata row: description (inline-editable), created/updated dates, tags (inline-editable)
  - Overflow menu (...): Open Deployments, Project Settings, Duplicate Project, Export Project (disabled), Delete Project (danger)

## Change Requirements

### Page Layout Restructure

Update `ProjectOverviewPage.tsx` (specifically `ProjectOverviewPageInner`) to render sections in this order:

1. **Refined Header** — project name, metadata, primary actions, overflow menu
2. **Summary Row Slot** — empty div or slot where T-03 will place the summary row
3. **Mappings Section** — `MappingListSection` (promoted to first content section)
4. **Schemas Section** — `SchemaManagementSection` (moved below mappings)
5. **Compact Footer** (optional) — any remaining secondary actions not absorbed by the header

### Refined Header Pattern

Create a `ProjectHeader` component (or refactor `ProjectMetadataSection`) that consolidates:

**Title Row:**
- Project name as a large heading (`h1` or similar), inline-editable on click (preserving existing `InlineEditableText` behavior)
- Right-aligned action buttons:
  - "Create Mapping" — primary button, calls `onCreateMapping`
  - "Add Schema" — secondary button, calls `onAddSchema`
  - Overflow menu button ("...") with dropdown containing:
    - "Open Deployments" — navigates to `/projects/:projectId/deployments`
    - "Project Settings" — navigates to `/projects/:projectId/settings`
    - "Duplicate Project" — calls `onDuplicateProject`
    - "Export Project" — disabled with "Coming in Phase 1" tooltip
    - Separator
    - "Delete Project" — danger action, calls `onDeleteProject` (with existing confirmation dialog)

**Metadata Row:**
- Description (inline-editable via `InlineEditableText`)
- Created date and Updated date (read-only, formatted)
- Tags (inline-editable via `InlineEditableTags`)

### Overflow Menu

- Use a button with `MoreHorizontal` (or similar Lucide icon) to trigger a dropdown
- Dropdown items have text labels and optional icons
- "Delete Project" styled as danger (red text)
- The menu closes on item click or outside click
- Keyboard accessible: Enter/Space to open, arrow keys to navigate, Escape to close

### Action Redistribution

| Current Location (ProjectActionsSection) | New Location |
|---|---|
| Create Mapping | Header title row — primary button |
| Add Schema | Header title row — secondary button |
| Duplicate Project | Header overflow menu |
| Export Project (disabled) | Header overflow menu |
| Project Settings link | Header overflow menu |
| Delete Project | Header overflow menu (danger) |

### Backward Compatibility

- The `useProjectOverview` hook API does not change
- All existing action callbacks (`onCreateMapping`, `onAddSchema`, etc.) are preserved
- The `SchemaUploadDialog` and `SchemaLinkPicker` modal triggers continue to work
- `data-testid="page-project-overview"` is preserved on the root element

## Notes

- The `ProjectActionsSection` component is retired (Q3 resolution). It should no longer be rendered by `ProjectOverviewPage`. All its actions are absorbed into the header: primary actions as buttons, secondary/destructive actions in the overflow menu. The component file may be deleted or marked as deprecated — do not retain a minimal footer version. If stronger Delete discoverability is desired in the future, that belongs on the Project Settings page, not as a section on the overview.
- The summary row slot is an intentional placeholder — T-03 will fill it with the actual component. Use a `{/* Summary row slot — see T-03 */}` comment or render a fragment.
- Consider whether `ProjectHeader` should be a new component in `features/projects/components/` or a refactor of `ProjectMetadataSection`. A new component is cleaner if the prop surface changes significantly.
