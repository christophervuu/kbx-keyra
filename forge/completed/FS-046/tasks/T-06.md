## Summary

Integrate the Auto-Map review drawer into the Mapping Editor by composing it at the route-page level, adding the trigger mechanism for section-based Auto-Map, and connecting the drawer's actions to the editor's `useMappingEditor` draft model.

---

## Scope

### In Scope

1. **Route-page composition**: Render `AutoMapReviewDrawer` (or composition wrapper) in `ui/src/routes/pages/MappingEditor.tsx`, alongside the existing `VersionHistoryDrawer` and `UnsavedChangesOverlay`
2. **Hook instantiation**: Call `useAutoMapReview` at the route-page level with editor state from `useMappingEditor`
3. **Trigger mechanism**: Add "Auto-Map This Section" button in `ObjectSummaryPanel` (right panel for object-type nodes):
   - Button visible when an object node is selected and the section has child fields
   - Button triggers `autoMapReview.triggerAutoMap(selectedTargetPath)`
   - Button shows loading state when request is in flight
4. **Editor navigation on Edit**: When user clicks Edit on a suggestion, `setSelectedTargetPath` navigates the editor to the target field, and the suggested expression is loaded as a draft
5. **Loading state**: Show a loading indicator on the trigger button or inline below it while the request is in flight

### Out of Scope

- Alternative trigger placements (context menu, EditorTopBar) — deferred to Q1 resolution
- Backend endpoint implementation
- Filtering within the drawer (deferred to later enhancement)
- EditorTopBar modifications (Auto-map placeholder remains as-is)

## Change Requirements

### Route-page composition

Add the Auto-Map review drawer alongside existing overlays in the route page:

```tsx
// ui/src/routes/pages/MappingEditor.tsx
// (conceptual — actual structure follows existing composition patterns)

const autoMapReview = useAutoMapReview({
  adapter,
  projectId,
  mappingId,
  rules: editor.rules,
  updateDraft: editor.updateDraft,
  setSelectedTargetPath,
  parsedSourceSchema,
});

return (
  <>
    <MappingEditorPage ... />
    {/* Existing overlays */}
    {showVersionHistory && <VersionHistoryDrawer ... />}
    {showUnsavedChanges && <UnsavedChangesOverlay ... />}
    {/* New Auto-Map review drawer */}
    <AutoMapReviewDrawer
      isOpen={autoMapReview.isDrawerOpen}
      onClose={autoMapReview.closeDrawer}
      ...
    >
      {/* cards */}
    </AutoMapReviewDrawer>
  </>
);
```

### ObjectSummaryPanel trigger

Add an "Auto-Map This Section" button to `ObjectSummaryPanel`:

```tsx
interface ObjectSummaryPanelProps {
  // ... existing props
  onAutoMapSection?: (sectionPath: string) => void;
  isAutoMapLoading?: boolean;
}
```

- Button renders below the existing coverage summary
- Button styling: outline/secondary button with a sparkle (✨) or wand icon
- Button text: "Auto-Map This Section"
- Disabled when `isAutoMapLoading === true` (shows spinner)
- Calls `onAutoMapSection(targetPath)` on click

This replaces the existing disabled "Auto-map this schema" placeholder in `BuilderEmptyState` for section-level scope. The `BuilderEmptyState` placeholder can remain as-is (it targets the full schema, which is a future capability).

### Drawer-editor interaction on Edit

When the user clicks Edit:
1. `editSuggestion(targetPath)` is called on the hook
2. The hook calls `updateDraft(targetPath, expression)` and `setSelectedTargetPath(targetPath)`
3. The editor's right panel switches to `ScalarFieldBuilder` for the target field
4. The suggested expression is loaded as the draft for that field
5. The drawer remains open — the user can return to reviewing other suggestions

### Mutual exclusion with other overlays

- If the Version History drawer is open, close it before opening the Auto-Map review drawer (and vice versa)
- At most one overlay drawer should be open at a time
- `UnsavedChangesOverlay` is a modal and takes priority when open
