## Summary

Configure CI pipeline integration so the E2E suite runs as a path-filtered parity gate: both Playwright projects (`localStorage` and `httpBackend`) must pass for the gate to be green. Add a GitHub Actions workflow file that triggers on PRs touching relevant paths (`ui/src/lib/api/`, `src/lambda/`, `src/lib/persistence/`, route/config/bootstrap files), starts mock server via Playwright `webServer`, runs both projects, and reports combined pass/fail status.

---

## Scope

### In Scope

- GitHub Actions workflow (`.github/workflows/e2e-parity.yml`) for E2E parity gate
- Path-filtered trigger (`on.pull_request.paths`) for:
  - `ui/src/lib/api/**`
  - `src/lambda/**`
  - `src/lib/persistence/**`
  - `tests/e2e/**`
  - `ui/src/main.tsx`
  - `ui/src/lib/api/bootstrap.ts`
- Mock server and Vite lifecycle managed by Playwright `webServer` (no manual CI process management)
- Combined pass/fail reporting (both projects must pass = green)
- Artifact collection: screenshots on failure, Playwright trace on first retry
- pnpm script for running the full parity gate locally: `pnpm test:e2e:parity`
- Documentation of how to run the parity gate locally and in CI

### Out of Scope

- Modifying existing CI workflows for other test types
- Cross-browser testing configuration
- Deployment or staging environment integration

---

## Relevant Areas

- `.github/workflows/e2e-parity.yml` — new (or equivalent CI config)
- `tests/e2e/playwright.config.ts` — may need CI-specific adjustments
- `package.json` — parity gate script
- `tests/e2e/mock-server/` — startup integration

---

## Change Requirements

- CI must:
  1. Install dependencies (`pnpm install`)
  2. Install Playwright browsers (`npx playwright install chromium`)
  3. Run `npx playwright test` (Playwright `webServer` starts mock server + Vite automatically)
  4. Both projects must pass for workflow to succeed
  5. Collect artifacts on failure
- Path filter must cover: `ui/src/lib/api/**`, `src/lambda/**`, `src/lib/persistence/**`, `tests/e2e/**`, bootstrap/main files
- Local parity script must replicate CI behavior:
  - Run both projects via single Playwright invocation
  - Report combined result
- Retries: 1 on CI (per `e2e-testing.md` guidance), 0 locally
- Reporter: `list` on CI, `html` locally (already in playwright.config from T-01, verify)

---

## Verification Requirements

- `pnpm test:e2e:parity` runs both projects and reports pass/fail locally
- CI workflow (if GitHub Actions) passes on a clean branch with all prior tasks complete
- Failure in either project causes combined failure
- Artifacts (screenshots/traces) are uploaded on failure
- Mock server is properly cleaned up even on test failure

---

## Acceptance Checks

- CI configuration file exists and is syntactically valid
- `pnpm test:e2e:parity` script runs successfully end-to-end
- Both Playwright projects are executed in CI
- CI workflow fails if either project fails
- Artifacts are collected on failure
- Mock server process does not leak (verified by checking port availability after run)
- No `ui/src/` source changes

---

## Blockers / Risks

- CI environment may not have Playwright browsers pre-installed (installation step handles this)
- Mock server port conflicts in CI (use dynamic port or ensure 4100 is free)
- Vite dev server startup time in CI may require health-check waiting

---

## Notes

- Consider using Playwright's built-in `webServer` array config to manage both Vite and mock server lifecycles, reducing CI script complexity
- If GitHub Actions is used, the `actions/setup-node` and pnpm caching patterns from existing workflows should be reused
- The parity gate does not need to run on every commit initially — it can be triggered on PRs touching relevant paths, but start with always-on for safety
