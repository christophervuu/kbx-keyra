## Summary

Implement comprehensive integration and composition tests that verify array functions work correctly when composed together. This covers the §6 patterns from the DSL Arrays spec, triple nesting verification, cross-array lookups, scope stack correctness across complex compositions, and error recovery scenarios. These tests exercise the full interaction between scope-creating functions, scope-reading functions, and array manipulation functions.

## Change Requirements

After this task is complete:

1. `tests/engine/functions/arrays-integration.test.ts` exists with comprehensive test suites covering:

   **Scope Stack Tests (Critical):**
   - `item()` reads from current element in `map()`
   - `item()` outside any context → E010
   - `parent()` reads from outer element in nested `map()`
   - `parent()` in single-level `map()` → E013
   - `source()` always reads root, even inside doubly-nested `map()`
   - `item("")` returns entire element (primitive arrays)
   - `parent("")` returns entire outer element
   - Scope is correctly popped after `map()` completes (subsequent `item()` outside → E010)
   - Scope is correctly popped even when an error occurs mid-iteration
   - Sequential `map()` calls don't leak scope (first finishes cleanly, second starts fresh)

   **Composition Tests:**
   - `map(filter(source("x"), condition), template)` — filter then map
   - `flatten(map(source("x"), item("subarray")))` — collect nested arrays
   - `get(find(source("x"), condition), "field")` — lookup pattern
   - `get(first(source("x")), "field")` — first + get
   - `join(map(source("x"), item("name")), ",")` — map then join
   - `count(filter(source("x"), condition))` — filter then count
   - `merge(map(...), map(...))` — merge transformed arrays
   - `array(first(source("a")), first(source("b")))` — array from computed values

   **§6 Pattern Tests:**
   - Pattern 6.1: Source with multiple items, template with field renames and computed values
   - Pattern 6.2: Filter for discountAmount > 0, then map to subset of fields
   - Pattern 6.4: `array()` of object templates, then `filter()` to remove nulls
   - Pattern 6.5: `merge()` of two `map()` calls with different templates
   - Pattern 6.7: Cross-reference with `find()` + `parent()` + `get()` — the full tax line lookup pattern
   - Pattern 6.10: Nested `map()` with departments/employees and `parent("name")` access
   - Pattern 6.11: `flatten(map(source("departments"), item("employees")))`

   **Triple Nesting Test:**
   - Three levels of `map()` — verify `item()` reads innermost, `parent()` reads middle, outermost is NOT accessible via `parent()`
   - Verify no error is thrown for triple nesting (it works, just limited access)

   **Error Recovery Tests:**
   - Expression error in one element of `map()` → other elements still processed
   - Expression error in `filter()` condition → element excluded, iteration continues
   - `find()` with no match inside `map()` → null returned, outer map continues

2. All tests pass end-to-end with the full function registry populated.

## Notes

- This is the most important verification task in the spec. The scope stack is the most complex runtime mechanism in the engine, and composition bugs will only surface in these integration tests.
- Use the exact examples from `specs/KEYRA-DSL-ARRAYS.md` §6 as test fixtures where possible — these are the canonical expected behaviors.
- The cross-array lookup pattern (Pattern 6.7) is the single most complex composition in the DSL. Test it thoroughly with multiple matching and non-matching elements.
- For triple nesting: verify that `parent()` at the third level reads from the SECOND level (immediate outer), not the first level. This is the documented v1.0 limitation.
