## Summary

Implement five array construction and manipulation functions that do NOT create scopes: `array()` builds arrays from individual expressions, `merge()` concatenates multiple arrays, `flatten()` removes one level of nesting, `first()` returns the first element, and `nth()` returns an element by index (with negative index support). These functions handle null/empty inputs per the DSL Arrays spec §5 behavior table.

---

## Scope

### In Scope

- Implement `array()`, `merge()`, `flatten()`, `first()`, `nth()` in `src/engine/functions/arrays.ts`
- `array()`: variadic, minimum 1 arg (E003 if zero — handled by evaluator arity check), null args included as null elements
- `merge()`: variadic, `handlesNull: true`, null args skipped, E005 if non-null arg is not array
- `flatten()`: one level of nesting removal, null → null, empty → `[]`
- `first()`: return `array[0]` or null, null/empty → null
- `nth()`: 0-based index, negative indices, W004 if out of bounds
- Register all in function registry
- Comprehensive unit tests for each function

### Out of Scope

- Deep flatten (only one level)
- Sorting, deduplication
- Type coercion within arrays

## Change Requirements

After this task is complete:

1. `array()` implementation:
   - Signature: variadic params (minimum 1), type `'any'` for each, `handlesNull: false` (standard propagation does NOT apply — null args are intentionally included)
   - Actually: since null args should be included, this function needs `handlesNull: true` to bypass null propagation (which would short-circuit on any null arg)
   - Collects all evaluated argument values into an array and returns it
   - Null values are included as-is (never filtered)

2. `merge()` implementation:
   - Signature: variadic params (minimum 1), type `'array'` for each, `handlesNull: true`
   - Iterates all arguments:
     - If arg is null → skip (treated as empty)
     - If arg is array → spread its elements into result
     - If arg is not null and not array → emit E005, skip that arg
   - Returns concatenated result
   - If ALL args are null → return `[]` (all skipped, result is empty)

3. `flatten()` implementation:
   - Signature: `[{ name: 'array', type: 'array' }]`, `handlesNull: false` (standard null propagation)
   - If input is `[]` → return `[]`
   - Iterates elements: if element is array, spread one level; otherwise keep as-is
   - Only ONE level of flattening: `[[1, [2]], [3]]` → `[1, [2], 3]`

4. `first()` implementation:
   - Signature: `[{ name: 'array', type: 'array' }]`, `handlesNull: false`
   - Null array → null (via standard propagation)
   - Empty array → null
   - Otherwise → `array[0]`

5. `nth()` implementation:
   - Signature: `[{ name: 'array', type: 'array' }, { name: 'index', type: 'number' }]`, `handlesNull: false`
   - Null array → null (via standard propagation)
   - Negative index: convert to `array.length + index`
   - Out of bounds (positive or negative) → null + W004 warning via `context.addDiagnostic()`
   - Valid index → `array[index]`

## Notes

- This task can be developed in parallel with T-01, T-02, and T-03.
- The `handlesNull` behavior for `array()` and `merge()` is critical: without it, the evaluator's standard null propagation would short-circuit on any null argument and return null, which is wrong for both functions.
- `array()` uses `handlesNull: true` because null arguments should be passed through (included in result), not trigger short-circuit.
- `merge()` uses `handlesNull: true` because null arguments should be skipped (not trigger short-circuit).
- `flatten()`, `first()`, `nth()` use standard null propagation (`handlesNull: false`) — null array input correctly produces null via the evaluator's standard mechanism.
