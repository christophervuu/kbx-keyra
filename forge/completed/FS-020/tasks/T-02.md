## Summary

Build the Target Schema Worklist component that renders the target schema as a navigable tree of field rows with mapping status indicators, section coverage, and support for grouping modes. This is the center column content and the primary interaction surface of the redesigned editor.

---

## Scope

### In Scope

- `TargetWorklist` component that accepts parsed target schema + mapping rules + validation results
- Renders target fields as an indented tree (respecting schema hierarchy)
- Each node renders using `TargetFieldRow` (T-03)
- Object nodes show expand/collapse behavior and section coverage indicators ("N/M mapped")
- Array nodes are visually distinct from scalar/object nodes (array badge)
- Supports grouping modes: schema hierarchy (default), required-first, unmapped-first, warnings/errors-first
- Emits `onSelectNode(targetPath, nodeType)` when a field row is clicked
- Highlights the currently selected target field
- Accepts filter/search state from Global Toolbar (T-04) to show/hide fields
- Computes mapping status per field: unmapped / mapped / warning / error (derived from rules + validation results)
- Section coverage computation for object nodes

### Out of Scope

- Global Toolbar component itself (T-04)
- Breadcrumb drill-down mode (T-11)
- Right panel builder content (T-05, T-06, T-07)
- Source panel interactions (T-09)
- Rules View (T-12)
- Virtualization of the tree for very large schemas (future optimization)

## Change Requirements

After this task is complete:

- `TargetWorklist` renders a tree of target fields from a parsed schema
- Each field's mapping status is computed by cross-referencing rules (by target path) and validation diagnostics
- Object nodes display coverage: count of mapped children / total children
- Tree supports expand/collapse for object and array nodes
- Active grouping mode reorders/groups the tree (controlled via prop)
- Active search/filter hides non-matching fields (controlled via prop)
- Selected field is visually highlighted (controlled via `selectedPath` prop)
- Click on any field row fires `onSelectNode(path, nodeType)` callback
- Component is purely presentational — state is owned by parent composition

Hook `useTargetStatus(rules, validationResult, parsedTargetSchema)`:
- Returns a `Map<string, TargetFieldStatus>` where status includes: `mapped | unmapped | warning | error`
- Returns section coverage data: `Map<string, { mapped: number; total: number }>`
- Re-derives on rules/validation changes
