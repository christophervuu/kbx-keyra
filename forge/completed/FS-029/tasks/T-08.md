## Summary

Create or update the expression decomposer to parse existing DSL expression strings back into the new `ValueModeState` shape. This enables editing existing mappings in the new builder by reconstructing the state tree from a DSL string, including recursive decomposition of nested function calls within argument positions.

---

## Scope

### In Scope

- New or updated decomposer in `ui/src/features/mappings/lib/` (e.g. `source-card-decomposer.ts`).
- Decomposes expressions into the new state variants:
  - `source("path")` → `DirectCopy`
  - `functionName(source("path"), literal, ...)` → `SourceWithTransform` (when first arg is a source and the function is a single-input transform)
  - `functionName(arg1, arg2, ...)` → `FunctionCall` with appropriate slot modes
  - Nested: `concat(upper(source("a")), source("b"))` → `FunctionCall` with slot 1 having a nested transform
- Each argument in a function call is decomposed:
  - `source("path")` → `{ mode: 'source', path }`
  - Literal string/number → `{ mode: 'literal', value }`
  - Nested function call → `{ mode: 'source', path, transform }` or `{ mode: 'expression', node }` depending on structure
- Round-trip guarantee: `generate(decompose(expr)) === expr` for all supported expression patterns.

### Out of Scope

- UI components.
- Expressions that cannot be represented in the builder (complex nested conditionals, etc.) — these should fall back gracefully (return null or a "raw" indicator).
- Changes to the engine parser.

## Change Requirements

- Export a `decomposeToSourceCardState(expression: string): ValueModeState | null` function.
- Returns `null` for expressions that cannot be represented in the new builder model.
- Uses the existing DSL parser/AST (from `ast-decomposer.ts` patterns) to parse the expression.
- Recursively decomposes nested function calls into argument slot states.
- Heuristic for `SourceWithTransform` vs `FunctionCall`: if the expression is `fn(source("x"), ...literals)` and the function's first parameter conceptually takes a "value", decompose as SourceWithTransform. Otherwise, decompose as FunctionCall.

## Notes

The existing `pipeline-decomposer.ts` and `ast-decomposer.ts` handle decomposition for the old pipeline model. The new decomposer should leverage existing AST parsing infrastructure but produce the new state types. It's acceptable to delegate parsing to the existing AST parser and focus this task on the AST → state mapping.
