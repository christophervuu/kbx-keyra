## Summary

Define the new `ValueModeState` type shape that replaces the current linear pipeline model. The new state represents a tree of Source Card nodes, Argument Form nodes with per-slot nested expressions, and a Connector node — enabling direct copy, single-source transforms, multi-input functions, and nested argument transforms.

---

## Scope

### In Scope

- New TypeScript types/interfaces in `expression-builder-state.ts`:
  - `SourceCardNode` — holds a source path and optional inline transform (function name + argument slots).
  - `ArgumentSlot` — a discriminated union: `{ mode: 'source', path: string, transform?: InlineTransform }` | `{ mode: 'literal', value: string }` | `{ mode: 'expression', node: ArgumentFormNode }`.
  - `InlineTransform` — `{ functionName: string, args: ArgumentSlot[] }` for nested transforms within a slot.
  - `ArgumentFormNode` — holds a function name and ordered `ArgumentSlot[]`.
  - `ConnectorNode` — holds function name, source cards being connected, and resolved argument slots.
  - Top-level `ValueModeState` as a discriminated union: `DirectCopy | SourceWithTransform | FunctionCall | PendingConnector`.
- State factory/helper functions: `createDirectCopyState`, `createSourceWithTransformState`, `createFunctionCallState`, `createPendingConnectorState`.
- Type exports for downstream consumers.

### Out of Scope

- UI components (those are separate tasks).
- Expression generation logic.
- Any changes to Conditional or Value Map mode state.

## Change Requirements

- The existing `ValueModeState` (with `sources` and `transforms` arrays) must be replaced or extended with the new discriminated union shape.
- The new state types must be rich enough to represent all Acceptance Examples (AE-01 through AE-07), including nested transforms within argument slots.
- Factory functions must produce valid default states for each variant.
- The `PendingConnector` variant represents the transient state where 2+ sources exist but no combining function has been selected yet.
- All types must be `readonly` where appropriate for immutability.

---

## Verification Requirements

- Unit tests for each factory function producing valid state.
- Type-level tests: ensure the discriminated union narrows correctly with type guards.
- Typecheck passes (`tsc --noEmit`).
- Existing imports of `ValueModeState` are updated or a compatibility shim is in place (may temporarily break downstream — tracked by T-09 integration task).
