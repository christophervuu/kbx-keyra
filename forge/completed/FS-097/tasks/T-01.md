## Summary

Establish the new conditional-builder state model, tray usage model, and deterministic conversion between guided conditional state and existing DSL. This task provides the core contracts used by UI components and compatibility behavior.

---

## Scope

### In Scope

- Define/extend state types for tray items, usages, condition rows, values, match mode, and per-usage transforms.
- Implement DSL decomposition for representable conditional expressions into guided state.
- Implement DSL generation from guided state using existing DSL functions only.
- Add unsupported-expression classification used by guided fallback notice.

### Out of Scope

- Full UI component rendering for tray and builder sections.
- Source Browser mode UI changes.

---

## Relevant Areas

- `ui/src/features/mappings/lib/smart-builder-state.ts`
- `ui/src/features/mappings/lib/smart-builder-expression-generator.ts`
- `ui/src/features/mappings/lib/*decomposer*.ts`
- `ui/src/features/mappings/lib/*smart-builder*.test.ts`

---

## Change Requirements

- Representable flat All/Any conditionals must round-trip without semantic drift.
- Unsupported nested logical groups and non-lossless reconstruction cases must be detected deterministically.
- Usage derivation must map field references to condition-left, condition-right, then, otherwise locations and direct mapping usage.

---

## Verification Requirements

- Unit tests for state typing + round-trip behavior.
- Tests for unsupported-expression detection and no-mutation fallback marker.
- Typecheck/lint on touched modules.

---

## Acceptance Checks

- Guided conditional state serializes to valid existing DSL for AE-01/AE-02 patterns.
- Representable DSL decomposes back into equivalent guided state.
- Unsupported nested/non-lossless expressions are marked unsupported (AE-11) with stable reason classification.
- Tests pass for touched builder-state/generator/decomposer modules.

---

## Blockers / Risks

- Existing decomposition utilities may not expose all metadata needed for per-usage transform reconstruction.

---

## Notes

- Ensure no new DSL syntax/function names are introduced.
