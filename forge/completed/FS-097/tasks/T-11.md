## Summary

Scope tray session state to the active target rule key and implement method-switch confirmation flows that preserve tray contents while preventing silent loss of conditional-specific configuration.

---

## Scope

### In Scope

- Scope session-only staged tray state by target key (`mappingId + targetPath`, or canonical rule id when available).
- Restore target-specific tray state when switching selected targets.
- Keep new unmapped targets initialized with empty tray + Direct default behavior.
- Implement Conditional→Direct (or other method) confirmation dialog with discard semantics for method-specific config.
- Preserve tray rows on both cancel and confirm paths.

### Out of Scope

- Persisting unused staged tray rows to mapping config.
- New global draft/save model beyond FS-094 behavior.

## Change Requirements

- Target switch must restore per-target tray session state deterministically.
- Method change confirmation must list conditional data being discarded and explicitly state tray preservation.
- Cancel must leave current method/draft/tray unchanged.
- Confirm must discard conditional-specific config while preserving tray.

---

## Verification Requirements

- Integration tests for per-target tray isolation and restoration behavior.
- UI tests for confirmation dialog cancel/confirm outcomes and preserved tray content.
- Regression tests aligned with FS-094 unsaved navigation behavior.

---

## Acceptance Checks

- Staged tray rows are isolated per target session key and do not leak across targets.
- Conditional→Direct method change shows confirmation and preserves tray on cancel/confirm.
- Existing unsaved navigation protections continue to function.
- Tests pass for target-scoped state and method-change confirmation behavior.
