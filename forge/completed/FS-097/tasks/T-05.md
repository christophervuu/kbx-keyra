## Summary

Implement left-type-based operator filtering, right-value editor specialization, and compatibility checks for field-to-field and field-to-fixed comparisons across multi-input conditionals.

---

## Scope

### In Scope

- Operator registry filtering by effective left-side type.
- Right-value editor mode selection (string/number/boolean/date/enum/null-check).
- Comparison compatibility checks and explicit transform affordance paths.
- Error presentation and apply-disable behavior for incompatible values.

### Out of Scope

- Silent coercion logic.
- New DSL functions for unsupported operator semantics.

## Change Requirements

- Operators shown must be representable via existing DSL composition.
- Incompatible selections remain visible but flagged with deterministic diagnostics.
- Explicit transform option required where compatibility requires conversion.

---

## Verification Requirements

- Unit/component tests for operator filtering matrix by type.
- Tests for incompatible comparisons blocking apply with no silent cast.

---

## Acceptance Checks

- Operator choices are type-aware and valid for supported DSL output.
- Right-side editors are type-aware and respect operator semantics.
- Incompatible comparisons are blocked and surfaced (AE-04).
- Tests pass for compatibility and validation pathways.
