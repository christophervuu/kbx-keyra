## Summary

Replace the fixed-percentage column widths in MappingEditorPage with user-resizable panels. Add vertical drag handles between Source/Target and Target/Builder columns. Enforce min/max width constraints. Support double-click to collapse Source and Builder panels. Enhance the existing bottom panel resize with double-click collapse. Persist the full layout state (column widths, bottom height, collapse states) in localStorage.

---

## Scope

### In Scope

- Create a `useResizableLayout` hook that manages column widths, bottom height, collapse states, drag logic, and localStorage persistence.
- Render vertical drag handles (6px interactive zones) between column panels.
- Apply min-width constraints: Source 180px, Target 250px, Builder 300px.
- Double-click a vertical drag handle to collapse the panel to its left (Source handle collapses Source) or right (Builder handle collapses Builder). Target is not collapsible.
- When a panel is collapsed, render a persistent expand strip (12-16px wide) on the collapsed edge with a chevron icon and the panel label rotated vertically. Clicking the strip restores the panel. This is the primary restore mechanism. Double-click on the drag handle is the secondary power-user shortcut.
- Enhance the existing bottom-panel resize handle to support double-click collapse (collapses to InlinePreviewStrip collapsed state) and localStorage persistence of height.
- Persist layout to `keyra:editor-layout` localStorage key.
- Restore layout from localStorage on mount; fall back to defaults if missing, corrupt, or violating constraints.
- Ensure drag handles do not interfere with HTML5 DnD (source-to-builder drag).

### Out of Scope

- Keyboard-based panel resizing.
- Panel resizing on mobile viewports.
- Changes to panel content or slot contracts.
- Any changes to toolbar controls (handled in T-01).

## Change Requirements

**`useResizableLayout` hook:**

Signature:
```ts
interface LayoutState {
  sourceWidth: number;
  targetWidth: number;
  bottomHeight: number;
  sourceCollapsed: boolean;
  bottomCollapsed: boolean;
}

interface UseResizableLayoutResult {
  layout: LayoutState;
  sourceHandleProps: ResizeHandleProps;
  builderHandleProps: ResizeHandleProps;
  bottomHandleProps: ResizeHandleProps;
  expandSource: () => void;
  collapseSource: () => void;
  expandBottom: () => void;
  collapseBottom: () => void;
}
```

- Reads initial state from `keyra:editor-layout` in localStorage.
- Falls back to defaults: `{ sourceWidth: 240, targetWidth: 450, bottomHeight: 260, sourceCollapsed: false, bottomCollapsed: false }`.
- On mount, validates stored values against min/max constraints and current viewport. Clamps or falls back if invalid.
- Writes to localStorage on every drag end and collapse/expand action (not during drag — only on mouse up).
- Drag logic: mousedown on handle starts resize mode. Sets `cursor: col-resize` (or `row-resize` for bottom) on `document.body`. Mousemove updates widths. Mouseup ends resize and persists.
- Min-width enforcement: during drag, clamp the shrinking panel to its minimum; the expanding panel gets whatever space was freed.
- Double-click on source handle: toggle `sourceCollapsed`. Double-click on builder handle: toggle builder collapsed state (derive from available width — if builder < its min, it's collapsed). Double-click on bottom handle: toggle `bottomCollapsed`.
- Expose `ResizeHandleProps` for each handle: `onMouseDown`, `onDoubleClick`, `style` (cursor, position).

**MappingEditorPage.tsx:**

- Replace fixed percentage widths with pixel widths from `useResizableLayout`.
- Source column: `width: layout.sourceCollapsed ? 0 : layout.sourceWidth` (with transition).
- Target column: `flex: 1` or `width: totalAvailable - sourceWidth - builderWidth` (derived).
- Builder column: derived from remaining space or collapsible.
- When a column is collapsed, render a thin expand strip (12-16px wide, full height, with a chevron icon and the panel label rotated vertically). Clicking the strip restores the panel.
- Bottom area: `height: layout.bottomCollapsed ? 0 : layout.bottomHeight`.
- Replace the existing bottom resize `useEffect` (mousedown/mousemove/mouseup) with the hook's `bottomHandleProps`.

**ResizeHandle component (optional extraction):**

A small presentational component rendering the drag handle UI:
- 6px wide (vertical) or 6px tall (horizontal).
- `hover:bg-blue-500/20` visual feedback.
- `cursor: col-resize` or `cursor: row-resize`.
- `data-testid="resize-handle-source"`, `resize-handle-builder"`, `resize-handle-bottom"`.

**Collapsed panel strip:**

When Source is collapsed, render a 12-16px-wide persistent expand strip in its place:
- Rotated label: "Source".
- ChevronRight icon.
- `onClick` calls `expandSource()` (primary restore mechanism).
- Double-click on the drag handle is the secondary restore shortcut.
- `data-testid="expand-source"`.

When bottom is collapsed, the InlinePreviewStrip already has a collapsed state (`isCollapsed`). Wire `layout.bottomCollapsed` to drive `isCollapsed` in `ConnectedInlinePreviewStrip`.

## Notes

- The existing bottom resize in `MappingEditorPage` uses `useState(bottomHeight)`, a `startResize` callback, and a `useEffect` with mousemove/mouseup. This should be consolidated into the new `useResizableLayout` hook.
- Builder panel collapse is derived: if the user double-clicks the builder handle, the builder shrinks to zero and Target panel expands. However, the builder panel is the primary editing surface and collapsing it is less useful. For this task, implement Source and Bottom collapse only. Builder handle is resize-only with no collapse behavior.
- Expand strip spec: 12-16px wide, persistent, always visible when collapsed. Primary restore mechanism is clicking the strip; double-click on drag handle is the secondary shortcut. Follows the VS Code / Chrome DevTools / IntelliJ pattern.
- Transition animation: use `transition: width 200ms ease` on columns and `transition: height 200ms ease` on bottom for collapse/expand. Disable transition during active drag (set a `dragging` class).
