## Summary

Add a test case selector dropdown to the inline preview strip (Target View) and to the BottomArea (Rules View) so users can load saved test data into the source textarea without manually pasting JSON. The dropdown lists test cases from `useTestCases(mappingId)` and populates `sourceData` on selection. Both surfaces share the same hook and produce identical behavior.

---

## Scope

### In Scope

- Add a `<select>` dropdown (or custom dropdown) to `InlinePreviewStrip.tsx` in the expanded view, positioned next to the source textarea label.
- Add `testCases` and `onLoadTestCase` props to `InlinePreviewStripProps`.
- In `ConnectedInlinePreviewStrip`, call `useTestCases(mappingId)` and pass `testCases` and an `onLoadTestCase` handler that sets `sourceData` state.
- Add the same test case selector dropdown to `BottomArea.tsx` in its source data section.
- Wire `BottomArea` to receive `testCases` and `onLoadTestCase` props from the composition layer.
- Empty state: when `testCases.length === 0`, show "No saved test cases" as a disabled option (in both surfaces).
- When a test case is selected, populate the source textarea with the test case's `sourceData`.
- After loading, the dropdown resets to a neutral "Load test case..." placeholder to allow re-selecting the same case.
- Update component tests for both surfaces.

### Out of Scope

- Test case CRUD in the preview strip or BottomArea (save, edit, delete remain on Advanced Testing page only).
- Changes to `useTestCases` hook internals.

## Change Requirements

**InlinePreviewStrip.tsx:**

Add to `InlinePreviewStripProps`:
```ts
testCases?: readonly TestCase[];
onLoadTestCase?: (id: string) => void;
```

In the expanded view, render a dropdown above or inline with the source textarea:
- Label: "Test case" or icon-only with tooltip.
- Default option: "Load test case..." (disabled, selected by default).
- One `<option>` per test case: display `testCase.name`.
- `onChange` fires `onLoadTestCase(selectedId)` then resets the dropdown to the placeholder.
- When `testCases` is empty or undefined, render the dropdown with only "No saved test cases" (disabled).
- `data-testid="strip-test-case-selector"`.

Position the dropdown in the source section header (left 30% area), below the "Source JSON" label and above the textarea.

**ConnectedInlinePreviewStrip.tsx:**

- Import and call `useTestCases(mappingId)` (add `mappingId` to its props if not already present — it already receives `mappingId`).
- Derive a `handleLoadTestCase` callback:
  ```ts
  const handleLoadTestCase = useCallback((id: string) => {
    const tc = loadTestCase(id);
    if (tc) setSourceData(tc.sourceData);
  }, [loadTestCase]);
  ```
- Pass `testCases` and `onLoadTestCase={handleLoadTestCase}` to `InlinePreviewStrip`.

**BottomArea.tsx:**

- Add `testCases?: readonly TestCase[]` and `onLoadTestCase?: (id: string) => void` to `BottomAreaProps`.
- In the source data section (the Preview tab or source input area), render the same dropdown pattern as InlinePreviewStrip:
  - Default option: "Load test case..." (disabled, selected by default).
  - One `<option>` per test case: display `testCase.name`.
  - `onChange` fires `onLoadTestCase(selectedId)` then resets.
  - Empty state: "No saved test cases" (disabled).
  - `data-testid="bottom-test-case-selector"`.
- The composition layer that owns BottomArea's props must wire `useTestCases(mappingId)` and pass `testCases` + `onLoadTestCase` (same pattern as ConnectedInlinePreviewStrip).

This is fine — both read on mount and each owns its own copy of state. Changes made on the Advanced Testing page won't live-sync to the strip (user must navigate back). This is acceptable for Phase 0.
- The `TestCase` type is likely defined in `use-test-cases.ts` or `types.ts`. Check the feature barrel for the exported type.
