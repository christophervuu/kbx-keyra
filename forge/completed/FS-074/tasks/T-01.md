## Summary

Establish the canonical cross-feature suggestion review contract (state/action semantics) and enforce mutation guardrails so AI generation lifecycle events cannot mutate mapping config without explicit user acceptance/apply actions.

---

## Scope

### In Scope

- Shared suggestion artifact type/state contract updates in domain/API layers.
- Explicit action-intent boundaries between generation events and mutation events.
- Hook/service-level guardrails for mutation entry points.
- Universal invalid/stale apply block policy in shared eligibility semantics.
- Tests asserting no mutation on generate/refresh/retry/failure without accept/apply.

### Out of Scope

- UI visual component implementation details.
- Feature-specific card rendering polish.

---

- `ui/src/lib/types/domain.ts`

## Change Requirements

- Define a reusable suggestion state model supporting generated/edited/accepted/dismissed/stale and action eligibility metadata.
- Ensure generation lifecycle callbacks do not call rule mutation APIs.
- Ensure only explicit accept/apply handlers invoke draft mutation paths.
- Enforce universal block rules: invalid suggestions cannot apply; stale suggestions cannot apply in V1.
- Provide deterministic error/refresh behavior that preserves no-mutation invariants.

---

## Verification Requirements

- Unit tests for state transitions and mutation gating.
- Regression tests proving mapping config stability across non-accept lifecycle paths.
- Typecheck for touched UI/domain files.

## Acceptance Checks

- Shared contract exists and is used by affected AI suggestion flows.
- Non-accept lifecycle events do not mutate mapping config.
- Explicit accept/apply path remains the only mutation path for AI suggestions.
- Tests mapped to `AE-02` and `AE-05` pass.
