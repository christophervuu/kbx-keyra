## Summary

Add per-environment deployment status badges (current / stale / not deployed) to mapping cards on the project overview page and home dashboard. Badges reflect staleness computed from `getCurrentDeployments()` response.

---

## Scope

### In Scope

- Extend `StatusBadge` component (or create `DeploymentBadge`) for deployment states
- Project overview mapping cards: show DEV/QA/PROD badges
- Home dashboard mapping items: show deployment indicators
- Fetch current deployments alongside mapping data

### Out of Scope

- Deployment page (T-05/T-06)
- Deployment API/adapter (T-04)

---

## Relevant Areas

- `ui/src/components/StatusBadge.tsx`
- `ui/src/features/projects/components/` (mapping cards)
- `ui/src/features/home/components/` (dashboard items)
- `ui/src/features/projects/hooks/`
- `ui/src/features/home/hooks/`

---

## Change Requirements

- Create or extend badge component for three states: current (green), stale (amber/yellow), not-deployed (gray)
- Badge shows environment label (D/Q/P or DEV/QA/PROD) + status color
- Fetch `getCurrentDeployments()` for each mapping displayed and render badges
- Handle loading/error states gracefully (badge shows dash or loading indicator)

---

## Verification Requirements

- Component tests: badge renders correct state for each status value
- Integration with mock adapter: badges appear on mapping cards
- `tsc --noEmit` passes

---

## Acceptance Checks

- Mapping cards show per-environment deployment badges
- "Current" badge renders green
- "Stale" badge renders amber
- "Not deployed" renders gray
- Badges appear on both project overview and home dashboard
- `tsc --noEmit` and lint pass

---

## Blockers / Risks

- Performance: fetching current deployments for many mappings on list pages could be slow; may need batch endpoint or aggregation (acceptable as follow-up optimization)
