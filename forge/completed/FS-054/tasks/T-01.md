## Summary

Perform a comprehensive filesystem audit comparing the actual repository layout (`src/`, `ui/`, `tests/`, top-level config files) against the documented structure in `forge/architecture/project-structure.md`. Produce a structured list of drift points: entries documented but not present, entries present but not documented, and entries that are accurately documented.

---

## Scope

### In Scope

- Traversing `src/` directory tree (all subdirectories) and comparing against documented layout
- Traversing `ui/src/` directory tree and comparing against documented layout
- Traversing `tests/` directory tree and comparing against documented layout
- Checking top-level files/directories against documented layout
- Identifying non-existent documented entries (e.g., `src/types/` which does not exist)
- Identifying architecturally significant undocumented entries
- Light structural review of `e2e-testing.md` and `ai-runtime.md` for filesystem-level drift (documented paths that don't exist, or important undocumented paths)
- Producing a structured audit findings document as task output

### Out of Scope

- Updating any architecture documents (that is T-04)
- Auditing code content, correctness, or test coverage
- Evaluating whether the structure is well-designed
- Deep content review of `e2e-testing.md` or `ai-runtime.md` beyond path accuracy

---

## Relevant Areas

- `forge/architecture/project-structure.md`
- `forge/architecture/e2e-testing.md` (path references only)
- `forge/architecture/ai-runtime.md` (path references only)
- `src/` (actual filesystem)
- `ui/src/` (actual filesystem)
- `tests/` (actual filesystem)
- Root directory (actual filesystem)

---

## Change Requirements

This task produces a **structured audit findings document** (not committed — used as input to T-04). The findings document must contain:

1. **Confirmed entries**: Documented paths that match reality (brief confirmation, no detail needed)
2. **Documented but missing**: Paths listed in `project-structure.md` that do not exist in the repository. For each: path, what the doc says it is, and a note on whether it was never created or was moved/renamed.
3. **Present but undocumented**: Architecturally significant paths that exist in the repository but are not listed in `project-structure.md`. "Architecturally significant" means: directories that represent module boundaries, new feature modules, shared utilities, or test infrastructure. Individual component files within already-documented feature folders do NOT need to be listed (those are handled at the feature-module granularity level).
4. **e2e-testing.md path accuracy**: Any paths referenced in `e2e-testing.md` that don't exist or are stale
5. **ai-runtime.md path accuracy**: Any paths referenced in `ai-runtime.md` that don't exist or are stale

The findings should be organized by top-level area (`src/`, `ui/`, `tests/`, root) for clarity.

---

## Verification Requirements

- Every "documented but missing" entry can be confirmed by attempting to access the path
- Every "present but undocumented" entry can be confirmed by listing the directory
- No false positives: if a directory exists, it must not appear in "documented but missing"
- Findings cover all areas of `project-structure.md` (no sections skipped)

---

## Acceptance Checks

- At least the known drift point (`src/types/` documented but non-existent) is identified
- All architecturally significant directories in `src/`, `ui/src/`, and `tests/` are accounted for (either confirmed or noted as undocumented)
- E2E testing and AI runtime docs are checked for path accuracy
- Findings are structured clearly enough to be directly actionable by T-04
