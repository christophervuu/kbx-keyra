## Summary

Perform a content-level audit comparing the UI application implementation (`ui/src/`) against the architecture documentation in `forge/architecture/ui-application.md`. Identify drift between documented module structure, patterns, adapter layer, state management, routing, component organization, and the actual implemented code. Produce structured findings for T-06 and Phase 1 readiness context for T-07.

## Change Requirements

Produce a **structured audit findings document** (used as input to T-06 and T-07) containing:

1. **Module structure alignment**: Compare documented `ui/src/` module structure tree against actual filesystem. Note directories/files that are documented but don't exist, or exist but aren't documented (at the architecturally significant level — not every component file).

2. **Adapter pattern alignment**: Verify documented adapter contracts match actual `ApiAdapter` interface methods. Check that `LocalStorageAdapter`, `HybridAdapter`, `bootstrap.ts` behave as documented. Note any methods or behaviors that have drifted.

3. **State management alignment**: Verify no external state libraries are installed (check `package.json`). Verify `AsyncState<T>` shape matches documentation. Note any emergent state patterns not documented.

4. **Routing alignment**: Compare documented routes against actual `App.tsx` route configuration. Note any routes added/removed/changed since documentation.

5. **Component organization alignment**: Verify shared components match documented primitives. Verify feature modules match documented list. Note any cross-feature imports that violate documented rules.

6. **Engine integration alignment**: Verify `ui/src/lib/engine/` exports and pattern match documentation. Check hook patterns (`useEngineValidation`, `useExpressionPreview`) match documented contracts.

7. **Mapping Editor architecture alignment**: Verify layout structure, view toggle pattern, component hierarchy, and slot model match documentation.

8. **Phase 1 boundary inventory**: For each adapter method, document:
   - What it does today (localStorage behavior)
   - What Phase 1 backend must provide
   - Any implicit assumptions about data shape, pagination, error handling, latency
   - AI showcase methods (HybridAdapter overrides) and their transition path

9. **Undocumented conventions**: Identify patterns that have become convention across the codebase but are not explicitly documented in the architecture doc (e.g., naming conventions, hook patterns, test colocation strategy).
