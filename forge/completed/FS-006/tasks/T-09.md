## Summary

Implement the coverage computation that calculates what percentage of required target fields have a corresponding mapping rule. Returns a `CoverageResult` with total, mapped, percentage, and optional list of unmapped field paths.

---

## Scope

### In Scope

- Function `computeCoverage(rules, targetSchema): CoverageResult`
- Walk target SchemaTree to get all required leaf field paths via `getRequiredLeafPaths()`
- Build a set of all `rule.target` values from the rules array
- For each required leaf path, check if any rule targets it
- Compute:
  - `total` = number of required leaf paths
  - `mapped` = number of required leaf paths present in the rule targets set
  - `percentage` = `total === 0 ? 100 : Math.round((mapped / total) * 100)` (vacuous truth for empty)
  - `unmappedFields` = list of required leaf paths NOT in the rule targets set
- Unit tests

### Out of Scope

- Emitting diagnostics for unmapped fields (the orchestrator or caller may use coverage data to produce W005 warnings if desired, but that's not this task's responsibility)
- Checking whether the rule is valid (coverage counts rule presence, not correctness)
- Target path validation (T-04)
- Optional field tracking

## Change Requirements

The coverage computation:

1. Calls `targetSchema.getRequiredLeafPaths()` to get the list of required target field paths
2. Creates a `Set<string>` of all `rule.target` values from the config
3. For each required leaf path, checks set membership
4. Returns `CoverageResult`:
   ```typescript
   {
     total: requiredPaths.length,
     mapped: matchedCount,
     percentage: total === 0 ? 100 : Math.round((mapped / total) * 100),
     unmappedFields: unmatchedPaths.length > 0 ? unmatchedPaths : undefined,
   }
   ```

Edge cases:
- Empty rules array → mapped = 0, percentage = 0 (if required fields exist)
- No required fields in schema → total = 0, mapped = 0, percentage = 100
- All required fields mapped → percentage = 100, unmappedFields = undefined
- Rule targets a non-required field → doesn't count toward coverage (but doesn't hurt)
- Rule targets a path that doesn't exist in schema → counted normally (E031 catches this separately)

## Verification Requirements

Unit tests:
- 3 required fields, all mapped → total=3, mapped=3, percentage=100, no unmapped
- 4 required fields, 2 mapped → total=4, mapped=2, percentage=50, unmapped=['b','d']
- No required fields → total=0, mapped=0, percentage=100
- Empty rules → total=N, mapped=0, percentage=0, unmapped lists all
- Rules targeting non-existent paths → still counted in mapped check (they don't match required paths)
- Rules targeting optional fields → don't affect coverage calculation
- Large schema (100+ required fields) → correct computation

TypeScript strict compilation passes.

## Notes

Coverage computation is purely structural — it doesn't validate whether the rules are correct, only whether required target fields have at least one rule targeting them. A rule with a type mismatch still "covers" the field for coverage purposes. The separate validation passes catch the correctness issues.
