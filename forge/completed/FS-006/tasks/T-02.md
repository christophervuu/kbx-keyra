## Summary

Update the `ValidationResult` interface in `src/engine/types/results.ts` to replace the simple `coverage?: number` field with a structured `CoverageResult` object containing total, mapped, percentage, and unmappedFields. This is a foundational type change that the coverage computation (T-09) and orchestrator (T-10) depend on.

---

## Scope

### In Scope

- Define `CoverageResult` interface in `src/engine/types/results.ts`
- Update `ValidationResult.coverage` from `number` to `CoverageResult | undefined`
- Ensure existing code that references `ValidationResult` still compiles (the stub in validate.ts returns no coverage, so it should be fine)

### Out of Scope

- Implementing the coverage computation logic (that's T-09)
- Changing any other types
- Adding new error/warning codes

---

## Relevant Areas

- `src/engine/types/results.ts`
- `src/engine/types/index.ts` (barrel export)
- `src/engine/validate.ts` (must still compile)

---

## Change Requirements

Add `CoverageResult` interface:

```typescript
export interface CoverageResult {
  readonly total: number;       // total required target fields
  readonly mapped: number;      // required target fields with a rule
  readonly percentage: number;  // mapped / total * 100, or 100 if total === 0
  readonly unmappedFields?: readonly string[];  // paths of unmapped required fields
}
```

Update `ValidationResult`:

```typescript
export interface ValidationResult {
  readonly valid: boolean;
  readonly diagnostics: readonly Diagnostic[];
  readonly coverage?: CoverageResult;
}
```

Ensure `CoverageResult` is exported from the types barrel.
