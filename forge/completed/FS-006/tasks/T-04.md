## Summary

Implement the validation pass that checks every `rule.target` against the target SchemaTree, emitting E031 for paths that don't exist. Additionally, detect when multiple rules map to the same target path and emit a warning diagnostic for each duplicate.

---

## Scope

### In Scope

- Function `validateTargetPaths(rules, targetSchemaTree): Diagnostic[]`
- For each rule, check `targetSchemaTree.hasPath(rule.target)`
- Emit E031 diagnostic for non-existent target paths with:
  - `code: 'KEYRA-E031'`
  - `severity: 'error'`
  - `message` containing the invalid path
  - `ruleIndex` and `targetPath`
- Function `detectDuplicateTargets(rules): Diagnostic[]`
- Detect rules sharing the same `target` value
- Emit `KEYRA-W006` warning for each duplicate occurrence (the second and subsequent rules targeting the same path)
- Add `KEYRA-W006` to `diagnostics/codes.ts` with template: `"Duplicate target path: \`{path}\` is mapped by rules at indices {indices}"`
- Unit tests

### Out of Scope

- Source path validation (T-03)
- Type checking of target values (T-06)
- Coverage computation (T-09)

## Change Requirements

**Target path validation:**
1. Iterate over all rules
2. For each rule, call `targetSchemaTree.hasPath(rule.target)`
3. If false, emit E031 with the target path and rule index

**Duplicate target detection:**
1. Build a map of `target → ruleIndex[]`
2. For any target with 2+ rules, emit a warning for each rule after the first
3. Warning should include both the target path and the indices of conflicting rules

If no existing diagnostic code covers duplicate targets, add `KEYRA-W006` to `diagnostics/codes.ts` with template: `"Duplicate target path: \`{path}\` is mapped by rules at indices {indices}"`. (Confirmed — W006 is the code to use.)

## Verification Requirements

Unit tests:
- Valid target path → no diagnostic
- Invalid target path → E031 with correct path and ruleIndex
- Multiple invalid targets → one E031 per rule
- Two rules with same target → warning diagnostic for the duplicate
- Three rules with same target → warning for rule 2 and rule 3
- Duplicate detection does not affect `valid` (warnings only)
- Empty rules array → no diagnostics

TypeScript strict compilation passes.

## Notes

The duplicate target check is intentionally a warning, not an error. At runtime the last rule wins, but duplicates are almost always a mistake. The warning should help BAs catch copy-paste errors in the Mapping Editor.
