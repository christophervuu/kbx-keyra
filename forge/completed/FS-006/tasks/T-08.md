## Summary

Implement the validation pass that checks all `constant("name")` and `external("name")` calls in rule ASTs against the mapping config's declared constants and externalSources. Emits E011 for undefined constants (error) and E012 for undeclared externals (warning).

---

## Scope

### In Scope

- Function `validateConstantsAndExternals(rules, parsedAsts, config): Diagnostic[]`
- For each rule's AST, find all `constant("name")` calls:
  - Check if `name` exists as a key in `config.constants`
  - If not → emit E011 (error)
- For each rule's AST, find all `external("name")` calls:
  - Check if `name` exists in `config.externalSources` array
  - If not → emit E012 (warning)
- Reuse AST walking utility from T-03 (`findFunctionCalls` or equivalent)
- Unit tests

### Out of Scope

- Validating the type/value of constants
- Checking external source availability at runtime
- Source or target path validation

## Change Requirements

The validator:

1. Uses the AST walking utility to find all `FunctionCall` nodes named `constant` in each rule's AST
2. For each, checks if the first argument is a `StringLiteral`
3. If yes, checks if `config.constants[argument.value]` exists (key presence, not value truthiness — the constant can be `null` or `0`)
4. If the key doesn't exist → emit E011 with the constant name, ruleIndex, targetPath

Similarly for `external`:
1. Find all `FunctionCall` nodes named `external`
2. Check first argument is `StringLiteral`
3. Check if `config.externalSources.includes(argument.value)`
4. If not declared → emit E012 (severity: warning) with the external name

Edge cases:
- `constant()` with non-literal argument → skip (name not statically determinable)
- `external()` with non-literal argument → skip
- Config with empty constants object → every constant() call with a literal name produces E011
- Config with empty externalSources array → every external() call produces E012

---

## Verification Requirements

Unit tests:
- `constant("EXISTING")` with key in config → no diagnostic
- `constant("MISSING")` → E011 error with name in message
- `constant("ZERO_VALUE")` where value is 0 → no diagnostic (key exists)
- `external("declared")` in externalSources → no diagnostic
- `external("undeclared")` not in externalSources → E012 warning
- E012 severity is warning → valid remains true
- Multiple constant calls, mix of valid/invalid → correct diagnostics for each
- Non-literal argument → gracefully skipped
- Rule with null AST → skipped

TypeScript strict compilation passes.

## Notes

This validation pass has no dependency on SchemaTree — it only needs the config object and the parsed ASTs. It could technically run in parallel with T-03/T-04, but depends on T-03 for the shared AST walking utility.

The `hasOwnProperty` or `in` operator check (not truthiness) is important for constants — a constant with value `null`, `0`, `""`, or `false` is still a valid defined constant.
