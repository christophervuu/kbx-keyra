## Summary

Implement a static type inference utility that determines the output type of a parsed AST expression without executing it. Uses function signatures from the registry to infer return types, and the source SchemaTree to resolve source path types. This utility is consumed by type compatibility checking (T-06) and array context validation (T-07).

---

## Scope

### In Scope

- Function `inferType(node: AstNode, context: TypeInferenceContext): ValueType | undefined`
- `TypeInferenceContext` containing:
  - `registry: FunctionRegistry` — for function return type lookup
  - `sourceSchema: SchemaTree` — for resolving `source("path")` types
  - `arrayDepth: number` — tracks nesting for item/parent resolution
- Type inference rules:
  - `StringLiteral` → `'string'`
  - `NumberLiteral` → `'number'`
  - `BooleanLiteral` → `'boolean'`
  - `NullLiteral` → `'null'`
  - `ObjectTemplate` → `'object'`
  - `FunctionCall` → look up function in registry, return `signature.returnType`
  - Special cases:
    - `source("path")` → look up type from sourceSchema
    - `cast(expr, "targetType")` → return the target type literal
    - `item("path")` → context-dependent (from array element type if determinable, else `any`)
    - `map(...)` → `'array'`
    - `filter(...)` → `'array'`
    - `find(...)` → infer from array element type or `any`
    - `if(cond, then, else)` → unify types of then/else branches (or `any` if they differ)
    - `static(value)` → infer from literal argument type
  - When type cannot be determined → return `undefined` (signals "skip check")
- Unit tests

### Out of Scope

- Emitting diagnostics (this utility just returns types; callers emit diagnostics)
- Runtime evaluation
- Full type unification or generic type algebra
- Handling every possible function (best-effort for known builtins, fallback to returnType from signature)

## Change Requirements

The `inferType` function recursively walks the AST to determine the output type:

1. **Literals** — return their literal type directly
2. **FunctionCall** — look up function name in registry:
   - If not found → return `undefined` (can't infer)
   - If found → return `signature.returnType`
   - Override for special functions:
     - `source("path")`: if path argument is StringLiteral, look up `sourceSchema.getTypeAtPath(path)`; if found return it, else return `any`
     - `cast(expr, "type")`: if second arg is StringLiteral, return that type as ValueType
     - `map(...)`: always `'array'`
     - `filter(...)`: always `'array'`
     - `find(...)`: return element type if determinable, else `any`
     - `if(cond, then, else)`: infer types of then and else; if same, return it; if different, return `any`
     - `static(value)`: infer from literal type of argument
3. **ObjectTemplate** — return `'object'`
4. **When returnType is `'any'`** from the registry — return `undefined` (don't enforce a specific type)

Return `undefined` to signal "cannot determine" — callers must treat undefined as "skip type check".

## Verification Requirements

Unit tests:
- String literal → infers `'string'`
- Number literal → infers `'number'`
- Boolean literal → infers `'boolean'`
- Null literal → infers `'null'`
- ObjectTemplate → infers `'object'`
- `source("customer.age")` with schema saying number → infers `'number'`
- `source("customer.name")` with schema saying string → infers `'string'`
- `cast(source("age"), "string")` → infers `'string'`
- `concat(...)` → infers `'string'` (from registry returnType)
- `add(...)` → infers `'number'`
- `gt(...)` → infers `'boolean'`
- `map(...)` → infers `'array'`
- `source("unknown.path")` where path exists as object → infers `'object'`
- `source("not.in.schema")` → infers `'any'` (path not in schema but may exist at runtime)
- Unknown function → returns `undefined`
- Registry function with returnType `'any'` → returns `undefined`

TypeScript strict compilation passes.

## Notes

The type inference is intentionally best-effort. The goal is to catch obvious mismatches (e.g., number where string is expected) without producing false positives. When in doubt, return `undefined` to signal "skip check".

The `'any'` return type on functions like `static`, `default`, `coalesce` means we generally can't infer their output type statically — which is correct. These are polymorphic functions where the type depends on the input value at runtime.
