## Summary

Replace the validate() stub in `src/engine/validate.ts` with the full orchestrator that sequences all validation passes, aggregates diagnostics, computes the `valid` flag, attaches coverage data, and returns the complete `ValidationResult`.

---

## Scope

### In Scope

- Rewrite `src/engine/validate.ts` to:
  1. Convert raw schemas to SchemaTree via `getOrBuildSchemaTree()` (WeakMap-cached — same schema object reference reuses cached tree)
  2. Parse all rule expressions via `parse(expr, { registry })`
  3. Run each validation sub-pass with parsed ASTs and schema trees
  4. Aggregate all diagnostics from all passes
  5. Compute `valid = diagnostics.filter(d => d.severity === 'error').length === 0`
  6. Attach coverage result
  7. Return complete `ValidationResult`
- Handle graceful degradation:
  - If sourceSchema is null/undefined → skip source path validation, type inference uses 'any' fallback
  - If targetSchema is null/undefined → skip target path validation, type compatibility, coverage
  - If registry is not available from options → skip function-level validation
- Ensure validate() never throws — catch any unexpected errors and convert to diagnostics
- Update `src/engine/index.ts` to pass the default registry to validate if not in options
- Unit tests for the orchestrator (end-to-end wiring)

### Out of Scope

- Implementing any individual validation pass (all done in T-03–T-09)
- Performance optimization
- UI integration

## Change Requirements

The orchestrator follows this sequence:

```typescript
export function validate(
  config: MappingConfig,
  sourceSchema: unknown,
  targetSchema: unknown,
  options?: EngineOptions,
): ValidationResult {
  // 1. Build schema trees (WeakMap-cached — same ref = instant return)
  const sourceTree = sourceSchema ? getOrBuildSchemaTree(sourceSchema) : null;
  const targetTree = targetSchema ? getOrBuildSchemaTree(targetSchema) : null;
  
  // 2. Get registry (from options or default)
  const registry = getRegistry(options);
  
  // 3. Parse all rules
  const parseResults = config.rules.map((rule, i) => ({
    ruleIndex: i,
    rule,
    result: parse(rule.expression, { registry }),
  }));
  
  // 4. Collect parse diagnostics (attach ruleIndex/targetPath)
  const parseDiagnostics = collectParseDiagnostics(parseResults);
  
  // 5. Run validation passes (only for rules with successful ASTs)
  const validAsts = parseResults.filter(p => p.result.ast !== null);
  
  const diagnostics: Diagnostic[] = [...parseDiagnostics];
  
  if (sourceTree) {
    diagnostics.push(...validateSourcePaths(validAsts, sourceTree));
  }
  if (targetTree) {
    diagnostics.push(...validateTargetPaths(config.rules, targetTree));
  }
  diagnostics.push(...detectDuplicateTargets(config.rules));
  if (sourceTree && targetTree && registry) {
    diagnostics.push(...validateTypeCompatibility(validAsts, sourceTree, targetTree, registry));
  }
  if (registry) {
    diagnostics.push(...validateArrayContext(validAsts, registry, sourceTree));
  }
  diagnostics.push(...validateConstantsAndExternals(validAsts, config.config));
  
  // 6. Compute coverage
  const coverage = targetTree ? computeCoverage(config.rules, targetTree) : undefined;
  
  // 7. Determine validity
  const valid = !diagnostics.some(d => d.severity === 'error');
  
  return { valid, diagnostics, coverage };
}
```

Key behaviors:
- Schema conversion is WeakMap-cached by object reference — repeated validate() calls with the same schema object pay zero conversion cost
- Parse diagnostics have ruleIndex/targetPath attached by the orchestrator
- Each sub-validator is called independently — one failure doesn't prevent others from running
- The orchestrator wraps the entire body in try/catch as a safety net
- Schema conversion failures should produce an informational diagnostic, not throw

## Notes

The orchestrator is the glue — it should be thin. All complex logic lives in the sub-validators. The orchestrator's job is: convert inputs (with caching), sequence passes, aggregate results, handle edge cases.

The WeakMap cache lives at module scope in `validate.ts` (or in `validate/schema-tree.ts` and imported). This is intentional — it's the one piece of mutable state in the engine, but it's an invisible optimization (same inputs always produce same outputs regardless of cache state).

Consider whether the `EngineOptions` type needs a `registry` field or if the orchestrator should accept registry via a different mechanism. The current `validate()` signature doesn't include registry — it may need to be added to options or imported from the default.
