## Summary

Implement the validation pass that walks each rule's parsed AST, finds all `source("path")` function calls, and checks that each referenced path exists in the source SchemaTree. Emits KEYRA-E030 for each invalid source path with the exact path string and rule location.

---

## Scope

### In Scope

- Function `validateSourcePaths(rules, parsedAsts, sourceSchemaTree): Diagnostic[]`
- AST walking utility to extract all `FunctionCall` nodes with name `source` from an AST
- For each `source("literal_path")` call, check `sourceSchemaTree.hasPath(path)`
- Emit E030 diagnostic with:
  - `code: 'KEYRA-E030'`
  - `severity: 'error'`
  - `message` containing the invalid path
  - `ruleIndex` of the rule containing the call
  - `targetPath` of the rule
  - `expression` of the rule
- Handle edge cases:
  - `source("")` (empty path) — valid (resolves to root object)
  - `source()` with non-literal argument (variable/function result) — skip check (path not statically determinable)
  - Multiple `source()` calls in one expression — check each independently
- Unit tests

### Out of Scope

- Target path validation (T-04)
- Type checking of source values (T-06)
- Modifying the parser or SchemaTree

## Change Requirements

Create an AST walking utility that can recursively find all `FunctionCall` nodes matching a given name within an AST tree. This utility will be reused by other validation passes (T-04, T-07, T-08).

The source path validator:
1. Iterates over each rule's parsed AST (skipping rules with parse failures — null AST)
2. Finds all `FunctionCall` nodes where `name === 'source'`
3. For each, checks if the first argument is a `StringLiteral`
4. If yes, calls `sourceSchemaTree.hasPath(argument.value)`
5. If `hasPath` returns false (and path is not empty string), emits E030 diagnostic
6. Empty string path is always valid (root reference)

---

## Verification Requirements

Unit tests:
- Valid source path → no diagnostic produced
- Invalid source path → E030 with correct path, ruleIndex, targetPath
- Multiple source() calls in one expression, one invalid → only the invalid one produces E030
- source("") → no diagnostic (empty path is valid root reference)
- source(someFunction()) → no diagnostic (non-literal, skip)
- Nested source() inside other function calls (e.g., `concat(source("a"), source("b"))`) → both paths checked
- Rule with null AST (parse failure) → skipped, no crash

TypeScript strict compilation passes.
