## Summary

Define the `SchemaTree` interface that the validator operates on for path existence checks, type lookups, required field enumeration, and array detection. Implement a JSON Schema → SchemaTree adapter that converts standard JSON Schema objects into this internal representation. Implement a `WeakMap`-based cache so repeated calls with the same schema object skip conversion. Include an XSD stub that returns a permissive tree (`hasPath` always true, `getTypeAtPath` always undefined, `getRequiredLeafPaths` empty) and emits an `info`-severity diagnostic.

## Scope

### In Scope

- `SchemaTree` interface definition in `src/engine/types/` or `src/engine/validate/`
- `SchemaNode` type representing a single node in the tree (type, required flag, children, isArray)
- `buildSchemaTree(schema: unknown, format?: 'json-schema' | 'xsd'): SchemaTree` factory function
- `WeakMap<object, SchemaTree>` cache — `getOrBuildSchemaTree(schema)` returns cached tree if same reference seen before
- JSON Schema traversal logic:
  - Object properties → child nodes
  - `type` field → ValueType mapping
  - `required` array → marks child nodes as required
  - `items` (for arrays) → marks node as array, recurses into item schema
  - Nested `$ref` resolution within the same document (local refs only)
  - `allOf` / basic composition support (merge properties)
- `SchemaTree` methods/functions:
  - `hasPath(path: string): boolean`
  - `getTypeAtPath(path: string): ValueType | undefined`
  - `getRequiredLeafPaths(): string[]`
  - `isArrayPath(path: string): boolean`
- XSD adapter stub:
  - Returns a permissive `SchemaTree` where `hasPath()` always returns `true`
  - `getTypeAtPath()` always returns `undefined`
  - `getRequiredLeafPaths()` returns `[]`
  - `isArrayPath()` returns `false`
  - Emits a single `info`-severity diagnostic: "XSD schema support is not yet implemented — schema-dependent validation checks are skipped"
- Unit tests in `tests/engine/validate/schema-tree.test.ts`

### Out of Scope

- Full JSON Schema validation (we only need structural traversal for validation)
- Remote `$ref` resolution (external URLs)
- JSON Schema draft version detection/migration
- Full XSD parsing
- `oneOf`, `anyOf`, `if/then/else` complex composition (best-effort or skip)

## Change Requirements

The `SchemaTree` interface must support the four operations the validator needs:

1. **Path existence** — `hasPath("customer.address.street")` checks if each segment exists in the tree hierarchy. Supports dot-notation paths. Array items are traversed transparently (e.g., `orders.items.sku` works whether `items` is an array or object).

2. **Type at path** — `getTypeAtPath("customer.age")` returns the declared type (`string`, `number`, `boolean`, `array`, `object`, or `any` if ambiguous). Returns `undefined` for non-existent paths.

3. **Required leaf enumeration** — `getRequiredLeafPaths()` returns all paths that are: (a) leaf nodes (no children or array items without object children), AND (b) marked as required by their parent. Uses full dot-notation paths.

4. **Array detection** — `isArrayPath("orders.items")` returns true if the node at that path is typed as an array.

The JSON Schema adapter must handle:
- Top-level `{ type: "object", properties: {...}, required: [...] }`
- Nested objects with their own `properties` and `required`
- Arrays with `items` containing object schemas
- Primitive leaf types (string, number, integer→number, boolean)
- `$ref` pointing to `#/definitions/Foo` or `#/$defs/Foo` (local only)
- Missing or unknown types default to `any`

The adapter must not throw on malformed schemas — return a best-effort tree.

**WeakMap caching:**

The orchestrator calls `getOrBuildSchemaTree(schema)` which checks a module-level `WeakMap<object, SchemaTree>`. If the schema object reference is already a key, the cached `SchemaTree` is returned. Otherwise, `buildSchemaTree` is called and the result is stored. This ensures repeated `validate()` calls (e.g., on every keystroke) with the same schema reference pay zero conversion cost after the first call. When the schema object is garbage collected, the cache entry is freed automatically.

## Verification Requirements

Unit tests covering:
- Simple flat object schema → correct paths, types, required list
- Nested object schema → deep path lookup works
- Array schema → `isArrayPath` returns true, items properties accessible
- Schema with `$ref` → referenced definition's properties are inlined
- Non-existent path → `hasPath` returns false, `getTypeAtPath` returns undefined
- Required field enumeration → only leaf + required nodes returned
- Malformed schema (missing `properties`, wrong `type`) → no throw, best-effort tree
- Empty schema → empty tree, all lookups return false/undefined
- WeakMap cache: same object reference → same SchemaTree instance returned
- WeakMap cache: different object with same content → separate SchemaTree (reference equality, not deep equality)
- XSD format → permissive tree (hasPath=true, getType=undefined, requiredLeafs=[]) + info diagnostic

TypeScript strict compilation passes.

## Notes

This is the foundational task for the validate pipeline. All schema-dependent validation passes (T-03, T-04, T-06, T-07, T-09) depend on this being complete.

The `SchemaTree` is intentionally minimal — just enough for validation. It is NOT a general-purpose schema management system. Keep the implementation focused on the four operations needed.

Place the implementation in a new `src/engine/validate/` directory to keep validate internals separate from the public validate.ts orchestrator.
