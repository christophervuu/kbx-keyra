## Summary

Create a React context (`PreviewContext`) and provider component that shares preview state — including the current valid source data, execution status, and last execution result — with all panels in the Mapping Editor. This context is the bridge between FS-012's preview panel and FS-011's expression preview.

---

## Scope

### In Scope

- New file `ui/src/features/mappings/context/preview-context.tsx`
- `PreviewContext` created with `createContext`
- `PreviewProvider` component that wraps children and manages context value
- `usePreviewContext()` consumer hook with meaningful error if used outside provider
- Integration into `MappingEditorPage.tsx` — wrap the panel grid with `PreviewProvider`

### Out of Scope

- Execution logic (T-04)
- Source data input UI (T-07)
- Connecting to FS-011's expression preview (T-13)

---

## Relevant Areas

- `ui/src/features/mappings/context/preview-context.tsx` (new)
- `ui/src/features/mappings/components/MappingEditorPage.tsx`

---

## Change Requirements

- Create `PreviewContext` using `createContext<PreviewContextValue | null>(null)`
- `PreviewProvider` accepts props: `children`, and exposes setter functions for internal state updates (via a stable ref or by being composed with the execution hook in a parent)
- Export `usePreviewContext()` that throws if context is null (used outside provider)
- Export `PreviewProvider` that renders `PreviewContext.Provider`
- In `MappingEditorPage.tsx`, wrap the panel grid (or the appropriate subtree) with `<PreviewProvider>`
- The provider should expose both the read-only context value AND setters so the preview panel can update it (use a split pattern: value context + dispatch context, or expose setters via a second context)
