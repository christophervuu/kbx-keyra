## Summary

Remove the behavior where clicking Apply (or Direct Copy) automatically advances focus to the next unmapped target field. After Apply, the builder remains on the current field showing a "committed" state. Add an explicit "Next unmapped -->" button as an optional accelerator for users who want to advance manually, with a keyboard shortcut (`Ctrl+]` / `Cmd+]`).

---

## Scope

### In Scope

- Remove auto-advance logic from `useMappingEditor.applyRule()` / the `onRuleApplied` callback chain that triggers navigation.
- Remove auto-advance from the Direct Copy shortcut in `UnifiedExpressionBuilder`.
- After Apply: disable the Apply button and show an "Applied" indicator until further edits are made.
- Add a "Next unmapped -->" button below/beside the Apply button:
  - Only visible when unmapped target fields remain.
  - Clicking it navigates to the next unmapped target field in document order.
  - Hidden when all target fields are mapped.
- Add keyboard shortcut `Ctrl+]` (macOS: `Cmd+]`) that triggers the same "next unmapped" navigation.
- Ensure the Direct Copy toast ("Direct copy applied") still shows but no navigation occurs.
- Ensure the `onRuleApplied` callback is preserved for preview auto-run purposes (FS-022/FS-024 behavior) — it just no longer triggers navigation.

### Out of Scope

- Builder state hydration (that's T-01).
- Navigation reset on field switch (that's T-02).
- Conditional branch expressions (that's T-03).
- Changes to the navigation guard dialog itself.
- Changes to the Ctrl+S Save shortcut.

## Change Requirements

**Remove auto-advance from Apply:**

- In the composition layer (likely `MappingEditorPage.tsx` or equivalent): the current post-Apply handler that calls something like `selectNextUnmappedTarget()` must be removed.
- The `onRuleApplied` callback on `useMappingEditor` must be decoupled from navigation. It should still fire (for preview auto-run in `ConnectedInlinePreviewStrip`), but the composition layer must not use it to trigger target selection changes.
- In `ScalarFieldBuilder`: after `onApply` fires, do NOT call any navigation function. Instead:
  - Set a local `isApplied` state to `true`.
  - The Apply button renders as disabled with text "Applied" (or shows a checkmark icon).
  - The `isApplied` state resets to `false` when the user makes any edit that changes the expression from the applied value.

**Remove auto-advance from Direct Copy:**

- In `UnifiedExpressionBuilder`: the Direct Copy handler currently fires `onApply` and then calls a navigation function (or relies on `onRuleApplied` triggering navigation). Remove the navigation call.
- Direct Copy still: fires `onApply` with the `source("field")` expression, shows the "Direct copy applied" toast.
- After Direct Copy: the builder shows the "Applied" state (same as normal Apply).

**Add "Next unmapped -->" button:**

- Render a secondary button below (or inline-right of) the Apply button area.
- Label: "Next unmapped -->" (or "Next unmapped" with a right arrow icon).
- Behavior: fires `onAdvanceToNext()` callback which the composition layer handles by finding and selecting the next unmapped target field.
- The composition layer determines "next unmapped" by:
  1. Get the flat list of target fields in document order.
  2. Find the current `selectedTargetPath` index.
  3. Search forward (wrapping if needed) for the first field whose status is `'unmapped'` in the target status map.
  4. If found, set `selectedTargetPath` to that field (triggering navigation + load).
  5. If not found (all mapped), the button should not be visible.
- Visibility: only render the button when at least one unmapped target field exists.

**Add keyboard shortcut:**

- Bind `Ctrl+]` (macOS: `Cmd+]`) at the builder panel level to trigger the same "next unmapped" navigation.
- Use a `useEffect` with `keydown` listener on the document (or scoped to the builder container).
- The shortcut should only fire when the builder panel is active/focused.
- Prevent default browser behavior for this key combination.

**Preserve preview auto-run:**

- The `onRuleApplied` callback in `useMappingEditor` must continue to fire after `applyRule()` — it signals `ConnectedInlinePreviewStrip` to auto-preview.
- Only the navigation side effect is removed; the callback itself is not removed.

## Blockers / Risks

- The existing auto-advance may be wired in multiple places (composition layer, hook callbacks, Direct Copy handler). All paths must be found and updated. Search for any `selectNextUnmapped`, `advanceToNext`, or similar navigation calls triggered by Apply.
- The `onRuleApplied` callback serves dual purposes (preview + navigation). Decoupling navigation from it while preserving preview requires careful wiring.
- The `Ctrl+]` shortcut may conflict with browser extensions or OS-level shortcuts. If conflicts are found, document an alternative (e.g., `Ctrl+Down`) in the implementation.

## Notes

- This task is independent of T-01, T-02, T-03 and can be implemented in parallel.
- The FS-021 spec AE-02 states "Focus advances to the next unmapped target field in the worklist." This spec (FS-025) explicitly reverses that behavior. The architecture update (T-05) will document this change.
- The "Applied" state on the Apply button is a local UI concern within `ScalarFieldBuilder` / `ExpressionBuilderPanel`. It compares current expression to last-applied expression for the current target.
- Consider using `aria-label` on the "Next unmapped" button for accessibility: "Navigate to next unmapped target field".
