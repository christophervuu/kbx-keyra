## Summary

Extend the conditional mode's `BranchValueSelector` to support a "Build expression" option that renders an inline mini-builder (Source + Transform chain) within Then/Else branches. Also extend `ConditionRowEditor` to support transforms on the left operand. This enables users to compose full expressions within conditional branches without switching to Editor mode.

---

## Scope

### In Scope

- Add `type: 'expression'` variant to the `BranchValue` discriminated union in the expression builder state model.
- Implement the "Build expression" option in `BranchValueSelector` that renders an inline compact builder.
- The inline mini-builder reuses `SourceChipPicker` and `TransformPipeline` components rendered within the branch container.
- The inline mini-builder is Value mode only (Source + Transforms) — no nested conditionals or value maps within it.
- Add a generated sub-expression preview (read-only) within the inline mini-builder.
- Extend `ConditionRowEditor` left operand to support a "Transform..." option that opens the same inline mini-builder pattern.
- Add `type: 'expression'` variant to `ConditionOperand` type for left operands.
- Update `generateExpressionFromState()` (or its conditional generation path) to handle `BranchValue.type === 'expression'` by generating the composed sub-expression.
- Update `generateExpressionFromState()` condition generation to handle `ConditionOperand.type === 'expression'` for the left side.
- Update `decomposeExpression()` (or its conditional decomposition path) to detect and hydrate expression-type branches when loading existing conditionals (e.g., detecting `upper(source("tier"))` as a branch expression rather than failing decomposition).
- Update `decomposeExpression()` to detect and hydrate expression-type left operands (e.g., `length(source("name"))`) in conditions.

### Out of Scope

- Nested conditional or value map modes within a branch mini-builder (only Value mode is supported inline).
- Changes to the Transform pipeline component itself (it's reused as-is).
- Changes to `SourceChipPicker` component (reused as-is).
- Builder state hydration lifecycle (that's T-01).
- Navigation reset (that's T-02).
- Apply/advance changes (that's T-04).

## Change Requirements

**State model changes:**

The `BranchValue` type must be extended:

```typescript
type BranchValue =
  | { type: 'static'; value: string }
  | { type: 'source'; path: string }
  | { type: 'expression'; state: ValueModeState }  // NEW
  | { type: 'elseIf'; condition: ConditionGroup; thenBranch: BranchValue; elseBranch: BranchValue };

// Where ValueModeState is:
type ValueModeState = { sources: SourceSelection[]; transforms: TransformStep[] };
```

The `ConditionOperand` type (or equivalent in `ConditionRow`) must support expressions:

```typescript
type ConditionOperand =
  | { type: 'source'; path: string }
  | { type: 'expression'; state: ValueModeState }  // NEW
  | { type: 'static'; value: string };
```

**UI changes in `BranchValueSelector`:**

- Add a third option: "Build expression" (alongside existing "Static value" and "Source field").
- When "Build expression" is selected, render an inline container with:
  - `SourceChipPicker` (compact variant if available, otherwise standard)
  - `TransformPipeline` (compact: smaller step cards, no drag handles if space is tight)
  - Read-only sub-expression preview line showing the generated DSL for the branch
- The inline mini-builder manages its own local `ValueModeState` and propagates changes upward via `onChange(branchValue)`.

**UI changes in `ConditionRowEditor`:**

- The left operand field gains a small "Transform..." button/link next to the source field picker.
- Clicking "Transform..." switches the left operand to `type: 'expression'` and shows the inline mini-builder.
- A "Simple" toggle returns to the basic `type: 'source'` mode.

**Expression generation:**

- When generating a conditional expression and encountering `BranchValue.type === 'expression'`, call the value-mode expression generation utility on `state` to produce the sub-expression string.
- When generating condition comparisons and encountering `ConditionOperand.type === 'expression'`, generate the composed left operand expression.

**Expression decomposition:**

- When decomposing a conditional expression's Then/Else branches:
  - If the branch is a simple literal → `{ type: 'static', value }`.
  - If the branch is `source("path")` → `{ type: 'source', path }`.
  - If the branch is a composed expression (function call wrapping source/other functions) → attempt to decompose as Value mode: `{ type: 'expression', state: decomposedValueState }`.
  - If the branch is itself `if(...)` → `{ type: 'elseIf', ... }` (existing behavior).
- When decomposing condition left operands:
  - If it's `source("path")` → `{ type: 'source', path }`.
  - If it's a composed expression → `{ type: 'expression', state: decomposedValueState }`.

## Blockers / Risks

- The `decomposeExpression()` function may need extension to correctly identify and decompose branch sub-expressions. Currently it may treat any non-trivial branch as a decomposition failure for the entire expression. This task may need to modify the decomposer's conditional path to attempt per-branch decomposition.
- UI space constraints: the inline mini-builder within a branch adds visual complexity. The compact layout must remain usable within the builder panel's width. Test at minimum panel width (300px per FS-022 constraint).
- The depth of inline builders is capped: inline mini-builders do NOT support Conditional mode within them (prevents unbounded nesting).

## Notes

- The inline mini-builder is fundamentally a compact instance of the Value mode form. It should reuse the same `SourceChipPicker` and `TransformPipeline` components with potentially a `compact` or `inline` prop/variant for tighter spacing.
- For expression generation, extract a `generateValueExpression(state: ValueModeState): string` utility from the existing `generateExpressionFromState()` function (which currently handles the full discriminated union). The branch generation path calls this utility.
- Consider whether the sub-expression preview within the branch should use `LiveExpressionDisplay` or a simpler inline `<code>` element. A simpler element is recommended to avoid visual overload.
