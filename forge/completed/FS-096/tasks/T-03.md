## Summary

Implement value-table backend APIs for project-level CRUD, immutable revision creation, usage retrieval, revision diff retrieval, archive behavior, and resolve-before-save support for mapping pinning/adoption flows.

---

## Scope

### In Scope

- Add routes/handlers for list/get/create/duplicate/archive/value-table revision retrieval and creation.
- Add usage endpoint(s) that return mapping/version/direction/pinned-revision summaries.
- Add revision diff endpoint for adoption review.
- Add resolve endpoint logic used by mapping save to embed pinned resolved entries.
- Add delete guard that blocks deletion when references exist.

### Out of Scope

- UI component implementation.
- Engine parser/evaluator behavior.

---

## Relevant Areas

- `src/lambda/project/*`
- `src/lambda/mapping/*`
- `src/lambda/shared/*`
- `tests/lambda/**/*`

---

## Change Requirements

- All endpoints must use canonical error envelope and requestId semantics.
- Revision creation must be immutable and append-only.
- Delete/Archive semantics must enforce referenced-table safety rules from spec.

---

## Verification Requirements

- Handler unit tests for validation, conflict, and success paths.
- Integration tests for end-to-end revision and usage flows.
- Verify optimistic concurrency behavior where mapping save/adoption workflows intersect.

---

## Acceptance Checks

- Backend exposes complete value-table route surface required by adapters.
- Editing a table creates a new immutable revision.
- Usage and diff endpoints support explicit revision-adoption review workflows.
- Referenced-table delete requests fail with deterministic conflict details.

---

## Blockers / Risks

- Route-surface creep if table management and mapping-save responsibilities are not clearly separated.

---

## Notes

- Keep API contracts consistent with existing mapping save/version route semantics.
