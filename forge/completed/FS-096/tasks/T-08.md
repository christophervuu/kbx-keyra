## Summary

Update deploy/promote/rollback and runtime execution paths to guarantee that mapping artifacts embed exact resolved value-table data and that deployment lifecycle operations preserve immutable pinned behavior across environments.

---

## Scope

### In Scope

- Ensure mapping artifact generation includes resolved value-table entries used by saved mapping revision/version.
- Ensure promote reuses same artifact identity and payload including value-table data.
- Ensure rollback restores prior artifact data exactly.
- Add runtime assertions/tests that no table fetch occurs during transformation execution.

### Out of Scope

- UI deployment page redesign.
- Project table management screens.

---

## Relevant Areas

- `src/lambda/deployment/*`
- `src/lambda/runtime/*`
- `src/lib/persistence/deployments.ts`
- `src/lib/persistence/s3/deployment-snapshot.ts`
- deployment/runtime tests in `tests/lambda/**/*` and related integration suites

---

## Change Requirements

- Save/deploy separation must remain unchanged.
- Runtime transform path must stay no-I/O relative to project value-table storage.
- Deployment artifact invariants must be explicit and test-covered.

---

## Verification Requirements

- Integration tests for deploy/promote/rollback artifact equality and embedded data stability.
- Runtime execution tests confirming absence of table-fetch dependency.
- Regression tests for non-value-table mappings.

---

## Acceptance Checks

- Deployment snapshots include exact resolved table data from saved mapping state.
- Promotion reuses identical artifact payload.
- Rollback reactivates original embedded data without recomputation.

---

## Blockers / Risks

- Hidden artifact-generation coupling may unintentionally re-resolve against latest project state if not guarded.

---

## Notes

- Align with `deployments.md` immutable artifact and runtime-local execution contracts.
