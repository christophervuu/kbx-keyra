## Summary

Add persistence-layer support for project value-table metadata, immutable revision rows, usage lookup indexes, archive flags, and row payload storage strategy (DynamoDB vs S3 threshold) while preserving deterministic retrieval for mapping save/deploy flows.

---

## Scope

### In Scope

- Define new DynamoDB entity structures/keys/indexes for value-table metadata and revisions.
- Define optional S3 payload storage strategy for large revision row sets and corresponding references.
- Add persistence modules for CRUD/revision/usage/diff-oriented retrieval.
- Add usage index maintenance helpers for mapping-table references.

### Out of Scope

- Lambda handler route wiring beyond persistence integration points.
- UI integration behavior.

---

## Relevant Areas

- `src/lib/persistence/types.ts`
- `src/lib/persistence/config.ts`
- `src/lib/persistence/*` (new value-table modules)
- `src/lib/persistence/s3/*` (if threshold storage needed)
- persistence test suites under `tests/lib/persistence/*`

---

## Change Requirements

- Revision records must be immutable and retrievable by table+revision efficiently.
- Persistence design must support project list/sort/search usage patterns and usage tracking queries.
- Archive state must be explicit and queryable for selection filtering.

---

## Verification Requirements

- Unit tests for persistence CRUD/revision retrieval and usage indexing operations.
- Integration coverage for large-row threshold path if S3 spillover is implemented.
- Typecheck/lint passes for persistence modules.

---

## Acceptance Checks

- Persistence layer supports metadata + revision + usage data model contracts.
- Immutable revision creation and retrieval behavior is enforced.
- Archive and reference-guard query paths are supported.

---

## Blockers / Risks

- Unresolved row-size threshold decision may require iterative tuning once real data sizes are profiled.

---

## Notes

- Keep schema consistent with existing persistence conventions and table naming patterns.
