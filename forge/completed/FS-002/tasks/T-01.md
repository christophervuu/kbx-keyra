## Summary

Define all TypeScript types for the DSL parser module: the AST node discriminated union, token types with position information, `ParseOptions`, `ParseResult`, and `ObjectTemplateProperty`. These are pure type definitions with no runtime code — they form the contract that the tokenizer, parser, and public API build on.

---

## Scope

### In Scope

- AST node type definitions as a discriminated union on a `type` field:
  - `StringLiteralNode` — `{ type: "StringLiteral", value: string, start: number, end: number }`
  - `NumberLiteralNode` — `{ type: "NumberLiteral", value: number, start: number, end: number }`
  - `BooleanLiteralNode` — `{ type: "BooleanLiteral", value: boolean, start: number, end: number }`
  - `NullLiteralNode` — `{ type: "NullLiteral", start: number, end: number }`
  - `FunctionCallNode` — `{ type: "FunctionCall", name: string, arguments: AstNode[], start: number, end: number }`
  - `ObjectTemplateNode` — `{ type: "ObjectTemplate", properties: ObjectTemplateProperty[], start: number, end: number }`
- `ObjectTemplateProperty` type — `{ key: string, value: AstNode, start: number, end: number }`
- `AstNode` union type (all six node types)
- Token type definitions:
  - `TokenType` enum/union: `StringLiteral`, `NumberLiteral`, `BooleanLiteral`, `NullLiteral`, `Identifier`, `OpenParen`, `CloseParen`, `Comma`, `OpenBrace`, `CloseBrace`, `Colon`, `EOF`
  - `Token` interface: `{ type: TokenType, value: string, start: number, end: number }`
- `ParseOptions` type: `{ registry?: FunctionRegistry, maxDepth?: number }`
- `ParseResult` type: `{ success: boolean, ast: AstNode | null, diagnostics: Diagnostic[] }`
- Barrel export from `src/engine/dsl/types.ts`

### Out of Scope

- Runtime code (tokenizer, parser logic)
- Test files (covered by T-05)
- Modifying existing type files in `src/engine/types/`

## Notes

- Use `interface` for node types and `type` for the union. This allows individual nodes to be extended later if needed.
- The `TokenType` can be a string union (e.g., `type TokenType = "StringLiteral" | "NumberLiteral" | ...`) rather than an enum, keeping it consistent with the AST node `type` field pattern.
- Position tracking uses character offsets (0-indexed) from the start of the expression string, not line/column numbers. This is simpler and sufficient since DSL expressions are single-line in practice.
