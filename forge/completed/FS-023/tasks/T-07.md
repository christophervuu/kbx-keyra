## Summary

Implement the Live Expression and Live Result display sections, wire the Builder <-> Editor mode toggle through the new decomposer, and integrate the `UnifiedExpressionBuilder` into both `ScalarFieldBuilder` (Target View) and `ExpressionBuilderPanel` (Rules View), replacing the old `GuidedBuilder`. This is the integration task that brings all sub-components together into a working end-to-end flow.

---

## Scope

### In Scope

- Create `LiveExpressionDisplay.tsx`: always-visible section showing the generated DSL expression in real-time. Styled as a code block. Clickable to switch to Editor mode.
- Create `LiveResultDisplay.tsx`: shows evaluated output when test data is available via `useExpressionPreview`. Shows "Load test data to see live results." when no test data.
- Wire into `UnifiedExpressionBuilder`: render both displays below the mode-specific content.
- Mode toggle (Builder <-> Editor) with new decomposer:
  - Builder -> Editor: generate expression from state, pass to `RawDslEditor`.
  - Editor -> Builder: call `decomposeExpression()`. On success, hydrate `UnifiedExpressionBuilder` state (auto-detect mode). On failure, stay in Editor mode and show "Complex expression -- edit in Editor mode" banner.
- Replace `GuidedBuilder` in `ScalarFieldBuilder.tsx` with `UnifiedExpressionBuilder`.
- Replace `GuidedBuilder` in `ExpressionBuilderPanel.tsx` with `UnifiedExpressionBuilder`.
- Ensure panel parity: both integrations use the same component with the same behavior.
- Update `use-expression-builder.ts` hook to use the new decomposer and state model.
- Remove old components that are no longer used: `BuilderStepIndicator.tsx`, `ExpressionPreviewStep.tsx`. Mark `GuidedBuilder.tsx`, `SourceFieldPicker.tsx`, `TransformPicker.tsx`, `ArgumentConfigurator.tsx` as deprecated or remove if no other consumers exist.
- Remove old `expression-generator.ts` and `ast-decomposer.ts` if fully replaced.
- Update barrel exports in `ui/src/features/mappings/index.ts`.
- Component and integration tests.

### Out of Scope

- Changes to `RawDslEditor.tsx` itself.
- Changes to the Apply/Save model.
- Changes to AI action buttons (remain as placeholders).
- Changes to the Inline Preview Strip or Advanced Testing page.
- Array mapping builder.

## Change Requirements

**`LiveExpressionDisplay.tsx`:**

- Props:
  - `expression: string` — the current generated expression
  - `onClickToEdit: () => void` — fires when user clicks the expression to switch to Editor mode
- Renders:
  - Label: "Expression"
  - Code block showing the DSL expression with basic syntax highlighting (reuse `dsl-tokenizer.ts` if applicable, or simple monospace display).
  - If expression is empty, show muted placeholder text: "Select a source field or enter a static value to begin."
  - Click handler on the expression text triggers `onClickToEdit`.
  - Tooltip or hint: "Click to edit in raw editor mode."

**`LiveResultDisplay.tsx`:**

- Props:
  - `expression: string`
  - `sourceData: unknown | null` — from preview context or prop
- Internally uses `useExpressionPreview(expression, sourceData)` to evaluate.
- Renders:
  - Label: "Result"
  - If `sourceData` is null: muted text "Load test data to see live results."
  - If evaluating: loading spinner/skeleton.
  - If result available: formatted output value (JSON-formatted for objects, quoted for strings, raw for numbers/booleans).
  - If evaluation error: error message in red.

**`UnifiedExpressionBuilder` updates:**

- Add `LiveExpressionDisplay` and `LiveResultDisplay` as bottom sections (always rendered regardless of mode).
- Accept `sourceData` prop (from preview context) for `LiveResultDisplay`.
- Expose `onSwitchToEditor` callback for when user clicks the live expression.

**Mode toggle integration:**

- `ScalarFieldBuilder` and `ExpressionBuilderPanel` both maintain a `mode: 'builder' | 'editor'` state.
- Builder -> Editor: take current expression string, switch mode.
- Editor -> Builder: call `decomposeExpression(expression)`. If success:
  - Auto-detect `activeMode` from result state's `mode` field.
  - Hydrate `UnifiedExpressionBuilder` with the decomposed state.
  - Switch to builder mode.
- If failure:
  - Stay in editor mode.
  - Show `ComplexExpressionWarning` banner (reuse existing component or create similar).

**`ScalarFieldBuilder.tsx` integration:**

- Replace `GuidedBuilder` import/usage with `UnifiedExpressionBuilder`.
- Pass `parsedSourceSchema`, `expression`, `onExpressionChange`.
- The mode toggle (Builder/Editor) remains in `ScalarFieldBuilder`'s header area.
- `onApply` and apply button remain unchanged (gated on valid non-empty expression).
- Drop zone for DnD source field insertion: wire `insertSourceField` to add a source chip in the new builder.

**`ExpressionBuilderPanel.tsx` integration:**

- Replace `GuidedBuilder` import/usage with `UnifiedExpressionBuilder`.
- Same props/wiring as `ScalarFieldBuilder` minus the target field header.
- The `ExpressionBuilderPanelRef.insertSourceField` method should add a source chip in the new builder.

**`use-expression-builder.ts` updates:**

- Replace `BuilderState` references with `ExpressionBuilderState`.
- Replace `ast-decomposer.ts` import with `pipeline-decomposer.ts`.
- Update decomposition logic to use `decomposeExpression()`.
- On decomposition success, return the state with detected mode.
- On decomposition failure, return failure with reason.

**Cleanup:**

- Remove `GuidedBuilder.tsx` (or keep as deprecated if any other consumers — verify).
- Remove `BuilderStepIndicator.tsx`, `ExpressionPreviewStep.tsx`, `ArgumentConfigurator.tsx`.
- Remove old `expression-generator.ts` and `ast-decomposer.ts`.
- Update barrel exports to remove old, add new.
