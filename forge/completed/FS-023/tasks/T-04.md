## Summary

Implement the transform pipeline section of the Value mode builder. Users can add transform steps from a function picker, see each step as a numbered card with auto-wired first parameter and editable additional parameters (derived from `DSL_FUNCTION_CATALOG`), reorder steps via drag interaction, and remove steps. The pipeline generates nested DSL expressions in real-time.

---

## Scope

### In Scope

- Create `TransformPipeline.tsx` component: renders a vertical list of `TransformPipelineStep` components plus an [+ Add Transformation] button.
- Create `TransformPipelineStep.tsx` component: renders a single transform step with step number, function name, auto-wired value parameter (read-only), and dynamic additional parameter input fields.
- Create `TransformFunctionPicker.tsx` component (or refactor from existing `TransformPicker.tsx`): categorized function list with search. Categories: String, Date & Time, Math, Conditional, Lookup, Array, Null Handling, Type Conversion. Optional type-based suggestion sorting.
- Dynamic parameter rendering: derive input fields from `DSL_FUNCTION_CATALOG` entry for the selected function. Skip the first parameter (auto-wired). Render remaining parameters as labeled inputs with type hints and required/optional indicators.
- Variadic parameter support: for functions like `concat`, show an [+ Add argument] button after the initial parameter set.
- Auto-wiring display: first parameter shows "from source" (step 1) or "from step N-1" with a visual connector/pipe indicator.
- Drag-to-reorder: steps can be reordered via drag handles. This uses state-level reorder (move array index), not HTML5 DnD library. A simplified up/down button approach is acceptable as an alternative.
- Remove step: each step has an x/remove button that removes it from the pipeline.
- Wire expression generation: on any pipeline change, regenerate the expression via `generateExpressionFromState()`.
- Component tests.

### Out of Scope

- Function picker intelligence (type-based priority suggestions) — include basic category filtering only. Advanced type inference is a future enhancement.
- Conditional mode or Value Map mode UI.
- Live Expression/Result display (T-07).
- Integration into the parent `UnifiedExpressionBuilder` beyond the Value mode section slot.

## Change Requirements

**`TransformPipeline.tsx`:**

- Props:
  - `transforms: TransformStep[]`
  - `onTransformsChange: (transforms: TransformStep[]) => void`
  - `sourceDescription: string` — label for what feeds step 1 (e.g., "source('email')")
- Renders:
  - Ordered list of `TransformPipelineStep` components.
  - Visual flow indicator between steps (a vertical line or arrow between cards).
  - [+ Add Transformation] button at the bottom that opens `TransformFunctionPicker`.
  - Empty state: "No transforms added. Source value will be used directly." (with the Direct Copy shortcut visible above in the source section).

**`TransformPipelineStep.tsx`:**

- Props:
  - `stepIndex: number`
  - `transform: TransformStep`
  - `inputDescription: string` — what feeds this step ("source('email')" or "output of step N")
  - `onUpdate: (updated: TransformStep) => void`
  - `onRemove: () => void`
  - `onMoveUp?: () => void`
  - `onMoveDown?: () => void`
- Renders:
  - Step number badge (1-indexed).
  - Function name label.
  - Auto-wired first parameter: read-only field showing `inputDescription` with a muted/locked style.
  - Additional parameters: for each parameter in the catalog entry (after index 0), render a labeled input field. Input type derived from parameter type (string -> text, number -> number input, boolean -> checkbox). Required parameters show a red asterisk; optional show "(optional)" hint.
  - Reorder controls: up/down arrow buttons (up disabled on step 1, down disabled on last step).
  - Remove button (x icon).

**`TransformFunctionPicker.tsx`:**

- Opens as a dropdown/popover when [+ Add Transformation] is clicked.
- Search input at top filters by function name and description.
- Category sections: collapsible or tabbed. Uses `FunctionCategory` from `dsl-functions.ts`.
- Excludes `SourceAccess` category (source, item, parent, constant, external, static).
- Each function entry shows: name, brief description. Clicking selects and closes picker.
- Optionally: if source type is known, sort the most relevant category to the top.

**Integration into `UnifiedExpressionBuilder`:**

- In Value mode, render `TransformPipeline` below the source section.
- Pass current `transforms` from state, wire `onTransformsChange`.
- Compute `sourceDescription` from selected sources (e.g., `source("email")` or "static value").
- On transforms change, regenerate expression and fire `onExpressionChange`.

## Blockers / Risks

- The dynamic parameter rendering depends on `DSL_FUNCTION_CATALOG` having accurate parameter metadata. Verify that all functions have proper `parameters` arrays.
- Drag-to-reorder without an external DnD library means using up/down buttons or a simpler state-based approach. This is intentional to avoid adding dependencies.

## Notes

- The visual design should communicate data flow: Source -> Step 1 -> Step 2 -> ... -> Output. Use vertical spacing, connecting lines or arrows, and step number badges.
- The auto-wired first parameter should be visually distinct from editable parameters (e.g., gray background, lock icon, italic text).
- For the function picker, consider showing the function's example from the catalog as a tooltip or detail row to help users understand what each function does.
- The `data-testid` pattern: `transform-pipeline`, `transform-step-{index}`, `transform-add-btn`, `transform-function-picker`, `transform-step-remove-{index}`, `transform-step-param-{name}`.
