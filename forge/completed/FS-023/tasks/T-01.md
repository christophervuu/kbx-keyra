## Summary

Create the new `ExpressionBuilderState` type system and the `generateExpressionFromState()` pure function that converts the state model into valid DSL expression strings. This is the foundational data layer for the redesigned builder — all three modes (Value, Conditional, Value Map) generate expressions through this single function.

---

## Scope

### In Scope

- Define `ExpressionBuilderState` discriminated union type with `value`, `conditional`, and `valueMap` mode variants.
- Define supporting types: `SourceSelection`, `TransformStep`, `TransformParameter`, `ConditionGroup`, `ConditionRow`, `ComparisonOperator`, `BranchValue`, `ValueMapEntry`, `FallbackValue`.
- Implement `generateExpressionFromState(state: ExpressionBuilderState): string` pure function.
- Value mode generation: wraps source in nested transform functions (pipeline order: first transform wraps source, second wraps first, etc.).
- Conditional mode generation: produces `if(condition, then, else)` with comparison operators mapped to DSL functions (`eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `contains`, `isNull`, `not(isNull(...))`). Compound conditions with a single operator produce `and(...)`/`or(...)`. **Nested condition groups** produce nested `and()`/`or()` calls (e.g., `and(condA, or(condB, condC))`). Nested else-if produces nested `if()`.
- Value Map mode generation: produces `valueMap(source, mappingObject, fallback)`.
- Static value generation: produces `static("val")`, `static(123)`, `static(true)`, `static(null)`.
- Direct Copy shortcut: single source + no transforms = `source("path")`.
- Unit tests covering all generation paths (all acceptance examples).

### Out of Scope

- UI components (separate tasks).
- Expression decomposition (T-02).
- Modifying `DSL_FUNCTION_CATALOG` or existing `expression-generator.ts` (the new generator is a parallel file; old one can be removed in T-07).

## Change Requirements

**Type definitions** (`expression-builder-state.ts`):

- `ExpressionBuilderState` — discriminated union on `mode: 'value' | 'conditional' | 'valueMap'`
- Value mode fields: `sources: SourceSelection[]`, `transforms: TransformStep[]`, `staticValue?: StaticValue`
- `SourceSelection` — `{ path: string; type?: string }`
- `TransformStep` — `{ functionName: string; parameters: TransformParameterValue[] }` (first parameter is always auto-wired from previous step, not stored explicitly)
- `TransformParameterValue` — `{ name: string; value: string | number | boolean | null; type: string }` (for additional parameters beyond the first)
- `ConditionGroup` — `{ operator: 'and' | 'or'; conditions: (ConditionRow | ConditionGroup)[] }` (recursive — groups can contain nested groups for mixing AND/OR)
- `ConditionRow` — `{ leftOperand: Operand; comparison: ComparisonOperator; rightOperand: Operand }`
- `Operand` — `{ kind: 'source' | 'static' | 'expression'; value: string }`
- `ComparisonOperator` — `'eq' | 'neq' | 'gt' | 'gte' | 'lt' | 'lte' | 'contains' | 'isNull' | 'isNotNull'`
- `BranchValue` — `{ kind: 'static' | 'source' | 'expression' | 'conditional'; value: string | ExpressionBuilderState }`
- `ValueMapEntry` — `{ whenValue: string; mapTo: string }`
- `FallbackValue` — `{ kind: 'value' | 'null'; value?: string }`

**Generator function** (`pipeline-expression-generator.ts`):

- Export `generateExpressionFromState(state: ExpressionBuilderState): string`
- Value mode: if `staticValue` is set, generate `static(...)`. If sources has 1 entry and transforms is empty, generate `source("path")`. Otherwise, build nested function calls: innermost is `source("path")`, each transform wraps the previous result.
- Multi-source handling: if multiple sources selected, the first transform must accept variadic/multiple args. This is an edge case; for now, use the first source as the primary input.
- Conditional mode: map `ComparisonOperator` to DSL function calls. Generate the condition, then produce `if(condition, thenExpr, elseExpr)`. Recursive for nested conditionals.
- Value Map mode: produce `valueMap(source("inputField"), {"key1": "val1", ...}, fallbackExpr)`.
- All string values properly escaped/quoted.
- Function is pure, deterministic, has no side effects.
