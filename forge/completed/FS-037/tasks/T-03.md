## Summary

Create a `useDeploymentContext` hook that loads deployment context for a mapping via `adapter.getDeploymentContext()`. This provides the data needed to determine which environments have active deployments and are therefore available for comparison. The hook handles Phase 0 stub data gracefully.

---

## Scope

### In Scope

- Create `ui/src/features/mappings/hooks/use-deployment-context.ts`
- Implement `useDeploymentContext(mappingId)` hook:
  - Loads `DeploymentContext` on mount and exposes it
  - Derives per-environment availability: `Map<Environment, { available: boolean; version?: number; deployedAt?: string }>`
  - Derives per-comparison-mode availability using `COMPARISON_MODES` config and environment availability
  - Handles loading, error, and empty states
- Add unit tests with mock adapter

### Out of Scope

- Deployment actions (deploy, promote, rollback)
- UI components
- Real backend integration

## Change Requirements

Create the hook with:

- `deploymentContext: DeploymentContext | null` — raw loaded context
- `isLoading: boolean` — loading state
- `error: string | null` — error state
- `environmentStatus: Map<Environment, DeploymentEnvironmentStatus>` — derived per-environment status
- `isModeAvailable(mode: ComparisonMode): { available: boolean; reason?: string }` — returns whether a comparison mode can be executed:
  - `current-vs-saved`: always available
  - Modes with environment sides: available only if the required environment(s) have `status === 'active'` deployment
  - In Phase 0 (adapter error on load): all environment modes unavailable with reason "requires backend connection"
- `refresh(): void` — re-fetch deployment context

The hook loads deployment context once on mount. Error from Phase 0 adapter is caught and treated as "all environments unavailable."
