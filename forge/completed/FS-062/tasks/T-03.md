## Summary

Add the S3 bucket resource to the SAM template with CORS configuration for browser-based access, a lifecycle rule to expire temporary Step Functions batch artifacts, and stage-aware naming.

---

## Scope

### In Scope

- `AWS::S3::Bucket` resource definition in `template.yaml`
- CORS configuration (allow `*` origins, GET/PUT/DELETE methods, Content-Type header)
- Lifecycle rule: expire objects under `schemas/*/batches/` prefix after 7 days
- Stage-prefixed bucket naming with account ID for uniqueness
- Bucket policy for Lambda access (or rely on IAM role — determine simplest approach)
- Update Globals.Function.Environment to reference bucket

### Out of Scope

- Bucket replication, versioning, or encryption configuration
- CloudFront distribution
- Public access block configuration (defaults are fine for Phase 1)
- S3 helper TypeScript code (FS-058)

---

## Relevant Areas

- `template.yaml` (modify — add resource)
- `forge/architecture/persistence-model.md` (reference — S3 layout)

---

## Change Requirements

Add to `template.yaml` Resources section:

**StorageBucket** (`AWS::S3::Bucket`)
- BucketName: `!Sub '${Org}-keyra-${Stage}-${AWS::AccountId}'` (where `Org` is a template parameter, e.g., `kbx`)
- CorsConfiguration:
  - AllowedOrigins: `['*']`
  - AllowedMethods: `['GET', 'PUT', 'DELETE']`
  - AllowedHeaders: `['Content-Type', 'Authorization']`
- LifecycleConfiguration:
  - Rule: Prefix `schemas/*/batches/`, ExpirationInDays 7, Status Enabled
- DeletionPolicy: Retain (do not delete bucket on stack deletion — data preservation)

Update:
- Globals.Function.Environment.Variables to include `STORAGE_BUCKET: !Ref StorageBucket`
- Outputs to include StorageBucketName and StorageBucketArn

## Verification Requirements

- `sam validate` passes after adding bucket resource
- CORS configuration allows browser PUT/GET/DELETE from any origin
- Lifecycle rule targets the correct prefix pattern for temporary batch files
- Bucket name is unique per stage and account

---

## Acceptance Checks

- S3 bucket resource defined in `template.yaml`
- CORS allows `*` origin with GET, PUT, DELETE methods
- Lifecycle rule expires `schemas/*/batches/` objects after 7 days
- Bucket name includes org prefix, stage, and account ID for global uniqueness
- `STORAGE_BUCKET` environment variable references the bucket
- `sam validate` passes

---

## Blockers / Risks

- S3 lifecycle prefix rules use exact prefix matching — the pattern `schemas/*/batches/` may need to be expressed differently (as a tag-based rule or multiple prefix rules). Verify CloudFormation syntax.

---

## Notes

- The lifecycle rule is for temporary batch files created by Step Functions during large schema ingestion. These are intermediate artifacts that are no longer needed once ingestion completes.
- S3 bucket names must be globally unique. The `{Org}-keyra-{Stage}-{AccountId}` pattern ensures uniqueness without requiring manual coordination. The `Org` parameter defaults to `kbx` and can be overridden per deployment.
