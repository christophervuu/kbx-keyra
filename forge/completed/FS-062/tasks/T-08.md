## Summary

Create the local development environment configuration: `docker-compose.yml` for DynamoDB Local and LocalStack S3, a setup script to create tables and bucket in local emulators, a `.env.example` file documenting all environment variables, and a `env.local.json` for `sam local` invocation.

---

## Scope

### In Scope

- `docker-compose.yml` at repo root with DynamoDB Local and LocalStack services
- `scripts/setup-local.sh` — idempotent script to create all DynamoDB tables and S3 bucket in local emulators
- `.env.example` — reference file documenting all environment variables with defaults
- `env.local.json` — SAM local environment override file (passed via `--env-vars`)
- Documentation in script comments for developer onboarding
- Health check commands to verify local services are running

### Out of Scope

- OpenSearch local emulation (no good local option for Serverless — use mocks in tests)
- Step Functions local emulation (use `sam local` for individual functions)
- CI/CD environment configuration
- Secrets management (no secrets in Phase 1)

## Change Requirements

Create `docker-compose.yml`:
```yaml
services:
  dynamodb-local:
    image: amazon/dynamodb-local:latest
    ports:
      - '8000:8000'
    command: '-jar DynamoDBLocal.jar -sharedDb'
  localstack:
    image: localstack/localstack:latest
    ports:
      - '4566:4566'
    environment:
      - SERVICES=s3
      - DEFAULT_REGION=us-east-1
```

Create `scripts/setup-local.sh`:
- Check that Docker services are running (health check on ports 8000, 4566)
- Create all 5 DynamoDB tables with correct key schemas and GSIs (matching T-02 definitions)
- Use `aws dynamodb create-table --endpoint-url http://localhost:8000` commands
- Create S3 bucket: `aws s3 mb s3://dev-keyra-storage-local --endpoint-url http://localhost:4566`
- Idempotent: use `|| true` or check existence before creating
- Print success summary showing created/existing resources

Create `.env.example`:
```
# AWS Region
AWS_REGION=us-east-1

# DynamoDB Tables
PROJECTS_TABLE=dev-keyra-projects
MAPPINGS_TABLE=dev-keyra-mappings
SCHEMA_METADATA_TABLE=dev-keyra-schema-metadata
SCHEMA_NODES_TABLE=dev-keyra-schema-nodes
MAPPING_VERSIONS_TABLE=dev-keyra-mapping-versions

# S3
STORAGE_BUCKET=dev-keyra-storage-local

# Endpoint overrides (local development)
DYNAMODB_ENDPOINT=http://localhost:8000
S3_ENDPOINT=http://localhost:4566

# OpenSearch (not emulated locally — use mock in tests)
OPENSEARCH_ENDPOINT=

# Step Functions
STATE_MACHINE_ARN=

# Stage
STAGE=dev
```

Create `env.local.json` (for `sam local start-api --env-vars env.local.json`):
```json
{
  "Parameters": {
    "PROJECTS_TABLE": "dev-keyra-projects",
    "MAPPINGS_TABLE": "dev-keyra-mappings",
    "SCHEMA_METADATA_TABLE": "dev-keyra-schema-metadata",
    "SCHEMA_NODES_TABLE": "dev-keyra-schema-nodes",
    "MAPPING_VERSIONS_TABLE": "dev-keyra-mapping-versions",
    "STORAGE_BUCKET": "dev-keyra-storage-local",
    "DYNAMODB_ENDPOINT": "http://host.docker.internal:8000",
    "S3_ENDPOINT": "http://host.docker.internal:4566",
    "AWS_REGION": "us-east-1",
    "STAGE": "dev"
  }
}
```

Note: `sam local` runs in Docker, so `localhost` must be `host.docker.internal`.

## Verification Requirements

- `docker-compose up -d` starts both services without errors
- `scripts/setup-local.sh` creates all tables and bucket successfully
- Running `setup-local.sh` a second time does not error (idempotent)
- DynamoDB Local responds on port 8000 (`aws dynamodb list-tables --endpoint-url http://localhost:8000`)
- LocalStack S3 responds on port 4566 (`aws s3 ls --endpoint-url http://localhost:4566`)
- `.env.example` documents all required variables

## Blockers / Risks

- Docker must be installed on developer machines. Document this prerequisite.
- `host.docker.internal` works on macOS and Windows Docker Desktop but may require `--network host` on Linux. Note this in script comments.

---

## Notes

- OpenSearch is intentionally not emulated locally. Integration tests that need OpenSearch should mock the OpenSearch client. A future task may add OpenSearch Local or use the OpenSearch Docker image, but this is not required for Phase 1 baseline.
- The `setup-local.sh` script should use AWS CLI v2 commands. Ensure developers have AWS CLI installed (can use the `aws` command against local endpoints without real credentials — any dummy credentials work).
- For the env.local.json SAM file, the format uses function names as top-level keys when targeting specific functions, or `Parameters` for globals. Verify correct SAM local env-vars format.
