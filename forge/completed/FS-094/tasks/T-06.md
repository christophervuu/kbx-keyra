## Summary

Wire non-primary input kinds into the smart tray and guided builders so users can author with enrichment inputs, constants, static values, and array-scope sources while preserving UI terminology and valid DSL generation.

---

## Scope

### In Scope

- Tray input creation/editing flows for enrichment/constant/static/expression fallback.
- Enrichment badges and alias-aware labeling (`ENR1`, etc.).
- DSL generation paths for `external`, `constant`, `static`, `item`, `parent` usage.
- Null/convert actions for mixed input kinds.

### Out of Scope

- Backend metadata schema changes.
- Full array UI redesign.

---

- `ui/src/features/mappings/components/SmartBuilderPanel.tsx`
- `ui/src/features/mappings/components/InputTray.tsx`

- `ui/src/features/mappings/lib/smart-builder-action-resolver.ts`
- `ui/src/features/mappings/**/*.test.ts(x)`

---

## Change Requirements

- Guided label uses "Enrichment input" while generated DSL uses `external("alias")`.
- Enrichment generation rules are strict: alias-root selection emits `external("alias")`, nested field selection emits `get(external("alias"), "field.path")`.
- Constant/static input flows generate valid DSL and show tray summary metadata.
- Item/parent availability must be gated by array-scope context.

---

## Verification Requirements

- Tests for expression generation per source kind.
- UI tests for enrichment tray rendering and selection behavior.
- Typecheck/lint for touched files.

---

## Acceptance Checks

- Tray supports all specified input kinds with appropriate labels and DSL output.
- Enrichment root and nested field selections emit the correct distinct DSL forms without raw DSL editing.
- Item/parent options appear only in valid contexts.
- Null/convert actions apply correctly on mixed inputs.
