## Summary

Create a central action catalog and resolver that determines enabled/disabled actions from builder context, grouped by category, with deterministic unavailable reasons. Ensure guided actions map only to valid registered DSL functions.

---

## Scope

### In Scope

- New action catalog metadata model.
- Availability resolver by target type, input count/types, nullability, scope, focused slot, and composition context.
- Disabled reason generation strings.
- DSL coverage accounting helper for catalog-to-registry mapping.

### Out of Scope

- Final UI rendering of action list.
- Engine registry implementation changes.

---

## Relevant Areas

- `ui/src/features/mappings/lib/smart-builder-action-catalog.ts`
- `ui/src/features/mappings/lib/smart-builder-action-resolver.ts`
- `ui/src/features/mappings/lib/smart-builder-dsl-coverage.ts`
- `ui/src/lib/data/dsl-functions.ts`
- `ui/src/features/mappings/lib/*.test.ts`

---

## Change Requirements

- Actions grouped under text/number/date/condition/null/lookup/array/convert/advanced.
- Resolver must sort enabled before disabled.
- Disabled actions remain visible with reason details.
- Coverage utility must classify each DSL function: user-facing, input-type, advanced-only, or intentionally unsupported.
- Guard against unregistered function emission in guided actions.
- Remove unregistered pseudo-operators from guided condition catalog entries (including `startsWith`).
- `isTruthy` / `isFalsy` may remain only if they compile to valid registered DSL patterns and have direct compile-path tests.

---

## Verification Requirements

- Resolver unit tests across mixed type/input contexts.
- Coverage tests against current DSL function catalog/registry surface.
- Typecheck/lint for touched modules.

---

## Acceptance Checks

- Resolver outputs enabled+disabled lists with deterministic reasons.
- All current DSL functions are accounted for in coverage report output.
- No action resolves to unregistered DSL function names.
- Guided operator catalog excludes unregistered pseudo-operators; truthy/falsy entries (if present) are compile-tested to registered DSL.
- Tests pass for resolver and coverage modules.

---

## Blockers / Risks

- Current operator enums may include non-DSL values requiring careful deprecation mapping.

---

## Notes

- Keep reason strings user-facing and actionable.
