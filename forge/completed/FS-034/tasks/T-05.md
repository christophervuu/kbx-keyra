## Summary
Build the `useBatchExecution` hook that orchestrates sequential execution of multiple test cases. Supports Run All (all saved cases) and Rerun Failed (only cases with `fail` status). Records pass/fail results via `useTestRunResults` as each case completes.

---

## Scope

### In Scope
- Create `useBatchExecution` hook at `ui/src/features/mappings/hooks/use-batch-execution.ts`
- Sequential execution of test cases using the engine `execute()` function
- Progress tracking: `isRunning`, `progress: { current: number; total: number }`
- `runAll(testCases: TestCase[])` — execute all provided cases
- `rerunFailed(testCases: TestCase[], results: Record<string, TestRunResult>)` — filter to failed cases, execute
- `cancel()` — stop execution after current case completes
- Per-case result determination: pass = zero error-severity diagnostics; fail = any error diagnostics, execution error, or invalid JSON sourceData
- `onCaseComplete` callback parameter for real-time UI updates
- Cleanup on unmount (cancel pending execution)

### Out of Scope
- UI rendering (buttons, progress indicator) — T-06
- Parallel execution
- Expected-output diffing as pass/fail signal

## Change Requirements
- Hook signature: `useBatchExecution(options: { config: MappingConfig | null; sourceSchema: SchemaDetail | null; targetSchema: SchemaDetail | null; onCaseComplete?: (testCaseId: string, result: TestRunResult) => void })`
- Returns: `{ isRunning, progress, runAll, rerunFailed, cancel }`
- For each test case: parse `sourceData` as JSON; if invalid, mark as fail with "Invalid JSON" error; if valid, call engine `execute()` with the parsed data
- Pass/fail determination: count error-severity diagnostics in `ExecutionResult.diagnostics`; zero errors = pass, any errors = fail
- Build `TestRunResult` from execution result: status, errorCount, warningCount, executedAt (ISO string), durationMs (from stats), outputSnapshot (from result.output)
- Fire `onCaseComplete` after each case
- Cancellation: set a ref flag, check before each case execution, stop if cancelled
- Cleanup on unmount via `useEffect` cleanup
- Sequential execution: use async loop with state updates between cases
