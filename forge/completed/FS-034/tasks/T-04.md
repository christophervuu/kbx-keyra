## Summary
Add "Add New" and "Save As Test Case" action buttons to the `TestCaseListPanel` toolbar area. "Add New" creates a blank test case with a default name. "Save As Test Case" saves the current scratchpad source data as a named test case with an inline name input flow.

---

## Scope

### In Scope
- Add "Add New" button to `TestCaseListPanel` toolbar
- Add "Save As Test Case" button (enabled only in scratchpad mode when source data is non-empty)
- "Add New" behavior: creates blank test case with name "Test Case N" (auto-incrementing), selects it, clears source textarea
- "Save As Test Case" behavior: shows inline name input (same pattern as existing save flow in `TestCaseManager`), on confirm creates a new test case with the current source data and the entered name, selects the new case
- Wire callbacks through `TestCaseListPanel` props

### Out of Scope
- Run All / Rerun Failed (T-06)
- Batch execution
- Wiring into AdvancedTestingPage

## Change Requirements
- "Add New" button calls `onAddNew()` callback; parent is responsible for calling `saveTestCase({ name: 'Test Case N', sourceData: '' })`
- Default naming: "Test Case 1", "Test Case 2", etc. — next number derived from existing test case count
- "Save As Test Case" button triggers inline name input flow; on confirm calls `onSaveCurrentInput(name: string)` callback
- "Save As Test Case" is disabled when `sourceDataRaw` is null/empty or when a saved test case is already selected (not in scratchpad mode)
- Both buttons are in a toolbar row above the test case list
