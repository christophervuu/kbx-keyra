## Summary
Extend the `useTestCases` hook with `renameTestCase`, `duplicateTestCase`, and `updateTestCase` operations. These are foundational CRUD operations that the new test case list UI depends on. The existing `TestCase` domain type is not modified — the hook gains new mutation methods that operate on the existing type shape.

---

## Scope

### In Scope
- Add `renameTestCase(id: string, newName: string): void` to the hook
- Add `duplicateTestCase(id: string): TestCase | null` to the hook — creates a copy with " (copy)" suffix, new ID, new timestamp
- Add `updateTestCase(id: string, updates: Partial<Pick<TestCase, 'sourceData' | 'expectedOutput'>>): void` to the hook
- Update `UseTestCasesResult` interface with new methods
- Ensure backward compatibility — existing localStorage data loads without error

### Out of Scope
- Modifying the `TestCase` domain type in `domain.ts`
- Run result storage (separate task)
- UI components

---

## Relevant Areas
- `ui/src/features/mappings/hooks/use-test-cases.ts`
- `ui/src/features/mappings/hooks/use-test-cases.test.ts`

---

## Change Requirements
- `renameTestCase` must find the case by ID, update its name, persist to localStorage
- `duplicateTestCase` must create a new case with a new `id` (crypto.randomUUID), name = `originalName + " (copy)"`, same `sourceData` and `expectedOutput`, new `createdAt` timestamp; append to list and persist; return the new case or null if source not found
- `updateTestCase` must find the case by ID and merge partial updates into `sourceData` and/or `expectedOutput` fields only; persist
- All operations must persist immediately to localStorage (same pattern as existing `saveTestCase` and `deleteTestCase`)
- Existing test case arrays must load correctly — no schema migration needed since `TestCase` type is unchanged

---

## Verification Requirements
- Unit tests for `renameTestCase`: rename existing case, rename non-existent ID is no-op, name persists to localStorage
- Unit tests for `duplicateTestCase`: creates copy with correct name suffix, new ID, same sourceData, returns new case, persists; duplicate of non-existent ID returns null
- Unit tests for `updateTestCase`: updates sourceData only, updates expectedOutput only, updates both, non-existent ID is no-op, persists
- Existing tests continue to pass
- TypeScript strict typecheck passes
