## Summary

Define and implement additive domain/API contracts needed by the redesigned Mapping Editor: row model payload shape, sample-selection/add-sample interactions, filter-scoped auto-map requests, AI suggestion lifecycle fields, and save-state metadata compatibility. This task establishes stable interfaces that UI tasks consume.

---

## Scope

### In Scope

- Update `ApiAdapter`/HTTP adapter/domain types for new Mapping Editor data requirements.
- Add/adjust backend handler request/response contracts as needed for:
  - sample picker selection/add flow integration,
  - filter-scoped auto-map invocation,
  - suggestion status metadata transport.
- Preserve backward compatibility for existing mapping persistence/versioning contracts.

### Out of Scope

- Building the Mapping Editor UI components.
- Architecture documentation updates (handled in dedicated architecture task).
- Deployment/test-lab route redesign.

## Change Requirements

- Contracts must encode visible-target scope for auto-map (deterministic list or equivalent bounded filter expression).
- Sample payload add/select APIs must support editor-level sample context without forcing full Test Lab workflows.
- Suggestion payload must carry state needed to render distinct AI rows and explicit accept/edit/dismiss actions.
- Save response/state must continue to reflect revision/version updates and no deploy side effects.

---

## Verification Requirements

- Unit tests for adapter/domain serialization and request construction.
- Handler contract tests for new/changed request validation and response shapes.
- Backward compatibility checks for legacy mapping save/load flows.
- Typecheck/lint for all touched modules.

---

## Acceptance Checks

- Auto-map contract supports explicit filter/visible scope semantics (AE-09).
- Sample add/select contract supports editor field-feedback usage (AE-03, AE-04, AE-05).
- Suggestion lifecycle fields required by UI review actions are present and typed (AE-10).
- Save contract remains mapping-only persistence with version increment compatibility (AE-15).
- Tests and quality gates pass for touched backend/adapter areas.

- Sample selection contract must support finalized precedence and persistence model (per-user mapping override + mapping-level default fallback chain).
