## Summary

When expected output exists (from a loaded test case), the Advanced Testing page should treat the diff as the primary result surface: auto-switch to the Diff tab after execution, show a diff mismatch summary in the execution summary bar, and add a badge to the Diff tab label showing the mismatch count.

---

## Scope

### In Scope

- After execution completes, auto-switch `activeTab` to `'diff'` when expected output is available
- Compute `DiffResult` from actual output vs expected output after each execution
- Generate a human-readable diff summary label from `DiffResult.summary` (e.g., "3 mismatches: 1 missing, 2 value")
- Pass `diffResult` and `diffSummaryLabel` to `ExecutionSummaryBar` (wiring the forward props from T-03)
- Add a mismatch count badge to the Diff tab label (similar to the existing diagnostics badge)
- Pass `diffResult` to `deriveExecutionVerdict` so pass/fail considers diff match status

### Out of Scope

- Changes to `computeDiff()` or diff types (completed in T-01)
- Changes to DiffDisplay rendering (completed in T-02)
- ExecutionSummaryBar component creation (completed in T-03)
- Batch execution

## Change Requirements

### Auto-Tab Switch

In `AdvancedTestingPage`, after execution completes (state transitions to `success`):
- If `expectedOutput` is truthy and parseable as JSON, set `activeTab` to `'diff'`
- If no expected output, leave `activeTab` unchanged (current behavior — defaults to `output`)
- The auto-switch should not fire on subsequent re-renders — only on the transition from `executing` to `success`

### Diff Computation

After each successful execution:
- Parse `expectedOutput` as JSON
- Call `computeDiff(state.result.output, parsedExpected)` to get `DiffResult`
- Store `diffResult` in component state for passing to:
  - `ExecutionSummaryBar` (via `diffResult` and `diffSummaryLabel` props)
  - `deriveExecutionVerdict` (so pass/fail considers diff)
  - The Diff tab badge

### Diff Summary Label Generation

Create a utility to generate a human-readable summary from `DiffSummary`:

```typescript
function formatDiffSummary(summary: DiffSummary): string;
```

Examples:
- `{ total: 0 }` → "" (empty, isEqual is true)
- `{ total: 3, byCategory: { missing_field: 1, value_mismatch: 2, ... } }` → "3 mismatches: 1 missing, 2 value"
- `{ total: 1, byCategory: { type_mismatch: 1, ... } }` → "1 mismatch: 1 type"

Use shortened category labels: missing, extra, value, type, null, structural.

### Diff Tab Badge

Add a badge to the Diff tab label:
- When `diffResult` exists and `!diffResult.isEqual`: show count badge (red) with `diffResult.summary.total`
- When `diffResult` exists and `diffResult.isEqual`: show green check mark
- When no diff result: no badge

### Verdict Wiring

Pass `diffResult` to `deriveExecutionVerdict` call in `AdvancedTestingPage` so the summary bar verdict considers diff match status.

## Notes

- The auto-tab-switch should use a `useEffect` that watches `state.status` transition. Use a ref to track previous status to detect the `executing → success` transition specifically, avoiding re-triggers on re-renders.
- If `expectedOutput` is not valid JSON, the diff computation should fail gracefully — show a parse error in the diff area but do not crash the page. The verdict should treat unparseable expected output as "no expected output" for pass/fail purposes.
