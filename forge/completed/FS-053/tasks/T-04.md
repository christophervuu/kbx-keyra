## Summary

Replace `ArgumentSlotInput` usage in `ArgumentForm` with the new `ParameterValueInput` component. This is the primary integration task that brings the new mode model into the production editing flow. The `ArgumentForm` component resolves parameter hints, context (item vs source), and presentation metadata — then passes these to `ParameterValueInput`. Backward compatibility is maintained: all existing `ArgumentSlot` emission patterns are preserved.

---

## Scope

### In Scope

- Update `ArgumentForm.tsx` to render `ParameterValueInput` instead of `ArgumentSlotInput` for each parameter slot
- Wire `PARAMETER_HINTS` resolution: call `resolveParameterOptions()` (from T-02) and pass result as `options` prop
- Wire `PARAMETER_PRESENTATION` metadata: pass `label` and `description` from existing registry
- Wire `isItemContext` based on existing `conditionArrayPath` / array context detection
- Wire `sourceOptions` through (same as today)
- Preserve the `forceConditionEditor` special case for filter/find condition parameters (this parameter uses `ConditionRowEditor` directly, not the mode toggle — preserve this)
- Preserve variadic `[+ Add value]` button and slot removal behavior
- Update `ArgumentForm.test.tsx` to reflect new component rendering
- Ensure all existing `ArgumentForm.test.tsx` tests pass with adapted assertions
- Mark `ArgumentSlotInput` as deprecated (add JSDoc deprecation notice) but do not delete it yet (may still be used by other surfaces)

### Out of Scope

- ChainStepCard layout changes (T-05)
- SourceCard integration (T-06)
- Deletion of `ArgumentSlotInput` (retained for backward compat)
- Changes to slot factories or expression-builder-state
