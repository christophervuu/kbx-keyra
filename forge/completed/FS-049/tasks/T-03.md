## Summary

Create the "Continue Where You Left Off" section that shows the user's most recently accessed projects and mappings. This includes: a `useRecentActivity` hook that reads/writes localStorage, a `ContinueWhereYouLeftOff` display component, and recording calls in relevant route pages (ProjectOverview, MappingEditor, TestLabPage) to populate the recent activity data.

---

## Scope

### In Scope

- Define `RecentActivityEntry` type: `{ type: 'project' | 'mapping', id: string, projectId?: string, name: string, timestamp: string }`
- Create `useRecentActivity` hook in `ui/src/features/home/hooks/use-recent-activity.ts`:
  - `getRecentItems(): RecentActivityEntry[]` — reads from `keyra:recent-activity` localStorage key, returns up to 10 entries sorted by timestamp descending
  - `recordActivity(entry: Omit<RecentActivityEntry, 'timestamp'>): void` — adds/updates an entry with current timestamp; deduplicates by `type + id`; maintains max 10 entries
  - Handles corrupted/missing localStorage gracefully (returns empty, silently fails writes)
- Create `ContinueWhereYouLeftOff.tsx` component in `ui/src/features/home/components/`:
  - Accepts `items: RecentActivityEntry[]` prop
  - Renders up to 3 compact horizontal cards: name, type indicator (folder icon for project, file icon for mapping), relative timestamp
  - Each card is clickable (triggers `onItemClick(entry)` callback)
  - If `items` is empty: the component returns `null` (renders nothing)
- Add `recordRecentActivity()` calls in:
  - `ui/src/routes/pages/ProjectOverview.tsx` (or the feature component it wraps)
  - `ui/src/routes/pages/MappingEditor.tsx` (or the feature component it wraps)
  - `ui/src/routes/pages/MappingTestLab.tsx` (or the feature component it wraps)
- Export new hook and component from feature barrel
- Add tests for hook and component

### Out of Scope

- Wiring into the page layout (T-05 handles composition)
- Styling integration with the two-column layout
- Recording activity for schema views or other pages

## Blockers / Risks

- Recording activity in route pages requires understanding the project/mapping name resolution from route params and adapter data. The feature page components (ProjectOverviewPage, MappingEditor) already load entity data — recording should happen after data loads successfully.

---

## Notes

- The recording mechanism should be lightweight: a single `useEffect` in each route page that fires when entity data loads successfully.
- For MappingEditor and TestLab, the mapping name and projectId are available from the loaded mapping config or route params.
- The hook should be purely a localStorage utility — it does not use the ApiAdapter.
- Use `Date.now()` for timestamp generation and `toISOString()` for storage.
