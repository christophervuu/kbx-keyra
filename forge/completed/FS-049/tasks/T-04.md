## Summary

Update the `MetricsBar` component to remove the "Deployed" metric card (which is always 0 in Phase 0) and add visual emphasis to the "Has Errors" status when its count is greater than zero. This makes the metrics bar more actionable by highlighting what needs attention and removing non-informative data.

---

## Scope

### In Scope

- Remove the "Deployed" metric card from `MetricsBar`
- Update `DashboardMetrics` type to make `deployedCount` optional or remove it
- Update `computeMetrics` in `useDashboardData` if `deployedCount` is removed from the type
- Add visual emphasis to the "Has Errors" status item when count > 0: use a subtle background highlight (e.g., `bg-red-500/10` behind the item or a slightly larger/bolder treatment)
- Update MetricsBar skeleton to match new card count (4 cards instead of 5)
- Update existing MetricsBar tests

### Out of Scope

- Adding new metrics (e.g., "Ready to Deploy")
- Making metrics clickable/linkable
- Changing the metrics data source or adapter calls
- Changing the layout position of MetricsBar (handled in T-05)

## Change Requirements

After this task is complete:

- MetricsBar renders 4 items: Projects, Mappings, Schemas, Status (breakdown)
- No "Deployed" metric card is rendered
- `DashboardMetrics.deployedCount` is removed from the type (or made optional with deprecation comment)
- `computeMetrics` no longer computes `deployedCount`
- When `statusBreakdown.hasErrors > 0`, the "Has Errors" status item has additional visual emphasis (background accent or border accent) to draw the user's eye
- When `statusBreakdown.hasErrors === 0`, the "Has Errors" item renders normally (no special emphasis)
- Skeleton renders 4 placeholder cards (previously 5)

- The skeleton card count change is minor but ensures visual consistency between loading and loaded states.
