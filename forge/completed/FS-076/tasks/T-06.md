## Summary

Implement CDM schema UI behavior for explicit re-sync, sync-state badge rendering, and hard read-only action gating across Project Overview and Schema Detail surfaces.

---

## Scope

### In Scope

- Wire `syncCdmSchema` API call in backend mode.
- Wire lightweight status-refresh read calls to surface `update-available` without requiring user re-sync.
- Add/update UI actions for explicit re-sync trigger on CDM schemas.
- Render sync badges for `synced`, `update-available`, and `sync-failed` states.
- Enforce CDM read-only actions (hide/disable edit/replace/remove/publish/promote).
- Add/adjust user-facing failure/retry messaging for sync errors.
- Ensure duplicate-link idempotent return path yields deterministic UI success behavior (no hard warning).

### Out of Scope

- Backend sync implementation details.
- Non-CDM action/permissions redesign.
- Auto-sync behavior.

## Change Requirements

- Re-sync must be user-initiated only (button/action).
- CDM surfaces must clearly indicate read-only status.
- Read-only gating must consistently suppress disallowed actions in all touched surfaces.
- Sync-state badge rendering must be deterministic and consistent.

---

## Verification Requirements

- Component tests for action gating and badge rendering for all states.
- Interaction tests for successful re-sync, unchanged re-sync, and failed re-sync user feedback.
- Typecheck/lint for touched modules.

---

## Acceptance Checks

- CDM schemas expose only allowed read-only actions (including explicit Re-sync).
- Edit/Replace/Remove/Publish/Promote actions are not available for CDM records.
- Sync status badges render correctly for all required states.
- Re-sync failure messaging is actionable and non-technical.
