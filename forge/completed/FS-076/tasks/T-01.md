## Summary

Define and wire the foundational contract changes required for CDM integration, including source metadata (`repoId`) and sync-state representation that supports `synced`, `update-available`, and `sync-failed`.

---

## Scope

### In Scope

- Update backend and shared contract types for CDM link/sync payloads and results.
- Add `repoId` support to schema source metadata shape and persistence mapping.
- Project `repoId` into query/index fields used for filtering/reporting.
- Align sync-state enum/model to include required FS-076 states.
- Keep backward compatibility strategy explicit for existing non-CDM records.

### Out of Scope

- Implementing GitHub API calls.
- UI rendering and interaction changes.
- Full endpoint behavior implementation.

## Change Requirements

- Contracts must represent CDM provenance using: `origin=cdm`, `repo`, `repoId`, `branch`, `path`, `commitSha`.
- Sync-state model must expose FS-076 required states and preserve deterministic mapping for existing records.
- Type and serialization boundaries (adapter/API/persistence) must remain consistent.
