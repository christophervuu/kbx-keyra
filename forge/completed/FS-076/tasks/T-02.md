## Summary

Implement backend read-only CDM listing under `JSONSchemas/CommonDataModels/` with strict path scoping and no-write GitHub client behavior.

---

## Scope

### In Scope

- Add/enable backend route/handler/service for CDM listing.
- Enforce root/path validation so listing cannot escape CommonDataModels scope.
- Enforce one-directory-level-per-request listing semantics (no recursive default).
- Transform GitHub listing response into `GitHubFile[]` contract.
- Add error handling for not-found/validation/rate-limit scenarios.

### Out of Scope

- Linking schemas to projects.
- Re-sync behavior.
- UI picker changes.

## Change Requirements

- CDM listing must be constrained to repo `KBXT/KBX-Canonicals` and root `JSONSchemas/CommonDataModels/`.
- Requests with out-of-root path input must fail validation.
- Listing response must represent only the requested directory level; child navigation is client-driven via follow-up path requests.
- Only GitHub read endpoints may be used.
- Response must contain only browse-appropriate file/directory entries.

---

## Verification Requirements

- Handler/service tests covering in-root success and out-of-root rejection.
- Tests for API error normalization on GitHub read failures.
- Explicit tests/assertions that no GitHub write methods are invoked.

---

## Acceptance Checks

- Listing endpoint returns only CommonDataModels-root entries.
- Out-of-scope path requests are rejected with deterministic validation error.
- No write-path GitHub client method is called in listing flow.
- Targeted backend tests pass.

---

## Blockers / Risks

- GitHub API pagination/rate-limit behavior may require clear UX-safe error mapping.
