## Summary

Update server-side preview backend behavior so preview requests route to selected runtime environments and responses include environment + artifact identity metadata that proves which deployed snapshot produced output.

---

## Scope

### In Scope

- Preview routing contract from control plane to selected runtime environment.
- Runtime preview execution against local active artifact.
- Response envelope fields for environment and artifact metadata.
- Deterministic error behavior for not-deployed runtime environments.

### Out of Scope

- UI selector rendering (T-06).
- Auth/security controls for preview endpoints.

## Change Requirements

- Preview request carries runtime target (`DEV|PREPROD|PROD`) and routes accordingly.
- Runtime preview executes against local active artifact (not draft/save state, not sandbox pointers).
- Response includes: environment, artifactId (and/or hash), deployedAt/source metadata as available.

---

## Verification Requirements

- Integration tests for preview in multiple environments with different active artifacts.
- Tests for no-active-artifact error behavior.
- Typecheck/lint pass for touched backend areas.

---

## Acceptance Checks

- Preview against Preprod returns output generated from Preprod-local active artifact.
- Response metadata makes artifact/environment provenance explicit.
- Preview for environment with no deployment returns deterministic not-deployed style error.
- Targeted backend tests pass.

---

## Blockers / Risks

- Existing preview implementation may be tightly coupled to old DEV/QA/PROD naming.

---

## Notes

- Keep preview contract aligned with deployment model and avoid introducing deploy-side mutations.
