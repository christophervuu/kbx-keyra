## Summary

Implement/update `POST /ai/validate-mappings` so the backend validates input, assembles mapping/schema/optional sample-data context, invokes shared AI runtime, and returns a structured AI validation report with normalized failure handling.

---

## Scope

### In Scope

- Request validation for AI validation input payload.
- Enforce V1 single-mapping-only request policy (reject batch payloads).
- Server-side context assembly from mapping + schema records and optional sample data.
- Enforce sample-data constraints: JSON/XML text only, max 1 MB, reject-over-limit policy.
- Shared runtime invocation (`invokeAI`) for validate-mappings prompt.
- Structured output schema enforcement for report payload.
- Normalized success/error response mapping via shared backend envelope conventions.
- Backend tests for success contract and failure paths.

### Out of Scope

- UI rendering and rule-link interaction.
- Adapter/domain typing in UI workspace.
- Prompt authoring workflow.

## Change Requirements

- Endpoint contract supports mapping-level AI validation request with optional sample data.
- Backend, not UI, assembles prompt context for mapping and schema surfaces.
- Success payload includes structured report with summary + issues containing category/severity/affectedRules/description/recommendation.
- Issue category is constrained to V1 taxonomy: `correctness | completeness | maintainability | risk`.
- Issue severity is constrained to V1 scale: `info | warning | error`.
- Parse/runtime/provider failures return normalized envelopes and never return malformed partial report payloads.

## Verification Requirements

- Unit tests for payload validation and invalid input behavior.

- Unit tests for sample-data type/size validation and >1 MB rejection without truncation.
- Unit tests for context assembly and invokeAI variable wiring.
- Unit tests for structured report parse success/failure behavior.
- Unit tests for normalized runtime/provider error mapping.

## Acceptance Checks

- Backend returns structured AI validation report shape for successful requests.

- Failure responses are normalized and non-destructive.
- Tests covering `AE-01`, `AE-02`, `AE-05`, `AE-06`, `AE-07`, and `AE-08` pass.
