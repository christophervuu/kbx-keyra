## Summary

Add/update a dedicated AI validation hook and related mapping-surface state so users can trigger AI validation, receive structured report data, and recover from failures with deterministic retry/reset behavior.

---

## Scope

### In Scope

- Implement/update hook for AI validation request lifecycle (`idle/loading/success/error`).
- Support optional sample-data request wiring.
- Expose structured report data and error state for UI rendering surfaces.
- Provide retry/reset behavior and ensure non-destructive failure handling.
- Add hook tests for success/failure/retry transitions.
- Add hook tests asserting manual-trigger-only behavior (no auto-refresh after edits).

### Out of Scope

- Final visual report component rendering details.
- Backend endpoint implementation.
- Unrelated mapping editor state refactors.

## Change Requirements

- Hook triggers `validateMappings` with updated request contract and captures structured report output.
- Hook exposes explicit state for loading, success, and normalized errors.
- Hook retry/reset semantics are deterministic.
- Request failure must not mutate mapping draft/rule state.

---

## Verification Requirements

- Hook tests for successful request and report-state capture.
- Hook tests for failure and retry/reset transitions.
- Assertions proving no mapping/rule mutation side effects on failure.
- Typecheck/tests for touched hook files.

---

## Acceptance Checks

- Hook can request AI validation and provide structured report state.
- Failure/retry behavior is deterministic and non-destructive.
- Hook supports optional sample-data input fields.
- Hook does not auto-trigger new AI validation requests after mapping edits unless explicitly invoked by user action.

---

## Blockers / Risks
