## Summary
Create a new `ChainBuilder.tsx` component as the chain-based builder orchestration surface. This is a new component boundary — it does NOT extend or refactor `UnifiedExpressionBuilder.tsx`. ChainBuilder manages `ChainState` internally, renders the source entry, ordered step list, and unified step picker. It wires expression generation through `generateExpressionFromChain()` and structural validity gating for `[+ Add Step]`. Steps after completed conditions and value maps are supported.

## Change Requirements
Create `ChainBuilder.tsx` as a new component (not modifying `UnifiedExpressionBuilder`). This is a deliberate component boundary decision — see spec Rev 2.

The component manages `ChainState` internally:
1. On mount/prop change, it hydrates via `decomposeToChain(initialExpression)` or initializes empty chain
2. On every state change, it calls `generateExpressionFromChain(chain)` and propagates the result via `onExpressionChange`
3. Renders: (1) source selector, (2) ordered step list, (3) `[+ Add Step]` button when last step is structurally valid
4. The step picker shows transform functions filtered by `getCompatibleChainableTransforms(outputType)`, plus "Add condition" and "Add value map" entries
5. `[+ Add Step]` is also visible after completed conditions and value maps (they produce values that become the new current value)

No mode tabs — the chain model subsumes Value/Conditional/ValueMap modes.

Props contract:
- `initialExpression?: string` — expression to decompose for hydration
- `onExpressionChange: (expression: string) => void` — fires on every state change
- `parsedSourceSchema?: ParsedSchema | null` — for source field suggestions
- `targetType?: string` — for type compatibility context
