## Summary
Define the new `ChainState`, `ChainSource`, `ChainStep`, `TransformStep`, `ConditionStep`, `ValueMapStep`, `OperandValue`, `DraftFieldState`, and related types in a new file `chain-builder-state.ts`. These types replace the existing `ExpressionBuilderState` discriminated union with a unified chain model. The `OperandValue` type must include a `currentValue` kind for condition left-operand defaults. Also define the `DraftRulesMap` type used by `useMappingEditor`.

## Change Requirements
Create `chain-builder-state.ts` with all new chain model types. Key requirements:

- `ChainState` must support: source selection (field path or static value or none), ordered steps array
- `ChainStep` is a discriminated union of `TransformStep`, `ConditionStep`, `ValueMapStep`
- `ConditionStep` must structurally enforce required else branch (non-optional `elseBranch: ChainState` field)
- `ConditionStep.conditions[].predicates[]` use `Predicate` type with `left: OperandValue`, `operator`, `right: OperandValue`
- `OperandValue` must support four kinds: `{ kind: 'currentValue' }` (implicit chain value), `{ kind: 'field'; path: string }`, `{ kind: 'static'; value: StaticValue }`, `{ kind: 'expression'; dsl: string }`
- `ValueMapStep` must structurally enforce required default (non-optional `defaultValue: ChainState` field)
- `DraftFieldState` captures per-field draft lifecycle state
- Export all new types from the feature barrel

The `currentValue` kind in `OperandValue` is critical — it enables conditions to default their left operand to the accumulated chain value while explicitly distinguishing this from a manually selected source field. The expression generator (T-02) will substitute the actual chain accumulator expression when it encounters `kind: 'currentValue'`.
