## Summary

Implement the `useDashboardData` hook that loads all projects, schemas, and mapping counts from the adapter, computes aggregated metrics (totals, status breakdown), derives per-project worst-status, and builds the `ProjectListItem[]` view model. Handles loading, error, and retry states using `useAsyncState`.

## Change Requirements

Hook signature:
```typescript
function useDashboardData(): {
  loadState: DashboardLoadState;
  metrics: DashboardMetrics | null;
  projects: ProjectListItem[];
  schemaCount: number;
  retry: () => void;
}
```

Behavior:
- On mount: set `loadState: 'loading'`, execute parallel calls:
  - `adapter.listProjects()` → ProjectMetadata[]
  - `adapter.listSchemas()` → SchemaMetadata[] (only need `.length`)
  - For each project: `adapter.listMappings(project.projectId)` → MappingMetadata[]
- After all resolve: compute `DashboardMetrics`:
  - `totalProjects` = projects.length
  - `totalMappings` = sum of all mapping arrays
  - `totalSchemas` = schemas.length
  - `statusBreakdown` = count all mappings by their `status` field
  - `deployedCount` = 0 (Phase 0)
- Build `ProjectListItem[]`:
  - For each project, set `mappingCount` from its mapping array length
  - Derive `worstStatus`: has-errors > draft > ready > no-mappings (if empty)
  - Set all deploy badges to `'not-deployed'`
- On error: set `loadState: 'error'`
- `retry()`: re-execute all loads
- Performance note: `Promise.all` for parallel project/schema loads, then `Promise.all` for mapping loads. With 50 projects this should be < 100ms from localStorage.

Worst-status derivation:
```typescript
function deriveWorstStatus(mappings: MappingMetadata[]): ProjectWorstStatus {
  if (mappings.length === 0) return 'no-mappings';
  if (mappings.some(m => m.status === 'has-errors')) return 'has-errors';
  if (mappings.some(m => m.status === 'draft')) return 'draft';
  return 'ready';
}
```

## Notes

The N+1 pattern (load projects, then load mappings per project) is acceptable for Phase 0 localStorage. In Phase 1 with an HTTP backend, this would be replaced by a single aggregated endpoint. The dashboard should not assume any particular aggregation exists — it builds its own view model from primitive adapter calls.

If `ProjectMetadata.mappingCount` is reliably populated by FS-013's adapter enhancements, consider using it directly and skipping per-project `listMappings` calls for the count. But worst-status derivation requires knowing individual mapping statuses, so loading mappings may still be needed.
