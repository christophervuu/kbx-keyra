## Summary

Implement the DSL asset loader that loads the DSL reference text from S3 with in-memory caching and a 5-minute TTL. Also implement a local file-based adapter for development and testing without S3 access. Both adapters conform to the `DslAssetLoader` interface defined in T-01.

## Change Requirements

### S3DslAssetLoader

- Constructor accepts `bucket: string`, `key: string`, and optional `S3Client` (for DI in tests)
- `loadDslReference()`:
  1. Check in-memory cache — if entry exists and is < 5 minutes old, return cached string
  2. On cache miss or expiry: call `GetObjectCommand` with the configured bucket and key
  3. Read the response body as a UTF-8 string
  4. Cache the result with current timestamp
  5. Return the DSL reference text
  6. On S3 error (NoSuchKey): throw with meaningful message indicating asset not found
  7. On other S3 errors: throw with meaningful message

### LocalDslAssetLoader

- Constructor accepts `filePath: string`
- `loadDslReference()`:
  1. Check in-memory cache (same TTL logic)
  2. On cache miss: read file at `filePath` as UTF-8 text
  3. Cache the result
  4. If file not found: throw with meaningful message

### Factory Function

- `createDslAssetLoader(config)`:
  - If `config.mode === 'local'` and `config.dslAssetLocalPath` is set: return `LocalDslAssetLoader`
  - Otherwise: return `S3DslAssetLoader` with `config.dslAssetBucket` and `config.dslAssetKey`

### Cache Implementation

- Single `{ content: string; fetchedAt: number } | null` cache field per adapter instance
- TTL check: `Date.now() - entry.fetchedAt < 300_000`

## Notes

- Can be executed in parallel with T-02, T-04, T-05 after T-01 is complete.
- The S3 response body is a `ReadableStream` in the AWS SDK v3. Use `await response.Body?.transformToString()` to read it as a string.
- The DSL reference content may be several KB of markdown text. This is fine to cache as a single string in memory.
