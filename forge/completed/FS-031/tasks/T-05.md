## Summary

Implement the GitHub Models client wrapper that calls the GitHub Models inference API via the OpenAI SDK. The wrapper configures the client with the GitHub Models base URL, supports model selection from the prompt record, enforces deterministic output (temperature=0), handles structured output via JSON schema response format, and returns normalized success/error objects.

## Change Requirements

### ModelClient

Define invocation parameters:

```typescript
interface ModelInvocationParams {
  promptId: string;
  model: string;
  temperature: number;
  maxTokens: number;
  systemMessage: string;
  userMessage: string;
  responseSchema: object;  // parsed JSON Schema
}
```

**Behavior:**

1. Create or reuse an `OpenAI` client instance configured with:
   - `baseURL`: from config (`GITHUB_MODELS_ENDPOINT` env var, default `https://models.inference.ai.azure.com`)
   - `apiKey`: from config (`GITHUB_TOKEN` env var)
2. Call `client.chat.completions.create()` with:
   - `model`: from params
   - `temperature`: from params
   - `max_tokens`: from params
   - `messages`: `[{ role: 'system', content: systemMessage }, { role: 'user', content: userMessage }]`
   - `response_format`: `{ type: 'json_schema', json_schema: { name: promptId, strict: true, schema: responseSchema } }`
3. Extract `response.choices[0]?.message?.content`
4. Extract usage stats from `response.usage`
5. Return raw content string and usage stats

**Error handling:**

- Catch OpenAI SDK errors and classify:
  - Status 429 → `MODEL_RATE_LIMITED`
  - Status 401/403 → `MODEL_ERROR` with auth context
  - Status 400 → `MODEL_ERROR` with request validation context
  - Network errors → `MODEL_ERROR`
  - Other errors → `MODEL_ERROR`
- Return `AIError` with appropriate code and message

### Output Parser (`output-parser.ts`)

```typescript
function parseModelOutput(
  content: string | null,
  promptId: string,
  model: string,
  usage?: { prompt_tokens: number; completion_tokens: number; total_tokens: number }
): AIResponse<unknown>
```

**Behavior:**

1. If `content` is null or empty: return `AIError` with code `PARSE_ERROR`
2. Try `JSON.parse(content)`
3. On success: return `AIResult` with parsed data, promptId, model, and normalized usage
4. On JSON parse error: return `AIError` with code `PARSE_ERROR` and the parse error message

### Client Lifecycle

The `OpenAI` client instance should be created once per `ModelClient` instance (not per invocation). This allows Lambda warm starts to reuse the HTTP connection.
