## Summary

Implement the prompt renderer that replaces `{{placeholder}}` tokens in system message and user message templates with actual values. The renderer is a pure function with no I/O dependencies, handling both system-managed placeholders (like `{{dslReference}}`) and request-scoped placeholders (like `{{targetPath}}`, `{{expression}}`).

## Change Requirements

### renderPrompt Function

```typescript
function renderPrompt(
  promptRecord: PromptRecord,
  variables: Record<string, string>
): { systemMessage: string; userMessage: string }
```

**Behavior:**

1. Start with `promptRecord.systemMessage` and `promptRecord.userMessageTemplate`
2. For each `{{key}}` pattern found in either template:
   - If `key` exists in `variables`, replace with `variables[key]`
   - If `key` does not exist in `variables`, leave `{{key}}` unchanged
3. Use a regex replacement: `/\{\{(\w+)\}\}/g`
4. Return the rendered system message and user message

**Design decisions:**

- The renderer does NOT validate that all placeholders were replaced. This is intentional — it allows prompt templates to evolve (add new placeholders) without requiring simultaneous code changes in every Lambda.
- The caller is responsible for merging system-managed variables (like `dslReference`) with request-scoped variables before calling `renderPrompt`.
- Variable values are always strings. The caller converts any non-string values to strings before passing them.
