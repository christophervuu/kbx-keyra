## Summary

Ensure CDM re-sync terminal outcomes are persisted consistently in schema metadata and activity records with actionable reason context for failures and clear no-op/update result semantics.

---

## Scope

### In Scope

- Persist sync outcome metadata for `updated`, `no-op`, and `failed`.
- Persist commit transition details and timestamps for successful updates.
- Emit activity entries tied to sync outcome and summary context.

### Out of Scope

- New activity UI components.
- Non-CDM schema status policy overhaul.

## Change Requirements

- No-op runs must record no-update state without mutating schema content/index artifacts.
- Failed runs must persist clear failure reason metadata suitable for caller display.
- Successful runs must persist updated commit SHA and refreshed sync status.

---

## Verification Requirements

- Persistence-layer tests for status transitions and metadata fields.
- Handler tests for activity emission and failure reason propagation.
- Typecheck/lint for touched modules.

- Targeted tests, typecheck, and lint pass.
