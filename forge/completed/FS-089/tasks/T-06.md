## Summary

Remove legacy link/publish/sync options from Add Schema and keep only user-created schema creation via Upload File and Paste Content tabs with proper metadata classification.

---

## Scope

### In Scope

- Remove Link CDM/Published and sync-related options from Add Schema modal.
- Keep Upload File and Paste Content tabs with required inputs.
- Ensure created records are ownership `user` and readonly `false`.
- Ensure input-kind detection maps to correct dataFormat/sourceKind/status behavior.

### Out of Scope

- CDM seed behavior.
- Schema library list/card visual redesign.
- Duplication-from-existing flow unless already supported and explicitly wired.

---

## Relevant Areas

- `ui/src/features/schemas/components/**/*`
- `ui/src/features/projects/components/*Schema*`
- `ui/src/lib/api/types.ts`
- `ui/src/lib/api/local-storage-adapter.ts`

---

## Change Requirements

- Modal must no longer present linking/published/sync terminology.
- Upload and paste pathways must still support JSON Schema, XSD, sample JSON, and sample XML.
- Inferred sample inputs must map to `needs_review` status where applicable.

---

## Verification Requirements

- UI tests for modal tab/options and removed legacy actions.
- Metadata classification tests for four input classes.
- Manual creation flow checks from schema library and project context entry points.

---

## Acceptance Checks

- Add Schema modal exposes only Upload File and Paste Content user-created flows.
- Created schemas are marked user-owned and editable (subject to existing permissions).
- JSON Schema/XSD/sample JSON/sample XML map to expected metadata fields.
- No Link CDM/Published/Sync copy remains in modal.

---

## Blockers / Risks

- Shared dialog reuse with project-specific schema linking surfaces may require careful separation.

---

## Notes

- If duplicate action is already implemented, keep it outside Add Schema modal unless product confirms inclusion.
