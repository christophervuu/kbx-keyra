## Summary

Align Create Mapping schema selector displays with simplified schema metadata and ensure CDM schemas appear immediately without pre-link/add requirements, including status-aware selection handling.

---

## Scope

### In Scope

- Update selector list item rendering to include:
  - CDM badge (where applicable)
  - readiness status
  - format + field count
- Ensure selector data source includes default CDM records.
- Enforce non-selectable `error` behavior and implement decided `needs_review` handling.

### Out of Scope

- Full Create Mapping page redesign beyond selector behavior.
- Auto-map orchestration behavior changes unrelated to schema selection.

---

## Relevant Areas

- `ui/src/features/projects/components/CreateMappingPage.tsx`
- `ui/src/features/projects/components/__tests__/CreateMappingPage.test.tsx`

## Change Requirements

- CDM schemas must be visible by default in selector sources.
- Selector labels must use data format (JSON/XML), not source-kind labels.
- Status treatment must be explicit and consistent with schema library semantics.

---

## Verification Requirements

- UI tests for selector row rendering and CDM presence.
- Tests for status-based selection behavior (`error` blocked; `needs_review` warning-selectable).
- Manual flow test from fresh project into Create Mapping.

---

## Acceptance Checks

- Create Mapping selectors show CDM schemas without prior Add Schema step.
- Selector rows show CDM badge/status/format/field count.
- Error-status schemas are clearly non-selectable.
- Selector copy avoids scope/sync/publish vocabulary.

## Blockers / Risks
