## Summary

Harden remote orchestration reliability by implementing bounded retry/backoff behavior, timeout handling, ambiguous-outcome reconciliation, and deterministic deployment error taxonomy propagation to control-plane history and API consumers.

---

## Scope

### In Scope

- Bounded retries for retryable remote runtime call failures.
- Timeout handling with orchestration status transitions.
- Reconciliation checks for ambiguous outcomes (e.g., timeout after potential runtime success).
- Deployment-specific error code mapping (integrity mismatch, artifact missing, not-deployed preview, etc.).
- Persisting attempt metadata and last error details.

### Out of Scope

- UI visual design changes.
- Security hardening/auth failures beyond current taxonomy mapping.

## Change Requirements

- Retry only retryable classes (timeouts/network/5xx/rate-limit), fail-fast on non-retryable 4xx.
- Persist attempt count and retrying status updates.
- Implement reconciliation call path to runtime status endpoint for ambiguous timeout outcomes.
- Ensure idempotency prevents duplicate pointer mutations under retries.
