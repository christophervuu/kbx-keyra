## Change Requirements

### ai-runtime.md

1. **Module Structure** — Add to the `src/lambda/ai/` listing:
   ```
   auto-map.ts           Third consumer Lambda — section-based auto-map handler with expression validation
   ```

2. **Lambda Handler Pattern** — Add a paragraph after the existing handler pattern description:
   > The `auto-map.ts` handler extends the thin-handler pattern with a post-processing step: after a successful `invokeAI` call, it validates each generated expression using the engine's `parse()` function and attaches validation results to each rule. This is Lambda-specific logic — the shared runtime is not modified. This is the only AI Lambda that imports from `src/engine/`, which is permitted by the project structure rules (Lambda handlers may import from `src/engine/` and `src/lib/`; only `src/lib/ai/` has the engine-import restriction).

3. **Constraints** — Update the Step Functions note:
   > Step Functions are **not used** for lightweight AI endpoints (explain-rule, suggest-expression, auto-map section-based). Step Functions are reserved for future long-running operations like large-schema auto-map across all sections.
