## Summary

Create the initial architecture document for the schema ingestion pipeline subsystem at `forge/architecture/schema-ingestion.md`. This documents the pipeline design, module boundaries, data flow, DynamoDB/S3/OpenSearch usage patterns, inline vs Step Functions path decision, and key design constraints. Also update `forge/architecture/INDEX.md` with the new entry and `forge/architecture/project-structure.md` to reflect new `src/lambda/schema/` and `src/lib/schema/` directories.

---

## Scope

### In Scope

- Create `forge/architecture/schema-ingestion.md` documenting:
  - Pipeline overview (upload → parse → store → index → ready)
  - Module structure (`src/lib/schema/` subdirectories)
  - Data model (SchemaNodes, SchemaMetadata tables, S3 keys, OpenSearch index)
  - Inline path flow diagram
  - Step Functions path flow diagram
  - Threshold decision logic (< 500 inline, >= 500 SFN)
  - Batch sizing rationale (25 DynamoDB, 500 OpenSearch, 500 SFN)
  - Error handling philosophy (metadata status lifecycle, non-blocking OpenSearch failures)
  - Query endpoint architecture (BM25 + structural enrichment)
  - Future extension points (vector embeddings, hybrid search, re-ingestion)
  - Performance targets and constraints
- Update `forge/architecture/INDEX.md` with new row
- Update `forge/architecture/project-structure.md` to include:
  - `src/lambda/schema/` directory and files
  - `src/lib/schema/` directory structure
  - `tests/lambda/schema/` and `tests/lib/schema/` directories
  - `tests/integration/schema-ingestion/` directory

### Out of Scope

- Modifying other architecture documents
- Implementation code
