## Summary

Implement the `querySchemaNodes` Lambda handler that accepts search queries against a schema's indexed nodes, executes keyword-based search via OpenSearch, enriches results with structural context from DynamoDB (parent chain), and returns ranked search results. This endpoint powers schema field discovery in the UI and serves as the foundation for future RAG retrieval.

---

## Scope

### In Scope

- Lambda handler at `src/lambda/schema/query-schema-nodes.ts`
- Request: `POST /schemas/:id/query` with body `{ query: string, filters?: { type?: string[], isArray?: boolean, depth?: number }, includeParentChain?: boolean, limit?: number }`
- OpenSearch query construction:
  - Multi-match on `fieldName` (boost 3), `path` (boost 2), `embeddingText` (boost 1)
  - BM25 scoring
  - Schema-scoped: filter by `schemaId`
  - Optional type/isArray/depth filters
- Result enrichment from DynamoDB (opt-in via `includeParentChain: true`, default `false`):
  - When enabled: for each result, query `parentPath-index` GSI to build parent chain
  - When disabled: skip DynamoDB lookups entirely (faster response)
- Response: `SchemaSearchResult[]` with `{ path, fieldName, type, depth, isArray, score, parentChain?, embeddingText }`
- Default limit: 20 results
- Maximum limit: 100 results

### Out of Scope

- Vector search / k-NN (deferred to embedding generation spec)
- Hybrid search fusion (requires vectors)
- Cross-schema search (query is always scoped to a single schema)
- Result caching

## Change Requirements

- OpenSearch query module (`src/lib/schema/opensearch/query.ts`):
  - `searchSchemaNodes(schemaId: string, query: string, filters?: QueryFilters, limit?: number): Promise<RawSearchResult[]>`
  - Constructs `bool` query with `must` (multi_match) + `filter` (schemaId term + optional type/isArray/depth)
  - Returns raw hits with `_score`
- DynamoDB node reader (`src/lib/schema/dynamo/node-reader.ts`):
  - `getParentChain(schemaId: string, path: string): Promise<string[]>`
  - Uses `parentPath-index` GSI: repeatedly query parent until root
  - `getNodeChildren(schemaId: string, parentPath: string): Promise<SchemaNode[]>`
  - Uses `parentPath-index` GSI: query all nodes with given parentPath
- Lambda handler:
  - Extract `schemaId` from path parameter
  - Validate request body
  - Call OpenSearch search
  - If `includeParentChain: true`: enrich top results with parent chain (parallel DynamoDB lookups)
  - If `includeParentChain` is false/absent: skip enrichment, `parentChain` omitted from results
  - Return 200 with `SchemaSearchResult[]`
  - Return 400 for invalid request
  - Return 404 if schema doesn't exist (check metadata first)
- Response time target: < 500ms for typical queries on 500-field schemas (without parentChain); < 800ms with parentChain enabled

## Blockers / Risks

- Parent chain enrichment adds latency (sequential DynamoDB lookups per ancestor). For deeply nested schemas, consider caching or limiting depth.
- OpenSearch Serverless has different authentication requirements — ensure query client configuration matches indexer.

---

## Notes

The parent chain lookup could be optimized by batching: collect all unique parentPaths from results, deduplicate, fetch in parallel. This avoids N sequential lookups for N results.

Future enhancement: when vector embeddings are populated, this query module will add a k-NN clause and use reciprocal rank fusion to merge scores. The module should be structured to accommodate this addition cleanly.
