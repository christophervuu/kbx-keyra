## Summary

Define all `KEYRA-E###` error codes and `KEYRA-W###` warning codes from the DSL specification as typed constants with their severity levels and parameterized message templates. This module is the single source of truth for all engine diagnostics codes.

---

## Scope

### In Scope

All error and warning codes from `specs/KEYRA-DSL-SPECIFICATION.md` §5.2 and `specs/KEYRA-DSL-ARRAYS.md` §7:

**Syntax & Structure Errors (E001–E009):**
- `KEYRA-E001` — Invalid syntax: {detail}
- `KEYRA-E002` — Unknown function: {name}
- `KEYRA-E003` — Wrong number of arguments for {name}: expected {expected}, got {actual}
- `KEYRA-E004` — Expression exceeds maximum nesting depth ({depth})
- `KEYRA-E005` — Type mismatch in {function}: expected {expected}, got {actual} for argument {argName}

**Array Context Errors (E010–E019):**
- `KEYRA-E010` — item() used outside array context
- `KEYRA-E013` — parent() used outside nested array context
- `KEYRA-E015` — map() template must be an object literal or an expression
- `KEYRA-E016` — (warning) filter() produced empty array
- `KEYRA-E017` — filter()/find() condition must evaluate to a boolean
- `KEYRA-E018` — get() first argument must be an object, got {type}
- `KEYRA-E019` — (warning) find() matched no elements

**Constant & External Errors (E011–E012):**
- `KEYRA-E011` — Undefined constant: {name}
- `KEYRA-E012` — (warning) External source not available: {name}

**Cast Errors (E020–E029):**
- `KEYRA-E020` — Unsupported cast: {fromType} → {toType}
- `KEYRA-E021` — Unknown target type: {targetType}

**Schema Path Errors (E030–E039):**
- `KEYRA-E030` — Source path not found in schema: {path}
- `KEYRA-E031` — Target path not found in schema: {path}

**Date Errors (E040–E049):**
- `KEYRA-E040` — Date parse failed: value "{value}" does not match format "{format}"

**Math Errors (E050–E059):**
- `KEYRA-E050` — Division by zero

**Lookup Errors (E060–E069):**
- `KEYRA-E060` — valueMap mappings argument must be an object literal

**Warnings (W001–W099):**
- `KEYRA-W001` — Null propagation: {function} received null argument {argName}
- `KEYRA-W002` — Source path resolved to null at runtime: {path}
- `KEYRA-W003` — valueMap no match for value "{value}" — returning fallback
- `KEYRA-W004` — Array index out of bounds: index {index}, array length {length}
- `KEYRA-W005` — Required target field {path} has no mapping rule — defaulting to null

Implementation approach:
- A typed const object (e.g., `DIAGNOSTIC_CODES` or `ErrorCodes`) where each key is the code string
- Each entry has: `code: string`, `severity: DiagnosticSeverity`, `messageTemplate: string`
- A helper function `formatDiagnosticMessage(code: DiagnosticCode, params: Record<string, string>): string` that interpolates template parameters
- A `DiagnosticCode` type (union of all valid code strings) for type safety

### Out of Scope

- Diagnostic formatting for display (future spec)
- Diagnostic emission logic (part of execution/validation)
- Localization of messages

## Notes

- Note the asymmetry: `KEYRA-E012`, `KEYRA-E016`, and `KEYRA-E019` have `severity: "warning"` despite their E-prefix. This matches the DSL spec exactly — do not "fix" the severity.
- Message templates use `{paramName}` syntax for interpolation (e.g., `"Unknown function: \`{name}\`"`).
- Consider using `as const` satisfies pattern for maximum type inference while maintaining runtime access.
- The formatter should handle missing params gracefully (leave placeholder unreplaced or throw) — leaving unreplaced is safer for a scaffold.
