## Summary

Update `InlinePreviewStrip` expanded state and `BottomArea` Preview tab so that source/output content areas expand to fill all available vertical space within the bottom panel. When the panel is resized taller, users gain more visible working space inside the text areas rather than empty padding.

---

## Scope

### In Scope

- `InlinePreviewStrip` expanded layout: convert to flex column with fixed-height header/controls and `flex-1 min-h-0 overflow-auto` content areas
- Source JSON textarea: grows with available height, scrolls internally
- Output display area: grows with available height, scrolls internally
- `BottomArea` Preview tab output area: same fill-height treatment
- Ensure the parent container passes explicit height (from `useResizableLayout.layout.bottomHeight`) as a style constraint or uses `h-full` correctly
- Verify behavior at minimum height (180px) — content areas still usable and scrollable

### Out of Scope

- Changes to `useResizableLayout` hook logic
- Changes to the collapsed state of `InlinePreviewStrip`
- Changes to other `BottomArea` tabs (Diagnostics, Trace, Test Cases) unless they share the same output area component
- Changes to the `MappingEditorPage` grid/flex structure (only the internal panel layout)

- `ui/src/features/mappings/components/InlinePreviewStrip.tsx`

## Change Requirements

- `InlinePreviewStrip` expanded container: add `flex flex-col` and explicit height from parent (either `h-full` with parent height constraint or `style={{ height }}` prop).
- Source textarea: change from fixed `rows` attribute to `flex-1 min-h-0` with `overflow-y: auto`. Remove any fixed `h-*` Tailwind class.
- Output display area: same treatment — `flex-1 min-h-0 overflow-y-auto`.
- If the expanded layout splits source and output side-by-side, each column should be `flex-1` within a `flex-row` container that itself is `flex-1 min-h-0`.
- If the expanded layout stacks source and output vertically, use a percentage or equal split (`flex-1` on each) within a flex column that is `flex-1 min-h-0`.
- `BottomArea` Preview tab: apply the same pattern to the output `<pre>` or `<div>` that renders mapped JSON.
- Verify `MappingEditorPage` passes `bottomHeight` from layout state as a CSS style on the bottom panel container, enabling internal flex to consume available space.

## Blockers / Risks

- The current `InlinePreviewStrip` layout may use absolute positioning or complex grid patterns that need careful refactoring to flex.
- Textarea `rows` attribute conflicts with flex height — must be removed or set to a minimum.

---

## Notes

- The key CSS pattern is: outer container gets explicit height → inner flex column → fixed header → `flex-1 min-h-0` body → content with `overflow-auto`.
- This pattern is already used elsewhere in the app (e.g., SchemaTreeView with maxHeight). Apply consistently here.
- `min-h-0` is critical on flex children to allow shrinking below content size.
