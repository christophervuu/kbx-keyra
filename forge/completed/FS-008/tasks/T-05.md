## Summary

Implement the `LocalStorageAdapter` class that satisfies the full `ApiAdapter` interface using browser localStorage for persistence. Also implement the `AdapterProvider` React context and `useAdapter()` hook so any component can access the active adapter. AI and GitHub methods throw "Not available in offline mode".

## Change Requirements

**LocalStorageAdapter:**
- Implements the full `ApiAdapter` interface
- Uses namespaced localStorage keys: `keyra:projects`, `keyra:schemas`, `keyra:mappings`, `keyra:templates`, `keyra:deployments`, `keyra:activity`
- CRUD methods for Projects, Schemas, Mappings:
  - `list*` — read from localStorage, parse JSON, return array
  - `get*` — find by ID in the stored array, throw AppError if not found
  - `create*` — generate UUID, add to array, persist, return created entity
  - `update*` — find by ID, merge changes, persist, return updated entity
  - `delete*` — filter out by ID, persist
- `duplicateMapping` — copies mapping with new name and new ID
- Templates: `listTemplates` returns empty array, `getTemplate` throws not found (no template authoring in Phase 0)
- Deployment methods: stub implementations that read/write to `keyra:deployments`
- AI methods throw: `autoMap`, `suggestExpression`, `explainRule`, `smartFix`, `validateMappings` all throw `Error("Not available in offline mode")`
- GitHub methods throw: `listCdmSchemas`, `linkCdmSchema`, `syncCdmSchema`, `listPublishedSchemas`, `publishSchemaToGitHub`, `linkPublishedSchema` all throw `Error("Not available in offline mode")`
- `previewOnServer` throws `Error("Not available in offline mode")`
- `querySchemaNodes` returns empty array (search requires backend)
- `listActivity` returns from localStorage or empty array
- Handle corrupted localStorage gracefully (JSON.parse failures return empty results)
- Handle quota exceeded by throwing AppError with `retryable: false`

**AdapterProvider:**
- React Context created with `createContext<ApiAdapter | null>(null)`
- `AdapterProvider` component accepts `adapter: ApiAdapter` prop and provides it via context
- `useAdapter()` hook reads from context, throws if used outside provider
- Implementation uses React Context only (no external state library per constraints)

## Notes

- Use `crypto.randomUUID()` for ID generation (available in all modern browsers and Node 19+)
- Storage format: each key stores a JSON-serialized array of entities
- Consider a simple version key (`keyra:version`) for future migration support, but do not implement migration logic now
- The AdapterProvider is intentionally thin — it just holds and provides the adapter instance. No reducer needed here (the adapter itself is stateless from the provider's perspective).
