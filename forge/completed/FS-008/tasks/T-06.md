## Summary

Implement the adapter bootstrap logic that selects the active adapter at app startup based on the `VITE_API_URL` environment variable. If not set, use LocalStorageAdapter. If set, throw "HttpAdapter not implemented". Wire the selected adapter into the AdapterProvider at the app root.

## Change Requirements

**Bootstrap function:**
```typescript
function createAdapter(): ApiAdapter {
  const apiUrl = import.meta.env.VITE_API_URL;
  if (apiUrl) {
    throw new Error("HttpAdapter not implemented");
  }
  return new LocalStorageAdapter();
}
```

**Environment type declaration:**
- Extend `ImportMetaEnv` to include `VITE_API_URL?: string`

**App root wiring:**
- Call `createAdapter()` at the top level of the app (outside component tree, or in a module-level constant)
- Wrap the app tree in `<AdapterProvider adapter={adapter}>...</AdapterProvider>`

## Notes

- The bootstrap runs once at app initialization. The adapter instance is stable for the lifetime of the app.
- In tests, the bootstrap can be tested by mocking `import.meta.env`.
- The throw behavior is intentional — it forces developers to know they need the HttpAdapter before they can run against a real backend.
