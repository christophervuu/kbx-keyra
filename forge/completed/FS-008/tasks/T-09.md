## Change Requirements

**Button:**
- Variants: `primary`, `secondary`, `ghost`, `danger`
- Sizes: `sm`, `md`, `lg`
- Props: `variant`, `size`, `disabled`, `loading`, `children`, standard button HTML attributes
- Loading state shows a spinner indicator and disables interaction
- Styled with Tailwind utility classes
- Accessible: proper `disabled` attribute, `aria-busy` when loading

**Card:**
- A container component with consistent padding, border, rounded corners, and optional shadow
- Props: `children`, `className` (for extension), optional `title` and `description` header
- Composable — can contain any content

**PageHeader:**
- Renders a page title (`<h1>`), optional description, and optional action slot (right-aligned)
- Props: `title`, `description?`, `actions?` (ReactNode for buttons/controls)
- Consistent spacing below for page content

**StatusBadge:**
- Renders deploy status as a colored badge (dot + label)
- Props: `status: DeployStatus`
- Status → appearance mapping (from Section 6.1):
  - `"deployed"` → green dot + "Deployed"
  - `"stale"` → orange dot + "Stale"
  - `"not-deployed"` → gray dot + "Not deployed"
  - `"deploying"` → yellow dot + "Deploying"
- Compact display, suitable for inline use in tables and cards

## Notes

- These components are intentionally minimal. They will evolve as downstream specs (FS-009+) identify additional needs.
- Use `React.forwardRef` for Button and Card so they can be composed with third-party libraries if needed later.
- StatusBadge uses the `DeployStatus` type from the shared domain types (T-02). If T-02 is not complete, define the type inline temporarily.
- Prefer `cva` (class-variance-authority) or a simple variant mapping object for managing Tailwind class variants. Either pattern is acceptable.
