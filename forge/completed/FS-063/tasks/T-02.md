## Summary

Create/modify Lambda handlers for the revised save-revision and create-version flows. Update the mapping update handler to use revision semantics with no-op detection and optimistic concurrency. Add new revision list/get and version create/list/get endpoints.

---

## Scope

### In Scope

- Modify `PUT /mappings/:id` handler to save a revision (increment revision, compute hash, detect no-op, write S3 revision snapshot)
- New `POST /mappings/:id/versions` handler (create version from latest revision; support implicit save)
- New/modify `GET /mappings/:id/revisions` handler (list revisions descending)
- New/modify `GET /mappings/:id/revisions/:revision` handler (get specific revision)
- Modify `GET /mappings/:id/versions` to use new table schema
- Modify `GET /mappings/:id/versions/:version` to include revisionNumber in response
- Optimistic concurrency: reject save if client-supplied revision doesn't match current

### Out of Scope

- UI changes
- Adapter changes
- Infrastructure/SAM template changes

## Change Requirements

- `update-mapping` handler: accept `expectedRevision` in body; compare against stored `revision`; on match, save revision via persistence; on mismatch, return CONFLICT; on no-op (hash unchanged), return success with `noChange: true` flag
- `create-version` handler: read latest revision; if body contains `implicitSave: true` + config, save revision first; then create version pointing to latest revision; return version metadata
- `list-revisions` handler: query MappingRevisions table descending by revision
- `get-revision` handler: get item + S3 content
- Update existing version handlers to use new MappingVersions table schema
- All handlers follow existing conventions (response helpers, error codes, requestId)

---

## Verification Requirements

- Unit tests for each new/modified handler
- Integration test (DynamoDB Local): save revision → verify revision created, no-op detection, concurrency conflict, create version → verify points to revision
- `npm run typecheck` passes

## Acceptance Checks

- `PUT /mappings/:id` with matching `expectedRevision` creates a revision
- `PUT /mappings/:id` with mismatched `expectedRevision` returns 409 CONFLICT
- `PUT /mappings/:id` with unchanged config returns success with `noChange: true`
- `POST /mappings/:id/versions` creates version pointing to latest revision
- `POST /mappings/:id/versions` with `implicitSave: true` saves revision first
- `GET /mappings/:id/revisions` returns revisions descending
- `GET /mappings/:id/versions` returns versions with `revisionNumber`
- All tests pass
- `npm run typecheck` passes
