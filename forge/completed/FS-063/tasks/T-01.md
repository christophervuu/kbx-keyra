## Summary

Replace the current single `MappingVersions` table with a `MappingRevisions` table and a new `MappingVersions` table. Update the `Mappings` table to track `revision` (current) and `latestVersion`. Update persistence modules, types, S3 key patterns, and config references.

---

## Scope

### In Scope

- New `MappingRevisions` DynamoDB table schema (PK=mappingId, SK=revision)
- Revised `MappingVersions` DynamoDB table schema (PK=mappingId, SK=version, with revisionNumber pointer)
- `Mappings` table: field rename `version` → `revision`, add `latestVersion`, add `configHash`
- S3 key pattern change: `mappings/{mappingId}/revisions/r{N}.json`
- Persistence module updates: `mapping-versions.ts` → split into `mapping-revisions.ts` + `mapping-versions.ts`
- Types in `src/lib/persistence/types.ts`
- Config in `src/lib/persistence/config.ts` (table names, S3 key builders)
- Content hash computation utility (SHA-256 of config JSON)
- No-op save detection logic in the persistence layer

### Out of Scope

- Lambda handler changes (T-02)
- UI changes
- SAM template / infrastructure changes (document in notes for follow-up)

## Change Requirements

- Define `MappingRevisionItem` type: `mappingId`, `revision` (number), `savedAt`, `savedBy`, `ruleCount`, `configS3Key`, `configHash`
- Define `MappingVersionItem` type: `mappingId`, `version` (number), `revisionNumber`, `createdAt`, `createdBy`
- Update `MappingItem` to use `revision` instead of `version`, add `latestVersion` (number | null), add `configHash`
- Create `mapping-revisions.ts` with: `save(mappingId, entry)` (with hash-based no-op detection), `list(mappingId)`, `get(mappingId, revision)`
- Update `mapping-versions.ts` to work with new schema: `create(mappingId, { revisionNumber })`, `list(mappingId)`, `get(mappingId, version)`
- Update S3 key builder: `revisionConfigKey(mappingId, revision)` → `mappings/{mappingId}/revisions/r{N}.json`
- Add `computeConfigHash(config: unknown): string` utility
- Update `mappings.ts` update method to increment `revision` field and accept `configHash`
- Prune logic: retain most recent 50 unversioned revisions; revisions referenced by a version are exempt from pruning (query MappingVersions to determine referenced revisions before prune)
- Add environment variable `MAPPING_REVISIONS_TABLE` to config
