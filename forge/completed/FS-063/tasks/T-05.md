## Summary

Refactor `useMappingEditor` to implement the three-tier model: autosave drafts to localStorage, save creates a revision via adapter, version creates a version via adapter. Add draft persistence, restore-on-load prompt, and no-op save handling.

---

## Scope

### In Scope

- Draft autosave to localStorage (`keyra:draft:{mappingId}`) on a debounced interval; store base revision number alongside draft content
- Draft restore logic on editor load: if draft exists and base revision matches server, prompt "Restore draft" / "Discard draft"; if server has newer revision, prompt with context ("newer saved changes on server") and offer "Restore local draft" / "Load latest saved revision"
- `save()` calls adapter `saveMapping`, handles `noChange` response
- `createVersion()` calls adapter `createVersion` (with implicit save if draft exists); show success toast "Version {N} created from Revision {R}"
- Expose `currentRevision`, `currentVersion`, `hasDraft`, `hasUnsavedChanges` state
- Clear draft on successful save

### Out of Scope

- EditorTopBar UI changes (T-06)
- History UI (T-07)

## Change Requirements

- Add autosave effect: debounce 5s after any draft rule change → write to localStorage
- On load: check `keyra:draft:{mappingId}` existence and timestamp; if newer than loaded revision, set `hasStaleDraft: true`
- `save()`: call `adapter.saveMapping()`; if `noChange`, surface via return value / state; if success, clear draft, update `currentRevision`
- `createVersion()`: if `hasUnsavedChanges`, call save first; then call `adapter.createVersion()`; update `currentVersion`
- Expose: `currentRevision: number`, `currentVersion: number | null`, `hasDraft: boolean`, `canSave: boolean` (false when no changes)
