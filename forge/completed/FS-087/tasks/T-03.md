## Summary

Update shared type and persistence contracts so schema access scope is no longer a behavioral axis, while preserving backward compatibility for legacy records and origin/sync metadata semantics.

---

## Scope

### In Scope

- Update domain/persistence schema metadata types to represent shared-library semantics.
- Introduce normalization utilities for legacy scope-bearing records (localStorage + backend payloads).
- Move canonical project linkage model to `linkedSchemaIds: string[]` with legacy `schemaRefs` read-time normalization.
- Preserve mapping schema references and deployment snapshot schema refs as explicit rich refs.
- Define canonical origin/format labels and compatibility mappings.

### Out of Scope

- UI rendering updates.
- Full backend route behavior changes beyond contract/normalization plumbing.

---

## Relevant Areas

- `ui/src/lib/types/domain.ts`
- `ui/src/lib/api/types.ts`
- `ui/src/lib/api/local-storage-adapter.ts`
- `src/lib/persistence/types.ts`
- `src/lib/persistence/schema-metadata.ts`
- shared normalization helpers under `src/lib/persistence/*` and/or `ui/src/lib/*`

---

## Change Requirements

- Remove scope-driven availability from contracts (scope may remain optional legacy metadata only if needed).
- Add deterministic normalization from legacy scope/origin values to shared model, including `origin: local -> uploaded`.
- Ensure canonical project linkage uses `linkedSchemaIds`; avoid new rich `schemaRefs` writes for project linkage except temporary bridge.
- Add/update tests for normalization compatibility and non-breaking mapping references.

---

## Verification Requirements

- Unit tests for legacy record normalization.
- Typecheck for backend and UI packages touching shared types.
- Regression checks proving mapping schema refs remain stable across normalization.

---

## Acceptance Checks

- Legacy global/project schema records normalize to shared library behavior.
- Legacy local origin normalizes to uploaded and no new persisted records use local origin.
- Contracts no longer require scope to decide schema availability.
- Mapping source/target refs continue resolving by unchanged schema IDs.

---

## Blockers / Risks

- Risk: broad type contract changes can cascade through many UI/backend files; stage changes carefully.
