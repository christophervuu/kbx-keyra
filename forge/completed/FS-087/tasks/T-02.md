## Summary

Audit backend handlers, persistence contracts, and infrastructure-facing assumptions to locate schema scope dependencies and determine required remediations (or explicit no-change decisions) for the shared library model.

---

## Scope

### In Scope

- Audit schema Lambdas (`create/get/list/delete/link/sync/query`) for scope behavior.
- Audit project/mapping handlers where schema linkage or schema resolution is scope-coupled.
- Audit persistence models (`src/lib/persistence/types.ts`, schema metadata/project records).
- Explicitly audit whether schema ownership is coupled to `projectId` in DynamoDB PK/SK, GSIs, Lambda query patterns, API route behavior, S3 key conventions, and OpenSearch filters.
- Audit architecture assumptions for DynamoDB, S3 pathing, OpenSearch query filters, GitHub integration, deployment snapshot dependencies, and IAM/env config implications.

### Out of Scope

- Implementing audited code changes.
- UI surface changes.

## Change Requirements

- Produce a backend/AWS audit report with:
  - each scope-bearing field/branch assumption,
  - each `projectId` ownership coupling assumption,
  - required action (`remove`, `ignore`, `migrate`, `rename`, `retain as metadata`),
  - migration compatibility strategy per affected persistence/API contract,
  - explicit statement for each audited AWS area: changed vs unaffected.

---

## Verification Requirements

- Validate audit includes all requirement-listed areas: API routes, Lambda handlers, DynamoDB, S3, OpenSearch, GitHub integration, deployment snapshots, IAM/env assumptions.
- Verify report includes explicit pass/fail statement on backend requirement: schemas must not require `projectId` ownership for cross-project availability.
- Ensure unresolved decisions are captured in FS-087 Open Questions or task notes.

---

## Acceptance Checks

- Backend/AWS scope assumption matrix is complete and reviewable.
- `projectId` ownership coupling matrix is complete (PK/SK, GSI, Lambda queries, API routes, S3 keys, OpenSearch filters).
- Every discovered scope dependency is mapped to a concrete follow-up implementation action.
- Audit explicitly states whether AWS infra changes are required or not.
