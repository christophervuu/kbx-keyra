## Summary

Fix the unapplied-expression modal to only appear when the current builder state genuinely differs from the last applied state for the selected target field. Currently the modal appears on any target switch regardless of whether edits were made, because dirty detection does not compare against the per-field applied state.

---

## Scope

### In Scope

- Track `lastAppliedExpression` per selected target field in `ScalarFieldBuilder`
- Derive `isDirty` by comparing current generated expression against `lastAppliedExpression`
- Update navigation guard to use field-level dirty comparison
- Ensure hydration from an existing rule sets `lastAppliedExpression` correctly
- Ensure Apply updates `lastAppliedExpression` to the committed expression

### Out of Scope

- Changes to the modal's visual design or copy
- Changes to the global Save-level navigation guard
- Auto-advance behavior (already removed)

---

## Relevant Areas

- `ui/src/features/mappings/components/ScalarFieldBuilder.tsx`
- `ui/src/features/mappings/components/MappingEditorPage.tsx` (navigation guard wiring)
- `ui/src/features/mappings/hooks/use-mapping-editor.ts` (canNavigateAway context)

---

## Change Requirements

- On target selection, capture the expression from the current rule (or `""` if unmapped) as `lastAppliedExpression`.
- On every builder state change, derive the current expression string and compare to `lastAppliedExpression`.
- `isDirty` = `currentExpression !== lastAppliedExpression`.
- The unapplied-expression modal / navigation guard must check `isDirty` before showing.
- After successful Apply, update `lastAppliedExpression` to the just-applied expression.
- When builder resets on new target selection (keyed re-mount), `lastAppliedExpression` resets to the new field's applied state.

---

## Verification Requirements

- Unit test: dirty state is `false` when builder hydrates with existing expression and no edits occur.
- Unit test: dirty state is `true` when expression changes from applied state.
- Unit test: dirty state resets to `false` after Apply.
- Component test: selecting a new target without edits does not trigger modal (AE-01).
- Component test: editing expression and selecting a new target triggers modal (AE-02).
- Typecheck passes for all touched files.
