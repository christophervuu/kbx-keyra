## Summary

Add a "Clear mapping" action to the Builder/Editor panel for mapped target properties. Clicking it removes the rule for the selected target property from the working session, marks the session as having unsaved changes, and immediately reflects the unmapped state.

---

## Scope

### In Scope

- Add "Clear mapping" button/action in `ScalarFieldBuilder` for mapped fields
- Hide/disable "Clear mapping" when no rule exists for the selected target
- On click: remove the rule from local state via `useMappingEditor`
- After clearing: target field shows unmapped state, builder resets to empty
- Clearing follows the Apply/Save model: marks session as having unsaved changes
- Increment `unsavedRuleCount` or equivalent to reflect the pending change

### Out of Scope

- Bulk clear / clear-all functionality
- Undo/redo for clear actions
- Clear from the object summary panel
- Clear from Rules View (RuleList already has delete)

---

## Relevant Areas

- `ui/src/features/mappings/components/ScalarFieldBuilder.tsx`
- `ui/src/features/mappings/hooks/use-mapping-editor.ts`
- `ui/src/features/mappings/components/MappingEditorPage.tsx` (composition wiring)

---

## Change Requirements

- Add a `clearRule(targetPath: string): void` action to `useMappingEditor` (or use existing `deleteRule` if it operates by target path).
- `ScalarFieldBuilder` renders a "Clear mapping" button when the current target has an existing applied rule.
- Button placement: in the header area or below the apply button — should be accessible but not easily confused with Apply.
- On click: call `clearRule(selectedTargetPath)`, which removes the rule from local rules array.
- After clear: `lastAppliedExpression` resets to `""`, builder resets to empty/default state, target row shows unmapped.
- `unsavedRuleCount` increments (or equivalent dirty tracking) so Save indicator updates.
- Button uses a destructive/secondary visual style (not primary blue).

## Notes

- If `useMappingEditor` already has a `deleteRule(index)` that works by rule index, the clear action needs to find the rule by `targetPath` first and then delete by index. Alternatively, add a `deleteRuleByTarget(targetPath)` convenience method.
