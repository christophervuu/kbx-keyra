## Summary

Add independent search inputs to both the source panel and target panel headers, and move the filter chips (Unmapped, Warnings, Required, Arrays) into the target panel's toolbar. Remove the global search from `GlobalToolbar` since it is superseded by per-panel search. Each panel filters independently.

---

## Scope

### In Scope

- Add search input to `SourceSchemaPanel` header area, wired to `useTreeSearch` hook (same hook used in target tree — provides expand-to-match, highlight, and collapse-non-matching behavior).
- Add search input to `TargetWorklist` header/toolbar area.
- Add filter chip buttons (Unmapped, Warnings, Required, Arrays) to `TargetWorklist` toolbar.
- Implement filter chip toggle logic: chips are combinable with AND semantics; target list shows only items matching all active filters AND the search query.
- Remove the search field from `GlobalToolbar` (it becomes a toolbar with only view toggle, sort, and Focus mode).
- Style chips as toggleable pill buttons (active = filled, inactive = outlined).

### Out of Scope

- Changes to panel widths (T-04, already completed when this runs).
- Save model changes (T-02).
- Bottom area changes (T-05).
- Creating new hook implementations if existing patterns suffice.

## Change Requirements

- **Source panel search:**
  - Add a compact search input (`<input type="search">`) to the `SourceSchemaPanel` header.
  - Wire to the existing `useTreeSearch` hook (from `ui/src/features/schemas/hooks/use-tree-search.ts`). This provides: expand ancestor nodes of matches, highlight matched nodes, collapse non-matching branches — the same behavior as VS Code's file explorer search.
  - No filter chips in the source panel (search only).
  - Show "N results" count when search is active.
  - At 15% panel width (~216px at 1440px), the search input fills the panel width. No special collapsible pattern needed.

- **Target panel search + filter chips:**
  - Add a search input to the `TargetWorklist` toolbar (above the field list, below any breadcrumb nav).
  - Add filter chip buttons below the search: `Unmapped`, `Warnings`, `Required`, `Arrays`.
  - Filter chip state: `activeFilters: Set<TargetFilter>` where `TargetFilter = 'unmapped' | 'warnings' | 'required' | 'arrays'`.
  - Filter logic (AND between all active criteria):
    - `unmapped`: show fields where `statusMap.get(path) === 'unmapped'`
    - `warnings`: show fields where `statusMap.get(path) === 'warning' || statusMap.get(path) === 'error'`
    - `required`: show fields marked required in the target schema
    - `arrays`: show fields of type `array`
  - Search query is an additive filter on top of chip filters (must match path/name substring).
  - Active chips render with filled/primary style; inactive with outlined/ghost style.

- **GlobalToolbar update:**
  - Remove the search input from `GlobalToolbar`.
  - Retain: view toggle (Target/Rules), sort control, Focus mode toggle.
  - Update tests accordingly.

- **Filter state ownership:**
  - Filter chip state lives in `TargetWorklist` or is lifted to composition level if needed by other components.
  - Search state is local to each panel.
