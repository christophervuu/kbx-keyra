## Summary

Create a new dedicated Advanced Testing page at `/projects/:projectId/mappings/:mappingId/test` that provides full test case management, trace mode, diff view, and diagnostics — the features previously available in the editor's bottom tabs. The page reuses existing preview/testing components and hooks without duplicating state or localStorage keys.

## Change Requirements

- **Route registration:**
  - Add route in `App.tsx`: `<Route path={PATHS.MAPPING_TEST} element={<MappingAdvancedTesting />} />`
  - The route is nested under the app layout (breadcrumbs can show for this page since it's a distinct page, not the editor).

- **Route page (`MappingAdvancedTesting.tsx`):**
  - Thin wrapper: extract `projectId` and `mappingId` from route params.
  - Render `AdvancedTestingPage` with IDs as props.

- **Feature page (`AdvancedTestingPage.tsx`):**
  - Load mapping config and schemas independently on mount (either full `useMappingEditor` in read-only mode or a lighter `useMappingDetail` hook that only loads without edit state). No shared React Context with the editor page — fully independent lifecycle.
  - Wire `usePreviewExecution` for execution.
  - Wire `useTestCases(mappingId)` for test case CRUD — reads fresh from localStorage on mount. Same keys (`keyra:testcases:{mappingId}`) ensure test cases created on either page are visible on the other after navigation.
  - Layout (two-panel, full page height):
    - **Left panel (~35%):**
      - `SourceDataInput` (full textarea)
      - `TestCaseManager` (below source input or in collapsible section)
    - **Right panel (~65%, tabbed):**
      - Tab bar: Output | Diagnostics | Trace | Diff
      - `OutputDisplay` (Output tab)
      - `DiagnosticsDisplay` (Diagnostics tab)
      - `TraceDisplay` (Trace tab)
      - `DiffDisplay` (Diff tab)
  - Top bar:
    - Mapping name + version (read-only context)
    - "← Back to Editor" link (navigates to Mapping Editor)
    - Trace mode toggle (checkbox/switch)
    - Run button (triggers execution)
    - Auto-run toggle (optional, reuse existing pattern)
  - Empty state: when no test cases exist, show "Create your first test case" CTA in `TestCaseManager`.

- **`PreviewContext` usage:**
  - The Advanced Testing page wraps its content in its own `PreviewProvider` (isolated from the editor's provider since they are separate routes and never co-mounted).
  - No cross-route shared context. Both pages independently access the same localStorage keys via their respective hook instances.
  - This is simpler to maintain, has no stale-reference risk with multiple tabs, and is future-proof for HttpAdapter migration (Phase 1+).

- **`project-structure.md` update:**
  - Add `MappingAdvancedTesting.tsx` to the routes/pages listing.
  - Add `AdvancedTestingPage.tsx` to the mappings feature components listing.

## Notes

- The Advanced Testing page is a new top-level page, not a modal or drawer. It gets its own route and loads independently from localStorage on mount.
- The `useTestCases` hook is keyed by `mappingId` and reads from `keyra:testcases:{mappingId}` — this ensures the same test cases appear whether accessed from the editor strip or the testing page. No coordination needed; localStorage is the single source of truth.
- Server-side preview is noted as a future consideration (Phase 1+); for now, the page runs client-side engine execution only.
- If the user saves a test case on the Advanced Testing page and navigates back to the editor, the editor's preview strip picks it up automatically on next load (both read same localStorage key).
