## Summary

Implement the `parseJsonSchema()` function that takes a JSON Schema string or object and produces a `ParsedSchema` containing a tree of `SchemaTreeNode` objects. The parser must handle properties, items, local `$ref`, required arrays, type, description, enum, and basic oneOf/anyOf (rendered as union type indicators). It must detect circular references and handle invalid input gracefully.

---

## Scope

### In Scope

- `parseJsonSchema(content: string | object): ParsedSchema` implementation
- Recursive traversal of JSON Schema `properties` and `items`
- Local `$ref` resolution (same-document references via `#/definitions/` or `#/$defs/`)
- `required` array handling — setting `isRequired` on child nodes
- Type mapping from JSON Schema types to `SchemaNodeType`
- `enum` detection → type becomes `'enum'`, values stored in `enumValues`
- `oneOf` / `anyOf` → type becomes `'union'`, member types stored in `unionTypes`
- `description` field extraction
- Circular `$ref` detection with max-depth guard (16 levels)
- Parse timing measurement (set `parseTimeMs` on output)
- Graceful error handling → throw `SchemaParseError` for invalid input
- Unit tests covering AE-01 and AE-08 scenarios

### Out of Scope

- Remote `$ref` resolution (URLs, cross-file references)
- `allOf` composition (deferred — complex merge semantics)
- JSON Schema conditional keywords (`if`/`then`/`else`)
- `patternProperties`, `additionalProperties` (beyond basic detection)
- XSD parsing (T-03)
- Inferred schema parsing (T-04)

## Change Requirements

Implement `parseJsonSchema()` with the following behavior:

1. **Input handling**: Accept either a JSON string (parse with `JSON.parse()`) or a pre-parsed object. If string is invalid JSON, throw `SchemaParseError`.

2. **Recursive traversal**:
   - Visit `properties` object — each key becomes a `SchemaTreeNode`
   - Visit `items` for array types — if items has properties, those become children
   - Set `depth` based on nesting level (root properties = depth 0)
   - Build `path` using dot-notation from root
   - Set `parentPath` to the parent node's path (null for root level)
   - Count children and set `childCount`

3. **Type mapping**:
   - `"type": "string"` → `SchemaNodeType = 'string'`
   - `"type": "number"` or `"integer"` → `'number'`
   - `"type": "boolean"` → `'boolean'`
   - `"type": "object"` (or has `properties`) → `'object'`
   - `"type": "array"` (or has `items`) → `'array'`, set `isArray = true`
   - `"enum"` present → `'enum'`, populate `enumValues`
   - `"type": "null"` → `'null'`
   - No type specified → `'any'`
   - `oneOf` / `anyOf` → `'union'`, extract member types into `unionTypes`

4. **Local `$ref` resolution**:
   - Parse `$ref` values starting with `#/`
   - Navigate the definitions path to find the referenced schema
   - Inline the referenced schema at the usage point
   - Track visited refs to detect cycles; if cycle detected, stop recursion and mark node with `"[Circular Reference]"` in description

5. **Required handling**:
   - Read `required` array from parent schema
   - Set `isRequired = true` on child nodes whose `fieldName` is in the parent's `required` array

6. **Performance**: Track start time, compute `parseTimeMs` in the output.

7. **Error cases**: Wrap all errors in `SchemaParseError` with informative messages.

## Notes

- The parser should be a pure function with no side effects and no React dependency. It is testable in isolation.
- For `oneOf`/`anyOf`, Phase 0 shows the union indicator but does not recursively expand all member schemas as separate sub-trees. If a member is an object, its properties are not inlined — that complexity is deferred.
- `additionalProperties: true` does not generate a node — only explicitly declared properties are shown.
