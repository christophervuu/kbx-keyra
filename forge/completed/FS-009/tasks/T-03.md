## Summary

Implement the `parseXsd()` function that takes an XSD (XML Schema Definition) string, parses it using the browser's `DOMParser` API, traverses the schema elements, and produces a `ParsedSchema` containing the same `SchemaTreeNode` shape as the JSON Schema parser. The parser must handle xs:element, xs:complexType, xs:simpleType, xs:sequence, xs:choice, xs:attribute, cardinality (minOccurs/maxOccurs), and annotations.

---

## Scope

### In Scope

- `parseXsd(content: string): ParsedSchema` implementation
- XML parsing using browser `DOMParser`
- Traversal of xs:element, xs:complexType, xs:simpleType, xs:sequence, xs:choice
- xs:attribute handling (rendered as child nodes with type indicator)
- Cardinality extraction: minOccurs/maxOccurs → `isRequired` (minOccurs >= 1), `isArray` (maxOccurs > 1 or "unbounded")
- xs:annotation/xs:documentation → `description` field
- xs:choice → `unionTypes` with member element types
- XSD built-in type mapping to `SchemaNodeType` (xs:string → 'string', xs:integer/xs:decimal → 'number', xs:boolean → 'boolean', etc.)
- Parse timing measurement
- Error handling for invalid XML and non-XSD XML
- Unit tests covering AE-02 and AE-08 scenarios

### Out of Scope

- XSD namespace handling beyond `xs:` prefix (no support for `xsd:` or custom prefixes in Phase 0)
- xs:import / xs:include (cross-file references)
- xs:restriction / xs:extension (complex type inheritance — show base type only)
- xs:group / xs:attributeGroup references
- xs:union (simpleType unions — show as 'union' type indicator without expansion)
- XSD-to-JSON-Schema conversion (explicitly excluded by spec)

## Change Requirements

Implement `parseXsd()` with the following behavior:

1. **Input handling**: Parse the input string using `new DOMParser().parseFromString(content, 'text/xml')`. Check for parser errors (parsererror element). If invalid, throw `SchemaParseError`.

2. **Root element discovery**: Find top-level `xs:element` declarations. Each becomes a root `SchemaTreeNode`.

3. **Complex type traversal**:
   - `xs:complexType` → type is `'object'`, traverse child elements
   - `xs:sequence` → ordered children, traverse each `xs:element` within
   - `xs:choice` → type becomes `'union'`, member element types collected into `unionTypes`
   - `xs:all` → treated same as `xs:sequence` for tree purposes

4. **Simple type mapping**:
   - `xs:string` → `'string'`
   - `xs:integer`, `xs:int`, `xs:long`, `xs:short`, `xs:decimal`, `xs:float`, `xs:double` → `'number'`
   - `xs:boolean` → `'boolean'`
   - `xs:date`, `xs:dateTime`, `xs:time` → `'string'` (with type shown as the XSD type in description)
   - `xs:anyType` → `'any'`
   - `xs:simpleType` with `xs:enumeration` restrictions → `'enum'`, extract `enumValues`

5. **Cardinality handling**:
   - `minOccurs` → stored on node; `isRequired = minOccurs >= 1` (default minOccurs = 1 per XSD spec)
   - `maxOccurs` → stored on node; `isArray = maxOccurs > 1 || maxOccurs === 'unbounded'`
   - Default maxOccurs = 1 per XSD spec

6. **Attributes**: `xs:attribute` elements become child nodes of their parent complex type. Mark with a distinguishing type or description noting they are attributes (not elements).

7. **Annotations**: Extract `xs:annotation/xs:documentation` text content → `description` field.

8. **Path building**: Use dot-notation consistent with JSON Schema parser. Root elements are at depth 0. Nested elements use parent path + "." + element name.

9. **Performance**: Track start time, compute `parseTimeMs`.

10. **Error handling**: Wrap failures in `SchemaParseError` with informative messages including the XML parser error details.

## Blockers / Risks

## Notes

- The `xs:` prefix is hardcoded for Phase 0. If the XSD uses `xsd:` or no prefix, the parser will not recognize elements. This is an acceptable limitation documented in the spec's Out of Scope.
- DOMParser in jsdom (Vitest test environment) supports basic XML parsing. Test with representative XSD samples.
- For inline anonymous complex types (xs:element containing an unnamed xs:complexType), treat the element as an object node and traverse its children normally.
