## Summary

Build the core `<SchemaTreeView />` React component that takes a `ParsedSchema` and renders an interactive tree with expand/collapse, type-specific Lucide icons, required-field indicators, depth indentation with tree line guides, node count badges, hover tooltips for descriptions, and all four component states (loading, empty, error, populated). This task establishes the visual foundation that subsequent tasks enhance with virtualization, search, selection, and keyboard navigation.

---

## Scope

### In Scope

- `<SchemaTreeView />` component accepting `SchemaTreeViewProps`
- Tree node rendering with:
  - Expand/collapse toggle on object/array nodes (click to toggle)
  - Lucide type icons: File (string), Hash (number), ToggleLeft (boolean), Braces (object), List (array), ListOrdered (enum), Circle (null/any), GitMerge or similar (union)
  - Required-field indicator (red asterisk or bold label) on nodes where `isRequired === true`
  - Field description tooltip on hover (using a simple tooltip — Tailwind-based, no library)
  - Depth indentation with visual tree lines/guides (vertical + horizontal connector lines)
  - Node count badge on expandable nodes: e.g., "address (5 fields)"
  - Inferred schema indicator (⚠ icon or banner when `ParsedSchema.inferred === true`)
- Component states:
  - **Loading**: skeleton tree placeholder (animated pulse lines)
  - **Empty**: "No schema loaded" message with icon
  - **Error**: "Failed to parse schema" with error detail and Retry button (calls `onRetry` prop or similar)
  - **Populated**: full interactive tree
- Expand state managed via local `useState` with `Set<string>` of expanded paths
- Auto-expand logic: always expand depth 0 on mount (show top-level children), never auto-expand deeper
- `variant` prop accepted but mapping status rendering deferred to T-08
- `editable` prop accepted but does nothing (placeholder)
- Basic ARIA roles: `role="tree"` on container, `role="treeitem"` on nodes, `aria-expanded` on expandable nodes
- Tailwind CSS 4 styling, no CSS modules
- Component tests with React Testing Library

### Out of Scope

- Virtualization (T-06)
- Search/filter (T-07)
- Selection highlighting and onSelectNode callback (T-08)
- Mapping status indicators (T-08)
- Keyboard navigation beyond basic click (T-09)
- Toolbar with expand-all/collapse-all buttons (T-08)

## Change Requirements

**Component structure:**

`<SchemaTreeView>` — outer container. Renders loading/empty/error states or the tree. Sets `role="tree"`.

`<SchemaTreeNodeRow>` (or similar) — renders a single tree node row including:
- Indentation spacing (depth * indent-width in pixels, e.g., 20px per level)
- Tree line guides (vertical lines connecting siblings, horizontal line to node)
- Expand/collapse chevron (for nodes with `childCount > 0`)
- Type icon (per `SchemaNodeType`)
- Field name text
- Required indicator (if `isRequired`)
- Child count badge (if expandable, e.g., "(3 fields)")
- Tooltip trigger area (shows `description` on hover if present)
- `role="treeitem"`, `aria-expanded` (if expandable), `aria-level={depth + 1}`

**State management:**
- `expandedPaths: Set<string>` — tracks which nodes are expanded
- Toggle function: add/remove path from set
- Initial expansion: on mount, expand all depth-0 nodes (their paths are added to the expanded set). No deeper auto-expansion.

**Icon mapping:**
- Create a mapping from `SchemaNodeType` to Lucide icon component
- Use consistent icon sizing (16px or similar)

**Tree line rendering:**
- Use CSS (Tailwind utilities + custom classes if needed) to draw:
  - Vertical lines along left edge for sibling continuity
  - Horizontal connector line from vertical line to node icon
  - Last child in a group gets an "elbow" connector instead of through-line

**Component states:**
- Accept an optional `state` prop or manage internally based on `schema` being null/undefined
- Loading: render when `schema` is undefined and a `loading` prop is true
- Empty: render when `schema.nodes.length === 0`
- Error: render when an `error` prop is provided (string or `SchemaParseError`)
- Populated: render tree when `schema.nodes.length > 0`

**Tooltip:**
- Simple hover tooltip using Tailwind (`group`/`group-hover` pattern or a lightweight custom component)
- Shows node description text
- Positioned above or to the right of the node
- Only renders if `description` exists

## Notes

- This task intentionally omits virtualization, search, selection, and keyboard nav to keep the core rendering focused and testable. Those are layered on in subsequent tasks.
- The component should be structured to accept virtualization wrapping in T-06 — avoid patterns that assume all nodes are always in the DOM.
- Auto-expand on mount: always expand depth 0 nodes. The "Expand to depth N" toolbar (T-08) handles deliberate deeper expansion.
- Icon choices are suggestions. The implementer may choose different Lucide icons if they provide better visual clarity, as long as each type has a distinct icon.
- Domain types (`SchemaTreeNode`, `ParsedSchema`) are imported from `ui/src/lib/types/domain.ts` per the Q5 decision in the spec.
