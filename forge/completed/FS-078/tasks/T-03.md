## Summary

Update Project Overview schema cards/management interactions to apply canonical CDM allowed/disallowed actions and consistent re-sync behavior/feedback.

---

## Scope

### In Scope

- Ensure CDM schemas in Project Overview only expose View, Re-sync, and Unlink (project link).
- Apply mixed disallowed-action strategy: hide disallowed actions in dense card/table contexts; use disabled+tooltip only where discoverability is needed.
- Align re-sync pending/success/failure feedback copy with FS-078 contract.

### Out of Scope

- Schema Detail-specific behavior.
- Broad non-CDM action redesign.

- `ui/src/features/projects/components/SchemaCard.tsx`

## Change Requirements

- CDM action gating must use shared policy logic rather than ad-hoc per-button checks.
- Unlink behavior remains project-link scoped and must stay available for CDM.
- Re-sync action must be labeled consistently with other surfaces.

---

## Verification Requirements

- Component tests for CDM and non-CDM action sets.
- Interaction tests for re-sync states (loading/success/error) where available.
- Typecheck/lint for touched files.

## Acceptance Checks

- Project Overview CDM cards show only allowed actions.
- Disallowed CDM actions are not executable and include clear rationale when visible.
- Re-sync action feedback is consistent with FS-078 wording and status behavior.
- Tests, typecheck, and lint pass.
