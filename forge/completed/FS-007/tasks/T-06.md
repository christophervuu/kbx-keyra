## Summary

Rewrite the existing stub tests in `tests/engine/execute.test.ts` and add comprehensive unit tests for the core execute pipeline. Cover basic execution, dot-notation target paths, error handling and isolation, constants, external sources, AST caching, and input immutability.

---

## Scope

### In Scope

- Rewrite `tests/engine/execute.test.ts` to test real execute behavior
- Add tests covering:
  - AE-01: Single rule → correct output at target path
  - AE-02: Multiple rules → correct nested output object via dot-notation
  - AE-03: Rule ordering (last write wins for same target path)
  - AE-04: Parse error → diagnostic emitted, target null/absent, other rules unaffected
  - AE-05: Runtime error (e.g., divide by zero) → diagnostic, target null, pipeline continues
  - AE-11: External source resolves correctly
  - AE-12: Missing external → E012 warning
  - AE-13: Constants resolve from config
  - AE-14: AST caching — two rules with same expression → both get correct values
  - AE-15: Input immutability — sourceData and config not mutated
  - Empty rules array → empty output with stats
  - Rule with evaluation warning (not error) → value is kept, warning is in diagnostics

### Out of Scope

- Bulk behavior tests (T-07)
- Trace and stats tests (T-07)
- Integration with array functions (T-07)
- Performance benchmark (T-07)

## Notes

The existing stub tests in `tests/engine/execute.test.ts` expect `{ output: {}, diagnostics: [] }` which will no longer be correct after T-03. These tests must be rewritten — they cannot simply be extended.

For AE-14 (AST caching), the test can verify that two rules with the same expression both produce correct values. Direct verification of cache internals is not required — the behavioral outcome (correct values for both rules) is sufficient. However, if a more direct test is desired, a separate test in `tests/engine/execute/ast-cache.test.ts` (from T-02) already covers cache mechanics.

For AE-15 (immutability), use `structuredClone()` to snapshot the inputs before calling execute(), then compare after execution with `expect(sourceData).toEqual(snapshot)`.
