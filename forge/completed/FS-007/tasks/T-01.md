## Summary

Extend the existing engine type definitions to support the full execute pipeline. Add `externalSources` and `validateBeforeExecute` fields to `EngineOptions`, add an `ExecutionStats` interface and optional `stats` field to `ExecutionResult`, and add an optional `durationMs` field to `TraceEntry`. Export all new types from the barrel.

---

## Scope

### In Scope

- Add `externalSources?: Readonly<Record<string, unknown>>` to `EngineOptions` in `src/engine/types/options.ts`
- Add `validateBeforeExecute?: boolean` to `EngineOptions` in `src/engine/types/options.ts`
- Add `ExecutionStats` interface to `src/engine/types/results.ts`:
  ```ts
  interface ExecutionStats {
    readonly rulesEvaluated: number;
    readonly rulesSucceeded: number;
    readonly rulesFailed: number;
    readonly durationMs: number;
  }
  ```
- Add `stats?: ExecutionStats` to `ExecutionResult`
- Add `durationMs?: number` to `TraceEntry`
- Export `ExecutionStats` from `src/engine/types/index.ts` barrel
- Verify `ExecutionStats` is re-exported from `src/engine/index.ts`

### Out of Scope

- Any implementation changes to execute.ts
- Any changes to validate.ts or the validate pipeline
- Any changes to the DSL parser or evaluator

## Change Requirements

After this task:

- `EngineOptions` has two new optional fields: `externalSources` (for passing runtime external data values to the execute pipeline) and `validateBeforeExecute` (for enabling optional pre-flight validation).
- `ExecutionResult` has a new optional `stats` field of type `ExecutionStats`.
- `TraceEntry` has a new optional `durationMs` field for per-rule timing.
- `ExecutionStats` is a new exported interface available from the engine's public API.
- All existing type consumers continue to compile — all new fields are optional and additive.
