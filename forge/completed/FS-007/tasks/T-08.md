## Change Requirements

The updated mapping-engine.md must:

1. **Replace "Execution Pipeline (Target Architecture)" section** with a definitive "Execute Pipeline" section that reflects the actual implementation.

2. **Document execution phases** with a clear sequence diagram:
   ```
   Phase 1: Pre-flight validation (optional) → abort if errors
   Phase 2: Parse all rule expressions (with AST caching)
   Phase 3: Build EvaluationContext
   Phase 4: Iterate rules and evaluate (sequential, error-isolated)
   Phase 5: Target path assembly (dot-notation → nested objects)
   Phase 6: Bulk behaviors (unmappedTargets → nullSubtrees)
   Phase 7: Assemble ExecutionResult (output + diagnostics + trace? + stats)
   ```

3. **Document internal utilities** — setAtPath and AstCache as implementation components.

4. **Document the EvaluationContext construction** — how execute builds the context from its inputs and wires it to the evaluate/pushScope/popScope/addDiagnostic callbacks.

5. **Document error handling philosophy for execute** — one failing rule does not crash the pipeline, error-severity diagnostics cause the rule value to be null, pipeline always completes.

6. **Document performance characteristics** — 500-rule target, AST caching amortization, synchronous single-pass design.

7. **Update module structure** to include `execute/` directory with `set-at-path.ts`, `ast-cache.ts`, `index.ts` if those were created.

8. **Update internal module boundaries table** to include the `execute/` module.
