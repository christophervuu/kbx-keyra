## Summary

Add comprehensive test coverage for bulk behaviors, trace recording, stats computation, validateBeforeExecute, array function integration, and performance benchmarks. These tests cover the full execute pipeline end-to-end after all implementation tasks (T-03, T-04, T-05) are complete.

---

## Scope

### In Scope

- Create `tests/engine/execute/integration.test.ts` with end-to-end tests:
  - AE-06: unmappedTargets "null" sets unmapped required fields to null
  - AE-07: unmappedTargets "omit" leaves unmapped fields absent
  - AE-08: unmappedTargets "error" emits W005 for unmapped required fields
  - AE-09: nullSubtrees overrides rule values
  - nullSubtrees + unmappedTargets interaction (nullSubtrees applied after unmapped targets)
  - nullSubtrees for non-existent path is silently ignored

  - Trace with failed rules includes the failed rule's entry
  - AE-16: stats computation matches expected values
  - AE-17: validateBeforeExecute aborts on validation errors
  - validateBeforeExecute with valid config proceeds normally
  - AE-18: map() expression produces array at target path
  - filter() + map() composition produces correct subset
  - Nested map() produces nested arrays in output
  - AE-19: Performance benchmark (500 rules, < 2 seconds)
- Tests must use the public `execute` import from `src/engine/index.ts`
- Performance test may use a longer Vitest timeout
- Create valid JSON schemas for tests that use unmappedTargets "null" or "error"

## Change Requirements

**Bulk behavior tests** must construct real JSON schemas using the same structure that `getOrBuildSchemaTree()` / `buildSchemaTree()` expects (standard JSON Schema format with `type`, `properties`, `required`).

**Trace tests** must verify:
- result.trace is undefined when trace is false
- result.trace has one entry per rule when trace is true
- Each TraceEntry has ruleIndex, targetPath, expression, outputValue
- Failed rules appear in the trace with null outputValue and diagnostics

**Stats tests** must verify:
- rulesEvaluated matches total rules
- rulesSucceeded + rulesFailed = rulesEvaluated
- durationMs is a positive number (non-negative for zero-rule case)

**validateBeforeExecute tests** must:
- Use a source schema and a rule with `source("nonexistent")` to trigger E030
- Verify output is null when validation fails
- Verify stats show 0 rules evaluated

**Array function integration tests** must:
- Use `map(source("items"), item("name"))` with array source data
- Verify the output target path contains an array
- Test filter/map composition
- Test nested map for nested array output

**Performance benchmark**:
- Generate 500 rules, each `source("field_N")` targeting `"target_N"`
- Generate source data with 1000 fields (`field_0` through `field_999`)
- Assert execution completes within 2000ms
- Use `{ timeout: 10000 }` for the test to allow measurement overhead

## Notes

This is the most comprehensive test task. It validates the entire execute pipeline working together end-to-end.

For the performance benchmark, keep the expressions simple (`source("field_N")`) to isolate execute pipeline overhead from DSL evaluation complexity. The goal is to verify that the iteration, parsing, evaluation, and output assembly loop scales to 500 rules within the time budget.

For array function integration tests, reference FS-005's test patterns in `tests/engine/functions/` for valid map/filter expressions and expected behaviors.

For JSON schema fixtures, a minimal valid target schema:
```json
{
  "type": "object",
  "properties": {
    "Order": {
      "type": "object",
      "properties": {
        "Type": { "type": "string" },
        "Status": { "type": "string" }
      },
      "required": ["Type", "Status"]
    }
  },
  "required": ["Order"]
}
```
