## Summary

Implement two independently testable utility modules for the execute pipeline: (1) a `setAtPath` function that sets a value at a dot-notation target path in an output object, auto-creating intermediate nested objects; and (2) an `AstCache` class that caches parsed ASTs by expression string for reuse across rules and across multiple executions of the same config.

---

## Scope

### In Scope

- Create `src/engine/execute/` directory
- Create `src/engine/execute/set-at-path.ts` with a `setAtPath(obj, path, value)` function:
  - Supports dot-notation paths (e.g., `"Order.Header.DocType"`)
  - Auto-creates intermediate objects when they don't exist
  - Overwrites existing values (last write wins)
  - Handles root-level paths (no dots, e.g., `"Status"`)
  - Handles array values being placed at a path
- Create `src/engine/execute/ast-cache.ts` with an `AstCache` class:
  - `get(expression: string): AstNode | null | undefined` — returns cached AST or undefined if not cached
  - `set(expression: string, ast: AstNode | null): void` — caches an AST (including null for parse failures)
  - `has(expression: string): boolean` — checks if expression is cached
  - `clear(): void` — clears the cache
  - Uses a plain `Map<string, AstNode | null>` internally
- Create `src/engine/execute/index.ts` barrel exporting both utilities
- Add unit tests for both utilities in `tests/engine/execute/`
- Update `forge/architecture/project-structure.md` if new files/folders are created

### Out of Scope

- The main execute() orchestrator (T-03)
- Bulk behavior application
- Integration with parse() or evaluate()

## Change Requirements

**setAtPath(obj, path, value)**:
- `obj` is a mutable record (the output object being assembled)
- `path` is a dot-notation string (e.g., `"Order.Header.Type"`)
- `value` is the value to set at that path
- Each dot-separated segment creates a nested object if it doesn't exist
- If an intermediate segment exists but is not an object (e.g., it was set to a scalar by a previous rule), it is overwritten with a new empty object to accommodate the deeper path
- Empty path string sets the value as the root (edge case — may not occur in practice, but handle gracefully)
- Returns void — mutates the obj parameter in place

**AstCache**:
- Backed by a `Map<string, AstNode | null>`
- The cache stores null for parse failures so the same broken expression is not re-parsed
- The same expression string always returns the same cached AST object reference (important for AE-14 verification)
- The cache is designed to be reusable across multiple execute() calls with the same config but different source data

## Verification Requirements

- Unit tests for setAtPath:
  - Single-segment path: `setAtPath(obj, "A", 1)` → `{ A: 1 }`
  - Multi-segment path: `setAtPath(obj, "A.B.C", 1)` → `{ A: { B: { C: 1 } } }`
  - Multiple calls build nested structure: set `"A.B"` then `"A.C"` → `{ A: { B: ..., C: ... } }`
  - Overwrite existing value (last write wins): set `"A"` twice → last value wins
  - Overwrite scalar with nested: set `"A"` to 1, then set `"A.B"` to 2 → `{ A: { B: 2 } }`
  - Array value at path: `setAtPath(obj, "Items", [1, 2])` → `{ Items: [1, 2] }`
  - Null value at path: `setAtPath(obj, "A", null)` → `{ A: null }`
- Unit tests for AstCache:
  - get() returns undefined for uncached expression
  - set() then get() returns the cached AST node
  - has() returns true for cached, false for uncached
  - Same expression returns same object reference
  - null ASTs are cached (parse failure caching)
  - clear() empties the cache
- TypeScript strict typecheck passes
- Lint passes

## Notes

The setAtPath function mutates the output object in place for performance. This is safe because the output object is freshly created by the execute pipeline — it never mutates the caller's input objects.

The AstCache is intentionally simple (a Map). No LRU eviction or size limits are needed for the current use case — mapping configs have at most hundreds of rules, and the cache is scoped to a single config's execution lifecycle.
