## Summary

Write integration tests proving that schema metadata persisted in DynamoDB and schema content stored in S3 are fully recoverable in a fresh session. Tests verify all metadata fields round-trip correctly and that the S3 content body (JSON Schema or XSD) is byte-for-byte consistent after retrieval.

---

## Scope

### In Scope

- Integration tests for schema metadata cross-session persistence
- Integration tests for schema S3 content round-trip (JSON Schema body)
- Verification of all `SchemaMetadata` fields from persistence-model.md
- Verification that `source` map field (with nested structure) persists correctly
- Content consistency assertion (byte-level after JSON normalization)

### Out of Scope

- Schema node batch write/read (SchemaNodes table — tested if time permits but not primary)
- Schema ingestion pipeline (FS-056)
- XSD content parsing
- OpenSearch indexing

## Change Requirements

- Create `tests/lambda/integration/persistence/schema-persistence.test.ts`
- Test cases:
  1. **Create metadata in A, Get in B**: Create schema metadata with all fields populated (including `source` map, `inferred` boolean, `syncStatus`). Fresh session retrieves by ID. Assert deep equality on all fields.
  2. **Store content in A, Get in B**: Write a JSON Schema body (realistic, ~2KB with properties/definitions) to S3 via schema content helper. Fresh session retrieves content. Assert JSON parse equality.
  3. **Combined metadata + content in A, Get in B**: Create metadata AND store content. Fresh session retrieves both. Assert metadata fields correct AND content body matches.
  4. **List schemas in B**: Create 3 schemas. Fresh session lists all. Assert all 3 present with correct metadata summaries.
  5. **Delete in A, Get in B**: Create schema, delete it (metadata + content). Fresh session get returns not-found. S3 content also gone.
  6. **Source map with optional fields**: Create schema with `source: { type: 'github', repo: 'org/repo', branch: 'main', path: '/schemas/order.json', commitSha: 'abc123' }`. Fresh session retrieves. Assert all nested fields present including optional `commitSha`.
  7. **Boolean and enum fields persist**: `inferred: true`, `format: 'xsd'`, `scope: 'project'`, `status: 'ready'`. Fresh session retrieves. Assert type-correct values (not stringified booleans).
- Fixture schema content should be a realistic JSON Schema with `$schema`, `type`, `properties`, `required`, `definitions`

---

## Verification Requirements

- All metadata fields from `SchemaMetadata` table definition are tested
- S3 content matches original after `JSON.parse()` (structural equality for JSON)
- Boolean fields return as booleans (not strings)
- Enum-like fields (`format`, `status`, `scope`, `origin`, `syncStatus`) return exact stored values
- `source` map with nested fields round-trips completely
- `createdAt`/`updatedAt` are valid ISO 8601
- Empty/optional fields handled correctly (not converted to `null` when absent)

## Notes

- DynamoDB stores Maps with present keys only — `undefined` values are stripped. The test should verify that optional fields that were never set are absent (not `null` or empty string) on retrieval.
- The `source` field has two variants: `{ type: 'upload' }` (minimal) and `{ type: 'github', repo, branch, path, commitSha? }` (full). Test both variants.
- Use `JSON.stringify(a) === JSON.stringify(b)` for content comparison only after sorting keys, or use a deep-equal utility that handles key ordering differences.
