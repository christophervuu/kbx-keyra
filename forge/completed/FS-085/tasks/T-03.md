## Summary

Update mappings table and row rendering so Project Overview clearly supports open/create/deploy navigation workflows: operational columns, compact deployment state in-row, and simplified row actions that avoid inline execution.

---

## Scope

### In Scope

- Update mapping table columns to include single Deployment column and maintain core operational columns.
- Add mappings search behavior for name and/or source/target schema matching in Project Overview.
- Replace environment-split deployment badges in overview rows with compact deployment-state label/value.
- Normalize stale display wording to user-facing `Changed since deploy` or `Out of date`.
- Implement status-based row actions:
  - Draft: Open primary, hide Deploy
  - Ready: Open + Deploy
  - Has Errors: Fix primary, hide Deploy
  - Keep less-common actions in overflow
- Avoid disabled Deploy buttons for this iteration.
- Ensure Deploy action performs navigation to deployment page only.
- Keep table usability for narrower widths (horizontal scroll/responsive behavior).

### Out of Scope

- Deployment activity feed backend work.
- Inline deployment execution.
- Mapping Editor redesign.
- New status-filter complexity unless existing primitives are trivially reusable.

## Change Requirements

- Table and row design must prioritize rapid mapping triage/action.
- Deployment column semantics must be understandable without environment matrix complexity.
- Existing internal deploy status values must map to clearer user-facing copy.
- Row actions must reflect status-based next action semantics (Open/Fix/Deploy) and avoid disabled Deploy affordances.
- No row action may trigger deployment execution inline.
- Search must be wired now; status filter remains deferred unless existing filter primitives can be reused with minimal complexity.
