## Summary

Create a complete inventory of all existing AI implementation surfaces and dependencies across UI, adapter/client, backend handlers, shared runtime, prompt logic, and schema-query integration points. This establishes the audit baseline required for drift and migration decisions.

---

## Scope

### In Scope

- Enumerate all AI-related UI surfaces and hooks currently exposed.
- Enumerate all adapter and API client pathways used for AI calls.
- Enumerate AI Lambda handlers, shared runtime modules, and prompt-related assets.
- Enumerate schema-query dependencies used by AI flows.
- Produce a durable inventory artifact under the FS-065 workspace.

### Out of Scope

- Drift classification or architecture decisions.
- Implementation changes to production code.

---

## Change Requirements

- Inventory must be exhaustive for currently reachable AI paths.
- Inventory entries must include code location, runtime path summary, and dependency notes.
- Inventory format must support downstream drift and keep/replace/retire analysis.

---

## Verification Requirements

- Verify every AI method in `ApiAdapter` has an inventory entry and current-path note.
- Verify all AI Lambda handlers and shared runtime modules are represented.
- Peer review inventory completeness against grep/file discovery.

---

## Acceptance Checks

- [ ] AI inventory artifact exists in `forge/active/FS-065/` and covers UI, adapter/client, lambda/runtime, and schema-query dependencies.
- [ ] Inventory explicitly maps each AI `ApiAdapter` method to current implementation status/path.
- [ ] Inventory completeness is validated against repository search results.
