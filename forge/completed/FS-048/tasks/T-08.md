## Summary

Wire the refresh/regenerate controls in the workspace toolbar to the hook's refresh methods, add inline confirmation for Refresh All, and ensure the merge logic correctly preserves accepted/edited suggestions while replacing suggested/dismissed/stale items with new backend results.

---

## Scope

### In Scope

- Wire "Refresh All", "Refresh Unmapped", and "Refresh Stale" toolbar buttons to hook methods
- Add inline confirmation for "Refresh All":
  - Confirmation text: "This will regenerate N suggestions. M accepted and edited suggestions will be preserved."
  - Confirm/Cancel buttons inline (not a modal dialog)
  - Auto-dismiss after 5 seconds if no action taken
- Implement the merge strategy in the hook's refresh handlers:
  - After backend returns new suggestions:
    - For each `accepted` item: keep the existing item (ignore any new suggestion for that target)
    - For each `edited` item: keep the existing item
    - For each `dismissed` item: keep the existing item in `dismissed` state **unless** the refresh action explicitly targets dismissed items (e.g., Refresh All replaces dismissed; Refresh Unmapped does not touch dismissed items that are for already-mapped targets)
    - For each `suggested`/`stale` item: replace with new backend result if available
    - For targets in the new response that have no existing item: add as new `suggested` items
    - For existing items with no corresponding new suggestion: retain as-is (do not remove — the backend may return fewer results on retry)
  - Update persistence after merge
  - Update summary counts

- Loading state during refresh:
  - Toolbar shows a spinner on the active refresh button
  - Existing cards remain visible during refresh (not replaced with loading state)
  - Cards that will be refreshed show a subtle loading indicator

- Error handling during refresh:
  - On error: show error inline in the toolbar area
  - Preserve previous suggestions (do not clear)
  - "Try Again" button re-attempts the same refresh scope

### Out of Scope

- Per-suggestion refresh (deferred — would require backend support for single-target generation)
- Backend changes to support filtered requests
- Toolbar component structure (T-07)

## Change Requirements

- Refresh All:
  - Triggers `adapter.autoMapSection()` for the full section
  - Shows inline confirmation before triggering
  - Merges results: preserve terminal states, replace non-terminal states
  - Updates `generatedAt` timestamp for refreshed items

- Refresh Unmapped:
  - Triggers `adapter.autoMapSection()` for the full section
  - Filters results client-side to only replace items where `isNew === true` and status is `suggested` or `stale`
  - Does not show confirmation (scoped action)

- Refresh Stale:
  - Triggers `adapter.autoMapSection()` for the full section
  - Filters results client-side to only replace items where `status === 'stale'`
  - Does not show confirmation (scoped action)

- All refresh operations:
  - Set `isRefreshing` flag to disable other refresh buttons
  - Support abort-on-reinvoke (starting a new refresh cancels the in-flight one)
  - Update sessionStorage persistence after merge
  - Recalculate summary counts

- Inline confirmation component:
  - Renders in the toolbar area (not a modal)
  - Shows count of items to be refreshed and items preserved
  - Confirm button styled as primary, Cancel as secondary
  - Auto-dismisses after 5 seconds if no action
