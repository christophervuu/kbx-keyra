## Summary

Add a "Jump to rule" button/link that appears when a diagnostic or trace entry is selected in the AdvancedTestingPage. Clicking it navigates in the same browser tab to the Mapping Editor with route state that pre-selects the responsible rule's target field. Navigation preserves normal browser back-button behavior so users can return to Test Lab easily. Update the Mapping Editor route page to read this state on mount and set `selectedTargetPath` accordingly.

---

## Scope

### In Scope

- Add a "Jump to rule" button in the AdvancedTestingPage that appears when `debugSelection` has a non-null `targetPath`
- Button uses React Router `navigate()` in the same tab with state: `{ selectedTargetPath: selection.targetPath }`
- Navigation preserves normal browser back-button behavior so users can return to Test Lab easily
- Update the Mapping Editor route page (`ui/src/routes/pages/MappingEditor.tsx`) to read `location.state?.selectedTargetPath` on mount and set `selectedTargetPath` if present
- Clear the route state after consuming it (to prevent stale state on page refresh)
- Unit tests for the navigation trigger and state consumption

### Out of Scope

- Jump-to-rule from InlinePreviewStrip (it already has `onNavigateToRule` which does this inline)
- Modifying the Mapping Editor's builder panel behavior (existing hydration on target selection handles the rest)

## Change Requirements

**AdvancedTestingPage:**

Add a "Jump to rule" action in the results area (e.g., above the tab bar, or as a floating action when selection is active):

```tsx
{debugSelection.selection?.targetPath && (
  <button
    onClick={() => navigate(
      `/projects/${projectId}/mappings/${mappingId}`,
      { state: { selectedTargetPath: debugSelection.selection!.targetPath } }
    )}
    className="..."
  >
    <ArrowLeft size={14} /> Jump to rule
  </button>
)}
```

The button should be visually anchored near the tab bar or selection indicator so it's discoverable but not intrusive.

**MappingEditor route page:**

On mount, check for `location.state?.selectedTargetPath`:

```typescript
const location = useLocation();

useEffect(() => {
  const incomingPath = location.state?.selectedTargetPath;
  if (incomingPath && typeof incomingPath === 'string') {
    setSelectedTargetPath(incomingPath);
    // Clear the state to prevent stale re-application on refresh
    navigate(location.pathname, { replace: true, state: {} });
  }
}, []);
```

This should integrate with the existing target selection state. The builder panel will automatically hydrate the selected rule's expression via the existing FS-025 T-01 mechanism.

## Notes

The `navigate()` call uses `{ state: { selectedTargetPath } }` which is the React Router v6 pattern for passing transient state between routes. This state does not appear in the URL and is lost on page refresh (which is the desired behavior — the user should land on the editor with fresh state on refresh, not a stale selection). The standard `navigate()` call (without `{ replace: true }`) pushes a new history entry, preserving back-button behavior to return to Test Lab.
