## Summary

Transform DiagnosticsDisplay from a read-only list into an interactive component that supports clicking diagnostic entries to fire linked selection, receiving highlight state from external selection, and filtering by severity and target path search. Also integrate the failure explainer helper (T-08) rendering slot for plain-language explanations below diagnostic messages.

---

## Scope

### In Scope

- Add `onSelect` callback prop to DiagnosticsDisplay for firing `DebugSelection` on click
- Add `selectedRuleIndex` and `selectedTargetPath` props for receiving external highlight state
- Add visual highlight styling on diagnostic rows that match the current linked selection
- Add severity filter chips (Error | Warning | Info) with toggle behavior and AND semantics
- Add search input for filtering by `targetPath` or `message` substring (case-insensitive, debounced 200ms)
- Add count display showing `{N} of {M} diagnostics` when filters/search are active
- Add `explanation` rendering slot below each diagnostic message for plain-language helper (renders `FailureExplanation` if provided)
- Update existing tests and add new tests for all interactive behaviors

### Out of Scope

- Implementing the `explainDiagnostic` function itself (T-08)
- Wiring to page-level orchestration (T-06)
- Changing the `Diagnostic` type from the engine

## Change Requirements

Extend `DiagnosticsDisplayProps`:

```typescript
interface DiagnosticsDisplayProps {
  state: PreviewExecutionState;
  // New props:
  onSelect?: (selection: DebugSelection) => void;
  selectedTargetPath?: string | null;
  selectedRuleIndex?: number | null;
  explainDiagnostic?: (diagnostic: Diagnostic, traceEntry?: TraceEntry) => FailureExplanation | null;
  traceEntries?: readonly TraceEntry[];
}
```

Each diagnostic `<li>` becomes a clickable `<button>` (or adds `role="button"` + `onClick`):
- On click: call `onSelect({ targetPath, ruleIndex, source: 'diagnostics' })`
- Apply highlight class when `selectedTargetPath === diagnostic.targetPath` or `selectedRuleIndex === diagnostic.ruleIndex`

Filter UI:
- Three toggle chips in a toolbar row above the list: Error, Warning, Info
- All severities are shown by default with no active filter on initial load
- Chip styling: active = filled color matching severity; inactive = outline/muted
- Error and warning rows are visually emphasized (bolder styling or stronger text color) relative to info rows, regardless of filter state
- Search input with debounce(200ms), placeholder "Filter by path or message…"
- Filter logic: severity chips AND search are combined (both must match)
- Count: `{filtered} of {total} diagnostics` shown when filtered count differs from total

Explanation rendering:
- After each diagnostic message, if `explainDiagnostic` is provided and returns non-null, render a helper block with the `summary` and optional `suggestion`
- Style: smaller text, info icon prefix, muted color (e.g., `text-blue-400` or `text-slate-400`)
