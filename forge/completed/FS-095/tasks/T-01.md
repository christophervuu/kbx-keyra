## Summary

Create shared types and state contracts for parameter-aware guided actions so parameterized actions can be authored through one deterministic lifecycle. This task establishes the model used by catalog entries, UI editors, and apply handlers.

---

## Scope

### In Scope

- Add parameter schema types for guided actions (required/optional, defaults, constraints, display metadata).
- Add action parameter draft state shape and validation result model.
- Add helpers to normalize and serialize parameter values for apply pipeline use.
- Add unit tests for schema normalization and parameter validation behavior.

### Out of Scope

- Smart Builder UI editor rendering.
- MappingEditor apply pipeline refactor.
- Picker visibility behavior changes.

---

## Relevant Areas

- `ui/src/features/mappings/lib/smart-builder-action-catalog.ts`
- `ui/src/features/mappings/lib/smart-builder-state.ts`
- `ui/src/features/mappings/lib/smart-builder-action-resolver.ts`
- `ui/src/features/mappings/lib/*smart-builder*.test.ts`

---

## Change Requirements

- Parameter schema model must support deterministic rendering and validation.
- Defaults for guided actions must be explicit in schema and not inferred implicitly at apply time.
- Validation model must provide deterministic machine/user-facing errors for missing/invalid values.
- Parameter payload output must be normalized for consumption by apply handlers.

---

## Verification Requirements

- Unit tests cover required/optional/default semantics and constraint validation.
- Unit tests cover normalization/serialization output for apply payloads.
- Lint/typecheck pass for touched files.

---

## Acceptance Checks

- Parameter schema contracts exist and are referenced by guided action definitions.
- Invalid parameter drafts are detected with deterministic error results.
- Valid parameter drafts serialize into normalized apply payloads.
- Tests pass for touched smart-builder state/catalog modules.

---

## Blockers / Risks

- Risk of overfitting schema to current actions; keep schema generic enough for full DSL action coverage.

---

## Notes

- Keep contracts small and composable so UI and apply layers can adopt incrementally.
