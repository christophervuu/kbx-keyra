## Summary

Add reusable Smart Builder parameter editor surfaces so parameterized actions can be configured, validated, and re-edited inline within recipe-first flow. This task delivers the user-facing controls and wiring for create/edit/apply behavior.

---

## Scope

### In Scope

- Render parameter editor UI in Smart Builder for selected parameterized actions.
- Show explicit values/defaults for required and optional parameters.
- Wire apply/cancel/reset behavior for pending action drafts.
- Support re-opening an existing parameterized step and hydrating editable values.
- Add component tests for parameter form rendering and edit lifecycle.

### Out of Scope

- Non-UI changes to action resolver ranking.
- Mapping Editor layout redesign.
- New DSL functions.

---

- `ui/src/features/mappings/components/ScalarFieldBuilder.test.tsx`

---

## Change Requirements

- Parameter editors must be deterministic, accessible, and visibly tied to selected recipe action context.
- Editor must block apply on invalid inputs and surface deterministic guidance.
- Re-edit path must update existing step intent rather than duplicating a new step implicitly.
- One-click actions without parameters must remain frictionless.

---

## Verification Requirements

- Component tests for parameter editor open/render/apply flows.
- Component tests for re-open and edit of applied parameterized step.
- Regressions ensuring one-click actions still apply immediately.
- Lint/typecheck pass for touched components.

---

## Acceptance Checks

- Selecting parameterized action opens explicit editor controls.
- Valid editor submission updates recipe and draft DSL immediately.
- Re-editing parameterized step hydrates prior values and updates deterministically.
- Non-parameterized actions preserve one-click behavior.

---

## Blockers / Risks

- UI complexity can grow quickly; keep editor componentization modular to avoid panel bloat.

---

## Notes

- Preserve existing recipe-first hierarchy and avoid reintroducing always-visible action catalogs.
