## Summary

Implement the `formatDate(value, inputFormat, outputFormat)` function that parses a date string using an input format pattern and reformats it using an output format pattern. All token parsing is manual (no external date libraries). Supports tokens YYYY, MM, DD, HH, mm, ss, and the special ISO8601 format. Emits E040 on parse failure.

---

## Scope

### In Scope

- Implement `formatDate(value: string, inputFormat: string, outputFormat: string): string`
- Parse input date string according to inputFormat tokens
- Format parsed date components according to outputFormat tokens
- Support all tokens: YYYY, MM, DD, HH, mm, ss
- Support special `ISO8601` as inputFormat and/or outputFormat
- Emit E040 when value cannot be parsed with inputFormat
- FunctionSignature
- Registration export
- Comprehensive unit tests for every token and combination

### Out of Scope

- Timezone conversion (parse and output in same timezone context)
- Date validation beyond format matching (e.g., checking if Feb 30 is valid)
- External date libraries (moment, date-fns, luxon, etc.)

## Change Requirements

**Signature:**
- Parameters: value (string, required), inputFormat (string, required), outputFormat (string, required)
- `handlesNull: false` (standard null propagation applies)
- returnType: string

**Token Table:**

| Token | Meaning | Format |
|-------|---------|--------|
| YYYY | Four-digit year | Always 4 digits |
| MM | Two-digit month | 01-12 |
| DD | Two-digit day | 01-31 |
| HH | Two-digit hour (24h) | 00-23 |
| mm | Two-digit minute | 00-59 |
| ss | Two-digit second | 00-59 |
| ISO8601 | Full ISO 8601 | `YYYY-MM-DDTHH:mm:ssZ` |

**Implementation approach:**

1. **Parsing phase:**
   - If inputFormat is `"ISO8601"`:
     - Parse standard ISO 8601 string (with or without timezone, with or without time)
     - Extract year, month, day, hour, minute, second
     - Handle variants: `2026-03-31T14:22:19Z`, `2026-03-31T14:22:19+05:00`, `2026-03-31T14:22:19`
   - Otherwise:
     - Walk through inputFormat identifying tokens (YYYY, MM, DD, HH, mm, ss)
     - Non-token characters are literal separators (must match exactly in input)
     - Extract numeric values at token positions from the input string
     - If extraction fails or values are non-numeric → E040

2. **Formatting phase:**
   - If outputFormat is `"ISO8601"`:
     - Produce `YYYY-MM-DDTHH:mm:ssZ` from extracted components (default missing time components to 00)
   - Otherwise:
     - Walk through outputFormat replacing tokens with extracted values
     - Pad numeric values to required width (YYYY=4, others=2)
     - Non-token characters pass through as literal separators

3. **Error handling:**
   - Input doesn't match format → emit E040, return null
   - Value is empty string → emit E040, return null

**ISO8601 special rules:**
- Cannot be combined with other tokens (standalone only)
- As inputFormat: parses ISO strings with various timezone formats
- As outputFormat: produces `YYYY-MM-DDTHH:mm:ssZ`

## Verification Requirements

- **Basic reformatting:**
  - `formatDate("2026-03-31T14:22:19Z", "ISO8601", "YYYY-MM-DD")` → `"2026-03-31"`
  - `formatDate("03/31/2026", "MM/DD/YYYY", "YYYY-MM-DD")` → `"2026-03-31"`
  - `formatDate("2026-04-02", "YYYY-MM-DD", "MM/DD/YYYY")` → `"04/02/2026"`

- **Every token:**
  - YYYY extraction and formatting
  - MM extraction and formatting (with zero padding)
  - DD extraction and formatting
  - HH extraction and formatting
  - mm extraction and formatting
  - ss extraction and formatting

- **ISO8601 as input:**
  - With Z timezone: `"2026-03-31T14:22:19Z"`
  - With offset: `"2026-03-31T14:22:19+05:00"`
  - Without timezone: `"2026-03-31T14:22:19"`
  - Date only (no time): `"2026-03-31"` with ISO8601 input (if supported)

- **ISO8601 as output:**
  - `formatDate("03/31/2026 14:22:19", "MM/DD/YYYY HH:mm:ss", "ISO8601")` → `"2026-03-31T14:22:19Z"`

- **Error cases:**
  - `formatDate("not-a-date", "YYYY-MM-DD", "MM/DD/YYYY")` → null + E040
  - `formatDate("", "YYYY-MM-DD", "MM/DD/YYYY")` → null + E040
  - Format mismatch: `formatDate("2026/03/31", "YYYY-MM-DD", "...")` → null + E040 (wrong separator)

- **Edge cases:**
  - Literal characters in format preserved correctly
  - Multiple tokens adjacent (e.g., `"YYYYMMDD"` without separators)
  - Same format in and out (identity transform)

- TypeScript typecheck passes

## Blockers / Risks

- Token parsing without a date library requires careful implementation. The format string parser must correctly identify tokens vs literal characters. Since token names (YYYY, MM, DD, HH, mm, ss) are all uppercase/lowercase letters, they won't conflict with typical separator characters (-, /, :, space, T).
- The `mm` token (minutes) must not be confused with `MM` (month) — parsing is case-sensitive.
- ISO8601 parsing of timezone offsets adds complexity. Decide whether to strip timezone info or account for it.
- Adjacent tokens without separators (e.g., `"YYYYMMDD"`) require the parser to know token widths.

## Notes

- This is the most complex single function to implement due to the format parsing logic.
- ISO8601 input parsing should be lenient with common ISO variants (with/without milliseconds, with/without timezone).
- The implementation should use fixed-width token extraction: YYYY always takes 4 chars, MM/DD/HH/mm/ss always take 2 chars.
- Zero runtime dependencies means no `moment`, `date-fns`, `luxon`, or `temporal`. All parsing is manual string manipulation.
- Consider organizing the implementation into helper functions: `parseDate(value, format)` → components, `formatComponents(components, format)` → string.
- The spec does not mention date validation (e.g., rejecting Feb 30). Focus on format matching, not calendar validity. If the string matches the format pattern numerically, accept it.
