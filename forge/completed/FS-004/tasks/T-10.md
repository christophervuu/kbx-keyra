## Change Requirements

**Pattern for each category module:**

Each category module (e.g., `source-access.ts`) should export a registration function:
```typescript
export function registerSourceAccessFunctions(registry: FunctionRegistry): void {
  registry.registerFunction('source', sourceSignature, sourceImplementation);
  registry.registerFunction('item', itemSignature, itemImplementation);
  // ... etc
}
```

**Barrel `src/engine/functions/index.ts`:**
```typescript
import { FunctionRegistry } from '../registry/function-registry.js';
import { registerSourceAccessFunctions } from './source-access.js';
import { registerTypeConversionFunctions } from './type-conversion.js';
// ... all categories

export function registerAllFunctions(registry: FunctionRegistry): void {
  registerSourceAccessFunctions(registry);
  registerTypeConversionFunctions(registry);
  // ... all categories
}
```

**Engine initialization:**

Ensure `registerAllFunctions(defaultRegistry)` is called. This can be done:
- As a side effect in `src/engine/functions/index.ts` (import triggers registration)
- OR explicitly in `src/engine/index.ts` or `src/engine/registry/index.ts`

The chosen approach should ensure that importing the engine automatically makes all functions available without requiring the consumer to call a setup function.

**Expected function list (37 total):**
- Source access: source, item, parent, constant, external, static (6)
- Type conversion: cast (1)
- Null handling: default, coalesce, isNull (3)
- Conditional: if, eq, neq, gt, gte, lt, lte, and, or, not (10)
- Lookup: valueMap (1)
- String: concat, substring, upper, lower, trim, replace, replaceAll, contains, length (9)
- Date: formatDate (1)
- Math: add, subtract, multiply, divide, round, abs (6)

## Blockers / Risks

- Registration order matters only if there's a dependency between functions (there isn't — functions don't call each other through the registry at runtime). Any order is acceptable.
- Must avoid circular imports between `functions/` and `registry/`. The barrel imports from `registry/` for the type, and individual function files import from `registry/` for types only.

---

## Notes

- The `createRegistry()` factory is useful for tests — each test can create an isolated registry and call `registerAllFunctions` on it independently.
- Consider whether `registerAllFunctions` should also be exported from `src/engine/index.ts` for consumer convenience (e.g., creating custom registries with all built-in functions).
- The function name `"if"` is a JavaScript reserved word but can be used as a string key in the registry without issue.
- The function name `"default"` is also a JS reserved word — same consideration.
