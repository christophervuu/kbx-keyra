## Summary

Implement the `cast(value, targetType)` function that converts values between string, number, and boolean types per the §3.3 cast compatibility matrix. This function handles E020 (unsupported cast), E021 (unknown target type), and null passthrough.

---

## Scope

### In Scope

- Implement `cast(value: any, targetType: string): any`
- Full cast matrix from §3.3:
  - string → number (parse, E020 if not parseable)
  - string → boolean ("true"→true, "false"→false, ""→false, any other→true)
  - number → string (format: 42→"42", 3.14→"3.14")
  - number → boolean (0→false, any other→true)
  - boolean → string (true→"true", false→"false")
  - boolean → number (true→1, false→0)
  - null → any type → null
  - array → any type → E020
  - object → any type → E020
  - same type → no-op
- Emit E020 for unsupported conversions
- Emit E021 for unknown target type (not "string", "number", or "boolean")
- FunctionSignature definition
- Registration export
- Unit tests covering every cell in the matrix

### Out of Scope

- Implicit type coercion anywhere else in the engine
- Cast to "array" or "object" types (not supported per spec)

## Change Requirements

**Signature:**
- Parameters: `value` (any type, required), `targetType` (string, required)
- handlesNull: true (because `cast(null, anyType)` returns null without W001)
- returnType: varies by target type, use a reasonable default

**Implementation logic:**

```
1. If value is null → return null
2. If targetType not in ["string", "number", "boolean"] → emit E021, return null
3. Determine fromType (typeof + array check)
4. If fromType === targetType → return value (no-op)
5. Apply conversion per matrix:
   - string→number: parseFloat, check isNaN → E020 if invalid
   - string→boolean: "true"→true, "false"→false, ""→false, anything else→true
   - number→string: String(value)
   - number→boolean: value === 0 → false, else true
   - boolean→string: String(value)
   - boolean→number: value ? 1 : 0
   - array/object→anything: E020
```

**String to number parsing:**
- Use `Number(value)` or `parseFloat(value)` — must reject strings like `"123abc"` (partial parses)
- The spec says "Parses numeric string. E020 if not parseable." — use strict parsing (entire string must be a valid number)
- Empty string `""` should produce E020 (not parseable as number)

## Blockers / Risks

- Number formatting edge cases: `Number(42).toString()` → `"42"` but what about `0.1 + 0.2`? The spec shows simple examples. Use `String(value)` for number→string which handles standard cases. Document if any floating-point edge cases arise.
- The "any other → true" rule for string→boolean means only "true", "false", and "" have special handling — everything else is true.

---

## Notes

- `cast` must have `handlesNull: true` because `cast(null, "string")` should return `null` directly (not trigger W001 null propagation).
- String→number parsing must be strict: `"123abc"` is NOT a valid number. Use a pattern like: `const num = Number(value); if (isNaN(num) || value.trim() === '') → E020`. Be careful with `Number("")` which returns `0` — the spec implies `""` is not a valid number string (only explicit numeric strings parse).
