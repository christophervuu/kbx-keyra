## Summary

Implement the 6 source access functions that read values from the evaluation context: `source`, `item`, `parent`, `constant`, `external`, and `static`. These functions use `resolvePath()` to traverse objects and emit specific diagnostics (W002, E011, E012) when lookups fail or resolve to null.

---

## Scope

### In Scope

- Implement `source(path)` — resolve path against `context.sourceData`, emit W002 if null
- Implement `item(path)` — resolve path against `context.currentItem` (E010 already handled by evaluator)
- Implement `parent(path)` — resolve path against `context.parentItem` (E013 already handled by evaluator)
- Implement `constant(name)` — look up in `context.constants`, emit E011 if undefined
- Implement `external(name)` — look up in `context.externalSources`, emit E012 if unavailable
- Implement `static(value)` — return value unchanged
- Define `FunctionSignature` for each
- Register each function (export registration function from `source-access.ts`)
- Unit tests for all 6 functions

### Out of Scope

- E010/E013 error emission (evaluator handles these pre-dispatch)
- Null propagation for source/item/parent/constant/external (evaluator handles — but note: `source` must still emit W002 for paths that resolve to null, which is different from null arg propagation)
- Schema-level validation of paths (E030 — that's validation-time, not execution-time)

## Change Requirements

Each function needs a signature and implementation:

**source(path: string): any**
- Signature: `{ parameters: [{ name: "path", type: "string", required: true }], returnType: "string", handlesNull: false }`
  - Note: returnType is effectively `any` but the closest ValueType is not important for dispatch since the evaluator does not check return types. Use a reasonable default.
- Implementation: `resolvePath(context.sourceData, args[0] as string)`, emit W002 if result is null/undefined
- Special: `source("")` returns the entire sourceData object

**item(path: string): any**
- Signature: same shape as source, `handlesNull: false`
- Implementation: `resolvePath(context.currentItem, args[0] as string)`
- Note: evaluator already validates that `currentItem` exists before calling

**parent(path: string): any**
- Same as item but reads from `context.parentItem`

**constant(name: string): any**
- Implementation: check if `name` exists in `context.constants` (use `Object.hasOwn` or `in` operator), if not emit E011 and return null, otherwise return the value
- Note: a constant CAN have a null value — that's different from being undefined

**external(name: string): any**
- Implementation: check if `name` exists in `context.externalSources`, if not emit E012 (warning) and return null
- E012 has severity `warning` per codes.ts

**static(value: any): any**
- Signature: `{ parameters: [{ name: "value", type: "string", required: true }], handlesNull: true }`
  - handlesNull: true because `static(null)` should return null without W001
  - type should be permissive — use a type that won't trigger E005 for any input. Since the evaluator skips type checking for null values already, and static accepts any type, consider using a broad type or noting this design decision.
- Implementation: return `args[0]`

## Blockers / Risks

- The `FunctionParameter.type` field is a `ValueType` which doesn't include `"any"`. Functions like `source`, `static`, `constant` accept string args but return any type. The signature's `returnType` and parameter types need a pragmatic approach — use the actual expected input type (e.g., `"string"` for the path parameter of source). The evaluator's type check is the enforcement point, so if a function legitimately accepts any type (like `static`), the signature type should be set to avoid false E005 errors. This may require using a type that the evaluator won't check against, or accepting the limitation. Document the approach taken.

---

## Notes

- The evaluator already checks E010/E013 before calling item/parent implementations, so those implementations just resolve the path — they don't need to re-check.
- `source("")` is documented to return the entire source object — test this case.
- `constant` must distinguish between "constant exists with null value" and "constant does not exist" — use `Object.hasOwn(context.constants, name)` or `name in context.constants` to check existence.
- The `static` function's signature type is tricky since ValueType has no "any". The pragmatic solution is to set `handlesNull: true` (so null passes through) and make the parameter type permissive. Since the evaluator type-checks against declared parameter types, `static` may need to declare its parameter as a type that won't conflict, or the implementation may rely on the evaluator not checking variadic/any-typed params. Document whatever approach is taken.
