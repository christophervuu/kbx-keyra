## Summary

Implement all 10 conditional logic functions. This includes the `if` branching function, equality/inequality comparators (`eq`, `neq`), numeric comparators (`gt`, `gte`, `lt`, `lte`), and logical operators (`and`, `or`, `not`). Several of these have special null handling behavior that makes them more complex than typical functions.

## Change Requirements

**if(condition: boolean, then: any, else: any): any**
- Signature: 3 required params, `handlesNull: true`
- Implementation: `condition === true ? args[1] : args[2]` (null or false → else branch)
- Note: both `then` and `else` are pre-evaluated by the evaluator — the function just picks which to return

**eq(a: any, b: any): boolean**
- Signature: 2 required params, `handlesNull: true`
- Implementation:
  - If both null → return `true`
  - If one null, other non-null → return `false`
  - Otherwise → `a === b` (strict equality)
- This is a special exception to null propagation per DSL spec

**neq(a: any, b: any): boolean**
- Signature: 2 required params, `handlesNull: true`
- Implementation: logical inverse of eq
  - If both null → return `false`
  - If one null, other non-null → return `true`
  - Otherwise → `a !== b`

**gt(a: number, b: number): boolean**
- Signature: 2 required number params, `handlesNull: false`
- Implementation: `(args[0] as number) > (args[1] as number)`
- E005 type checking handled by evaluator

**gte, lt, lte** — same pattern as gt with respective operators

**and(a: boolean, b: boolean): boolean**
- Signature: 2 required boolean params, `handlesNull: true`
- Implementation (null short-circuit per DSL spec):
  - `and(false, anything)` → `false` (including null)
  - `and(anything, false)` → `false`
  - `and(null, true)` → `null`
  - `and(true, null)` → `null`
  - `and(null, null)` → `null`
  - `and(true, true)` → `true`

**or(a: boolean, b: boolean): boolean**
- Signature: 2 required boolean params, `handlesNull: true`
- Implementation (null short-circuit per DSL spec):
  - `or(true, anything)` → `true` (including null)
  - `or(anything, true)` → `true`
  - `or(null, false)` → `null`
  - `or(false, null)` → `null`
  - `or(null, null)` → `null`
  - `or(false, false)` → `false`

**not(a: boolean): boolean**
- Signature: 1 required boolean param, `handlesNull: false`
- Implementation: `!(args[0] as boolean)`
- Standard null propagation (evaluator short-circuits null → null + W001)

## Blockers / Risks

- The `and`/`or` null short-circuit logic is the most complex part. The truth tables must match the DSL spec exactly. Careful attention to the asymmetric cases: `and(null, false)` → `false` but `and(null, true)` → `null`.

---

## Notes

- `and`/`or` are NOT JavaScript `&&`/`||`. They implement three-valued logic (true/false/null) with specific short-circuit rules defined in the DSL spec.
- `eq` uses strict equality (`===`). Per DSL spec, `eq(42, "42")` → `false` because types differ.
- The `if` function doesn't need to check whether `condition` is actually a boolean — the evaluator's type check handles that. But since it's `handlesNull: true`, it may receive null, and null is treated as false.
- For `and`/`or`, the implementation must handle null as a third value. The signature says type is "boolean" but since `handlesNull: true`, the actual arguments may be null. The implementation should check explicitly for `null`, `true`, and `false`.
