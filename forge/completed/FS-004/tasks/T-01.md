## Summary

Add an `addDiagnostic` callback to the `EvaluationContext` interface so function implementations can emit diagnostics without throwing. Update the evaluator to bind this callback to its internal diagnostics array when constructing invocation contexts. Create the `src/engine/functions/` directory skeleton with placeholder files for each category.

---

## Change Requirements

After this task is complete:

1. `EvaluationContext` has an `addDiagnostic` field of type `(diagnostic: Diagnostic) => void`
2. The evaluator's `evaluate()` function creates the root context with `addDiagnostic` bound to push onto its internal diagnostics array
3. Any diagnostics emitted via `context.addDiagnostic(...)` inside a function implementation appear in the final `EvaluationResult.diagnostics` array
4. The `src/engine/functions/` directory exists with empty category files (each exports nothing initially, or exports an empty registration function)
5. The `tests/engine/functions/` directory exists
6. Existing evaluator tests continue to pass (update any test context construction to include `addDiagnostic`)

The `addDiagnostic` binding pattern:
```typescript
// In evaluate() or evaluateFunctionCall():
const addDiagnostic = (diagnostic: Diagnostic): void => {
  state.diagnostics.push(diagnostic);
};

const invocationContext: EvaluationContext = {
  ...context,
  addDiagnostic,
};
```
