## Summary

Implement the `valueMap(value, mappings, fallback?)` function that performs static lookup table resolution. This function looks up a value in an object mapping and returns the corresponding output, with optional fallback. It has special null handling and emits E060 (invalid mappings) and W003 (no match).

---

## Scope

### In Scope

- Implement `valueMap(value: any, mappings: object, fallback?: any): any`
- Handle null value → return fallback (or null if no fallback)
- Validate that mappings is an object → E060 if not
- Convert value to string for key lookup (per spec: "The engine converts value to a string for lookup purposes")
- Return matched value from mappings
- Emit W003 on no match, return fallback or null
- FunctionSignature with `handlesNull: true` and optional third parameter
- Registration export
- Unit tests

### Out of Scope

- Regex or pattern matching in keys (keys are exact string matches)
- Dynamic mappings (mappings are always object literals from the AST)

## Change Requirements

**Signature:**
- Parameters:
  - `value` — required, any type, handlesNull applies
  - `mappings` — required, object type
  - `fallback` — optional, any type
- `handlesNull: true`

**Implementation logic:**
```
1. If value is null → return fallback (args[2]) or null if no fallback
2. If mappings is not a plain object (typeof !== 'object' || Array.isArray || null) → emit E060, return null
3. Convert value to string: String(value)
4. Look up stringified value in mappings object
5. If found → return the mapped value
6. If not found:
   a. Emit W003
   b. Return fallback if provided, else null
```

**Key conversion note:** Per the DSL spec, "Keys in the mappings object are always strings (JSON object keys). The engine converts value to a string for lookup purposes when matching keys." This means `valueMap(42, {"42": "found"})` → `"found"`.

## Verification Requirements

- **Match found:** `valueMap("web", {"web": "WEB_PORTAL"}, "UNKNOWN")` → `"WEB_PORTAL"`
- **No match with fallback:** `valueMap("mobile", {"web": "WEB_PORTAL"}, "UNKNOWN")` → `"UNKNOWN"` + W003
- **No match without fallback:** `valueMap("missing", {"a": "b"})` → `null` + W003
- **Null value with fallback:** `valueMap(null, {"a": "b"}, "default")` → `"default"`
- **Null value without fallback:** `valueMap(null, {"a": "b"})` → `null`
- **Non-object mappings:** `valueMap("x", "not-an-object")` → null + E060
- **Array as mappings:** `valueMap("x", [1,2,3])` → null + E060
- **Null mappings:** `valueMap("x", null)` → null + E060
- **Numeric value lookup:** `valueMap(42, {"42": "found"})` → `"found"` (string conversion)
- **Boolean value lookup:** `valueMap(true, {"true": "yes"})` → `"yes"`
- **Empty mappings object:** `valueMap("x", {})` → null + W003
- TypeScript typecheck passes

## Blockers / Risks

- The third parameter (fallback) is optional. The signature must correctly declare it as `required: false` so the evaluator allows 2 or 3 arguments.
- Need to handle the case where `args[2]` is `undefined` (not provided) vs `null` (explicitly passed as null). When not provided, the array won't have an element at index 2, so `args[2]` will be `undefined`. Treat `undefined` fallback as "no fallback provided" → return `null`.

---

## Notes

- The `mappings` argument comes from an `ObjectTemplate` AST node that the evaluator evaluates into a plain object. So at runtime, `args[1]` will be a plain JS object with string keys and evaluated values.
- W003 should include the value that didn't match in its message template parameters.
- The spec says value is matched "by strict equality" but then also says "The engine converts value to a string for lookup purposes when matching keys." This means: stringify the value, then do string key lookup in the object. This is different from strict equality — it's string-key matching.
