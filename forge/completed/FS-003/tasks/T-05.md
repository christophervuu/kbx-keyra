## Summary

Write a comprehensive test suite covering all evaluator behaviors: literal evaluation, function dispatch, null propagation, type mismatch halt, scope stack behavior, path resolution, recursion limits, object templates, diagnostic collection, trace mode at both verbosity levels, and nested function calls. Uses mock function implementations to exercise the evaluator without depending on FS-004/FS-005.

---

## Scope

### In Scope

- Test file at `tests/engine/dsl/evaluator.test.ts`
- Test file at `tests/engine/dsl/resolve-path.test.ts` (if not already created in T-02)
- Mock function registrations for testing (upper, lower, concat, default, coalesce, item, etc.)
- Test categories:
  - Literal evaluation (all four types) — AE-01
  - Function dispatch (registered function called correctly) — AE-02
  - Unknown function → E002 — AE-03
  - Arity mismatch → E003 — AE-04
  - Null propagation for standard functions (W001) — AE-05
  - Null propagation bypass for handlesNull functions — AE-06
  - Scope stack: item reads top via ExecutionContext.currentItem — AE-07
  - Scope stack: item outside context → E010 — AE-08
  - Path resolution: dot notation — AE-09
  - Path resolution: bracket + numeric — AE-10
  - Path resolution: missing intermediate → null — AE-11
  - Recursion depth limit → E004 — AE-12
  - Object template evaluation — AE-13
  - Nested function calls (3+ levels) — AE-14
  - Trace mode records FunctionCall entries only at default verbosity — AE-15
  - Multiple diagnostics collected — AE-16
  - Type mismatch halts function call → E005 — AE-17
  - Trace mode with "all" verbosity includes literals — AE-18
- Additional edge case tests:
  - Variadic function arity checking
  - Empty argument list for zero-param functions
  - Null propagation with multiple null arguments
  - Object template with nested function call values
  - Recursion at exactly the limit (32) succeeds, 33 fails
  - Implementation throw is caught and converted to diagnostic
  - ExecutionContext.currentItem/parentItem populated correctly at various stack depths

### Out of Scope

- Testing specific DSL functions (FS-004/FS-005 tests)
- Integration tests with the full execute() pipeline
- Performance benchmarks
- UI integration tests

## Notes

- Use `createRegistry()` from `src/engine/registry/function-registry.ts` for test isolation — each test gets its own registry with only the mock functions it needs.
- For scope stack tests, set up the `EvaluationContext.scopeStack` directly with test data. The actual push/pop mechanism (called by array functions) is FS-005 — here we just verify the evaluator reads from the correct stack position and populates ExecutionContext correctly.
- For AE-14 (nested calls), construct an AST manually that nests function calls 3 levels deep and verify inside-out evaluation order.
- For AE-12 (recursion), programmatically generate a deeply nested AST (function calling function calling function...) to hit the depth limit.
- For AE-17 (type mismatch), register a mock function with a spy/flag and verify the flag is NOT set after evaluate returns with E005.
- For AE-15 vs AE-18 (trace verbosity), run the same AST with different `traceVerbosity` settings and verify the trace array length and contents differ appropriately.
