## Summary

Implement the core `evaluate(node: AstNode, context: EvaluationContext): EvaluationResult` function — the recursive expression evaluator that handles all AST node types, dispatches function calls via the registry, applies centralized null propagation, halts on type mismatch (E005), constructs ExecutionContext from scope stack before dispatch, tracks recursion depth, evaluates object templates, and collects diagnostics and configurable trace entries.

---

## Scope

### In Scope

- `evaluate(node, context)` function — main entry point
- Literal evaluation: StringLiteral, NumberLiteral, BooleanLiteral, NullLiteral → return value directly
- FunctionCall dispatch:
  - Registry lookup (emit E002 if not found)
  - Arity checking (emit E003 if mismatch, respecting variadic parameters)
  - Recursive argument evaluation
  - Runtime type checking — emit E005 and halt (return null) for type mismatches (no implicit coercion per DSL spec §3.2)
  - Null propagation (emit W001 and short-circuit for standard functions; pass through for `handlesNull: true`)
  - ExecutionContext construction from scope stack (populate `currentItem`/`parentItem`) before calling implementation
  - Call implementation with evaluated args and EvaluationContext
- ObjectTemplate evaluation: evaluate each property value, assemble result object
- Recursion depth tracking: increment on entry, check against `options.maxRecursionDepth` (default 32), emit E004 if exceeded
- Diagnostic accumulation: collect diagnostics from all sub-evaluations into result
- Trace recording with configurable verbosity:
  - `"functions"` (default): trace only FunctionCall nodes (name, args, result)
  - `"all"`: trace every node including literals
- Exception safety: catch implementation throws, convert to diagnostic, return null
- Place in `src/engine/dsl/evaluator.ts`

### Out of Scope

- Scope stack push/pop logic (array functions in FS-005 call pushScope/popScope)
- Specific DSL function implementations
- The full execute() pipeline
- Public API export wiring (T-04)
- Comprehensive test suite (T-05)
- Path resolution implementation (T-02)

## Change Requirements

After this task:

- `evaluate(node: AstNode, context: EvaluationContext): EvaluationResult` exists in `src/engine/dsl/evaluator.ts`
- The function handles all 6 AST node types:
  - `StringLiteral` → `{ value: node.value, diagnostics: [] }`
  - `NumberLiteral` → `{ value: node.value, diagnostics: [] }`
  - `BooleanLiteral` → `{ value: node.value, diagnostics: [] }`
  - `NullLiteral` → `{ value: null, diagnostics: [] }`
  - `FunctionCall` → dispatch flow (lookup → arity → evaluate args → type check → null prop → construct ExecutionContext → call)
  - `ObjectTemplate` → evaluate each property value, return assembled object
- ExecutionContext construction:
  - Before dispatching to a function implementation, the evaluator constructs an `ExecutionContext` from the `EvaluationContext`'s scope stack
  - `currentItem` = last element of scopeStack (or undefined if empty)
  - `parentItem` = second-to-last element (or undefined if depth < 2)
  - This ExecutionContext is either passed within EvaluationContext or alongside it (per T-01 type design)
- Type mismatch behavior:
  - E005 halts the function call — implementation is NOT called
  - Returns null with E005 diagnostic
  - Consistent with E002 and E003 behavior (all pre-dispatch checks follow same pattern)
- Null propagation is centralized:
  - Check if function signature has `handlesNull: true`
  - If not, scan evaluated args for null values in required parameter positions
  - If null found, emit W001 and return `{ value: null }` without calling implementation
  - If `handlesNull: true`, pass all args through to implementation
- Recursion depth:
  - Context carries a depth counter (or the function accepts/increments one internally)
  - Before recursing, check if depth >= maxRecursionDepth
  - If exceeded, emit E004, return `{ value: null }`
- Trace collection:
  - When `context.options.trace` is true:
    - If `traceVerbosity` is `"functions"` (or unset/default): record entry only for FunctionCall nodes
    - If `traceVerbosity` is `"all"`: record entry for every node
  - Entry includes: node type, function name (if applicable), evaluated argument values (if function), output value
- Diagnostic accumulation:
  - Sub-evaluation diagnostics are merged into the parent's result
  - The evaluator never throws for data errors — always returns a result
- Exception handling:
  - If a function implementation throws, catch it, emit a diagnostic, return null for that expression

## Notes

- The evaluate function will be called recursively for nested expressions and by array function implementations (map/filter/find). Ensure the depth tracking works correctly across these re-entry patterns.
- Arity checking must account for variadic parameters (e.g., `concat` accepts 2+ arguments). The check is: `actualArgs >= requiredParams && (hasVariadic || actualArgs <= totalParams)`.
- For type checking (E005), compare the runtime type of evaluated arguments against `FunctionParameter.type`. Use a simple typeof-based check plus Array.isArray for arrays. The `ValueType` enum is: string, number, boolean, null, array, object. Type checking happens AFTER null propagation check — if null propagation already short-circuited, E005 is not reached.
- The null propagation check only considers `required: true` parameters. Optional parameters that are omitted (undefined) are not the same as explicit null.
- The `evaluate` callback placed on `EvaluationContext` (from T-01) should reference THIS function. The evaluator sets `context.evaluate = evaluate` (or it's set once at the top-level call and preserved through recursion).
