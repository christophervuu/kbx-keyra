# Infrastructure

This document defines the Phase 1 infrastructure architecture — IaC framework, resource inventory, naming conventions, environment configuration, local development approach, Lambda packaging, and deployment conventions.

Agents must load this document before implementing or modifying IaC resources, environment configuration, or deployment scripts.

---

## 1) Purpose and Scope

Purpose:
- Define the infrastructure-as-code approach for Phase 1 AWS resources
- Establish naming and configuration conventions for all deployed resources
- Document environment variable mapping across local/dev/prod
- Describe local development setup for backend integration testing
- Codify Lambda packaging and cold start mitigation strategies

Scope:
- SAM template structure and resource definitions
- DynamoDB, S3, API Gateway, Lambda, OpenSearch Serverless, Step Functions
- Environment configuration and local emulation
- Build and deployment workflow

Out of scope:
- CI/CD pipeline (GitHub Actions, CodePipeline) — future spec
- Authentication/authorization infrastructure (Cognito, API keys)
- Monitoring/alerting (CloudWatch alarms, dashboards)
- Multi-region or disaster recovery
- Custom domain / TLS / Route53
- AI runtime infrastructure beyond existing handlers

---

## 2) IaC Framework

**Choice: AWS SAM (Serverless Application Model)**

Rationale:
- Lambda-native: first-class support for Lambda, API Gateway, DynamoDB, Step Functions
- Local development: `sam local start-api` and `sam local invoke` for testing without deploying
- esbuild integration: built-in TypeScript bundling via `BuildMethod: esbuild`
- CloudFormation superset: full access to any CloudFormation resource when needed
- Minimal overhead: single `template.yaml` file, no build framework to maintain

**Template location:** `template.yaml` (repository root)
**Config location:** `samconfig.toml` (repository root)

## 4) Naming Conventions

- **Org prefix:** `{Org}-` (defaults to `kbx`) identifies the organization.
- **App name:** `keyra-` identifies the application.
- **Stage qualifier:** `{Stage}-` (dev/staging/prod) supports parallel environments.
- **Full pattern:** `{Org}-keyra-{Stage}-{suffix}` for globally unique resources (S3).
- **Non-global resources** (DynamoDB, Step Functions): `{Stage}-keyra-{resource}` (no org prefix needed since they're account-scoped).
- **Lambda functions:** SAM auto-generates names from stack name + logical ID. No explicit naming needed.
- **GSI naming:** descriptive hyphenated name matching the access pattern (e.g., `projectId-index`).

| `OPENSEARCH_ENDPOINT` | *(not set — mock in tests)* | Collection endpoint | Collection endpoint |

### Endpoint Override Pattern

SDK clients check for endpoint override environment variables:
```typescript
const dynamoClient = new DynamoDBClient({
  ...(process.env.DYNAMODB_ENDPOINT && { endpoint: process.env.DYNAMODB_ENDPOINT }),
});
```

When the variable is not set (deployed environments), SDK uses default AWS endpoints.

## 6) Local Development

### Services

| Service | Image | Port | Purpose |
|---------|-------|------|---------|
| DynamoDB Local | `amazon/dynamodb-local:latest` | 8000 | Table operations |
| LocalStack | `localstack/localstack:latest` | 4566 | S3 operations |

OpenSearch is not emulated locally. Tests that touch OpenSearch use mocked clients.

### Setup Flow

1. `docker-compose up -d` — start local services
2. `scripts/setup-local.sh` — create tables and bucket (idempotent)
3. `sam local start-api --env-vars env.local.json` — start API locally
4. Integration tests run against `http://localhost:3000`

### Files

| File | Purpose |

| `scripts/setup-local.sh` | Create tables and bucket in local emulators |
| `.env.example` | Reference for all environment variables |
| `env.local.json` | SAM local environment overrides |

## 7) Lambda Packaging

### Bundling

- **Tool:** esbuild via SAM `BuildMethod: esbuild`
- **Target:** `node20`
- **External:** `@aws-sdk/*` (provided by Lambda runtime, not bundled)
- **Tree-shaking:** enabled
- **Source maps:** enabled for dev/staging, disabled for prod
- **Minify:** disabled (readability > marginal size savings)

### Bundle Size Limits

- **Threshold:** 5MB per function
- **Enforcement:** `scripts/check-bundle-sizes.sh` reports sizes and fails CI if exceeded
- **Typical size:** ~200KB–1MB per function (esbuild with externalized SDK)

### Per-Function Bundling

Each Lambda function is independently bundled. Shared code from `src/lambda/shared/` and `src/lib/persistence/` is inlined into each bundle by esbuild. This approach:
- Keeps cold starts fast (each function loads only its code)
- Eliminates cross-function deployment coupling
- Makes bundle size per function predictable

## 8) Cold Start Strategy

| Factor | Configuration | Impact |
|--------|---------------|--------|
| Memory | 256MB default, 512MB for schema ingestion/query | Higher memory = faster CPU allocation = faster init |
| Bundle size | < 5MB, typically < 1MB | Smaller bundles load faster from S3 |
| SDK externals | `@aws-sdk/*` not bundled | Runtime-provided SDK initializes faster |
| Client reuse | Module-level SDK client instantiation | Warm invocations reuse clients |
| Provisioned concurrency | Configurable parameter, off by default | Eliminates cold starts entirely for critical paths |

### Critical Path Functions

These functions are on the user's hot path (TTFSM impact):
- `GetProjectFunction` — project load
- `ListMappingsFunction` — mapping list on project entry
- `GetMappingFunction` — mapping editor load
- `QuerySchemaNodesFunction` — schema search during mapping

These get 512MB memory. Provisioned concurrency is a parameter that can be enabled per-stage for prod.

## 9) Deployment Flow

```
sam validate          → Lint template syntax and references
sam build             → esbuild each function, package artifacts
sam deploy            → Upload to S3, create/update CloudFormation stack
                        --config-env {stage}
                        --parameter-overrides Stage={stage}
```

### Stack Outputs

After deployment, stack outputs provide:
- `ApiUrl` — API Gateway endpoint URL
- `StorageBucketName` — S3 bucket name
- Table ARNs (for cross-stack reference if needed)
- `OpenSearchCollectionEndpoint` — OpenSearch endpoint

## 10) Key Decisions

| Decision | Resolution | Rationale |
|----------|-----------|-----------|
| IaC framework | AWS SAM | Lambda-native, `sam local` support, esbuild integration, single template |
| OpenSearch provisioning | IaC target, separately allowed | Long creation time; allow separate provisioning in Phase 1 to avoid blocking |
| AI Lambdas | Excluded from Phase 1 stack | Phase 1 scope excludes AI; separate AI infra spec will follow |
| S3 naming | `{Org}-keyra-{Stage}-{AccountId}` | Org prefix for clarity and safety across accounts |
| SAM Accelerate | Optional, not required | Useful for iteration but not a build-system dependency |
| fieldName-index GSI SK | Single concatenated `schemaId#path` attribute | Matches documented model, simple, avoids filter overhead |
